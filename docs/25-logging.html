1. log 套件

log 是 Go 最早的日誌套件。套件層級的 log.Println、log.Printf 寫到 stderr，每一行前面加上日期和時間；要自己決定寫到哪裡、前面加什麼，用 log.New 建立自己的 *log.Logger：

func logDemo() {
	kitchen := log.New(os.Stdout, "[廚房] ", 0)
	kitchen.Println("開火")
	kitchen.Printf("第 %d 桌 %s 出餐", 7, "排骨飯") // 結尾沒有換行，log 會自動補上

	counter := log.New(kitchen.Writer(), "[外場] ", kitchen.Flags())
	counter.Println("叫號", 42)
}
[廚房] 開火
[廚房] 第 7 桌 排骨飯 出餐
[外場] 叫號 42
  • log 會自動補上結尾的換行，Printf 不用寫 \n。
  • 旗標用 | 組合：log.LstdFlags（日期加時間，預設值）、log.Lmicroseconds、log.LUTC、log.Lshortfile（印出 log.go:12: 這樣的檔名和行號）、log.Lmsgprefix（前綴改放在訊息前面，而不是一行的最前面）。本章的範例用 0，輸出才會每次一樣。
  • *log.Logger 可以被很多 goroutine 同時使用，每一行都會完整地寫出去，不會和別人的交錯。

log.Fatal 等於印出訊息再 os.Exit(1)，log.Panic 等於印出訊息再 panic。Fatal 不會執行 defer，檔案沒有 Close、緩衝區沒有 Flush 就結束了；它和 os.Exit 一樣只該出現在 main 裡（21 章）。

log 的限制在於它只有一行文字。正式環境的 log 通常送到集中的平台，有人要問「今天 ERROR 有幾筆」「七號桌的所有紀錄」「等超過 60 秒的單」，這些問題需要欄位，不是字串。這就是 slog 要解決的事。

2. slog：結構化的紀錄

log/slog（Go 1.21 起）的每一筆紀錄由一個固定的訊息加上一組屬性組成。訊息說發生什麼事，屬性是這次的資料，寫成交錯的鍵值對：

func dropTime(groups []string, a slog.Attr) slog.Attr {
	if a.Key == slog.TimeKey && len(groups) == 0 {
		return slog.Attr{} // 回傳空的 Attr 就是不輸出這個欄位
	}
	return a
}

var demoOptions = &slog.HandlerOptions{ReplaceAttr: dropTime}

func textJSONDemo() {
	text := slog.New(slog.NewTextHandler(os.Stdout, demoOptions))
	text.Info("出餐", "table", 7, "dish", "排骨飯", "note", "少飯 不要辣", "wait", 95*time.Second)

	jsonLog := slog.New(slog.NewJSONHandler(os.Stdout, demoOptions))
	jsonLog.Info("出餐", "table", 7, "dish", "排骨飯", "note", "少飯 不要辣", "wait", 95*time.Second)
}
level=INFO msg=出餐 table=7 dish=排骨飯 note="少飯 不要辣" wait=1m35s
{"level":"INFO","msg":"出餐","table":7,"dish":"排骨飯","note":"少飯 不要辣","wait":95000000000}
  • TextHandler 寫成 key=value，值裡有空白或特殊字元時才加引號，適合開發時在終端機看；JSONHandler 每一筆一行 JSON，適合送到 log 平台查詢。
  • 兩個 Handler 都可以傳 *slog.HandlerOptions，nil 就是預設值。ReplaceAttr 會對每個屬性呼叫一次，可以改名、改值，回傳空的 Attr 就是不輸出。本章的範例用它拿掉時間；正式的程式要保留時間，AddSource: true 還會加上原始碼的檔名和行號。
  • time.Duration 在 TextHandler 是 1m35s，在 JSONHandler 是奈秒數 95000000000。查 JSON 的人不一定知道單位，常見的做法是在 key 寫上單位（wait_ms）並傳整數。

還沒設定之前，套件層級的 slog.Info 經過 log 套件寫到 stderr。slog.SetDefault 換掉預設的 Logger 之後，連舊的 log.Println 也會改走新的 Handler。所以一個專案可以先換掉 main 裡的設定，舊的程式碼慢慢改：

func main() {
	log.Println("開火")
	slog.Info("出餐", "table", 7)

	slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stderr, nil)))
	log.Println("舊的程式碼呼叫 log")
	slog.Info("出餐", "table", 8)
}

實際執行的輸出（stderr，時間每次不同）

2026/11/20 20:53:36 開火
2026/11/20 20:53:36 INFO 出餐 table=7
{"time":"2026-11-20T20:53:36.201907+08:00","level":"INFO","msg":"舊的程式碼呼叫 log"}
{"time":"2026-11-20T20:53:36.201927+08:00","level":"INFO","msg":"出餐","table":8}

3. 屬性與 With

鍵值對很方便，但 key 和 value 的位置全靠你自己對齊。slog.Int、slog.String、slog.Any 這些函式直接建立一個 slog.Attr，型別寫在名稱上，不會錯位；slog.Group 把幾個屬性收成一組。兩種寫法可以混用：

func attrsDemo() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, demoOptions))
	logger.Warn("出餐延遲",
		slog.Int("table", 7),
		slog.Group("order", slog.String("dish", "排骨飯"), slog.Int("qty", 2)),
		slog.Any("err", errors.New("排骨還在炸")),
	)

	// LogAttrs 只收 Attr，不收鍵值對；在很常執行的路徑上，它的配置比較少。
	logger.LogAttrs(context.Background(), slog.LevelInfo, "出餐",
		slog.Int("table", 8), slog.String("dish", "雞腿飯"))
}
{"level":"WARN","msg":"出餐延遲","table":7,"order":{"dish":"排骨飯","qty":2},"err":"排骨還在炸"}
{"level":"INFO","msg":"出餐","table":8,"dish":"雞腿飯"}
  • error 的值會用 Error() 的結果。慣例是 key 寫 err，一筆紀錄只放一個錯誤。
  • 群組在 JSON 裡是巢狀的物件，在 TextHandler 裡是 order.dish=排骨飯。手上已經是 []slog.Attr 的話，用 slog.GroupAttrs（Go 1.25 起）。
  • slog.Int 這類函式把值存在 slog.Value 裡，整數、字串、時間這些常見的型別不會被轉成 any，少一次記憶體配置。

鍵值對少了一個時，slog 不會報錯，而是把落單的值記成 !BADKEY。go vet 會檢查 slog 的參數，這種錯誤在 commit 之前就能抓到：

package main

import "log/slog"

func main() {
	table, dish := 7, "排骨飯"
	slog.Info("出餐", "table", table, dish)
	slog.Info("出餐", table, "dish", dish)
}
go vet .

輸出

main.go:7:2: call to slog.Info missing a final value
main.go:8:22: slog.Info arg "table" should be a string or a slog.Attr (possible missing key or value)

這支程式照樣能執行，兩行分別記成 table=7 !BADKEY=排骨飯 和 !BADKEY=7 dish=排骨飯。沒有跑 vet 的話，要等到有人查 log 才會發現。

logger.With(...) 回傳一個新的 Logger，之後每一筆都自動帶著這些屬性；WithGroup 讓之後加上的屬性都放進一個群組：

func withDemo() {
	base := slog.New(slog.NewTextHandler(os.Stdout, demoOptions))
	order := base.With("order_id", "A042", "table", 7)
	order.Info("接單")
	order.Info("出餐", "dish", "排骨飯")

	pay := order.WithGroup("pay")
	pay.Info("付款", "method", "悠遊卡", "amount", 225)

	base.Info("打烊")
}
level=INFO msg=接單 order_id=A042 table=7
level=INFO msg=出餐 order_id=A042 table=7 dish=排骨飯
level=INFO msg=付款 order_id=A042 table=7 pay.method=悠遊卡 pay.amount=225
level=INFO msg=打烊
  • With 的屬性只格式化一次（在 Handler 的 WithAttrs 裡），之後每一筆直接用，不會每次重新處理。
  • With 不會改變原本的 Logger。在迴圈裡寫 logger = logger.With(...) 會讓屬性一圈一圈累積下去（練習 6）。

4. 層級

層級的型別是 slog.Level，其實就是 int，數字越大越嚴重：

func levelsDemo() {
	fmt.Println(slog.LevelDebug, slog.LevelInfo, slog.LevelWarn, slog.LevelError)
	fmt.Println(int(slog.LevelDebug), int(slog.LevelInfo), int(slog.LevelWarn), int(slog.LevelError))
	fmt.Println(slog.LevelInfo+2, slog.Level(-8))

	for _, s := range []string{"warn", "INFO+2", "verbose"} {
		var lv slog.Level
		if err := lv.UnmarshalText([]byte(s)); err != nil {
			fmt.Println(s, "→", err)
			continue
		}
		fmt.Println(s, "→", lv)
	}
}
DEBUG INFO WARN ERROR
-4 0 4 8
INFO+2 DEBUG-4
warn → WARN
INFO+2 → INFO+2
verbose → slog: level string "verbose": unknown name
  • 不在四個名稱上的值，印成「名稱加減差距」：2 在 INFO 和 WARN 之間，是 INFO+2；-8 比 DEBUG 還小 4，是 DEBUG-4。
  • Level.UnmarshalText 讀的就是這種文字，而且不分大小寫。從旗標或環境變數讀層級時直接用它（練習 1）。

每個層級什麼時候用，常見的分法是：Debug 只在找問題時打開；Info 是正常的重要事件（接單、結帳完成）；Warn 是不正常但程式自己處理掉了（重試成功、庫存快沒了）；Error 是需要人處理的失敗。

Handler 只記門檻以上的紀錄，門檻由 HandlerOptions.Level 決定，預設是 Info。傳一個 *slog.LevelVar 進去，就能在程式執行中調整門檻：

func levelVarDemo() {
	var level slog.LevelVar // 零值是 Info
	logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{Level: &level, ReplaceAttr: dropTime}))

	logger.Debug("看不到", "step", 1)
	logger.Info("接單", "table", 7)

	level.Set(slog.LevelDebug) // 例如收到管理指令，暫時打開 debug
	logger.Debug("看得到了", "step", 2)

	level.Set(slog.LevelWarn)
	logger.Info("看不到", "table", 8)
	logger.Warn("排骨快賣完了", "left", 3)
	fmt.Println("Info 要不要記：", logger.Enabled(context.Background(), slog.LevelInfo))
}
level=INFO msg=接單 table=7
level=DEBUG msg=看得到了 step=2
level=WARN msg=排骨快賣完了 left=3
Info 要不要記： false
  • LevelVar 可以被很多 goroutine 同時讀寫。常見的用法是收到 signal（21 章）或管理用的 HTTP 請求時，暫時把門檻調到 Debug。
  • logger.Enabled(ctx, level) 回答「這個層級現在會不會被記」。要記的資料計算起來很貴時，先問一下再算；下一節的 LogValuer 是另一種做法。

5. LogValuer

型別實作 slog.LogValuer（只有一個方法 LogValue() slog.Value），slog 記錄它的時候就用 LogValue 回傳的值，而不是型別本身。最重要的用途是遮蔽個資和秘密：

type Phone string

func (p Phone) LogValue() slog.Value {
	s := string(p)
	if len(s) < 7 {
		return slog.StringValue("***")
	}
	return slog.StringValue(s[:4] + "***" + s[len(s)-3:])
}

type Customer struct {
	ID      int
	Name    string
	Phone   Phone
	Address string
}

func (c Customer) LogValue() slog.Value {
	return slog.GroupValue(slog.Int("id", c.ID), slog.Any("phone", c.Phone))
}

func valuerDemo() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, demoOptions))
	c := Customer{ID: 1024, Name: "王小明", Phone: "0912345678", Address: "台北市信義路五段 7 號"}
	logger.Info("外送訂單", "customer", c)
	logger.Info("回撥", "phone", c.Phone)
}
{"level":"INFO","msg":"外送訂單","customer":{"id":1024,"phone":"0912***678"}}
{"level":"INFO","msg":"回撥","phone":"0912***678"}
  • LogValue 回傳 slog.GroupValue(...) 就變成一個群組。群組裡的 Phone 又是 LogValuer，slog 會繼續展開。
  • 密碼、token、完整的卡號和身分證字號不該出現在 log 裡。log 會被很多人看、保存很久、複製到很多地方，比資料庫難保護得多。
  • 不是自己的型別、或想用 key 統一過濾（例如所有叫 password 的屬性），用 HandlerOptions 的 ReplaceAttr（練習 2）。

LogValue 只在這筆紀錄真的要寫出去時才被呼叫。被層級擋掉的紀錄，LogValue 一次都不會執行，所以很花時間才算得出來的資料也可以放心放進去：

type report struct{ calls *int }

func (r report) LogValue() slog.Value {
	*r.calls++
	return slog.StringValue("今日營收 12,345 元")
}

func lazyDemo() {
	logger := slog.New(slog.NewTextHandler(os.Stdout, demoOptions)) // 沒有設定 Level，最低是 Info
	calls := 0
	logger.Debug("報表", "report", report{&calls})
	fmt.Println("計算了", calls, "次")
	logger.Info("報表", "report", report{&calls})
	fmt.Println("計算了", calls, "次")
}
計算了 0 次
level=INFO msg=報表 report="今日營收 12,345 元"
計算了 1 次

6. Handler

slog.Handler 是一個有四個方法的 interface：Enabled（這個層級要不要記）、Handle（記一筆）、WithAttrs 和 WithGroup（logger.With、WithGroup 時呼叫，回傳一個新的 Handler）。最常見的需求不是從頭寫一個，而是組合或包裝現有的。

要同時寫到兩個地方，用 slog.NewMultiHandler（Go 1.26 起）。每個 Handler 有自己的格式和門檻，例如全部寫到 stdout，Warn 以上另外寫一份 JSON 給告警系統：

func multiDemo() {
	var alerts strings.Builder // 實際的程式裡可能是檔案，或送到告警系統的 Writer
	logger := slog.New(slog.NewMultiHandler(
		slog.NewTextHandler(os.Stdout, demoOptions),
		slog.NewJSONHandler(&alerts, &slog.HandlerOptions{Level: slog.LevelWarn, ReplaceAttr: dropTime}),
	))
	logger.Info("接單", "table", 7)
	logger.Warn("排骨快賣完了", "left", 3)
	logger.Error("收銀機斷線", "err", errors.New("connection refused"))
	fmt.Print("告警：\n", alerts.String())
}
level=INFO msg=接單 table=7
level=WARN msg=排骨快賣完了 left=3
level=ERROR msg=收銀機斷線 err="connection refused"
告警：
{"level":"WARN","msg":"排骨快賣完了","left":3}
{"level":"ERROR","msg":"收銀機斷線","err":"connection refused"}

另一個常見的需求是 request id：一個請求經過很多函式，每一筆 log 都應該帶著同一個 id，才查得出「這個請求發生了什麼事」。id 放在 context 裡（18 章），但內建的 Handler 不會去看 context 的值，所以自己包一層：

type requestIDKey struct{}

func withRequestID(ctx context.Context, id string) context.Context {
	return context.WithValue(ctx, requestIDKey{}, id)
}

type ctxHandler struct {
	slog.Handler
}

func (h ctxHandler) Handle(ctx context.Context, r slog.Record) error {
	if id, ok := ctx.Value(requestIDKey{}).(string); ok {
		r.AddAttrs(slog.String("request_id", id))
	}
	return h.Handler.Handle(ctx, r)
}

func (h ctxHandler) WithAttrs(attrs []slog.Attr) slog.Handler {
	return ctxHandler{h.Handler.WithAttrs(attrs)}
}

func (h ctxHandler) WithGroup(name string) slog.Handler {
	return ctxHandler{h.Handler.WithGroup(name)}
}

嵌入 slog.Handler 之後，只要覆寫需要的方法，其他的方法自動用裡面那個的（09 章）。陷阱就在這裡：WithAttrs、WithGroup 也會「自動」用裡面那個的，而它們回傳的是裡面那個 Handler，外面那一層就不見了。把只覆寫 Handle 的版本放在一起比較：

type handleOnly struct {
	slog.Handler
}

func (h handleOnly) Handle(ctx context.Context, r slog.Record) error {
	return ctxHandler{h.Handler}.Handle(ctx, r)
}

func contextDemo() {
	ctx := withRequestID(context.Background(), "r-7f3a")
	inner := slog.NewTextHandler(os.Stdout, demoOptions)
	for _, h := range []slog.Handler{ctxHandler{inner}, handleOnly{inner}} {
		fmt.Printf("%T：\n", h)
		logger := slog.New(h)
		logger.InfoContext(ctx, "接單", "table", 7)
		logger.With("table", 7).InfoContext(ctx, "出餐")
	}
}
main.ctxHandler：
level=INFO msg=接單 table=7 request_id=r-7f3a
level=INFO msg=出餐 table=7 request_id=r-7f3a
main.handleOnly：
level=INFO msg=接單 table=7 request_id=r-7f3a
level=INFO msg=出餐 table=7
  • 沒有 With 的時候兩者完全一樣，所以這個 bug 很容易通過簡單的測試，上線後才發現一部分的 log 沒有 request id。
  • 要用 ...Context 版本的方法（InfoContext、ErrorContext），ctx 才會傳到 Handle。
  • request id 是在 Handle 裡加的，所以會放在當時開著的群組裡面；需要永遠在最外層時，Handler 要自己記住群組，處理起來比較複雜。
  • 自訂的 Handler 可以用標準庫的 testing/slogtest 檢查有沒有遵守 Handler 的規則，例如空的 Attr 要略過、群組要正確地巢狀（本章的 main_test.go 有用到）。它檢查的是輸出的內容，抓不到上面這種「外面那一層不見了」的 bug，這要自己寫測試。

7. 測試日誌

log 也是程式的輸出。付款失敗時有沒有記一筆 ERROR、有沒有帶著訂單編號，這些都值得測試，尤其是要靠 log 觸發告警的時候。前提是函式用的 Logger 是傳進來的：

type Order struct {
	ID    string
	Items int
	Total int
}

func checkout(ctx context.Context, logger *slog.Logger, o Order, pay func(amount int) error) error {
	logger = logger.With("order_id", o.ID)
	logger.DebugContext(ctx, "開始結帳", "items", o.Items)
	if err := pay(o.Total); err != nil {
		logger.ErrorContext(ctx, "付款失敗", "total", o.Total, "err", err)
		return fmt.Errorf("訂單 %s：%w", o.ID, err)
	}
	logger.InfoContext(ctx, "結帳完成", "total", o.Total)
	return nil
}

func checkoutDemo() {
	logger := slog.New(slog.NewTextHandler(os.Stdout, demoOptions))
	err := checkout(context.Background(), logger, Order{ID: "A042", Items: 3, Total: 225}, func(int) error {
		return errors.New("餘額不足")
	})
	fmt.Println(err)
}
level=ERROR msg=付款失敗 order_id=A042 total=225 err=餘額不足
訂單 A042：餘額不足

測試裡給它一個寫到 bytes.Buffer 的 JSONHandler，再用 23 章的 jsontext.Decoder 一筆一筆解開，檢查欄位，而不是比對整個字串。這樣以後多加一個屬性，測試也不會壞：

func logLines(t *testing.T, r io.Reader) []map[string]any {
	t.Helper()
	var lines []map[string]any
	dec := jsontext.NewDecoder(r)
	for {
		var m map[string]any
		err := json.UnmarshalDecode(dec, &m)
		if errors.Is(err, io.EOF) {
			return lines
		}
		if err != nil {
			t.Fatalf("log 不是合法的 JSON：%v", err)
		}
		lines = append(lines, m)
	}
}

func TestCheckoutLogs(t *testing.T) {
	var buf bytes.Buffer
	logger := slog.New(slog.NewJSONHandler(&buf, &slog.HandlerOptions{Level: slog.LevelDebug}))
	order := Order{ID: "A042", Items: 3, Total: 225}

	err := checkout(t.Context(), logger, order, func(int) error { return errors.New("餘額不足") })
	if err == nil {
		t.Fatal("付款失敗時 checkout 應該回傳錯誤")
	}
	lines := logLines(t, &buf)
	if len(lines) != 2 {
		t.Fatalf("記了 %d 筆，want 2：%v", len(lines), lines)
	}
	want := map[string]any{"level": "ERROR", "msg": "付款失敗", "order_id": "A042", "total": 225.0, "err": "餘額不足"}
	for key, w := range want {
		if got := lines[1][key]; got != w {
			t.Errorf("%s = %v，want %v", key, got, w)
		}
	}
}
  • 層級設成 Debug，Debug 的紀錄才會出現在 buffer 裡，測試才看得到全部。
  • JSON 的數字解到 any 是 float64，所以比對的是 225.0（23 章）。
  • 不在乎 log 的測試，傳 slog.New(slog.DiscardHandler)（Go 1.24 起），什麼都不寫。
  • 想在測試失敗時看到 log，用 t.Output()（Go 1.25 起）當 Writer：slog.New(slog.NewTextHandler(t.Output(), nil))。log 會和 t.Log 一樣跟著那個測試印出來，用 -v 或失敗時才看得到。

整個專案的 Logger 通常在 main 建立一次，傳給需要的元件（存在 struct 的欄位裡），或用 With 加上元件名稱後再傳下去。只有 main 和很小的程式才直接用套件層級的 slog.Info。

常見錯誤

1. 把資料拼進訊息裡

slog.Info(fmt.Sprintf("第 %d 桌出餐", 7)) 每一筆的訊息都不一樣，查不了「所有出餐」，也取不出桌號。訊息寫固定的文字，資料放在屬性裡（第 2 節）。

2. 鍵值對少一個

落單的值被記成 !BADKEY，後面的 key 和 value 全部錯位。跑 go vet；容易寫錯的地方改用 slog.Int、slog.String（第 3 節）。

3. 把密碼、token、個資記進 log

log 被保存得很久、看得到的人很多。敏感的型別實作 LogValuer，或用 ReplaceAttr 依 key 遮掉（第 5 節、練習 2）。

4. 在迴圈裡 logger = logger.With(...)

每一圈都在上一圈的基礎上加屬性，紀錄越來越長，而且帶著錯的資料。只屬於這一筆的資料直接寫在呼叫裡（第 3 節、練習 6）。

5. 包裝 Handler 時只覆寫 Handle

WithAttrs、WithGroup 會回傳裡面那個 Handler，logger.With 之後外面那一層就消失了。四個方法都要處理，回傳時再包一次（第 6 節）。

6. 在函式裡直接用全域的 Logger

測試換不掉，也無法讓不同的元件有不同的設定。Logger 從參數或 struct 欄位傳進來（第 7 節）。

7. 在 main 以外呼叫 log.Fatal

它直接結束程式，defer 不會執行，呼叫的一方也沒有機會處理。回傳錯誤，讓 main 決定（第 1 節）。

8. 在 JSON 裡記 time.Duration，卻沒說單位

JSONHandler 把它寫成奈秒的整數，查的人很容易看錯三個零。key 寫上單位並傳整數，或傳 Duration 的 String()（第 2 節）。

重點回顧

  • log 套件寫出一行文字；需要查詢的 log 用 log/slog。
  • 訊息寫固定的文字，資料放在屬性裡；TextHandler 給人看，JSONHandler 給機器查。
  • slog.Int、slog.String 不會錯位；鍵值對寫錯會變成 !BADKEY，用 go vet 抓。
  • With 回傳新的 Logger，適合一整段工作共同的屬性；不要在迴圈裡蓋掉原本的 Logger。
  • 層級是整數，門檻由 HandlerOptions.Level 決定，LevelVar 可以在執行中調整。
  • 個資和秘密用 LogValuer 或 ReplaceAttr 遮掉；LogValue 只在真的要記時才執行。
  • 寫到多個地方用 MultiHandler；包裝 Handler 時四個方法都要處理。
  • request id 放在 context，用 ...Context 方法和自訂 Handler 帶進每一筆紀錄。
  • Logger 從外面傳進來，測試時寫到 buffer，解開 JSON 檢查欄位。
