sync 與 data race

好幾個人同時在同一格寫字，結果一定亂掉；Mutex 是那一格的鑰匙。

看圖

最小範例

type Counter struct {
	mu sync.Mutex
	n  int
}

func (c *Counter) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.n++
}

func main() {
	var c Counter
	var hits atomic.Int64
	var wg sync.WaitGroup
	for range 1000 {
		wg.Go(func() { c.Inc(); hits.Add(1) })
	}
	wg.Wait()
	fmt.Println(c.n, hits.Load())
}

輸出

1000 1000

工程師筆記

  • 有疑慮就跑 go test -race：它在執行時抓出真的發生的 data race。CI 建議一直開著。
  • sync.Mutex 不可重入：同一個 goroutine 重複 Lock 會卡死。
  • 含有 Mutex 的 struct 不要複製，用指標傳遞；go vet 的 copylocks 檢查會抓這個錯。
  • 讀多寫少用 sync.RWMutex；只有一個數字時，用 atomic.Int64 這類型別比較簡單。
  • sync.OnceValue（Go 1.21）把「只做一次」和「回傳結果」包在一起，適合延遲初始化。
  • 鎖的範圍越小越好；拿著鎖時不要做 I/O，也不要等 channel。
