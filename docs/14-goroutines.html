goroutine

goroutine 是很便宜的分身：在函式呼叫前面加上 go，它就在背景自己跑。

看圖

最小範例

func main() {
	nums := []int{1, 2, 3, 4}
	out := make([]int, len(nums))
	var wg sync.WaitGroup
	for i, n := range nums {
		wg.Go(func() { out[i] = n * n }) // Go 1.25 起的寫法
	}
	wg.Wait() // 等全部做完
	fmt.Println(out)
}

輸出

[1 4 9 16]

工程師筆記

  • main 結束程式就結束，不會等 goroutine；要等就用 sync.WaitGroup。Go 1.25 起可以直接 wg.Go(f)。
  • 用傳統的 wg.Add(1) 時，要在 go 之前呼叫，不能放進 goroutine 裡。
  • 每個 goroutine 都要有結束的方式。卡在 channel 上永遠等不到的 goroutine 會一直佔著記憶體，叫 goroutine leak。
  • 多個 goroutine 寫同一個 slice 的不同格子沒問題；寫同一個變數就要加鎖（第 17 章）。
  • Go 1.22 起，迴圈變數每一圈都是新的一份，直接在 goroutine 裡用不會全部拿到最後一個值。
  • 同時跑在幾個 CPU 上由 GOMAXPROCS 決定，預設是 CPU 數；在 Linux 上還會參考容器（cgroup）的 CPU 限制。
