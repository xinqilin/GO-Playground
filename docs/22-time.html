時間

便當店牆上的時鐘告訴你「現在是哪一刻」，廚房的計時器告訴你「還要多久」。同一刻，台北的時鐘指著 6 點半，東京的指著 7 點半；而「下個月的今天」要看日曆，不是加 30 天。

1. Time 與 Duration

time 套件最重要的兩個型別：time.Time 表示一個時間點，例如「2026 年 11 月 19 日 11:52」；time.Duration 表示一段時間長度，例如「15 分鐘」。它們之間的運算用方法來做：t.Add(d) 是點加長度，t.Sub(u) 是兩個點相減。外送的預計送達時間：

func etaDemo() {
	ordered := time.Date(2026, time.November, 19, 11, 52, 0, 0, time.UTC)
	cook := 15 * time.Minute
	ride := 25*time.Minute + 30*time.Second

	eta := ordered.Add(cook + ride)
	fmt.Println("總共要花", cook+ride)
	fmt.Println("預計送達", eta.Format(time.TimeOnly))

	promised := time.Date(2026, time.November, 19, 12, 30, 0, 0, time.UTC)
	fmt.Println("比答應的晚了", eta.Sub(promised))
}
總共要花 40m30s
預計送達 12:32:30
比答應的晚了 2m30s
  • time.Date(年, 月, 日, 時, 分, 秒, 奈秒, 時區) 組出一個時間點。月份是 time.November 這種具名常數，不容易把月和日寫反。
  • 時區是必填的：同樣是「11:52」，在台北和在倫敦是不同的時間點（第 3 節）。
  • Duration 印出來是 40m30s 這種格式，人看得懂，也能用 time.ParseDuration 解析回來。

Duration 其實就是 int64，單位是奈秒。time.Minute 是 60,000,000,000 這個常數，15 * time.Minute 就是 15 分鐘：

func durationDemo() {
	d := 90 * time.Minute
	fmt.Println(d, d.Hours(), int64(d))

	wait, err := time.ParseDuration("1h15m30s")
	fmt.Println(wait, wait.Minutes(), err)

	people := 7
	perPerson := 3 * time.Minute
	fmt.Println("排隊要等", time.Duration(people)*perPerson)

	fmt.Println((95 * time.Second).Round(time.Minute), (95 * time.Second).Truncate(time.Minute))
}
1h30m0s 1.5 5400000000000
1h15m30s 75.5 <nil>
排隊要等 21m0s
2m0s 1m0s

注意第三段：人數 people 是 int 變數，不能直接乘上 Duration。15 * time.Minute 可以，是因為 15 是沒有型別的常數，會自動變成 Duration；變數就不會：

package main

import (
	"fmt"
	"time"
)

func main() {
	people := 7
	perPerson := 3 * time.Minute
	fmt.Println(people * perPerson)
}

編譯錯誤

./main.go:11:14: invalid operation: people * perPerson (mismatched types int and time.Duration)

寫成 time.Duration(people) * perPerson：先把人數轉成 Duration，意思是「7 倍」，再乘上每人 3 分鐘。反過來，time.Duration(5) 不是 5 秒，是 5 奈秒；從設定檔讀到「5」這種數字時，記得乘上單位：time.Duration(n) * time.Second。

  • d.Hours()、d.Minutes()、d.Seconds() 回傳 float64，d.Milliseconds() 回傳 int64。
  • d.Round(m) 四捨五入、d.Truncate(m) 無條件捨去到 m 的倍數。給人看的時候很好用：95 秒顯示成「約 2 分鐘」。
  • int64 的奈秒大約能表示正負 290 年，一般用途不會超過。

2. 格式化與解析

其他語言用 yyyy-MM-dd 這種代號描述格式。Go 用的是一個具體的時間：2006 年 1 月 2 日 15 點 04 分 05 秒，時區 -0700。想要什麼格式，就把這個參考時間照那個格式寫出來，這個字串叫做版面（layout）：

var weekdays = [...]string{"日", "一", "二", "三", "四", "五", "六"}

func receiptStamp(t time.Time) string {
	return t.Format("2006/01/02") + "（" + weekdays[t.Weekday()] + "）" + t.Format("15:04")
}

func layoutDemo() {
	t := time.Date(2026, time.November, 19, 18, 30, 5, 0, time.UTC)
	fmt.Println(t.Format(time.DateTime))
	fmt.Println(t.Format(time.RFC3339))
	fmt.Println(t.Format("01/02 15:04"), t.Format("1/2 3:04PM"), t.Format("Mon Jan 2"))
	fmt.Println(receiptStamp(t))
	fmt.Println(t.Format("YYYY-MM-DD hh:mm")) // 其他語言的寫法：沒有一個是 Go 認得的數字
}
2026-11-19 18:30:05
2026-11-19T18:30:05Z
11/19 18:30 11/19 6:30PM Thu Nov 19
2026/11/19（四）18:30
YYYY-MM-DD hh:mm
  • 常用的版面已經有常數：time.DateTime（2006-01-02 15:04:05）、time.DateOnly、time.TimeOnly（Go 1.20 起），以及 time.RFC3339。在 API、JSON、log 裡交換時間，用 RFC3339，它一定帶著時區。
  • 01 補零、1 不補零；15 是 24 小時制，3 搭配 PM 是 12 小時制；Mon、Jan 是英文的星期和月份。
  • 最後一行：YYYY-MM-DD hh:mm 裡沒有任何參考時間的數字，Go 全部當成一般文字，原樣印出來，不會報錯。
  • 月份、星期的名稱只有英文。中文的星期就像 receiptStamp 一樣，用 t.Weekday()（星期日是 0）自己對照。

反過來，time.Parse(版面, 字串) 把字串解析成時間，版面要和字串的樣子完全一樣，連分隔符號都是：

func parseDemo() {
	const layout = "2006/01/02 15:04"
	t, err := time.Parse(layout, "2026/11/19 18:30")
	fmt.Println(t, err)

	_, err = time.Parse(layout, "2026-11-19 18:30") // 分隔符號不一樣
	fmt.Println(err)

	_, err = time.Parse(time.DateOnly, "2026-02-30")
	fmt.Println(err)
}
2026-11-19 18:30:00 +0000 UTC <nil>
parsing time "2026-11-19 18:30" as "2006/01/02 15:04": cannot parse "-11-19 18:30" as "/"
parsing time "2026-02-30": day out of range
  • 解析出來的時間在 UTC：字串裡沒有時區，Parse 就當成 UTC。這常常不是你要的，第 3 節會說明。
  • 錯誤訊息會指出卡在哪一段：cannot parse "-11-19 18:30" as "/" 表示那裡應該是 /。
  • Parse 會檢查日期存不存在，2 月 30 日是錯誤；但第 4 節的 time.Date 不檢查，它會進位。

3. 時區

一個 time.Time 同時記著兩件事：它是哪一個瞬間，以及用哪個時區（*time.Location）顯示。t.In(loc) 換一個時區顯示同一個瞬間。時區用 time.LoadLocation 依照名稱載入，名稱是 IANA 時區資料庫的格式，例如 Asia/Taipei：

package main

import (
	"fmt"
	"time"
	_ "time/tzdata" // 把時區資料庫編進執行檔，沒有安裝時區資料的系統也能 LoadLocation
)

var (
	taipei = mustLoad("Asia/Taipei")
	tokyo  = mustLoad("Asia/Tokyo")
)

// mustLoad 載入時區。名稱寫錯是程式的錯，啟動時就該發現，所以直接 panic。
func mustLoad(name string) *time.Location {
	loc, err := time.LoadLocation(name)
	if err != nil {
		panic(err)
	}
	return loc
}

// zonesDemo 同一個瞬間，在不同時區有不同的「牆上時間」。
func zonesDemo() {
	paid := time.Date(2026, time.November, 19, 10, 30, 0, 0, time.UTC) // 資料庫裡存 UTC
	const layout = time.DateTime + " MST"

	fmt.Println(paid.Format(layout))
	fmt.Println(paid.In(taipei).Format(layout))
	fmt.Println(paid.In(tokyo).Format(layout))
	fmt.Println("是同一個瞬間？", paid.Equal(paid.In(tokyo)))
}

// parseZoneDemo 字串裡沒有時區時，Parse 當成 UTC，ParseInLocation 當成你指定的時區。
func parseZoneDemo() {
	const layout = "2006-01-02 15:04"
	a, err := time.Parse(layout, "2026-11-19 18:30")
	if err != nil {
		fmt.Println(err)
		return
	}
	b, err := time.ParseInLocation(layout, "2026-11-19 18:30", taipei)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(a.Location(), a.Format(time.RFC3339))
	fmt.Println(b.Location(), b.Format(time.RFC3339))
	fmt.Println("兩個差了", a.Sub(b))
}
2026-11-19 10:30:00 UTC
2026-11-19 18:30:00 CST
2026-11-19 19:30:00 JST
是同一個瞬間？ true
  • 常見的做法：儲存和傳遞都用 UTC（或帶時區的 RFC3339），只有在顯示給人看的時候才 In 成使用者的時區。
  • MST 在版面裡代表時區縮寫。縮寫會撞名：台北顯示 CST，美國中部時間也是 CST。交換資料時用 -07:00 這種數字的時差。
  • 時區名稱寫錯是程式的錯，所以 mustLoad 在程式啟動時就 panic，不要等到第一次用到才發現。

解析字串時，如果字串裡沒有時區，Parse 會當成 UTC。使用者在台北輸入的「18:30」被當成 UTC 的 18:30，就差了 8 個小時。這種情況用 time.ParseInLocation，指定字串是哪個時區的時間：

UTC 2026-11-19T18:30:00Z
Asia/Taipei 2026-11-19T18:30:00+08:00
兩個差了 8h0m0s

時區資料從哪裡來？

Go 的執行檔本身不帶時區資料。LoadLocation 依序在這幾個地方找：環境變數 ZONEINFO 指定的位置、作業系統的時區目錄（Unix 上通常是 /usr/share/zoneinfo）、Go 安裝目錄裡的 zoneinfo.zip，最後是 time/tzdata 套件（如果有 import 的話）。

開發機上都找得到，但精簡的容器映像檔或某些 Windows 機器上可能沒有，LoadLocation 就會回傳錯誤。zones.go 開頭的 import _ "time/tzdata" 把整份時區資料編進執行檔，執行檔大約多 450 KB，換來在哪裡都能載入。另一個做法是編譯時加 -tags timetzdata，效果一樣，但不用改程式碼。

本機的時區 time.Local 由作業系統決定，Unix 上會看環境變數 TZ。time.Now() 回傳的時間就在 time.Local。同一支程式在你的電腦上是台北時間，放進容器裡可能就變成 UTC，所以邏輯裡不要依賴 Local，明確地指定時區。

4. 日曆的計算

t.AddDate(年, 月, 日) 用日曆加減：加一個月就是月份加一，日不變。問題出在月底：會員 1 月 31 日加入，「一個月後」是 2 月 31 日，這天不存在。Go 不會報錯，也不會改成 2 月底，而是像 time.Date 一樣，把多出來的天數往後進位：

func monthEnd(t time.Time) time.Time {
	y, m, _ := t.Date()
	h, mi, s := t.Clock()
	return time.Date(y, m+1, 0, h, mi, s, t.Nanosecond(), t.Location())
}

func calendarDemo() {
	joined := time.Date(2026, time.January, 31, 12, 0, 0, 0, taipei)

	fmt.Println("加一個月：", joined.AddDate(0, 1, 0).Format(time.DateOnly))
	fmt.Println("2 月 31 日：", time.Date(2026, time.February, 31, 0, 0, 0, 0, taipei).Format(time.DateOnly))
	fmt.Println("2 月的最後一天：", monthEnd(time.Date(2026, time.February, 1, 0, 0, 0, 0, taipei)).Format(time.DateOnly))

	today := time.Date(2026, time.November, 19, 0, 0, 0, 0, taipei)
	xmas := time.Date(2026, time.December, 25, 0, 0, 0, 0, taipei)
	fmt.Println("離聖誕節還有", int(xmas.Sub(today).Hours()/24), "天")
}
加一個月： 2026-03-03
2 月 31 日： 2026-03-03
2 月的最後一天： 2026-02-28
離聖誕節還有 36 天
  • 進位不只發生在日：time.Date(2026, 13, 1, …) 是 2027 年 1 月 1 日，第 61 分鐘是下一個小時的第 1 分鐘。
  • monthEnd 反過來利用進位：下個月的第 0 天，往回退一天，就是這個月的最後一天。2 月、閏年都不用自己判斷。
  • 「到期日要夾到月底」這種業務規則，要自己寫出來（練習 3）。先問清楚規則：1/31 加一個月要變 2/28，那 2/28 再加一個月是 3/28 還是 3/31？
  • 算相差幾天，這裡用 Sub 再除以 24 小時，前提是兩個時間都在當地午夜、而且中間沒有夏令時間的切換（見下面的深入）。台灣目前沒有夏令時間。

另一個常見的誤會：t.Truncate(24 * time.Hour) 看起來像是「切到當天的開始」，但它切的是從時間零點起算的絕對時間，等於用 UTC 的午夜切。台北早上 7:45 切下去，得到的是前一天的 08:00。要當地的午夜，就用 Date 把日期拿出來重組：

func truncateDemo() {
	t := time.Date(2026, time.November, 19, 7, 45, 0, 0, taipei) // 台北早上 7:45
	fmt.Println("Truncate：", t.Truncate(24*time.Hour).Format(time.DateTime))

	y, m, d := t.Date()
	fmt.Println("當地午夜：", time.Date(y, m, d, 0, 0, 0, 0, t.Location()).Format(time.DateTime))
}
Truncate： 2026-11-18 08:00:00
當地午夜： 2026-11-19 00:00:00

一天不一定是 24 小時

有夏令時間的地方，每年有一天只有 23 小時、有一天有 25 小時。紐約在 2026 年 11 月 1 日凌晨把時鐘撥回一小時，那一天有 25 個小時。這時「加一天」和「加 24 小時」就不一樣了：

func dstDemo() {
	ny := mustLoad("America/New_York")
	t := time.Date(2026, time.October, 31, 12, 0, 0, 0, ny)
	const layout = time.DateTime + " MST"

	fmt.Println("AddDate：", t.AddDate(0, 0, 1).Format(layout))
	fmt.Println("Add 24h：", t.Add(24*time.Hour).Format(layout))
	fmt.Println("那一天其實有", t.AddDate(0, 0, 1).Sub(t))
}
AddDate： 2026-11-01 12:00:00 EST
Add 24h： 2026-11-01 11:00:00 EST
那一天其實有 25h0m0s

AddDate 加的是日曆上的一天，時刻保持 12:00；Add 加的是物理上的 24 小時，因為多了一小時，牆上時間只到 11:00。規則很簡單：「明天同一個時間」用 AddDate，「24 小時之後」用 Add。服務的使用者在其他國家時，這個差別就會出現。

5. 比較、單調時鐘與 Unix 時間

同一個瞬間換了時區，用 == 比較就不相等了，因為 == 比的是 struct 的每一個欄位，時區也算在內。比較時間一律用方法：Equal、Before、After，或 Go 1.20 起的 Compare（回傳 -1、0、1，可以直接給 slices.SortFunc 用）：

func equalDemo() {
	a := time.Date(2026, time.November, 19, 10, 30, 0, 0, time.UTC)
	b := a.In(taipei)
	fmt.Println(a == b, a.Equal(b), a.Compare(b))

	c := a.Add(time.Minute)
	fmt.Println(a.Before(c), c.After(a), a.Compare(c))
}
false true 0
true true -1

同樣的理由，time.Time 不適合直接當 map 的 key：同一個瞬間可能變成兩個不同的 key。要當 key，先統一成 t.UTC()，或用 Unix 時間這種整數。

time.Now() 回傳的時間除了牆上時間，還偷偷帶著一個單調時鐘（monotonic clock）的讀數。牆上時間可能被調整：電腦和網路校時、使用者手動改時間，都會讓它跳前跳後；單調時鐘只會往前走，專門用來量「經過了多久」。印出 time.Now() 時，m= 後面那段就是它：

func monotonicDemo() {
	start := time.Now()
	fmt.Println("Now 帶著單調時鐘：", strings.Contains(start.String(), " m="))
	fmt.Println("Round(0) 之後：", strings.Contains(start.Round(0).String(), " m="))
	fmt.Println("經過的時間不會是負的：", time.Since(start) >= 0)
}
Now 帶著單調時鐘： true
Round(0) 之後： false
經過的時間不會是負的： true
  • 兩個時間都帶著單調時鐘時，Sub、time.Since、time.Until 用它來算，校時也不會算出負的經過時間。量程式跑多久就寫 start := time.Now() 和 time.Since(start)。
  • t.Round(0) 是拿掉單調時鐘讀數的標準寫法；In、UTC、Local 也會拿掉。time.Date、time.Parse 做出來的時間本來就沒有。
  • 單調時鐘只在這一次執行的這台機器上有意義，存檔、傳到別台機器時不會帶出去。

Unix 時間是從 1970-01-01 00:00:00 UTC 起算的秒數，和時區無關，是不同系統之間交換時間最簡單的方式：

func unixDemo() {
	t := time.Date(2026, time.November, 19, 10, 30, 0, 0, time.UTC)
	fmt.Println(t.Unix(), t.UnixMilli())

	back := time.Unix(t.Unix(), 0) // 回來的時間用的是本機時區
	fmt.Println(back.UTC().Format(time.RFC3339), back.Equal(t))
}
1795084200 1795084200000
2026-11-19T10:30:00Z true
  • UnixMilli、UnixMicro 和對應的 time.UnixMilli(ms) 從 Go 1.17 起可以用，JavaScript 的 Date.now() 就是毫秒。
  • time.Unix 回傳的時間在 time.Local，印出來前記得 In 或 UTC，不然每台機器印的不一樣。

6. 計時器

16 章用過 time.After 和 Timer 在 select 裡等逾時。這一節補上另外兩種。time.AfterFunc(d, f) 在 d 之後呼叫 f，不用自己開 goroutine 等 channel。訂位系統幫客人保留座位，時間到了還沒付款就把座位放出來：

func holdSeat(seat string, d time.Duration, release func(seat string)) *time.Timer {
	return time.AfterFunc(d, func() { release(seat) })
}

func afterFuncDemo() {
	released := make(chan string, 1)
	release := func(seat string) { released <- seat }

	holdSeat("A1", 10*time.Millisecond, release)
	fmt.Println("逾時放出：", <-released)

	t := holdSeat("B2", time.Hour, release)
	fmt.Println("B2 付款了，計時停下來：", t.Stop())
	fmt.Println("再 Stop 一次：", t.Stop())
}
逾時放出： A1
B2 付款了，計時停下來： true
再 Stop 一次： false
  • Stop 回傳 true 表示在響之前攔下來了，f 不會被呼叫；回傳 false 表示已經響過（f 已經開始執行）或已經停過。
  • f 在它自己的 goroutine 裡執行。f 碰到的共用資料要加鎖或用 channel，這裡的 release 就是透過 channel 把結果交回來（17 章、練習 4）。

每隔固定時間做一件事，用 time.NewTicker(d)：它每隔 d 往 t.C 送一個時間。叫號機每隔一段時間叫下一號，同時聽著 ctx，打烊了就停：

func callNumbers(ctx context.Context, first, last int, every time.Duration, call func(n int)) {
	t := time.NewTicker(every)
	defer t.Stop()
	for n := first; n <= last; n++ {
		select {
		case <-ctx.Done():
			return
		case <-t.C:
			call(n)
		}
	}
}

func tickerDemo() {
	callNumbers(context.Background(), 101, 103, 10*time.Millisecond, func(n int) {
		fmt.Printf("請 %d 號到櫃台\n", n)
	})
}
請 101 號到櫃台
請 102 號到櫃台
請 103 號到櫃台
  • 用完要 defer t.Stop()，停止送 tick。
  • 收的人太慢時，Ticker 不會累積一堆 tick 等你，會調整間隔或丟掉來不及收的。所以它適合「大約每隔多久」，不適合用來數經過了幾次。
  • t.Reset(d) 可以改間隔。Go 1.23 起，Timer 和 Ticker 沒有 Stop 也會被回收，Reset 之後也不會再收到舊的那次（16 章），但 Stop 還是要寫：它表達的是「不再需要了」，Ticker 不停就會一直送。
  • 用 Ticker 限制呼叫速率的例子在 19 章。

7. 讓時間可以測試

「折價券到期了沒」這種邏輯，如果裡面直接呼叫 time.Now()，測試就只能等到真的過期，或是寫一張日期很遠的券，到了那天測試突然失敗。解法是讓「現在幾點」從外面傳進來：

type Coupon struct {
	Code    string
	Expires time.Time
}

type Checkout struct {
	now func() time.Time
}

func (c Checkout) Accept(cp Coupon) bool {
	return c.now().Before(cp.Expires)
}

func checkoutDemo() {
	cp := Coupon{Code: "雙11", Expires: time.Date(2026, time.November, 12, 0, 0, 0, 0, taipei)}

	for _, at := range []time.Time{
		time.Date(2026, time.November, 11, 23, 59, 0, 0, taipei),
		time.Date(2026, time.November, 12, 0, 0, 0, 0, taipei),
	} {
		c := Checkout{now: func() time.Time { return at }}
		fmt.Println(at.Format("01/02 15:04"), cp.Code, "可以用？", c.Accept(cp))
	}
}
11/11 23:59 雙11 可以用？ true
11/12 00:00 雙11 可以用？ false
  • 正式執行時寫 Checkout{now: time.Now}，函式本身就是值（04 章）；測試時換成回傳固定時間的函式。
  • 邊界值最容易出錯：到期的那一刻能不能用？Before 回傳 false，所以「12 日 00:00 起不能用」。規則要寫在註解裡，測試把邊界兩邊都測到。
  • 只需要「現在幾點」時，傳一個 func() time.Time 就夠了，不必為了這個定義一個 Clock interface。

和計時器有關的程式（AfterFunc、Ticker、Sleep）就沒辦法這樣換了。testing/synctest（Go 1.25 起）把測試放進一個泡泡，泡泡裡的 time.Now、time.Sleep、Timer 都使用假時間：泡泡裡所有的 goroutine 都在等的時候，時間直接跳到下一個計時器響的時刻。保留 15 分鐘的座位，測試一瞬間就跑完，而且能精確地檢查是在第 15 分鐘放出來的：

func TestHoldSeat(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		start := time.Now() // 泡泡裡的時間從 2000-01-01 00:00:00 UTC 開始
		released := make(chan string, 2)
		release := func(seat string) { released <- seat }
		holdSeat("A1", 15*time.Minute, release)
		paid := holdSeat("B2", 15*time.Minute, release)

		time.Sleep(14*time.Minute + 59*time.Second)
		synctest.Wait()
		if len(released) != 0 {
			t.Fatalf("還沒到 15 分鐘就放出了 %q", <-released)
		}
		paid.Stop() // B2 在最後一秒付款

		time.Sleep(time.Second)
		synctest.Wait()
		if n := len(released); n != 1 {
			t.Fatalf("15 分鐘時放出了 %d 個座位，want 1", n)
		}
		if seat := <-released; seat != "A1" || time.Since(start) != 15*time.Minute {
			t.Errorf("放出 %q，經過 %v；want A1、15m0s", seat, time.Since(start))
		}
	})
}
  • 泡泡裡的時間從 2000-01-01 00:00:00 UTC 開始，所以要比較的是「經過多久」，不是某個日期。
  • synctest.Wait() 等到泡泡裡其他的 goroutine 都卡住（例如 AfterFunc 的 f 已經跑完）才回來，之後再檢查結果就不會有時間差。
  • Ticker 一樣能測：main_test.go 裡的 TestCallNumbers 檢查叫號機在第 30 秒、第 60 秒各叫一號，打烊後立刻停下來，不用等到第 90 秒。

常見錯誤

1. 版面寫成 YYYY-MM-DD

Go 不認得這些代號，原樣印出來，也不會報錯。版面要用參考時間 2006-01-02 15:04:05，常用的直接用 time.DateTime、time.RFC3339 這些常數（第 2 節）。

2. 數字直接當成 Duration

time.Sleep(5) 睡的是 5 奈秒，不是 5 秒。int 變數和 Duration 相乘會編譯錯誤，寫成 time.Duration(n) * time.Second（第 1 節）。

3. 用 == 比較時間、用 Time 當 map 的 key

同一個瞬間換了時區、帶不帶單調時鐘讀數，== 的結果都不一樣。比較用 Equal、Before、After、Compare；當 key 先統一成 UTC 或 Unix 時間（第 5 節）。

4. 解析沒有時區的字串，用了 Parse

Parse 把它當成 UTC，台灣的使用者輸入的時間差了 8 小時。用 ParseInLocation 指定時區，或要求輸入帶時區的 RFC3339（第 3 節）。

5. 用 Truncate(24*time.Hour) 求當地的「今天」

它切的是 UTC 的午夜，在台北早上 8 點以前會切到前一天。用 t.Date() 取出年月日再組回 time.Date，或直接 Format 成日期（第 4 節、練習 5）。

6. 以為 AddDate 會夾到月底

1 月 31 日加一個月是 3 月 3 日。帳單、會員到期這類規則要自己寫，並且每次從起始日算，不要從上一次的結果一直往後加（第 4 節、練習 3）。

7. 依賴機器的本地時區

time.Now() 和 time.Unix 回傳的時間在 time.Local，它由作業系統和 TZ 環境變數決定。開發機上是台北，容器裡常常是 UTC。要顯示、要依日期分組時，明確地 In 到你要的時區（第 3 節）。

8. 邏輯裡直接呼叫 time.Now、測試裡用 time.Sleep 等

測試又慢又不穩定，邊界時刻也測不到。把「現在幾點」注入進去；和計時器有關的用 synctest（第 7 節）。

重點回顧

  • Time 是點，Duration 是長度：Add 得到點，Sub 得到長度。
  • Duration 是 int64 奈秒；變數要先轉成 Duration 再乘，數字要乘上單位。
  • 版面是把參考時間 2006-01-02 15:04:05 -0700 寫成你要的樣子；交換資料用 RFC3339。
  • 字串沒有時區時，Parse 當成 UTC，ParseInLocation 才是你指定的時區。
  • 儲存用 UTC，顯示時才 In 成使用者的時區；import _ "time/tzdata" 讓每台機器都載入得到時區。
  • AddDate 和 time.Date 會進位，不會夾到月底；下個月的第 0 天是這個月的最後一天。
  • Truncate(24h) 切的是 UTC 的午夜；當地的日期用 Date 或 Format 取。
  • 比較用 Equal、Before、After、Compare，不用 ==；量經過多久用 time.Since，靠的是單調時鐘。
  • Timer 響一次、Ticker 一直響、AfterFunc 在自己的 goroutine 呼叫 f；用完都 Stop。
  • 注入 func() time.Time 讓邏輯可以測試；計時器用 synctest 的假時間測試。
