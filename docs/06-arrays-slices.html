1. 陣列

陣列是一排數量固定、型別相同的元素。長度寫在型別裡：[7]int 是「7 個 int」，和 [30]int 是不同的型別。沒有給值的元素是零值：

func arrayBasics() {
	var sales [7]int // 一週七天的營業額，一開始全部是 0
	sales[0] = 3200
	sales[6] = 4100
	fmt.Println(sales, len(sales))

	weekdays := [...]string{"一", "二", "三", "四", "五"} // ... 讓編譯器自己數長度
	fmt.Println(len(weekdays), weekdays[len(weekdays)-1])

	booked := [5]bool{1: true, 3: true} // 指定索引給值，其他格是 false
	fmt.Println(booked)
}

輸出

[3200 0 0 0 0 0 4100] 7
5 五
[false true false true false]
  • 索引從 0 開始，最後一個是 len(a)-1。
  • [...]string{…} 讓編譯器依照給的值數長度，結果還是陣列，不是 slice。
  • {1: true, 3: true} 指定索引給值，適合大部分是零值、只有少數幾格要設定的情況。

陣列是值

func doubleAll(prices [3]int) {
	for i := range prices {
		prices[i] *= 2
	}
}

func arrayIsValue() {
	a := [3]int{85, 90, 15}
	b := a // 複製三格
	b[0] = 100
	fmt.Println(a, b)

	doubleAll(a)
	fmt.Println(a)

	fmt.Println(a == [3]int{85, 90, 15}, a == b)
}

輸出

[85 90 15] [100 90 15]
[85 90 15]
true false

和 Java 的陣列不同，Go 的陣列不是參考，而是一整塊值：b := a 複製了三個元素，doubleAll(a) 也只改到複本。元素型別可以比較時，陣列本身也能用 == 比較，比的是每個元素，所以陣列可以當 map 的 key。

長度是型別的一部分，所以不同長度的陣列不能互相指定：

package main

import "fmt"

func main() {
	var week [7]int
	var month [30]int
	week = month
	fmt.Println(week)
}

編譯錯誤

./main.go:8:9: cannot use month (variable of type [30]int) as [7]int value in assignment

這也代表寫不出「接受任意長度陣列」的函式。這正是陣列在 Go 裡很少直接使用的原因：日常的「一串資料」都用 slice。陣列適合長度本來就固定的資料，例如 RGB 顏色 [3]uint8、SHA-256 的雜湊值 [32]byte、井字棋盤 [3][3]string。

索引超出範圍

索引是常數時，編譯器就能檢查。對 prices := [3]int{85, 90, 15} 寫 fmt.Println(prices[3])，編譯器會拒絕：

./main.go:7:21: invalid argument: index 3 out of bounds [0:3]

索引是變數時，要到執行時才知道，超出範圍會 panic：

func indexOutOfRange() {
	defer func() {
		fmt.Println("panic:", recover())
	}()
	prices := [3]int{85, 90, 15}
	i := 3
	fmt.Println(prices[i])
}

輸出

panic: runtime error: index out of range [3] with length 3

訊息會告訴你用了哪個索引、長度是多少。Go 每次存取都會檢查範圍，不會像 C 一樣默默讀到別的記憶體；編譯器能證明不會超出範圍時，會把檢查省掉。

2. slice 是一扇窗

slice 的型別寫成 []int，方括號裡沒有長度。建立 slice 最常用字面值和 make：

func sliceLiteral() {
	menu := []string{"排骨", "雞腿", "素食"} // 方括號裡沒有長度：這是 slice
	fmt.Println(menu, len(menu), cap(menu))

	orders := make([]int, 3)    // len 3、cap 3，內容是零值
	queue := make([]int, 0, 10) // len 0、cap 10：先保留空間
	fmt.Println(orders, len(orders), cap(orders))
	fmt.Println(queue, len(queue), cap(queue))
}

輸出

[排骨 雞腿 素食] 3 3
[0 0 0] 3 3
[] 0 10

make([]T, len, cap) 建立一個長度 len 的 slice，元素都是零值；cap 可以省略，省略時等於 len。len 是目前看得到的元素個數，cap 是不換陣列的情況下最多能長到多長。

slice header

func sliceWindow() {
	arr := [5]int{10, 20, 30, 40, 50}
	s := arr[1:4] // 索引 1、2、3，不含 4
	fmt.Println(s, len(s), cap(s))
	s[0] = 99
	fmt.Println(arr)
}

輸出

[20 30 40] 3 4
[10 99 30 40 50]

一個 slice 其實只是三個欄位組成的小結構，叫做 slice header：

  • ptr：指向底層陣列的某一格，也就是這扇窗的起點。
  • len：窗戶的寬度，能用索引存取的範圍是 0 到 len-1。
  • cap：從起點到底層陣列結尾有幾格。

資料都在底層陣列裡，slice 只是看向它的窗，所以 s[0] = 99 改到的是 arr[1]。用字面值或 make 建立 slice 時，Go 會在背後配置一個沒有名字的陣列。把 slice 指定給另一個變數、傳給函式，複製的都只是這三個欄位，不會複製資料。

切片運算式

func sliceBounds() {
	s := []int{0, 1, 2, 3, 4, 5}
	fmt.Println(s[:2], s[4:], s[:])

	part := s[1:3]
	fmt.Println(part, len(part), cap(part))
	more := part[:4] // part 的長度只有 2，但容量有 5
	fmt.Println(more)
}

輸出

[0 1] [4 5] [0 1 2 3 4 5]
[1 2] 2 5
[1 2 3 4]

s[low:high] 包含 low、不包含 high，長度是 high-low。low 省略是 0，high 省略是 len(s)。high 可以超過 len，只要不超過 cap：part 的長度只有 2，但它的窗戶後面還有 3 格，所以 part[:4] 可以往後延伸，看到原本 s 裡的 3 和 4。超過 cap 就會 panic。

3. append

append 把元素加到 slice 的後面，回傳加長後的 slice。一次可以加好幾個，也可以用 ... 把另一個 slice 展開加進去（第 04 章的可變參數）：

func appendBasics() {
	var cart []string // nil slice，可以直接 append
	cart = append(cart, "排骨")
	cart = append(cart, "雞腿", "滷蛋")
	drinks := []string{"紅茶", "味噌湯"}
	cart = append(cart, drinks...)
	fmt.Println(cart, len(cart))
}

輸出

[排骨 雞腿 滷蛋 紅茶 味噌湯] 5

nil slice 可以直接 append，不需要先 make。這是 Go 最常見的寫法：宣告一個空的 slice，在迴圈裡一個一個 append。

什麼時候換陣列

func appendGrowth() {
	full := make([]int, 3) // len 3、cap 3：已經滿了
	grown := append(full, 4)
	grown[0] = 99
	fmt.Println(full, grown, cap(grown) > cap(full))

	roomy := make([]int, 3, 10) // len 3、cap 10：後面還有空間
	same := append(roomy, 4)
	same[0] = 99
	fmt.Println(roomy, same, &roomy[0] == &same[0])
}

輸出

[0 0 0] [99 0 0 4] true
[99 0 0] [99 0 0 4] true

append 的規則只有一條：

  • 容量夠：直接寫進原本陣列的下一格，回傳的 slice 和原本的 slice 共用同一個陣列。上面的 roomy 和 same 第一格的位址相同，改 same[0]，roomy[0] 也變了。
  • 容量不夠：配置一個更大的新陣列，把舊資料複製過去，再放進新元素。回傳的 slice 指向新陣列，和原本的 slice 從此分開。上面改 grown[0]，full 不受影響。

所以 append 的回傳值一定要接住，而且幾乎都是接回同一個變數：s = append(s, x)。沒接住時，加進去的元素可能留在一個沒有人看得到的新陣列裡。

事先保留容量

func countMoves(s []int, n int) int {
	moves := 0
	for i := range n {
		before := cap(s)
		s = append(s, i)
		if cap(s) != before {
			moves++
		}
	}
	return moves
}

func appendPrealloc() {
	fmt.Println("沒有保留容量，換過陣列：", countMoves(nil, 1000) > 0)
	fmt.Println("保留 1000 格，換陣列的次數：", countMoves(make([]int, 0, 1000), 1000))
}

輸出

沒有保留容量，換過陣列： true
保留 1000 格，換陣列的次數： 0

每次換陣列都要配置記憶體、複製所有舊資料。事先知道大概會有幾個元素時（例如把一個 slice 轉換成另一個），用 make([]T, 0, n) 保留容量，之後的 append 就不必換陣列。注意 len 要寫 0：寫成 make([]T, n) 會先有 n 個零值，append 會接在它們後面（常見錯誤 7）。

深入：第一次讀可以先跳過

3.1 新的容量是多少

容量不夠時，新陣列要多大是 runtime 的實作細節，規格沒有規定。目前的實作大致是：小的 slice 容量加倍，變大之後每次的成長比例逐漸降到約 1.25 倍，最後再依記憶體配置器的大小級距往上取整。這個策略讓一連串 append 的平均成本維持在常數時間，代價是可能浪費一些空間。

這些數字在不同 Go 版本之間調整過，所以本章的範例只比較容量的大小關係，不印出確切的數字。你的程式也不應該依賴它：需要確定的容量，就自己用 make 指定。

4. 共用底層陣列

把第 2 節和第 3 節合起來，就會得到 slice 最有名的陷阱：

func sharedBacking() {
	s := []int{1, 2, 3, 4}
	part := s[:2]           // len 2、cap 4：後面還有空間
	part = append(part, 99) // 容量夠，直接寫進底層陣列的索引 2
	fmt.Println(s, part)
}

輸出

[1 2 99 4] [1 2 99]

part := s[:2] 的長度是 2，但容量是 4。對 part append 時容量還夠，append 就照規則直接寫進底層陣列的索引 2，而那一格正是 s 的第三個元素。程式裡沒有任何一行明寫要改 s，s 卻被改了。這種 bug 很難追，因為修改發生的地方和出問題的地方可能相隔很遠。

完整切片運算式

func fullSliceExpr() {
	s := []int{1, 2, 3, 4}
	part := s[:2:2] // len 2、cap 2
	part = append(part, 99)
	fmt.Println(s, part)
}

輸出

[1 2 3 4] [1 2 99]

s[low:high:max] 多了第三個數字，把容量限制成 max-low。s[:2:2] 的容量只有 2，下一次 append 一定會換到新陣列，s 就安全了。把一個 slice 的一部分交給別人、而對方可能會 append 時，就用這個寫法把容量切掉。練習 4 就是這個 bug。

傳給函式的 slice

func raise(prices []int) {
	for i := range prices {
		prices[i] += 5
	}
}

func addItem(cart []string, item string) {
	cart = append(cart, item)
}

func withItem(cart []string, item string) []string {
	return append(cart, item)
}

func passSlice() {
	prices := []int{85, 90}
	raise(prices)
	fmt.Println(prices)

	cart := []string{"排骨"}
	addItem(cart, "滷蛋")
	fmt.Println(cart, len(cart))
	cart = withItem(cart, "滷蛋")
	fmt.Println(cart, len(cart))
}

輸出

[90 95]
[排骨] 1
[排骨 滷蛋] 2

這解答了第 05 章留下的問題。傳 slice 給函式時，複製的是 slice header（ptr、len、cap 三個欄位）：

  • 改元素：函式的 header 和呼叫端的 header 指向同一個陣列，所以 raise 的修改呼叫端看得到。
  • append：函式改的是自己那份 header 的 len（可能還有 ptr），呼叫端的 header 完全沒變，所以 addItem 之後，cart 的長度還是 1。

Go 的慣例是讓函式回傳新的 slice，由呼叫端接住，就像 append 本身一樣（withItem）。標準庫的 slices.Insert、slices.Delete 都是這樣設計的。

5. copy、插入與刪除

copy 與 Clone

func copyBasics() {
	src := []int{85, 90, 15}
	dst := make([]int, 2)
	n := copy(dst, src)
	fmt.Println(n, dst)

	clone := slices.Clone(src)
	clone[0] = 0
	fmt.Println(src, clone)
}

輸出

2 [85 90]
[85 90 15] [0 90 15]

內建的 copy(dst, src) 把元素從 src 複製到 dst，個數是兩者長度的較小值，回傳實際複製了幾個。注意它看的是 dst 的長度，不是容量：make([]int, 0, 10) 當 dst 一個都複製不進去。要一份內容相同、但完全獨立的 slice，用 slices.Clone 最簡單。

插入與刪除

func insertDelete() {
	queue := []string{"A01", "A02", "A03", "A04"}
	queue = slices.Delete(queue, 1, 2) // 刪掉 queue[1:2]，也就是 A02
	fmt.Println(queue)
	queue = slices.Insert(queue, 1, "V01")
	fmt.Println(queue)
}

輸出

[A01 A03 A04]
[A01 V01 A03 A04]

slices.Delete(s, i, j) 刪掉 s[i:j]，slices.Insert(s, i, v...) 在索引 i 插入值。兩者都會原地修改 s 的底層陣列，並回傳新的 slice，所以和 append 一樣要接回去。Go 1.22 起，Delete 會把尾端空出來的格子清成零值（圖中的 ""），舊的 slice 如果還看得到那一格，會看到零值而不是殘留的資料。

原地過濾

func filterInPlace() {
	prices := []int{85, 120, 90, 150, 70}
	cheap := prices[:0]
	for _, p := range prices {
		if p < 100 {
			cheap = append(cheap, p)
		}
	}
	fmt.Println(cheap)
	fmt.Println(prices) // 前三格被覆寫了，後面是舊資料

	others := []int{85, 120, 90, 150, 70}
	others = slices.DeleteFunc(others, func(p int) bool { return p >= 100 })
	fmt.Println(others)
}

輸出

[85 90 70]
[85 90 70 150 70]
[85 90 70]

prices[:0] 是一個長度 0、但沿用 prices 底層陣列的 slice。走過每個元素，把要留下的 append 進去：因為寫入的位置永遠不會超過正在讀的位置，所以不會蓋掉還沒讀到的資料，也不必配置新的陣列。代價是原本的 prices 被改掉了（後面殘留著舊資料），只有在不再需要原本的資料時才這樣做。slices.DeleteFunc 做的是同一件事，條件反過來：回傳 true 的元素會被刪掉。練習 3 用這個技巧去除相鄰的重複條碼。

6. nil slice 與空 slice

func nilVsEmpty() {
	var a []int
	b := []int{}
	c := make([]int, 0)
	fmt.Println(a == nil, b == nil, c == nil)
	fmt.Println(len(a), len(b), len(c))
	fmt.Printf("%v %v\n", a, b)
	fmt.Printf("%#v %#v\n", a, b)

	for range a {
		fmt.Println("不會執行")
	}
	a = append(a, 1)
	fmt.Println(a, len(a))
}

輸出

true false false
0 0 0
[] []
[]int(nil) []int{}
[1] 1

slice 的零值是 nil：ptr 是 nil，len 和 cap 都是 0。[]int{} 和 make([]int, 0) 則是長度 0、但不是 nil 的空 slice。兩者在幾乎所有操作上都一樣：len 是 0、range 一圈都不跑、可以 append、%v 都印成 []。只有和 nil 比較，以及用 %#v 印出時看得出差別。

  • 判斷是否為空：用 len(s) == 0，不要用 s == nil，這樣兩種情況都涵蓋得到。
  • 宣告：慣用 var s []int，不需要先建立空 slice。
  • 函式回傳：沒有結果時回傳 nil 即可，呼叫端用 len 判斷。少數情況下差別很重要，例如轉成 JSON 時，nil slice 是 null、空 slice 是 []，之後的「JSON 與資料編碼」那一章會再談。

7. slices 套件

Go 1.21 起，標準庫的 slices 套件提供了一整組處理 slice 的泛型函式，任何元素型別都能用（泛型在第 12 章）：

func slicesPackage() {
	prices := []int{90, 85, 120, 85, 70}
	fmt.Println(slices.Contains(prices, 120), slices.Index(prices, 85), slices.Index(prices, 999))
	fmt.Println(slices.Min(prices), slices.Max(prices))

	sorted := slices.Clone(prices)
	slices.Sort(sorted)
	fmt.Println(sorted)
	i, found := slices.BinarySearch(sorted, 90)
	fmt.Println(i, found)

	sorted = slices.Compact(sorted) // 移除相鄰的重複值
	fmt.Println(sorted)
	slices.Reverse(sorted)
	fmt.Println(sorted)
	fmt.Println(slices.Equal(sorted, []int{120, 90, 85, 70}))
}

輸出

true 1 -1
70 120
[70 85 85 90 120]
3 true
[70 85 90 120]
[120 90 85 70]
true
想做的事函式注意
找元素Contains、Index、IndexFunc找不到時 Index 回傳 -1
最大、最小Max、Min空的 slice 會 panic
排序Sort、SortFunc、SortStableFunc原地排序；自訂順序見第 04 章
二分搜尋BinarySearchslice 必須已經排好序；回傳位置和有沒有找到
比較內容Equalslice 不能用 == 比較（常見錯誤 4）
去除相鄰重複Compact只移除相鄰的重複，通常先排序
反轉Reverse原地反轉
複製、插入、刪除Clone、Insert、Delete、DeleteFunc要接住回傳值（第 5 節）

舊的程式碼常見 sort.Ints、sort.Slice，新程式優先用 slices 套件，型別更安全，通常也更快。Go 1.23 起還有 slices.All、slices.Sorted、slices.Chunk 這些和疊代器搭配的函式，第 13 章會介紹。

8. 二維 slice

Go 沒有專門的多維 slice，二維就是「元素是 slice 的 slice」。外層要先 make，再替每一列各自 make：

func newSeats(rows, cols int) [][]string {
	seats := make([][]string, rows)
	for r := range seats {
		seats[r] = make([]string, cols)
		for c := range seats[r] {
			seats[r][c] = "."
		}
	}
	return seats
}

func printSeats(seats [][]string) {
	for _, row := range seats {
		fmt.Println(strings.Join(row, " "))
	}
}

func seatGrid() {
	seats := newSeats(3, 4)
	seats[1][2] = "X"
	printSeats(seats)

	daily := [][]string{{"排骨"}, {"雞腿", "素食", "排骨"}, {}} // 每一列可以不一樣長
	for day, orders := range daily {
		fmt.Println(day, len(orders))
	}
}

輸出

. . . .
. . X .
. . . .
0 1
1 3
2 0

只 make 外層、忘了 make 每一列，每一列都是 nil slice，seats[1][2] = "X" 就會索引超出範圍而 panic。每一列各自獨立，所以長度可以不同，像 daily 每天的訂單數不一樣。

複製二維 slice

func gridCopy() {
	seats := newSeats(2, 3)
	shallow := slices.Clone(seats)
	shallow[0][0] = "X"
	fmt.Println(seats[0][0])

	var board [2][3]string
	copied := board
	copied[0][0] = "X"
	fmt.Printf("%q\n", board[0][0])
}

輸出

X
""

slices.Clone(seats) 只複製外層的三個 header，每一列還是同一個陣列，所以改 shallow 也改到了 seats。這和第 05 章的淺複製是同一件事。要完全獨立，就要逐列 Clone。二維陣列 [2][3]string 則是一整塊值，指定時全部複製。

深入：第一次讀可以先跳過

8.1 小 slice 拖住大陣列

func retainBig() {
	big := make([]byte, 1<<20) // 1 MB，例如整個讀進來的檔案
	header := big[:16]
	fmt.Println(len(header), cap(header))
	kept := slices.Clone(header)
	fmt.Println(len(kept), cap(kept) < 1024)
}

輸出

16 1048576
16 true

header 只有 16 個 byte，但它的容量是 1,048,576：它仍然指向整個 1 MB 的陣列。只要 header 還被保存著（例如存進一個長期存在的 map），垃圾回收器就無法回收那 1 MB，即使你只需要前 16 個 byte。從大量資料中切出一小段要長期保存時，用 slices.Clone 複製出來，大陣列就能被回收。字串也有同樣的問題，第 08 章會提到。

常見錯誤

1. 沒有接住 append 的回傳值

單獨寫一行 append(cart, "滷蛋") 會編譯失敗：

package main

import "fmt"

func main() {
	cart := []string{"排骨"}
	append(cart, "滷蛋")
	fmt.Println(cart)
}

編譯錯誤

./main.go:7:2: append(cart, "滷蛋") (value of type []string) is not used

比較難發現的是在函式裡 append 到參數上（第 4 節的 addItem）：編譯會過，呼叫端卻看不到新元素。一律寫 s = append(s, …)，函式要加長 slice 時就回傳新的 slice。

2. append 蓋掉別人的資料

從同一個 slice 切出來的 slice 共用底層陣列，對其中一個 append 可能寫進另一個的範圍（第 4 節）。把 slice 的一部分交出去時，用 s[low:high:high] 把容量限制住。

3. 以為 b := a 會複製 slice

對 slice 來說，b := a 只複製了 header，兩個變數看向同一個陣列，改 b[0] 就改了 a[0]。要獨立的複本用 slices.Clone(a)，二維的要逐列 Clone。練習 2 就是這個 bug。

4. 用 == 比較兩個 slice

package main

import "fmt"

func main() {
	a := []int{85, 90}
	b := []int{85, 90}
	fmt.Println(a == b)
}

編譯錯誤

./main.go:8:14: invalid operation: a == b (slice can only be compared to nil)

slice 只能和 nil 比較。比較內容用 slices.Equal(a, b)。這也代表 slice 不能當 map 的 key，需要時改用陣列或把內容轉成字串。

5. 在 range 裡改元素的複本

for _, p := range prices { p *= 2 } 改的是複本，prices 不會變。要修改元素就用索引：for i := range prices { prices[i] *= 2 }。見第 03 章的 range。

6. 索引超出範圍

執行時的錯誤訊息是 index out of range [3] with length 3，切片時是 slice bounds out of range。最常見的原因是把 len(s) 當成最後一個索引，或是在空的 slice 上取 s[0]。取第一個或最後一個元素前，先確認 len(s) > 0。

7. make 給了長度又 append

第 2 節的 orders := make([]int, 3) 已經有三個 0。如果接著寫 orders = append(orders, 85)，結果是 [0 0 0 85]，不是 [85]。打算用 append 填資料時，要寫 make([]int, 0, 3)（像 queue 那樣）；打算用索引 orders[i] = … 填資料時，才寫 make([]int, 3)。

重點回顧

  • 陣列的長度是型別的一部分；陣列是值，指定和傳參數都會整個複製，可以用 == 比較。
  • slice 是 ptr、len、cap 三個欄位的 header，資料在底層陣列裡；複製 slice 只複製 header。
  • s[low:high] 包含 low、不包含 high；high 不能超過 cap。
  • append 容量夠就寫進原本的陣列，不夠就換新陣列；一律寫 s = append(s, …)。
  • 知道大概的數量時用 make([]T, 0, n) 保留容量。
  • 共用底層陣列的 slice，append 可能互相覆蓋；交出 slice 的一部分時用 s[low:high:high] 限制容量。
  • 函式改 slice 的元素呼叫端看得到，append 看不到；要加長就回傳新的 slice。
  • copy 依兩邊長度的較小值複製；slices.Clone 產生獨立的複本；Insert、Delete 要接住回傳值。
  • 判斷 slice 是否為空用 len(s) == 0；nil slice 可以直接 append 和 range。
  • slice 不能用 == 比較，用 slices.Equal。
  • 二維 slice 要逐列 make，Clone 外層不會複製每一列。
  • 從大 slice 切出的小 slice 會拖住整個陣列，要長期保存就 Clone。
