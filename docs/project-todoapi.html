核心程式

main.go（節錄）

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

errCh := make(chan error, 1)
go func() {
	if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
		errCh <- err // 例如 port 被占用
	}
	close(errCh)
}()

select {
case err := <-errCh:
	return err
case <-ctx.Done(): // 等到 Ctrl-C 或 SIGTERM
}

shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
return srv.Shutdown(shutdownCtx)

測試裡用 httptest 跑一輪 CRUD 的結果

POST /todos → 201 {"id":1,"title":"寫 Go 手冊","done":false}
GET /todos → 200 [{"id":1,"title":"寫 Go 手冊","done":false}]
PATCH /todos/1 → 200 {"id":1,"title":"寫 Go 手冊","done":true}
DELETE /todos/1 → 204
GET /todos/1 → 404 {"error":"找不到這筆待辦"}

工程師筆記

  • handler 用到的東西（Store、logger）放進 api struct，測試時換一個丟掉 log 的 logger 就好，不需要全域變數。
  • 狀態碼要講清楚：格式錯是 400，內容不合規則是 422，找不到是 404，方法不對是 405（ServeMux 自動處理）。
  • DisallowUnknownFields 讓打錯欄位名稱的請求直接失敗；MaxBytesReader 限制 body 大小。
  • 空清單回傳 [] 而不是 null：先 make([]Todo, 0)，前端就不用多一個判斷。
  • http.Server 的四個逾時都設了；Shutdown 讓部署或重啟時不會砍斷進行中的請求。
  • 資料只在記憶體裡，重啟就沒了。換成資料庫時，讓新的實作提供同樣的方法，handler 就不用改。
