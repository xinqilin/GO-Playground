拆解問題：函式與清單

大問題沒辦法一口氣解決，但可以切成幾個小問題，每個小問題寫成一個有名字的函式。很多小問題其實長得一樣：加總、數數、找最大、找東西。

1. 函式：把步驟包起來

先修 3 已經用過帶參數的函式（passFail(72)），這一章正式學怎麼寫。函式（function）是一段有名字的程式，像一份食譜：參數（parameter）是食材，大括號裡是步驟，回傳值（return value）是做好的菜。

func greet(name string) {
	fmt.Println("早安，" + name)
}

func greetDemo() {
	greet("小明")
	greet("阿美")
}

輸出

早安，小明
早安，阿美

func greet(name string) 讀作：「定義一個叫 greet 的函式，它需要一個叫 name 的 string」。呼叫 greet("小明") 時，"小明" 會放進 name，然後執行大括號裡的步驟。同一個函式可以呼叫很多次，每次給不同的值。這個函式只負責印東西，沒有交回任何結果。

func subtotal(price, qty int) int {
	return price * qty
}

func subtotalDemo() {
	a := subtotal(85, 3)
	b := subtotal(90, 2)
	fmt.Println(a, b, a+b)
}

輸出

255 180 435
  • (price, qty int)：兩個參數都是 int 時，型別可以只寫一次。
  • 右括號後面的 int 是回傳值的型別：這個函式會交回一個整數。
  • return price * qty 算出結果並交回去。呼叫的地方 subtotal(85, 3) 就變成 255，可以存進變數，也可以直接拿去計算。

return 會立刻結束函式

func memberPrice(price int, member bool) int {
	if !member {
		return price
	}
	return price * 9 / 10
}

func memberPriceDemo() {
	fmt.Println(memberPrice(100, false))
	fmt.Println(memberPrice(100, true))
	fmt.Println(memberPrice(85, true))
}

輸出

100
90
76

不是會員時，第一個 return 直接交回原價，函式就結束了，後面打九折的那一行不會執行。所以這裡不需要 else。85 元打九折是 76.5，但 price * 9 / 10 全是整數運算，小數被丟掉，得到 76。先乘再除的順序也很重要：寫成 price / 10 * 9，85 / 10 會先變成 8，結果就是 72 了。

一次回傳兩個值

func hoursMinutes(minutes int) (int, int) {
	return minutes / 60, minutes % 60
}

func hoursMinutesDemo() {
	h, m := hoursMinutes(135)
	fmt.Println(h, "小時", m, "分")
}

輸出

2 小時 15 分

回傳值的型別寫成 (int, int)，return 後面用逗號列出兩個值，呼叫時用兩個變數接住：h, m := hoursMinutes(135)。先修 2 的練習已經用過這種寫法。

參數是一份複本

func addOne(n int) {
	n = n + 1
	fmt.Println("函式裡：", n)
}

func copyDemo() {
	count := 5
	addOne(count)
	fmt.Println("函式外：", count)
}

輸出

函式裡： 6
函式外： 5

呼叫 addOne(count) 時，函式拿到的是 count 的值 5，放進它自己的變數 n。函式改的是 n，外面的 count 還是 5。函式要讓外面知道結果，就用 return 交回去。（想讓函式直接改外面的變數，要用 05 指標，那是正文的內容。）

為什麼要把程式拆成函式？第一，有名字：讀到 subtotal(85, 3) 就知道在算小計，不用看裡面怎麼算。第二，可以重複用：寫一次，到處呼叫，改也只改一個地方。第三，可以單獨檢查：每個函式都能拿範例去試，這本手冊的練習就是這樣檢查你的答案的（第 7 節）。

2. 清單：slice

一週七天的營業額、一份菜單、排隊的名單：資料常常是一整串的。為每一筆都建立一個變數（day1、day2、day3……）太累了，而且數量會變。Go 用 slice 來存一份清單：

func listBasics() {
	prices := []int{85, 90, 75}
	fmt.Println(prices)
	fmt.Println(prices[0], prices[2])
	fmt.Println(len(prices))
	prices[1] = 95
	fmt.Println(prices)
	prices = append(prices, 100)
	fmt.Println(prices, len(prices))
}

輸出

[85 90 75]
85 75
3
[85 95 75]
[85 95 75 100] 4
  • []int{85, 90, 75}：[]int 是「一串 int」，大括號裡列出一開始的內容。
  • prices[0]：用中括號加索引（index）拿出某一格。索引從 0 開始，所以第一個是 [0]，第三個是 [2]。
  • len(prices)：清單的長度，也就是有幾格。
  • prices[1] = 95：把某一格換成新的值，和變數的指定一樣。
  • prices = append(prices, 100)：在最後面加一格。append 會交回加好的新清單，一定要用 = 接回去（常見錯誤 2）。
func stringList() {
	menu := []string{"排骨飯", "雞腿飯", "素食餐"}
	fmt.Println(menu[0])
	fmt.Println(menu[len(menu)-1])
}

func emptyList() {
	orders := []int{}
	fmt.Println(len(orders))
	orders = append(orders, 120)
	orders = append(orders, 85)
	fmt.Println(orders, len(orders))
}

輸出

排骨飯
素食餐
0
[120 85] 2

清單裡可以放任何型別，但同一份清單只能放同一種。最後一個元素的索引是 len(menu)-1：3 個元素的索引是 0、1、2。不知道一開始有什麼時，從空的清單 []int{} 開始，再一筆一筆 append。

索引超出範圍

3 個元素的清單沒有 [3]。用了不存在的索引，程式能編譯，但執行到那一行就會當掉：

func main() {
	menu := []string{"排骨飯", "雞腿飯", "素食餐"}
	for i := 0; i <= len(menu); i++ {
		fmt.Println(i, menu[i])
	}
}
go run ./chapters/pre-4-problems/outofrange

輸出（檔案路徑的前半段以 … 代替）

0 排骨飯
1 雞腿飯
2 素食餐
panic: runtime error: index out of range [3] with length 3

goroutine 1 [running]:
main.main()
	…/chapters/pre-4-problems/outofrange/main.go:12 +0xd8
exit status 2

前三圈正常，第四圈 i 是 3，訊息說得很清楚：索引 3 超出範圍，這份清單的長度是 3。原因是條件寫成 i <= len(menu)，多跑了一圈；正確的是 i < len(menu)。這是先修 1 說的執行時錯誤，也是先修 3 的「邊界差一」。

3. 走過清單

清單幾乎都是搭配迴圈使用的。第一種寫法用先修 3 學過的 for，讓 i 從 0 走到 len-1：

func loopIndex() {
	menu := []string{"排骨飯", "雞腿飯", "素食餐"}
	for i := 0; i < len(menu); i++ {
		fmt.Println(i, menu[i])
	}
}

輸出

0 排骨飯
1 雞腿飯
2 素食餐

條件用 i < len(menu)，不管清單有幾個元素都剛好走完，不會超出範圍。第二種寫法是 range，它會自動走過每一格：

func loopRange() {
	prices := []int{85, 90, 75}
	for i, p := range prices {
		fmt.Println("第", i+1, "個：", p, "元")
	}
}

輸出

第 1 個： 85 元
第 2 個： 90 元
第 3 個： 75 元
  • for i, p := range prices：每一圈 i 是索引、p 是值。不用自己寫起點、條件、更新，也就不會寫錯邊界。
  • 只需要值時，用底線 _ 丟掉索引：for _, p := range prices。Go 不允許建立了卻沒用到的變數，_ 就是「這個我不要」。
  • 只需要索引時，寫 for i := range prices。
  • 索引從 0 開始，給人看的「第幾個」通常是 i+1。

一般來說，用 range 比較不容易出錯；需要同時看「這一個和前一個」（練習 3）這種跟索引有關的計算時，用索引的寫法比較方便。

4. 四個基本演算法

演算法（algorithm）聽起來很難，其實就是「解決某一類問題的固定步驟」。處理清單時，有四個演算法出現的次數遠遠超過其他的。它們都是先修 3 的計數器和累加器的延伸：

加總

func sum(nums []int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func sumDemo() {
	sales := []int{3200, 4100, 2800, 5600, 4100}
	fmt.Println(sum(sales))
}

輸出

19800

累加器 total 從 0 開始，每個元素都加進去。這個函式不管清單有多長都能用；它自己不知道、也不需要知道 sales 是營業額，換成分數、重量也一樣。

計數

func countAtLeast(nums []int, limit int) int {
	count := 0
	for _, n := range nums {
		if n >= limit {
			count++
		}
	}
	return count
}

func countDemo() {
	sales := []int{3200, 4100, 2800, 5600, 4100}
	fmt.Println(countAtLeast(sales, 4000))
}

輸出

3

計數器 count 從 0 開始，只在條件成立時加 1。門檻 limit 做成參數，同一個函式可以數「4000 以上的天數」，也可以數「及格的人數」。

找最大值

func maxOf(nums []int) int {
	best := nums[0]
	for _, n := range nums {
		if n > best {
			best = n
		}
	}
	return best
}

func maxDemo() {
	sales := []int{3200, 4100, 2800, 5600, 4100}
	fmt.Println(maxOf(sales))
}

輸出

5600

想像你一張一張翻看成績單，手上只記一個數字「目前看過最高的」。翻到更高的，就把手上的數字換掉；翻完時，手上的就是最高分。best 一開始要設成清單的第一個值，不能隨便設成 0：

func wrongMax(nums []int) int {
	best := 0
	for _, n := range nums {
		if n > best {
			best = n
		}
	}
	return best
}

func wrongMaxDemo() {
	temps := []int{-3, -5, -1}
	fmt.Println(wrongMax(temps), maxOf(temps))
}

輸出

0 -1

高山上三天的最低氣溫是 -3、-5、-1 度，最高的應該是 -1。但 wrongMax 從 0 開始比，沒有任何一個溫度比 0 大，best 從頭到尾都是 0，最後交回一個清單裡根本沒有的數字。從第一個值開始比，就不會有這個問題。找最小值的做法完全一樣，只是把 > 換成 <（練習 6）。

搜尋

func indexOf(names []string, target string) int {
	for i, name := range names {
		if name == target {
			return i
		}
	}
	return -1
}

func searchDemo() {
	queue := []string{"小明", "阿美", "小華"}
	fmt.Println(indexOf(queue, "阿美"))
	fmt.Println(indexOf(queue, "小芬"))
}

輸出

1
-1

一個一個比對，找到就立刻 return 它的索引，後面的不用再看了。整份清單都走完還沒有 return，就表示找不到，回傳 -1。-1 不可能是真的索引，所以呼叫的人看到 -1 就知道「沒有」。

演算法迴圈前每一圈結果
加總total := 0total += ntotal
計數count := 0條件成立時 count++count
最大值best := nums[0]比 best 大就換掉best
搜尋（不用）找到就 return i走完還沒找到就 return -1

5. 拆解問題

便當店老闆想要一份一週營業報表：總營業額、平均每天多少、哪一天最好、有幾天達到 4500 元。第一次看到這種題目，很容易不知道從哪裡下手。拆解問題的步驟是：

  1. 用中文寫出要什麼：輸入是七天的營業額，輸出是四行報表。
  2. 拆成小問題：每一行報表就是一個小問題。
  3. 認出熟悉的形狀：總額是加總，達標天數是計數，最好的一天是找最大值，只是這次要的是「哪一天」，也就是最大值的索引。
  4. 一個小問題寫一個函式，各自測試沒問題之後，再組合起來。
func indexOfMax(nums []int) int {
	best := 0
	for i := range nums {
		if nums[i] > nums[best] {
			best = i
		}
	}
	return best
}

func weeklyReport() {
	sales := []int{3200, 4100, 2800, 5600, 4100, 6300, 5000}
	days := []string{"一", "二", "三", "四", "五", "六", "日"}

	total := sum(sales)
	fmt.Println("總營業額：", total)
	fmt.Println("平均每天：", total/len(sales))

	d := indexOfMax(sales)
	fmt.Println("最好的一天：星期"+days[d], sales[d])

	fmt.Println("達到 4500 的天數：", countAtLeast(sales, 4500))
}

輸出

總營業額： 31100
平均每天： 4442
最好的一天：星期六 6300
達到 4500 的天數： 3
  • sum 和 countAtLeast 直接用第 4 節寫好的函式，不用重寫。
  • indexOfMax 和 maxOf 幾乎一樣，差別是它記住的是「最大的那一格的索引」best，比較時用 nums[best] 拿出那一格的值。知道索引，就能從另一份清單 days 拿到星期幾。
  • 平均是 31100 / 7 = 4442.857…，整數除法丟掉了小數，得到 4442。要保留小數，就照先修 2 的做法先轉成 float64。

weeklyReport 本身讀起來就像報表的大綱，每一行都很短。這是拆成函式最大的好處：每一層只需要看懂一件事。

6. 用 Println 除錯

程式的結果不對，但看不出哪裡錯時，最簡單有效的方法是在中間加幾行 fmt.Println，把變數印出來，讓電腦替你填追蹤表。下面的函式想把 85、90、75 加起來，應該得到 250，結果卻是 165：

func buggyTotal(nums []int) int {
	total := 0
	for i := 1; i < len(nums); i++ {
		total += nums[i]
		fmt.Println("i =", i, "total =", total)
	}
	return total
}

func debugDemo() {
	fmt.Println(buggyTotal([]int{85, 90, 75}))
}

輸出

i = 1 total = 90
i = 2 total = 165
165

印出來的第一行就是 i = 1，total 一開始就是 90：第一個元素 85 根本沒有被加到。回頭看迴圈，起點寫成了 i := 1，應該是 0。除錯的步驟可以整理成：

  1. 先想好正確的答案（250），確認結果真的不對。
  2. 在迴圈裡、或可疑的那一行前後，印出相關的變數，並寫清楚印的是什麼（"i ="）。
  3. 把印出來的值和你腦中的追蹤表比對，找到第一個不一樣的地方。
  4. 修好之後，把除錯用的 Println 刪掉。

這個方法看起來很原始，卻是有經驗的工程師每天都在用的技巧。以後你會學到更強的工具，但它們做的事情本質上一樣：看清楚程式每一步實際做了什麼。

7. 用範例驗證

怎麼知道 maxOf 是對的？用幾個範例試試看：給它一份清單，看它交回的值是不是我們預期的。把這些範例寫成程式，就是測試（test）。下面是本章 maxOf 的測試，放在 main_test.go：

func TestMaxOf(t *testing.T) {
	tests := []struct {
		name string
		nums []int
		want int
	}{
		{"一般", []int{3, 9, 4}, 9},
		{"最大的在第一個", []int{9, 3, 4}, 9},
		{"最大的在最後", []int{3, 4, 9}, 9},
		{"只有一個", []int{7}, 7},
		{"全是負數", []int{-3, -5, -1}, -1},
		{"有一樣大的", []int{5, 5, 2}, 5},
	}
	for _, tt := range tests {
		if got := maxOf(tt.nums); got != tt.want {
			t.Errorf("%s：maxOf(%v) = %d, want %d", tt.name, tt.nums, got, tt.want)
		}
	}
}

現在不用看懂每個符號，只要知道：tests 是一份範例清單，每一行是「名稱、輸入、期望的答案」；下面的 for 一個一個拿出來執行 maxOf，答案不對就用 t.Errorf 報告。注意這些範例是怎麼挑的：一般的情況、最大值在最前面、在最後面、只有一個元素、全是負數、有一樣大的。很多 bug 都躲在這些邊緣的情況裡。如果把 maxOf 的起點改成 best := 0，執行 go test -run TestMaxOf ./chapters/pre-4-problems 會看到：

輸出（節錄）

--- FAIL: TestMaxOf (0.00s)
    main_test.go:142: 全是負數：maxOf([-3 -5 -1]) = 0, want -1
FAIL

其他五個範例都通過了，只有「全是負數」抓到了問題。如果當初只用 [3 9 4] 試，就永遠發現不了這個 bug。

這本手冊的每一題練習都附有這樣的測試，放在 exercises_test.go。卡住的時候，打開測試檔看看它用了哪些範例，常常就知道自己漏想了什麼情況。更好的習慣是先想範例、再寫程式：動手之前，先在紙上寫下三五組「輸入→答案」，包括空的清單、只有一個元素、邊界上的值。範例想清楚了，程式通常就不難寫了。

常見錯誤

1. 索引從 1 開始算

第一個元素是 [0]，最後一個是 [len-1]。迴圈條件寫成 i <= len(s) 會多跑一圈而 panic；起點寫成 i := 1 會漏掉第一個（第 6 節）。不需要索引時用 range，就不會有這些問題。

2. append 沒有接回去

package main

import "fmt"

func main() {
	prices := []int{85, 90, 75}
	append(prices, 100)
	fmt.Println(prices)
}

編譯錯誤

./main.go:7:2: append(prices, 100) (value of type []int) is not used

append 不會讓原本的清單變長，而是交回一份加好的清單。要寫成 prices = append(prices, 100)。

3. 最大值、最小值從 0 開始比

全是負數時找最大值、全是正數時找最小值，答案都會是 0。從清單的第一個值開始（第 4 節、練習 6）。

4. 有些路沒有 return

package main

import "fmt"

func memberPrice(price int, member bool) int {
	if member {
		return price * 9 / 10
	}
}

func main() {
	fmt.Println(memberPrice(100, true))
}

編譯錯誤

./main.go:9:1: missing return

說好要回傳 int 的函式，每一條可能走到結尾的路都要有 return。不是會員時，這個函式走到最後一個 } 都沒有交回任何值。

5. 以為函式改了參數，外面就會變

參數是一份複本（第 1 節）。要讓外面拿到結果，就用 return 交回去，再由呼叫的人接住。

6. 在迴圈裡又寫了一次 :=

迴圈裡寫 count := 0，建立的是一個同名的新變數，每圈都從 0 開始，迴圈外的 count 一次都沒被加到。迴圈裡改值要用 = 或 ++（練習 7）。

  3. 進階練習 3：最大漲幅

    找出相鄰兩天之間漲最多的金額。

	// TODO: 實作
	return 0
}

    測試：TestBiggestJump。

    提示

    每一天都要和前一天比，所以用索引的寫法，i 從 1 開始：prices[i] - prices[i-1]。這次 best 從 0 開始反而是對的，因為題目說「沒漲就回傳 0」。不到兩天時迴圈一圈都不會跑。

    回傳一份新的清單，只留下大於 limit 的價格。

	// TODO: 實作

}

    測試：TestAbove。

    提示

    從空的清單 result := []int{} 開始，條件成立就 result = append(result, p)。這也是累加器，只是累積的是一份清單。測試也會檢查你沒有改到傳進來的 prices。

  5. 挑戰練習 5：票選午餐

    大家投票決定午餐，找出得票最多的選項；平手時選比較早出現的。

    func MostVoted(votes []string) string {
	// TODO: 實作
	return ""
}

    測試：TestMostVoted。

    提示

    這題是「計數」放進「找最大值」裡面。外層迴圈走過每一張票 v，內層迴圈數出 v 一共有幾票；再像找最大值一樣，記住目前票數最多的選項和它的票數。要讓平手時留下比較早出現的，換掉的條件要用 > 而不是 >=。（學到 07 map 之後，會有更快的做法。）

  6. 找錯練習 6：最便宜的價格

    找最低價，但不管清單是什麼，答案都是 0。

    func CheapestPrice(prices []int) int {
	best := 0
	for _, p := range prices {
		if p < best {
			best = p
		}
	}
	return best
}

    測試：TestCheapestPrice。

    提示

    和第 4 節的 wrongMax 是同一種 bug，方向相反：所有價格都大於 0，沒有一個會「比 0 小」。

  7. 找錯練習 7：庫存不足

    數一數庫存低於門檻的品項，結果永遠是 0。

    func LowStock(stock []int, limit int) int {
	count := 0
	for _, s := range stock {
		count := 0
		if s < limit {
			count++
		}
	}
	return count
}

    測試：TestLowStock。

    提示

    在迴圈裡加一行 fmt.Println(count)，再在 return 前面也印一次，比較兩個 count。迴圈裡那個 count 是從哪裡來的？見常見錯誤 6。

參考解答：先自己寫完再看。

重點回顧

  • 函式有名字、參數和回傳值；return 交回結果並立刻結束函式。
  • 參數是複本，函式裡改參數不影響外面；結果要用 return 交回去。
  • slice 是一份清單：索引從 0 開始，len 是長度，append 的結果要接回去。
  • 用不存在的索引會 panic：index out of range。
  • for i, v := range s 走過每一格；不要的值用 _ 丟掉。
  • 四個基本演算法：加總、計數、找最大值（從第一個值開始比）、搜尋（找到就 return，找不到回傳 -1）。
  • 拆解問題：寫出要什麼、拆成小問題、認出熟悉的形狀、一個小問題一個函式。
  • 結果不對時，用 Println 印出變數，找出第一個和預期不同的地方。
  • 先想範例再寫程式，範例要包含空的、只有一個、邊界上的情況。
