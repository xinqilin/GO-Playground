函式

函式是一台機器：放進參數、拿出結果。在 Go 裡，機器本身也可以裝箱運送：存進變數、當成參數交給別人，甚至由另一台機器生產出來。

1. 宣告與呼叫

函式用 func 宣告，依序寫出名稱、參數列和回傳型別。參數和變數一樣是「名稱在前、型別在後」，相鄰的參數型別相同時可以合併：

func bentoTotal(qty, price int) int {
	return qty * price
}

func callBasics() {
	fmt.Println(bentoTotal(3, 85))
	fmt.Println(bentoTotal(2, 90) + bentoTotal(1, 25))
}

輸出

255
205

函式可以宣告在檔案的任何位置，呼叫的地方寫在前面或後面都沒關係，同一個 package 的其他檔案也能直接呼叫（第 00 章）。名稱大寫開頭就會匯出給其他 package 使用，小寫則只在自己的 package 裡可見。

參數一律傳值

func addOne(n int) {
	n++
	fmt.Println("函式裡：", n)
}

func passByValue() {
	stock := 10
	addOne(stock)
	fmt.Println("呼叫端：", stock)
}

輸出

函式裡： 11
呼叫端： 10

呼叫函式時，每個參數都會複製一份給函式。addOne 改的是自己那一份，呼叫端的 stock 不受影響。想讓函式改到呼叫端的變數，要傳指標（第 05 章）。要注意的是，slice 和 map 被複製的只是一個「指向底層資料的小結構」，所以函式透過它們改內容，呼叫端是看得到的，第 06、07 章會細講。

沒有預設參數，也沒有多載

Go 刻意不支援這兩個功能。寫成 Java 或 Python 的樣子會直接編譯失敗：

package main

import "fmt"

func total(qty int, price int = 85) int {
	return qty * price
}

func main() {
	fmt.Println(total(3))
}

編譯錯誤

./main.go:5:31: syntax error: unexpected = in parameter list; possibly missing comma or )
package main

import "fmt"

func total(qty int) int {
	return qty * 85
}

func total(qty, price int) int {
	return qty * price
}

func main() {
	fmt.Println(total(3), total(3, 90))
}

編譯錯誤

./main.go:9:6: total redeclared in this block
	./main.go:5:6: other declaration of total
./main.go:14:33: too many arguments in call to total
	have (number, number)
	want (int)

理由是讓呼叫的地方一眼就看得出呼叫了哪個函式、傳了哪些值。替代做法：取不同的名字（total 和 totalWithPrice），或者選項很多時，把參數包成一個 struct 傳進去，沒填的欄位就是零值（第 09 章）。

2. 多個回傳值

回傳型別有好幾個時，用括號包起來；return 後面依序寫出每個值：

func divmod(a, b int) (int, int) {
	return a / b, a % b
}

func multiReturn() {
	q, r := divmod(17, 5)
	fmt.Println(q, r)
	_, rest := divmod(1000, 3)
	fmt.Println(rest)
}

輸出

3 2
1

接收時，變數的個數要和回傳值一樣多。不需要的值用 _ 丟掉，但不能少寫。只寫一個變數去接兩個回傳值，編譯器會拒絕：

package main

import (
	"fmt"
	"strconv"
)

func main() {
	n := strconv.Atoi("85")
	fmt.Println(n)
}

編譯錯誤

./main.go:9:7: assignment mismatch: 1 variable but strconv.Atoi returns 2 values

這個限制是故意的：Atoi 的第二個回傳值是錯誤，Go 不讓你在不知不覺中漏掉它。真的不在乎時，也要明寫 n, _ := …，讀程式的人一看就知道這裡忽略了錯誤。

結果加 error

Go 沒有例外（exception）。可能失敗的函式，慣例是把 error 放在最後一個回傳值，成功時回傳 nil，失敗時回傳一個描述問題的 error，其他回傳值則填零值：

func parsePrice(s string) (int, error) {
	num, found := strings.CutSuffix(s, " 元")
	if !found {
		return 0, fmt.Errorf("%q 沒有「 元」結尾", s)
	}
	n, err := strconv.Atoi(num)
	if err != nil {
		return 0, fmt.Errorf("%q 的金額不是整數", s)
	}
	return n, nil
}

func valueAndError() {
	for _, s := range []string{"85 元", "八十五 元", "85"} {
		price, err := parsePrice(s)
		if err != nil {
			fmt.Println("錯誤：", err)
			continue
		}
		fmt.Println("價格：", price)
	}
}

輸出

價格： 85
錯誤： "八十五 元" 的金額不是整數
錯誤： "85" 沒有「 元」結尾

呼叫端的寫法幾乎都長這樣：呼叫完立刻檢查 err != nil，有錯就處理（印出來、往上回傳、換個方式），沒錯才繼續用結果。fmt.Errorf 和 Sprintf 用法一樣，只是回傳一個 error。strings.CutSuffix 是另一個「結果加一個布林」的例子：第二個回傳值告訴你字串原本有沒有這個結尾。錯誤處理的完整技巧（包裝、比對、自訂錯誤型別）在第 11 章。

具名回傳值

func splitBill(total, people int) (each, rest int) {
	if people < 1 {
		return // 回傳 0, 0
	}
	each = total / people
	rest = total % people
	return
}

func namedResults() {
	fmt.Println(splitBill(1000, 3))
	fmt.Println(splitBill(1000, 0))
}

輸出

333 1
0 0

回傳值可以取名字。它們就像在函式一開始宣告的變數，初始值是零值；不帶值的 return（naked return）會把它們當下的值回傳出去。名字也是文件的一部分：(each, rest int) 比 (int, int) 清楚得多。

但 naked return 在長函式裡會讓人找不到「到底回傳了什麼」，實務上的習慣是：名字可以取，return 還是把值寫出來；naked return 只用在幾行的短函式。具名回傳值真正不可取代的用途，是讓 defer 修改回傳值（第 7 節）。

3. 可變參數

最後一個參數的型別前面加上 ...，就能接受任意個值。fmt.Println、append 都是這樣寫的：

func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func joinWith(sep string, parts ...string) string {
	return strings.Join(parts, sep)
}

func variadic() {
	fmt.Println(sum(), sum(85), sum(85, 90, 15))
	prices := []int{85, 90, 15}
	fmt.Println(sum(prices...))
	fmt.Println(joinWith("、", "排骨", "雞腿", "滷蛋"))
}

輸出

0 85 190
190
排骨、雞腿、滷蛋
  • 不給任何值：nums 是 nil slice，長度 0，for range 一圈都不跑，所以 sum() 是 0。
  • 只能放在最後：一個函式最多一個可變參數，而且必須是最後一個，前面可以有一般參數，例如 joinWith 的 sep。
  • 展開現成的 slice：在呼叫時寫 prices...。這時不會建立新的 slice，函式拿到的就是 prices 本身，如果函式修改了 nums[0]，呼叫端的 prices 也會跟著變。
  • 不能混用：sum(15, prices...) 是編譯錯誤，展開的 slice 必須是唯一的那個可變參數：
./main.go:15:22: too many arguments in call to sum
	have (number, []int...)
	want (...int)

要合併時先用 append([]int{15}, prices...) 組出一個新的 slice 再展開。

4. 函式是值

在 Go 裡，函式和整數、字串一樣是一種值，有自己的型別，可以存進變數、放進 slice 或 map、當成參數傳遞、當成回傳值：

func double(n int) int { return n * 2 }

func funcValues() {
	f := double
	fmt.Println(f(21))

	square := func(n int) int { return n * n }
	fmt.Println(square(9))

	fmt.Printf("%T\n", square)

	var g func(int) int
	fmt.Println(g == nil)
}

輸出

42
81
func(int) int
true
  • f := double：沒有括號，代表「這個函式本身」，不是呼叫它。
  • func(n int) int { … }：沒有名字的函式字面值（function literal），也叫匿名函式，可以寫在任何需要值的地方。
  • 函式的型別由參數和回傳值決定：func(int) int。名字不是型別的一部分，所以 double 和 square 是同一個型別。
  • 函式的零值是 nil，呼叫一個 nil 函式會 panic。函式只能和 nil 比較，兩個函式之間不能用 ==（常見錯誤 6）。

函式型別

type PriceRule func(int) int

func applyRules(price int, rules []PriceRule) int {
	for _, rule := range rules {
		price = rule(price)
	}
	return price
}

func funcTypes() {
	memberDiscount := func(p int) int { return p * 9 / 10 }
	coupon := func(p int) int { return p - 50 }
	rules := []PriceRule{memberDiscount, coupon}
	fmt.Println(applyRules(500, rules))
	fmt.Println(applyRules(500, []PriceRule{coupon, memberDiscount}))
}

輸出

400
405

type PriceRule func(int) int 替函式的型別取了一個名字，讓程式更好讀。任何簽名相符的函式，不管有沒有名字，都可以當成 PriceRule 使用。applyRules 不知道也不在乎規則的內容，只負責依序呼叫；新增一條「滿千送百」的規則，只要多寫一個函式放進 slice。這種「把行為當成參數」的寫法，在 Java 要定義一個介面或用 lambda，在 Go 直接傳函式就好。

標準庫裡的例子

type bento struct {
	name  string
	price int
}

func sortWithFunc() {
	menu := []bento{{"雞腿", 90}, {"素食", 70}, {"排骨", 85}}
	slices.SortFunc(menu, func(a, b bento) int {
		return cmp.Compare(a.price, b.price)
	})
	fmt.Println(menu)
}

輸出

[{素食 70} {排骨 85} {雞腿 90}]

slices.SortFunc 負責排序的演算法，「誰應該排前面」則由你傳進去的函式決定：回傳負數表示 a 在前，正數表示 b 在前，0 表示一樣。cmp.Compare 剛好就照這個規則比較兩個值。標準庫還有很多這種設計，例如 strings.FieldsFunc、slices.IndexFunc、http.HandleFunc。

5. closure

函式字面值可以使用它外層的變數。函式加上它記住的這些變數，合起來叫做 closure。最經典的例子是一台叫號機：

func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

func closureCounter() {
	next := counter()
	fmt.Println(next(), next(), next())
	other := counter()
	fmt.Println(other(), next())
}

輸出

1 2 3
1 4

counter 已經 return 了，照理說它的區域變數 n 應該消失；但回傳出去的函式還在用 n，所以 Go 會讓 n 活下來，直到沒有人用它為止（變數活在哪裡，由編譯器的逃逸分析決定，第 05 章）。每呼叫一次 counter，就會建立一個新的 n 和一個新的 closure，所以 next 和 other 各數各的。

抓住的是變數，不是值

func closureShared() {
	price := 85
	show := func() { fmt.Println("目前價格：", price) }
	show()
	price = 90
	show()
}

輸出

目前價格： 85
目前價格： 90

closure 和外面的程式碼共用同一個 price 變數，而不是在建立時拍一張快照。所以外面改了，closure 看得到；closure 裡面改了，外面也看得到。這一點和 Java 的 lambda 不同：Java 只允許抓「實質上不會再改」（effectively final）的變數。共用很方便，但要小心多個 closure 同時改同一個變數，尤其是在 goroutine 裡（第 17 章）。

產生函式的函式

func greeter(prefix string) func(string) string {
	return func(name string) string {
		return prefix + name
	}
}

func closureFactory() {
	welcome := greeter("歡迎光臨，")
	call := greeter("請取餐：")
	fmt.Println(welcome("小明"))
	fmt.Println(call("A07"))
}

輸出

歡迎光臨，小明
請取餐：A07

greeter 先收下 prefix，回傳一個只需要 name 的函式。這種「先固定一部分參數，之後再補齊」的寫法，可以拿來做設定好的規則（練習 4 的 PercentOff）、HTTP 的 middleware，或者測試用的假資料產生器。

迴圈裡的 closure

在 for 迴圈裡建立 closure，以前是 Go 最有名的陷阱：所有 closure 抓到同一個迴圈變數。Go 1.22 起每一圈都是新的變數，這個問題已經不存在，詳細說明見第 03 章的 3.8 節。

6. 遞迴

函式可以呼叫自己，這叫遞迴。寫遞迴只要想清楚兩件事：終止條件（什麼時候可以直接回答），以及怎麼把問題縮小：

func binary(n int) string {
	if n < 2 {
		return strconv.Itoa(n)
	}
	return binary(n/2) + strconv.Itoa(n%2)
}

func recursion() {
	fmt.Println(binary(13), binary(255), binary(0))
}

輸出

1101 11111111 0

13 的二進位，等於「13/2 = 6 的二進位」後面接上「13%2 = 1」。6 再交給下一層，直到剩下 0 或 1，這時答案就是它自己。每一層都在等下一層的答案，所以呼叫會一層層疊起來，答案再從最底層一路往上組回去。

遞迴特別適合處理本身就是巢狀結構的資料：資料夾裡有資料夾、分類底下有子分類、JSON 裡有 JSON。練習 7 用遞迴計算「湊出一個金額有幾種付法」，把問題拆成「用這種硬幣」和「不用這種硬幣」兩個比較小的問題。

深入：第一次讀可以先跳過

6.1 忘了終止條件會怎樣

每一層呼叫都要在堆疊上佔一點空間。Go 的堆疊一開始很小，不夠時會自動長大，所以正常的遞迴深度不用擔心；但它有上限，64 位元系統上是 1 GB。沒有終止條件的遞迴最後會撞到這個上限，程式直接當掉，而且這不是 panic，recover 也救不了：

把 binary 的 if n < 2 那段拿掉，或寫一個永遠不停的 func depth(n int) int { return depth(n+1) + 1 }，執行的結果是（記憶體位址以 … 代替，後面幾千行的堆疊省略）：

runtime: goroutine stack exceeds 1000000000-byte limit
runtime: sp=… stack=[…]
fatal error: stack overflow

另外，Go 編譯器不做尾端呼叫最佳化（tail call optimization），把遞迴改寫成尾端呼叫的形式也不會省下堆疊。遞迴深度可能很深（例如走訪一條上百萬個節點的鏈），就改用迴圈。

7. defer

defer 把一個函式呼叫「登記」起來，等到外層函式結束前才執行。不管函式是正常 return、從中間某個 return 提早離開，還是發生 panic，登記過的 defer 都會執行：

func deferOrder() {
	defer fmt.Println("關店")
	defer fmt.Println("關燈")
	defer fmt.Println("收銀機結帳")
	fmt.Println("營業中")
}

輸出

營業中
收銀機結帳
關燈
關店

多個 defer 依照「後進先出」的順序執行，跟登記的順序相反。這個順序很合理：越晚取得的資源，通常依賴越早取得的資源，所以應該越早釋放。最常見的用法是「取得資源後馬上 defer 釋放」，例如：

  • 打開檔案後 defer f.Close()（20 章「檔案與 I/O」）。
  • 鎖上 mutex 後 defer mu.Unlock()（第 17 章）。
  • 建立有逾時的 context 後 defer cancel()（第 18 章）。

把「打開」和「關閉」寫在相鄰的兩行，不管函式後面有多少個 return，都不會漏掉關閉。

參數在登記時就算好

func deferArgs() {
	x := 10
	defer fmt.Println("參數：", x)
	defer func() { fmt.Println("closure：", x) }()
	x = 20
}

輸出

closure： 20
參數： 10

這是 defer 最容易誤會的地方。defer fmt.Println("參數：", x) 在登記的那一刻就把參數算好了，當時 x 是 10，所以之後 x 改成 20 也沒影響。如果要讀「執行時」的值，就 defer 一個 closure，讓它在真正執行時才去讀變數。兩個 defer 的輸出順序也再次說明了後進先出。

修改回傳值

func deferResult() (total int) {
	defer func() {
		total += 10 // 外送費
	}()
	return 85
}

輸出

95

return 85 其實分成兩步：先把 85 放進回傳值 total，然後執行 defer，最後才真正離開函式。因為回傳值有名字，defer 裡的 closure 可以讀到並修改它，所以最後回傳 95。這個技巧最常用在錯誤處理：在 defer 裡替回傳的 error 加上更多資訊，或者像第 8 節那樣，把 panic 轉成 error。回傳值沒有名字時，defer 改不到它，練習 6 就是這個 bug。

迴圈裡的 defer

錯誤寫法：資源要等整個函式結束才關閉

func deferInLoop() {
	for _, name := range []string{"a.txt", "b.txt"} {
		f := open(name)
		defer closeRes(f)
		fmt.Println("處理", f)
	}
	fmt.Println("迴圈結束")
}

輸出

開啟 a.txt
處理 a.txt
開啟 b.txt
處理 b.txt
迴圈結束
關閉 b.txt
關閉 a.txt

正確寫法：每一圈包成一個函式

func deferInLoopFixed() {
	for _, name := range []string{"a.txt", "b.txt"} {
		func() {
			f := open(name)
			defer closeRes(f)
			fmt.Println("處理", f)
		}()
	}
	fmt.Println("迴圈結束")
}

輸出

開啟 a.txt
處理 a.txt
關閉 a.txt
開啟 b.txt
處理 b.txt
關閉 b.txt
迴圈結束

defer 屬於函式，不屬於迴圈的某一圈。在迴圈裡 defer，所有資源都要等函式結束才釋放：處理一萬個檔案，就會同時開著一萬個檔案，很快就撞到作業系統的上限。解法是把每一圈的工作包成一個函式（可以是上面的匿名函式，也可以抽成一個有名字的函式），defer 就會在每一圈結束時執行。練習 5 會讓你修這個 bug。

8. panic 與 recover

panic 代表「程式遇到了不該發生的狀況，沒辦法繼續」。發生 panic 時，目前的函式立刻停止，開始一層層往上退出，途中執行每一層登記的 defer；退到最上層都沒有人處理，程式就印出錯誤和呼叫路徑，然後結束。第 01 章的整數除以 0、之後會看到的索引超出範圍、對 nil map 寫入，都是執行時自動產生的 panic；你也可以自己呼叫 panic(值)。

下面這支程式（chapters/04-functions/crash）第二次拿貨時拿太多，take 主動 panic：

func take(stock, n int) int {
	if n > stock {
		panic(fmt.Sprintf("庫存不足：剩 %d 個，要拿 %d 個", stock, n))
	}
	return stock - n
}

func main() {
	defer fmt.Println("main 的 defer 還是會執行")
	fmt.Println(take(5, 2))
	fmt.Println(take(3, 10))
	fmt.Println("這一行不會執行")
}
go run ./chapters/04-functions/crash

輸出（repo 所在的路徑以 … 代替）

3
main 的 defer 還是會執行
panic: 庫存不足：剩 3 個，要拿 10 個

goroutine 1 [running]:
main.take(...)
	…/chapters/04-functions/crash/main.go:11
main.main()
	…/chapters/04-functions/crash/main.go:19 +0xf4
exit status 2

讀法：第一行是 panic 的訊息；下面是 panic 發生時的呼叫路徑（stack trace），由內往外列出每一層的函式和行號：take 在第 11 行 panic，它是被 main 在第 19 行呼叫的。+0xf4 這類數字是機器碼裡的位置，每台電腦可能不同，可以忽略。注意 main 的 defer 在程式當掉之前執行了。最後一行是 go run 告訴你程式的結束碼是 2。這支程式故意會當掉，所以它沒有測試。

recover：在邊界把 panic 接住

func take(stock, n int) int {
	if n > stock {
		panic(fmt.Sprintf("庫存不足：剩 %d 個，要拿 %d 個", stock, n))
	}
	return stock - n
}

func safeTake(stock, n int) (left int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("拿貨失敗：%v", r)
		}
	}()
	return take(stock, n), nil
}

func panicRecover() {
	fmt.Println(safeTake(5, 2))
	fmt.Println(safeTake(3, 10))
	fmt.Println("程式繼續執行")
}

輸出

3 <nil>
0 拿貨失敗：庫存不足：剩 3 個，要拿 10 個
程式繼續執行

recover() 會停止正在進行的 panic，並回傳當初傳給 panic 的值；沒有 panic 時它回傳 nil。它有一個嚴格的限制：只有在 defer 的函式裡直接呼叫才有效。在一般的程式碼裡呼叫，或在 defer 函式呼叫的另一個函式裡呼叫，都只會得到 nil。所以 recover 幾乎都長成上面這個樣子：defer 一個 closure，裡面呼叫 recover，有值的話就修改具名的 error 回傳值（第 7 節的技巧）。

什麼時候該 panic

Go 的原則很清楚：可以預期的失敗用 error，程式寫錯了才 panic。

  • 用 error：使用者輸入錯誤、檔案不存在、網路斷線、資料庫查不到資料。這些都是正常程式會遇到的狀況，呼叫端應該決定怎麼處理。
  • 可以 panic：違反了函式的前提，表示呼叫端的程式有 bug，例如傳入了不可能的參數、走到了「不可能走到」的分支。還有初始化時的設定錯誤：程式一啟動就發現設定不對，與其帶著錯誤繼續跑，不如立刻停下來。標準庫的 regexp.MustCompile 就是這種設計，Must 開頭的函式失敗時會 panic，適合用在套件層級、內容寫死的正規表示式。
  • 用 recover：只用在「邊界」，例如 HTTP 伺服器在每個請求外面包一層 recover，一個請求的 bug 不會拖垮整台伺服器（標準庫的 net/http 就這樣做）。不要用 panic 和 recover 模擬 Java 的 try-catch 來處理一般錯誤。

還有一點：recover 只能接住同一個 goroutine 裡的 panic。別的 goroutine panic 了，整個程式一樣會當掉（第 14 章）。

常見錯誤

1. 拿到 error 卻不檢查

寫了 n, _ := strconv.Atoi(s) 或 n, err := … 之後沒有檢查 err，輸入錯誤時 n 是 0，程式會帶著錯誤的值繼續跑，問題在很遠的地方才浮現。每個 err 都要嘛處理、要嘛往上回傳。

2. 在迴圈裡 defer

資源要等整個函式結束才釋放，見第 7 節的對照。把每一圈包成一個函式。

3. 以為 defer 的參數最後才算

defer fmt.Println(x) 印出的是登記當下的 x。要讀最後的值，defer 一個 closure（第 7 節）。

4. 想在 defer 裡改回傳值，但回傳值沒有名字

defer 裡修改的只是一個區域變數，真正回傳的值不會變。要讓 defer 改得到，回傳值必須有名字（練習 6）。

5. recover 沒有放在 defer 的函式裡

在一般的程式碼裡呼叫 recover，或者在 defer 函式呼叫的另一個函式裡呼叫，都接不到 panic。recover 一定要在 defer 的函式裡直接呼叫。

6. 比較兩個函式

package main

import "fmt"

func double(n int) int { return n * 2 }

func main() {
	f := double
	g := double
	fmt.Println(f == g)
}

編譯錯誤

./main.go:10:14: invalid operation: f == g (func can only be compared to nil)

函式只能和 nil 比較。需要分辨「是哪一條規則」時，替規則取名字或編號，比較名字，而不是比較函式本身。

7. 用 panic 處理一般錯誤

找不到資料就 panic、輸入格式錯了就 panic，呼叫端只能用 recover 接，程式很快就變得難以理解。可以預期的失敗回傳 error（第 8 節）。

    b 是 0 時應該回傳 0 和錯誤，而且程式不能當掉。它確實沒有當掉，但回傳的錯誤是 nil。

    func SafeDiv(a, b int) (int, error) {
	var err error
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("除法失敗：%v", r)
		}
	}()
	return a / b, err

    錯誤訊息要是 除法失敗：runtime error: integer divide by zero。測試：TestSafeDiv。

    panic 發生時，return a / b, err 根本沒有執行完，函式回傳的是兩個回傳值的零值。defer 改了區域變數 err，但那不是回傳值。怎麼讓 defer 改得到回傳值？第 7 節「修改回傳值」。

重點回顧

  • 參數一律傳值，函式改參數不會影響呼叫端；沒有預設參數，也沒有多載。
  • 可能失敗的函式把 error 放在最後一個回傳值，呼叫完立刻檢查 err != nil。
  • 接收回傳值時個數要對上，不要的值用 _。
  • 具名回傳值是零值起跳；naked return 只用在短函式。
  • 可變參數在函式裡是 slice，只能放最後；呼叫時用 s... 展開現成的 slice。
  • 函式是值，型別由參數和回傳值決定；只能和 nil 比較。
  • closure 抓住的是變數本身，每次呼叫外層函式都會產生一份新的狀態。
  • 遞迴要有終止條件；Go 的堆疊會長大，但上限是 1 GB，而且沒有尾端呼叫最佳化。
  • defer 在函式結束前執行，後進先出，參數在登記時就算好；在迴圈裡 defer 要包成函式。
  • defer 搭配具名回傳值，可以在函式結束前修改回傳值。
  • panic 用在程式寫錯和無法繼續的狀況，可預期的失敗回傳 error；recover 只在 defer 的函式裡直接呼叫才有效，只用在邊界。
