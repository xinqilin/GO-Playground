泛型

泛型是一個模具：形狀先刻好，要用的時候再決定倒進去的是 int、string 還是你自己的型別。型別檢查仍然在編譯時完成。

1. 為什麼需要泛型

Go 1.18 加入了泛型。在那之前，同一個演算法要套用到不同的型別，只有兩條路：

func sumInts(s []int) int {
	total := 0
	for _, v := range s {
		total += v
	}
	return total
}

func sumFloats(s []float64) float64 {
	total := 0.0
	for _, v := range s {
		total += v
	}
	return total
}

func sumAny(s []any) float64 {
	total := 0.0
	for _, v := range s {
		switch x := v.(type) {
		case int:
			total += float64(x)
		case float64:
			total += x
		}
	}
	return total
}
  • 每種型別各寫一次：sumInts 和 sumFloats 只差在型別，邏輯一模一樣。要改一個 bug 就得改好幾份。
  • 用 any 什麼都收：只寫一次，但型別檢查從編譯期延到了執行期。sumAny 收到一個字串，編譯器不會阻止，只能在執行時用 type switch 判斷，遇到不認得的型別就默默跳過（10 章）。而且傳進來的 []int 得先一個一個搬進 []any。

泛型是第三條路：

func Sum[N int | float64](s []N) N {
	var total N
	for _, v := range s {
		total += v
	}
	return total
}

func whyDemo() {
	fmt.Println(sumInts([]int{85, 95}), sumFloats([]float64{1.5, 2.25}))
	fmt.Println(sumAny([]any{85, 2.5, "排骨飯"}))
	fmt.Println(Sum([]int{85, 95}), Sum([]float64{1.5, 2.25}))
}

輸出

180 3.75
87.5
180 3.75

函式名稱後面的中括號 [N int | float64] 宣告了一個型別參數（type parameter）N，它代表「呼叫時才決定的某個型別」，int | float64 是它的限制（constraint）：N 只能是 int 或 float64。函式本體裡，N 就像一個普通的型別，var total N 宣告一個 N 型別的零值。只寫一次，傳 []int 回傳 int，傳 []float64 回傳 float64，傳 []string 則是編譯錯誤。sumAny 那種「把字串偷偷略過」的情況不會發生。

2. 型別參數與限制

func Clamp[T cmp.Ordered](v, lo, hi T) T {
	if v < lo {
		return lo
	}
	if v > hi {
		return hi
	}
	return v
}

func CountOf[T comparable](s []T, v T) int {
	n := 0
	for _, x := range s {
		if x == v {
			n++
		}
	}
	return n
}

func paramsDemo() {
	fmt.Println(Clamp(20, 1, 12))
	fmt.Println(Clamp(0.35, 0.0, 0.3))
	fmt.Println(Clamp("Z", "A", "M"))
	fmt.Println(Clamp[float64](5, 1, 12.5))
	fmt.Println(CountOf([]string{"排骨飯", "雞腿飯", "排骨飯"}, "排骨飯"))
}

輸出

12
0.3
M
5
2

限制本身是一個 interface，標準庫已經準備好最常用的三個：

  • any：什麼型別都可以。但正因為什麼都可以，函式裡只能做「所有型別都能做」的事：指定、傳遞、轉成 any，不能用 +、<，也不能呼叫方法。
  • comparable：可以用 == 和 != 比較的型別，也就是能當 map key 的型別（07 章）。CountOf 只需要 ==，所以用它。
  • cmp.Ordered：可以用 <、> 比大小的型別，包括所有整數、浮點數和字串。Clamp 要比大小，所以用它；字串比的是 byte 順序，"Z" 比 "M" 大，結果是 M。

呼叫時可以把型別寫在中括號裡：Clamp[float64](5, 1, 12.5)，這叫實例化（instantiation），把 T 換成 float64，得到一個普通的函式，5 和 1 這兩個常數就會被當成 float64。大多數時候不用寫，Go 會從參數推論出來（第 4 節）。另外，Go 1.21 起有內建的 min 和 max，Clamp 也可以寫成 min(max(v, lo), hi)。

限制也是一份承諾：在函式裡用了限制不允許的運算，編譯器會擋下來，所以你不可能寫出「對某些型別會壞掉」的泛型函式：

package main

import "fmt"

func Largest[T any](s []T) T {
	best := s[0]
	for _, v := range s[1:] {
		if v > best {
			best = v
		}
	}
	return best
}

func main() {
	fmt.Println(Largest([]int{85, 95, 30}))
}

編譯錯誤

./main.go:8:6: invalid operation: v > best (type parameter T cannot use operator >)

T 是 any，any 裡有不能比大小的型別，所以不能用 >。把限制改成 cmp.Ordered 就好了。反過來，傳一個不滿足限制的型別進去，錯誤訊息會把限制允許的型別全部列出來，cmp.Ordered 的完整內容就藏在這裡：

package main

import (
	"cmp"
	"fmt"
)

type Bento struct {
	Name  string
	Price int
}

func Clamp[T cmp.Ordered](v, lo, hi T) T {
	return min(max(v, lo), hi)
}

func main() {
	a := Bento{Name: "排骨飯", Price: 85}
	b := Bento{Name: "雞腿飯", Price: 95}
	fmt.Println(Clamp(a, a, b))
}

編譯錯誤

./main.go:20:19: Bento does not satisfy cmp.Ordered (Bento missing in ~int | ~int8 | ~int16 | ~int32 | ~int64 | ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr | ~float32 | ~float64 | ~string)

3. 型別集合與 ~

限制是 interface，而 interface 除了列方法，還可以列出型別：用 | 隔開的型別就是這個限制的型別集合（type set），T 必須是集合裡的某一個。第 1 節的 int | float64 就是直接寫在中括號裡的型別集合。常用的集合可以取個名字：

type NTD int

func (n NTD) String() string {
	return fmt.Sprintf("NT$%d", int(n))
}

type Number interface {
	~int | ~int64 | ~float64
}

func Total[N Number](s []N) N {
	var total N
	for _, v := range s {
		total += v
	}
	return total
}

func typeSetDemo() {
	prices := []NTD{85, 95, 30}
	fmt.Println(Total(prices))
	fmt.Printf("%T\n", Total(prices))
	fmt.Println(Total([]int64{1, 2}))
}

輸出

NT$210
main.NTD
3

NTD 是 09 章那種自訂型別，底層型別是 int，但它不是 int。第 1 節的 Sum 限制寫的是 int | float64，NTD 就進不去：

package main

import "fmt"

type NTD int

func Sum[N int | float64](s []N) N {
	var total N
	for _, v := range s {
		total += v
	}
	return total
}

func main() {
	prices := []NTD{85, 95, 30}
	fmt.Println(Sum(prices))
}

編譯錯誤

./main.go:17:17: NTD does not satisfy int | float64 (possibly missing ~ for int in int | float64)

編譯器連解法都提示了：少了 ~。~int 的意思是「底層型別是 int 的所有型別」，所以 Number 寫成 ~int | ~int64 | ~float64，NTD 就能用。剛才錯誤訊息裡的 cmp.Ordered，每一個型別前面也都有 ~。自己寫限制時，幾乎都應該加上 ~，不然使用的人自訂的型別都會被擋在外面。

Total 回傳的型別就是傳進去的 NTD，所以印出來時 String 方法還在，顯示 NT$210，%T 也是 main.NTD。這是泛型和 any 的另一個差別：型別資訊一路都保留著，不需要 type assertion 取回來。

含有型別集合的 interface 只能當限制，不能拿來宣告一般的變數，因為「NTD 或 int64 或 float64 其中之一」的變數沒有辦法運算（常見錯誤 2）。

深入：第一次讀可以先跳過

3.1 限制裡也可以有方法

限制是 interface，所以也可以列方法，例如 interface{ ~int; String() string } 的意思是「底層型別是 int，而且有 String 方法」，NTD 符合。第 7 節的 joinLabels 直接拿 fmt.Stringer 當限制，也是一樣的道理：一般的 interface 都能當限制用。

comparable 有一個細節：interface 型別也算 comparable（Go 1.20 起），但像 10 章看過的，interface 裡裝著 slice 時，== 會在執行期 panic。所以 Set[any] 編譯得過，放進一個 slice 卻會 panic。用 comparable 的泛型型別時，元素型別盡量用具體的型別。

4. 型別推論

呼叫 Clamp(20, 1, 12) 時不用寫 [int]，因為 Go 會比對參數的型別，推論出 T 是什麼，這叫型別推論（type inference）。但推論只能從參數得到資訊：

func Convert[To, From Number](s []From) []To {
	out := make([]To, len(s))
	for i, v := range s {
		out[i] = To(v)
	}
	return out
}

func inferDemo() {
	prices := []NTD{85, 95}

	fs := Convert[float64](prices)
	fmt.Printf("%T %v\n", fs, fs)

	all := Convert[float64, NTD](prices)
	fmt.Println(all)

	var sumPrices func([]NTD) NTD = Total
	fmt.Println(sumPrices(prices))
}

輸出

[]float64 [85 95]
[85 95]
NT$180
  • Convert 有兩個型別參數。From 出現在參數 s []From 裡，傳進 []NTD 就知道 From 是 NTD；To 只出現在回傳值，沒有任何線索。
  • Convert[float64](prices) 只寫了第一個型別參數，剩下的交給推論，這叫部分實例化。所以設計泛型函式時，推論不出來的型別參數要排在前面，使用的人才能只寫一個。
  • 兩個都寫出來 Convert[float64, NTD](prices) 也可以，只是囉嗦。
  • 把泛型函式指定給一個型別已經確定的函式變數，也能推論：var sumPrices func([]NTD) NTD = Total，Go 從變數的型別知道 N 是 NTD。

什麼都不寫，推論就失敗了：

package main

import "fmt"

type Number interface {
	~int | ~int64 | ~float64
}

func Convert[To, From Number](s []From) []To {
	out := make([]To, len(s))
	for i, v := range s {
		out[i] = To(v)
	}
	return out
}

func main() {
	prices := []int{85, 95}
	fmt.Println(Convert(prices))
}

編譯錯誤

./main.go:19:21: in call to Convert, cannot infer To (declared at ./main.go:9:14)

5. 泛型型別

型別也可以有型別參數。07 章用 map[string]bool 當集合，每換一種元素型別就得重寫一次輔助函式；寫成泛型型別，只要一份：

type Set[T comparable] struct {
	m map[T]struct{}
}

func (s *Set[T]) Add(v T) {
	if s.m == nil {
		s.m = map[T]struct{}{}
	}
	s.m[v] = struct{}{}
}

func (s *Set[T]) Has(v T) bool {
	_, ok := s.m[v]
	return ok
}

func (s *Set[T]) Len() int {
	return len(s.m)
}

func setDemo() {
	var tables Set[int]
	tables.Add(3)
	tables.Add(5)
	tables.Add(3)
	fmt.Println(tables.Len(), tables.Has(5), tables.Has(7))

	var dishes Set[string]
	dishes.Add("排骨飯")
	fmt.Println(dishes.Has("排骨飯"), dishes.Len())
}

輸出

2 true false
true 1
  • 型別參數寫在型別名稱後面：type Set[T comparable] struct。map 的 key 必須可以比較，所以 T 的限制是 comparable。
  • 方法的 receiver 要把型別參數一起寫出來：func (s *Set[T]) Add(v T)。這裡的 T 只是重新取個名字，限制沿用型別宣告上的，不用再寫一次。
  • 使用時一定要寫出型別：var tables Set[int]。這裡沒有參數可以推論，而且 Set 本身不是一個完整的型別，Set[int] 才是。
  • 零值就能用：Add 第一次被呼叫時才建立 map，和 09 章的 Tally 一樣的技巧。
  • struct{} 不佔任何記憶體，拿來當「只在乎有沒有」的 map 值很常見。

標準庫裡也有泛型型別，例如 atomic.Pointer[T]（17 sync）。至於像 Set 這樣的容器，標準庫目前沒有提供，需要時自己寫幾行就好，或者直接用 map。

6. generic method

type Page[T any] struct {
	Items []T
	Next  int
}

func (p Page[T]) Map[U any](f func(T) U) Page[U] {
	out := Page[U]{Items: make([]U, len(p.Items)), Next: p.Next}
	for i, v := range p.Items {
		out.Items[i] = f(v)
	}
	return out
}

type Order struct {
	No   int
	Item string
}

func methodDemo() {
	p := Page[Order]{Items: []Order{{17, "排骨飯"}, {18, "雞腿飯"}}, Next: 19}
	labels := p.Map(func(o Order) string {
		return fmt.Sprintf("%d 號 %s", o.No, o.Item)
	})
	fmt.Printf("%T\n", labels)
	fmt.Println(labels.Items, labels.Next)
}

輸出

main.Page[string]
[17 號 排骨飯 18 號 雞腿飯] 19

Page 的方法本來就能用 receiver 帶來的 T。Map 要把每一筆資料換成另一種型別，需要第二個型別參數 U，而 U 只跟這一次呼叫有關，跟 Page 本身無關。Go 1.27 起，方法名稱後面可以再寫一組中括號 Map[U any]，這就是 generic method。呼叫時 U 一樣由參數推論：傳進去的函式回傳 string，U 就是 string。

在 Go 1.27 以前，這只能寫成一個普通的泛型函式 MapPage[T, U any](p Page[T], f func(T) U) Page[U]，呼叫時寫 MapPage(p, f)，不能用 p.Map(f) 一路串下去。舊的程式碼和文章裡會看到這種寫法。

generic method 有一個重要的限制：它不能用來滿足 interface。interface 的方法不能有型別參數，而 generic method 在實例化之前不是一個具體的方法，所以就算簽名看起來對得上也不算：

package main

import "fmt"

type Page[T any] struct {
	Items []T
}

func (p Page[T]) Map[U any](f func(T) U) Page[U] {
	out := Page[U]{Items: make([]U, len(p.Items))}
	for i, v := range p.Items {
		out.Items[i] = f(v)
	}
	return out
}

type Labeler interface {
	Map(f func(int) string) Page[string]
}

func main() {
	var l Labeler = Page[int]{Items: []int{17, 18}}
	fmt.Println(l)
}

編譯錯誤

./main.go:22:18: cannot use Page[int]{…} (value of struct type Page[int]) as Labeler value in variable declaration: Page[int] does not implement Labeler (wrong type for method Map)
		have Map[U any](func(int) U) Page[U]
		want Map(func(int) string) Page[string]

需要滿足 interface 的方法，就寫成普通的方法。

7. 什麼時候用泛型

泛型很好用，但不是每個地方都需要。先看一個非用不可的例子：

func joinLabels[T fmt.Stringer](s []T) string {
	parts := make([]string, len(s))
	for i, v := range s {
		parts[i] = v.String()
	}
	return strings.Join(parts, "、")
}

func whenDemo() {
	prices := []NTD{85, 95}
	fmt.Println(joinLabels(prices))
}

輸出

NT$85、NT$95

NTD 有 String 方法，所以 NTD 是 fmt.Stringer。可是 []NTD 不是 []fmt.Stringer：兩者在記憶體裡的樣子完全不同（一個存數字，一個存 interface 值的兩格），Go 不會自動轉換：

package main

import (
	"fmt"
	"strings"
)

type NTD int

func (n NTD) String() string {
	return fmt.Sprintf("NT$%d", int(n))
}

func joinAll(s []fmt.Stringer) string {
	parts := make([]string, len(s))
	for i, v := range s {
		parts[i] = v.String()
	}
	return strings.Join(parts, "、")
}

func main() {
	prices := []NTD{85, 95}
	fmt.Println(joinAll(prices))
}

編譯錯誤

./main.go:24:22: cannot use prices (variable of type []NTD) as []fmt.Stringer value in argument to joinAll

沒有泛型時，只能先建一個 []fmt.Stringer、一個一個搬過去。joinLabels 用 [T fmt.Stringer] 當限制，直接收 []NTD，什麼都不用搬。

適合用泛型的地方

  • 對 slice、map、channel 的通用操作，而且不在乎元素是什麼型別：過濾、分組、找最大值、去重複。標準庫的 slices、maps 套件就是這樣寫的，先找找看有沒有現成的（06 章）。
  • 容器型別：集合、快取、分頁結果、樹，裡面放什麼型別都一樣的資料結構。
  • 要保留呼叫者的具體型別：Total 傳 NTD 回傳 NTD；換成 interface 參數，回傳的就只剩 interface。
  • 同一段程式已經複製了第二、第三份，而且只差在型別。

不需要泛型的地方

  • 只是要呼叫方法：func notify[N Notifier](n N) 和 func notify(n Notifier) 做的事一樣，後者簡單得多。只要參數本身就是那個值（不是 slice 或 map 裡的元素），用 interface 就好（10 章）。
  • 只會用到一種型別：先寫普通的程式，等真的出現第二種型別再改成泛型。
  • 不同型別的實作根本不一樣：如果泛型函式裡要用 type switch 對每個型別各做一套，那其實是好幾個函式，或者該用 interface 讓每個型別自己實作方法。

還有一點：泛型的值在執行期仍然知道自己的型別，%T 印得出 main.NTD、main.Page[string]。但在泛型函式裡，不能直接對 T 型別的值做 type switch，要先轉成 any（常見錯誤 5）：

func kindOf[T any](v T) string {
	switch x := any(v).(type) {
	case int:
		return fmt.Sprint("整數 ", x)
	case string:
		return "字串 " + x
	default:
		return fmt.Sprintf("其他 %T", x)
	}
}

func kindDemo() {
	fmt.Println(kindOf(85), kindOf("排骨飯"), kindOf(NTD(30)))
}

輸出

整數 85 字串 排骨飯 其他 main.NTD

NTD(30) 的底層型別是 int，卻沒有落進 case int：type switch 比的是確切的型別，不是底層型別。會需要這樣寫，通常表示這裡不該用泛型。

常見錯誤

1. 限制少了 ~

寫 int | float64，自訂的 NTD 就進不去；寫 ~int | ~float64 才包含底層型別相同的型別（第 3 節）。編譯器的訊息會提示 “possibly missing ~”。

2. 把限制當成一般的型別

package main

import "fmt"

type Number interface {
	~int | ~int64 | ~float64
}

func main() {
	var n Number = 85
	fmt.Println(n)
}

編譯錯誤

./main.go:10:8: cannot use type Number outside a type constraint: interface contains type constraints

含有型別集合的 interface 只能寫在中括號裡當限制。只列方法的 interface（例如 fmt.Stringer）則兩種用法都可以。

3. 型別參數只出現在回傳值

推論不出來，呼叫的人每次都得寫 [float64]（第 4 節）。設計時把推論不出來的型別參數放在最前面，讓部分實例化可以只寫一個。

4. 限制是 any，卻用了 < 或 +

編譯錯誤 “type parameter T cannot use operator >”（第 2 節）。要比大小用 cmp.Ordered，要 == 用 comparable，要加減就自己定義一個列出數字型別的限制。

5. 直接對型別參數的值做 type switch

package main

import "fmt"

func describe[T any](v T) string {
	switch x := v.(type) {
	case int:
		return fmt.Sprint("整數 ", x)
	default:
		return "其他"
	}
}

func main() {
	fmt.Println(describe(85))
}

編譯錯誤

./main.go:6:14: cannot use type switch on type parameter value v (variable of type T constrained by any)

type switch 只能用在 interface 型別的值上，要先轉換：switch x := any(v).(type)（第 7 節的 kindOf）。但先想想是不是該用 interface 而不是泛型。

6. 以為 []NTD 可以當成 []fmt.Stringer

元素型別滿足 interface，不代表 slice 也能轉換（第 7 節）。用 [T fmt.Stringer](s []T) 這種泛型函式，或自己一個一個轉。

7. 期待 generic method 滿足 interface

interface 的方法不能有型別參數，generic method 也不會被當成符合 interface 的方法（第 6 節）。

8. 為了泛型而泛型

只呼叫方法的參數寫成 [N Notifier](n N)、只會用到一種型別的函式加上型別參數，都只是讓程式更難讀。先寫具體的程式，等重複出現了再抽成泛型。

    func Average[N Number](s []N) (float64, bool) {
	// TODO: 實作

    測試會用一個自訂的 type ntd int。測試：TestAverage。

    func (t *Tally[K]) Add(k K) {
	// TODO: 實作
}

func (t *Tally[K]) Count(k K) int {
	// TODO: 實作
	return 0
}

func (t *Tally[K]) Top(n int) []K {
	// TODO: 實作

}

    測試：TestTally。

    提示

    Add 和第 5 節的 Set 一樣先檢查 map 是不是 nil。Top 先把所有 key 放進一個 slice，再用 slices.SortFunc 排序：比較函式先用 cmp.Compare(t.counts[b], t.counts[a]) 讓次數多的在前，相等時再比 key。最後取 min(n, len(keys)) 個。

  5. 挑戰練習 5：一步接一步

    用 generic method 把好幾個可能失敗的步驟串起來：前面失敗了，後面就不做。

    type Result[T any] struct {
	Val T
	Err error
}
    func (r Result[T]) Then[U any](f func(T) (U, error)) Result[U] {
	// TODO: 實作
	return Result[U]{}
}

    Result[string]{Val: "4"}.Then(strconv.Atoi).Then(checkRange)：字串先轉成 int，再檢查範圍，每一步的型別都可以不同。測試：TestResultThen。

    提示

    r.Err 不是 nil 就回傳 Result[U]{Err: r.Err}；否則 v, err := f(r.Val)，包成 Result[U]{Val: v, Err: err}。

  6. 挑戰練習 6：記住算過的結果

    把任何「同樣的輸入一定得到同樣結果」的函式包起來，算過的就不再算。

    func Memo[K comparable, V any](f func(K) V) func(K) V {
	// TODO: 實作
	return f
}

    測試傳進去的函式會記錄自己被呼叫了幾次。測試：TestMemo。

    提示

    在 Memo 裡建立一個 map[K]V，回傳一個 closure 抓住它（04 章）。closure 裡先查 map，有就直接回傳；沒有才呼叫 f，存進 map 再回傳。

  7. 找錯練習 7：最大值是 0？

    全部都是負數時，Max 回傳 0。

    func Max[T cmp.Ordered](s []T) (T, bool) {
	var best T
	for _, v := range s {
		if v > best {
			best = v
		}
	}
	return best, len(s) > 0
}

    測試：TestMax。

    提示

    T 的零值是 0（或空字串），不一定在 slice 裡。從 s[0] 開始比。

重點回顧

  • 泛型讓同一段程式套用到很多型別，型別檢查仍然在編譯時完成。
  • 型別參數寫在中括號裡：func F[T 限制](…)、type S[T 限制] …。
  • 限制是 interface：any 什麼都收，comparable 能用 ==，cmp.Ordered 能比大小。
  • 限制可以列出型別集合 ~int | ~float64；~ 包含底層型別相同的自訂型別，自己寫限制時幾乎都要加。
  • 限制決定函式裡能用哪些運算；含型別集合的 interface 只能當限制。
  • 型別推論只看參數；推論不出來的型別參數排在前面，用部分實例化只寫它。
  • 泛型型別使用時要寫出型別：Set[int]；方法的 receiver 寫 (s *Set[T])。
  • Go 1.27 起方法可以有自己的型別參數，但 generic method 不能滿足 interface。
  • 只呼叫方法就用 interface；對 slice、map 做通用操作、寫容器、要保留具體型別時才用泛型。
