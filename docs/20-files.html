檔案與 I/O

便當店的檔案櫃：今天的菜單只有一張紙，整張拿出來看就好；一整年的流水帳很厚，只能一頁一頁翻；客人寄來的照片只能放進指定的抽屜；換新價目表時，先把新的寫好，再一次把舊的換下來。

本章你會學到

  • 用 os.ReadFile、os.WriteFile 一次讀寫整個檔案，並正確判斷「檔案不存在」。
  • 用 os.Open、os.Create、os.OpenFile 開檔，知道什麼時候一定要檢查 Close 的錯誤。
  • 用 io.Copy 和幾個 Reader 的組合處理大檔案，記憶體用量固定。
  • 用 filepath 組路徑，用 os.Root 擋住「../」這類跑出目錄的檔名。
  • 用 filepath.WalkDir 走訪整棵目錄樹，跳過不要的目錄。
  • 讓函式收 fs.FS：同一段程式可以讀磁碟、讀 embed 進執行檔的檔案，測試時讀記憶體裡的假檔案。
  • 用暫存檔加 Rename 覆寫檔案，寫到一半出錯也不會弄壞舊檔。

先備：02 章的 io.Reader 與 io.Writer、bufio.Scanner、04 章的 defer、11 章的 errors.Is 與 Close 的錯誤。

1. 一次讀寫整個檔案

最簡單的檔案操作只有兩個函式：os.ReadFile(name) 把整個檔案讀成 []byte，os.WriteFile(name, data, perm) 把整個 []byte 寫成一個檔案。開檔、關檔它們都幫你做好了：

func wholeDemo() {
	dir, done := scratch()
	defer done()

	path := filepath.Join(dir, "menu.txt")
	err := os.WriteFile(path, []byte("排骨飯 90\n雞腿飯 100\n"), 0o644)
	if err != nil {
		fmt.Println("寫入失敗：", err)
		return
	}

	data, err := os.ReadFile(path)
	if err != nil {
		fmt.Println("讀取失敗：", err)
		return
	}
	fmt.Printf("讀回 %d byte：\n%s", len(data), data)
}

輸出

讀回 27 byte：
排骨飯 90
雞腿飯 100
  • 0o644 是檔案權限，只在建立新檔時用到：擁有者可讀寫（6），同群組和其他人只能讀（4、4）。實際的權限還會被系統的 umask 拿掉一些位元。一般資料檔用 0o644，只有自己能看的（例如含密碼的設定檔）用 0o600。
  • WriteFile 遇到已經存在的檔案，會先清空再寫。寫到一半出錯，舊內容已經沒了，新內容只有一半（第 7 節教你怎麼避免）。
  • byte 數是 27 不是 13 個字：中文字在 UTF-8 裡一個字 3 個 byte（08 章）。

讀檔最常見的錯誤是檔案不存在。os 回傳的錯誤是 *fs.PathError，裡面記著做什麼（Op）、哪個檔案（Path）、作業系統給的原因（Err）。要判斷「是不是不存在」，用 errors.Is(err, fs.ErrNotExist)，不要比對錯誤訊息的字串：

func loadNotice(path string) (string, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, fs.ErrNotExist) {
		return "（今天沒有公告）", nil
	}
	if err != nil {
		return "", err
	}
	return string(data), nil
}

func missingDemo() {
	dir, done := scratch()
	defer done()

	path := filepath.Join(dir, "notice.txt")
	_, err := os.ReadFile(path)
	fmt.Println("不存在？", errors.Is(err, fs.ErrNotExist))

	if pe, ok := errors.AsType[*fs.PathError](err); ok {
		fmt.Printf("Op=%s 檔名=%s Err=%v\n", pe.Op, filepath.Base(pe.Path), pe.Err)
	}

	notice, err := loadNotice(path)
	fmt.Println(notice, err)
}

輸出

不存在？ true
Op=open 檔名=notice.txt Err=no such file or directory
（今天沒有公告） <nil>
  • 錯誤訊息裡的 no such file or directory 是作業系統給的，Windows 上寫法不一樣；fs.ErrNotExist 在每個系統上都一樣，所以判斷要用它。
  • 舊程式常寫 os.IsNotExist(err)，它出現在 errors.Is 之前，不會拆開用 %w 包過的錯誤（11 章）。新程式一律用 errors.Is。同一組還有 fs.ErrExist（已經存在）和 fs.ErrPermission（沒有權限）。
  • loadNotice 把「不存在」當成正常情況處理，其他錯誤（沒有權限、其實是目錄）照樣回傳。只處理你預期的那一種，其他的往上交。

2. 開檔與關檔

要一行一行讀、或是一筆一筆往後加，就要自己開檔。三個函式都回傳 *os.File，它同時是 io.Reader、io.Writer 和 io.Closer，所以 02 章學過的工具（Scanner、Fprintf、io.Copy）全部能用在檔案上。開了就要關：作業系統對一個程式同時開著的檔案數量有上限，忘了關的檔案會一直佔著名額。

func appendCall(path, line string) (err error) {
	f, err := os.OpenFile(path, os.O_WRONLY|os.O_CREATE|os.O_APPEND, 0o644)
	if err != nil {
		return err
	}
	defer func() {
		err = errors.Join(err, f.Close())
	}()

	_, err = fmt.Fprintln(f, line)
	return err
}

func countCalls(path string) (int, error) {
	f, err := os.Open(path)
	if err != nil {
		return 0, err
	}
	defer f.Close()

	n := 0
	sc := bufio.NewScanner(f)
	for sc.Scan() {
		if strings.TrimSpace(sc.Text()) != "" {
			n++
		}
	}
	return n, sc.Err()
}

func openDemo() {
	dir, done := scratch()
	defer done()

	path := filepath.Join(dir, "calls.log")
	for _, line := range []string{"A01 排骨飯", "A02 雞腿飯", "", "A03 魚排飯"} {
		if err := appendCall(path, line); err != nil {
			fmt.Println("寫入失敗：", err)
			return
		}
	}

	n, err := countCalls(path)
	fmt.Println("叫了", n, "號", err)
}

輸出

叫了 3 號 <nil>
  • 寫入的檔案：Close 可能才是真正把資料交出去的時候，它的錯誤一定要回傳。做法和 11 章一樣：回傳值取名 err，在 defer 裡 err = errors.Join(err, f.Close())。
  • 只讀的檔案：Close 失敗不會讓任何資料不見，defer f.Close() 就夠了。
  • O_WRONLY|O_CREATE|O_APPEND 是寫日誌的標準組合：不存在就建立，每次寫入前都先移到檔尾，不會蓋掉前面的紀錄。
  • defer 要寫在檢查 err 之後。開檔失敗時 f 是 nil，先 defer 再檢查，會在 nil 上呼叫 Close。
  • countCalls 用的 Scanner 一行最多 64 KB，超過要放寬（02 章）。

深入：第一次讀可以先跳過

寫進去了，就在磁碟上了嗎？

不一定。Write 成功只代表資料交給了作業系統，作業系統通常先放在記憶體裡的快取，稍後才真的寫到磁碟。程式結束沒關係，作業系統還在，資料遲早會寫出去；但如果是整台機器斷電，快取裡的資料就沒了。Close 也不保證資料已經落地。

真的需要「確定寫到儲存裝置上了」的時候（例如帳務、或第 7 節換檔之前），呼叫 f.Sync()，它會等作業系統把這個檔案的資料寫到儲存裝置才回傳。Sync 很慢，不要每寫一行就呼叫一次；在「這一批資料一定要保住」的時間點呼叫一次就好。

3. 串流：一塊一塊處理

一整年的流水帳可能有好幾 GB，ReadFile 會把它整個搬進記憶體。大檔案要用串流處理：每次讀一小塊、處理完、再讀下一塊。io.Copy(dst, src) 就是這樣做的，它內部只有一塊固定大小的緩衝區，不管檔案多大都夠用：

func copyFile(dst, src string) (n int64, err error) {
	in, err := os.Open(src)
	if err != nil {
		return 0, err
	}
	defer in.Close()

	out, err := os.Create(dst)
	if err != nil {
		return 0, err
	}
	defer func() {
		err = errors.Join(err, out.Close())
	}()

	return io.Copy(out, in)
}

func copyFileDemo() {
	dir, done := scratch()
	defer done()

	src := filepath.Join(dir, "menu.txt")
	if err := os.WriteFile(src, []byte("排骨飯 90\n雞腿飯 100\n"), 0o644); err != nil {
		fmt.Println("寫入失敗：", err)
		return
	}
	n, err := copyFile(filepath.Join(dir, "menu.bak"), src)
	fmt.Println("複製了", n, "byte", err)

	dst := filepath.Join(dir, "lost.bak")
	_, err = copyFile(dst, filepath.Join(dir, "lost.txt"))
	fmt.Println("來源不存在？", errors.Is(err, fs.ErrNotExist))
	_, err = os.Stat(dst)
	fmt.Println("目的檔不存在？", errors.Is(err, fs.ErrNotExist))
}

輸出

複製了 27 byte <nil>
來源不存在？ true
目的檔不存在？ true

順序很重要：先打開來源，成功了才建立目的檔。反過來寫，來源不存在時會留下一個空的目的檔，下次還以為備份成功過。

io 套件有一組小工具，接收 Reader 再回傳 Reader，可以自由組合。把三天的營業額接成一份，同時算出內容的 SHA-256 指紋，資料只要走過一次：

func copyWithSum(dst io.Writer, src io.Reader) (int64, string, error) {
	h := sha256.New()
	n, err := io.Copy(dst, io.TeeReader(src, h))
	return n, hex.EncodeToString(h.Sum(nil)), err
}

func mergeDemo() {
	days := io.MultiReader(
		strings.NewReader("週一 12800\n"),
		strings.NewReader("週二 9650\n"),
		strings.NewReader("週三 15020\n"),
	)

	var merged strings.Builder
	n, sum, err := copyWithSum(&merged, days)
	fmt.Print(merged.String())
	fmt.Println(n, "byte，SHA-256 開頭", sum[:12], err)
}

輸出

週一 12800
週二 9650
週三 15020
38 byte，SHA-256 開頭 36699ab88405 <nil>

只想看檔案開頭（例如判斷檔案格式、顯示預覽）時，用 LimitReader 限制最多讀多少：

func previewDemo() {
	const calls = "A01 排骨飯\nA02 雞腿飯\n"
	for _, n := range []int64{14, 12} {
		b, err := io.ReadAll(io.LimitReader(strings.NewReader(calls), n))
		fmt.Printf("前 %d byte：%q %v\n", n, b, err)
	}
}

輸出

前 14 byte："A01 排骨飯\n" <nil>
前 12 byte："A01 排骨\xe9\xa3" <nil>
  • LimitReader 數的是 byte。限制在 12 byte，剛好切在「飯」的 3 個 byte 中間，拿到兩個不完整的 byte（\xe9\xa3）。要顯示給人看的預覽，切完還要處理半個字（08 章）。
  • 另外兩個常用的：io.MultiWriter(w1, w2) 把寫進來的資料同時寫到好幾個地方（例如同時寫檔和印到畫面）；io.ReadAll(r) 把 Reader 剩下的全部讀完，和 ReadFile 一樣要小心大小，通常搭配 LimitReader 用。
  • 很多小筆的寫入，包一層 bufio.NewWriter 可以減少系統呼叫，記得最後要 Flush（02 章）。

深入：第一次讀可以先跳過

io.Copy 的捷徑

io.Copy 不一定真的用自己的緩衝區搬。來源如果有 WriteTo 方法，或目的地有 ReadFrom 方法，它會直接交給它們處理。*os.File 兩個都有：在 Linux 上，檔案到檔案、檔案到網路連線的複製，可能用 copy_file_range、sendfile、splice 這類系統呼叫，資料不必先搬進你的程式再搬出去。

所以用 TeeReader、LimitReader 包住 *os.File，除了多做的事，還會讓這條捷徑失效：io.Copy 只看得到外面那一層，只好退回一般的緩衝區。多數程式感覺不出差別；在搬大量檔案的服務裡，這是 profiling 時值得注意的地方。需要自己提供緩衝區時，用 io.CopyBuffer。

4. 路徑與 os.Root

路徑不要用字串相加。Windows 的分隔符號是 \，macOS 和 Linux 是 /；path/filepath 套件知道現在在哪個系統，組出來、拆開來都用對的符號，還會順便整理多餘的 /、. 和 ..：

func receiptPath(base, month, number string) string {
	return filepath.Join(base, month, number+".txt")
}

func receiptNumber(p string) string {
	return strings.TrimSuffix(filepath.Base(p), filepath.Ext(p))
}

func pathsDemo() {
	p := receiptPath("receipts", "2026-11", "A03")
	fmt.Println(filepath.ToSlash(p), "號碼", receiptNumber(p))
	fmt.Println("同一個月的放在", filepath.ToSlash(filepath.Dir(p)))

	// 設定檔裡的目錄常常寫得不乾淨，Join 會順便整理好
	messy := receiptPath("./receipts/", "2026-11/../2026-10", "A01")
	fmt.Println(filepath.ToSlash(messy), "號碼", receiptNumber(messy))
}

輸出

receipts/2026-11/A03.txt 號碼 A03
同一個月的放在 receipts/2026-11
receipts/2026-10/A01.txt 號碼 A01
  • Join 會呼叫 filepath.Clean：重複的分隔符號合成一個，. 去掉，.. 和前一段抵銷。所以 "./receipts/" 和 "2026-11/../2026-10" 組出來還是乾淨的路徑。
  • 拆路徑用 Dir（最後一段之前）、Base（最後一段）、Ext（副檔名，包含點）。
  • filepath.ToSlash 把分隔符號換成 /，示範裡用它讓輸出在每個系統上都一樣。真正拿去開檔的路徑不需要換。
  • 還有一個 path 套件，永遠用 / 分隔，給網址、fs.FS（第 6 節）這種「不管作業系統」的路徑用。處理磁碟上的路徑一律用 filepath。

危險的是檔名來自使用者：上傳的檔案、網址裡的參數、壓縮檔裡的路徑。Clean 會讓 .. 往上走，接在 uploads 後面就可能跑出去，這叫路徑穿越（path traversal）：

func traversalDemo() {
	for _, name := range []string{"A01.jpg", "../config.json", "photos/../../../etc/passwd"} {
		p := filepath.Join("uploads", name)
		fmt.Printf("%s → %s，IsLocal=%v\n", name, filepath.ToSlash(p), filepath.IsLocal(name))
	}
}

輸出

A01.jpg → uploads/A01.jpg，IsLocal=true
../config.json → config.json，IsLocal=false
photos/../../../etc/passwd → ../etc/passwd，IsLocal=false

filepath.IsLocal(name)（Go 1.20 起）可以先檢查名稱是不是「留在原地」的相對路徑。但它只看字串：uploads 裡如果有一個指向外面的符號連結，名稱完全合法，打開的卻是外面的檔案。Go 1.24 起有更徹底的做法 os.Root：先把目錄打開成一個根，之後所有操作都透過它，名稱用 ..、絕對路徑或符號連結想跑出去，都會失敗：

func rootDemo() {
	dir, done := scratch()
	defer done()

	root, err := os.OpenRoot(dir)
	if err != nil {
		fmt.Println("開不了目錄：", err)
		return
	}
	defer root.Close()

	if err := root.WriteFile("A01.jpg", []byte("照片"), 0o644); err != nil {
		fmt.Println("寫入失敗：", err)
		return
	}
	data, err := root.ReadFile("A01.jpg")
	fmt.Println(string(data), err)

	for _, name := range []string{"../config.json", "/etc/passwd"} {
		_, err := root.Open(name)
		fmt.Println(err)
	}
}

輸出

照片 <nil>
openat ../config.json: path escapes from parent
openat /etc/passwd: path escapes from parent

符號連結的情況用測試證明：同一個檔案，直接開打得開，透過 os.Root 就打不開：

func TestRootSymlink(t *testing.T) {
	outside := t.TempDir()
	if err := os.WriteFile(filepath.Join(outside, "secret.txt"), []byte("密碼"), 0o644); err != nil {
		t.Fatal(err)
	}
	dir := t.TempDir()
	if err := os.Symlink(outside, filepath.Join(dir, "link")); err != nil {
		t.Skip("這個系統不能建立符號連結：", err)
	}

	if _, err := os.ReadFile(filepath.Join(dir, "link", "secret.txt")); err != nil {
		t.Fatalf("直接開應該打得開：%v", err)
	}
	root, err := os.OpenRoot(dir)
	if err != nil {
		t.Fatal(err)
	}
	defer root.Close()
	if _, err := root.ReadFile("link/secret.txt"); err == nil {
		t.Error("透過 os.Root 不應該讀得到目錄外面的檔案")
	}
}
  • Root 有 Open、Create、OpenFile、Mkdir、Remove、Stat；ReadFile、WriteFile、MkdirAll、RemoveAll、Rename 是 Go 1.25 加的。只開一個檔案的話，可以用 os.OpenInRoot(dir, name)。
  • 需要 fs.FS 的地方，用 root.FS()，它一樣出不去。
  • 錯誤訊息的 openat 是底層的系統呼叫名稱。

5. 走訪目錄

只要列出一個目錄裡有什麼，用 os.ReadDir(dir)，它回傳依檔名排好的 []fs.DirEntry。要連子目錄一路走下去，用 filepath.WalkDir。先建一棵發票目錄樹：

func makeTree(dir string) error {
	files := map[string]string{
		"2026-10/A01.txt":       "90",
		"2026-10/A02.txt":       "100",
		"2026-11/A03.txt":       "85",
		"2026-11/draft/A04.txt": "120",
		"notes.md":              "月底對帳\n",
	}
	for name, body := range files {
		p := filepath.Join(dir, filepath.FromSlash(name))
		if err := os.MkdirAll(filepath.Dir(p), 0o755); err != nil {
			return err
		}
		if err := os.WriteFile(p, []byte(body), 0o644); err != nil {
			return err
		}
	}
	return nil
}

func walkDemo() {
	dir, done := scratch()
	defer done()
	if err := makeTree(dir); err != nil {
		fmt.Println("建立失敗：", err)
		return
	}

	err := filepath.WalkDir(dir, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err // 這個目錄讀不了：回傳錯誤，整個走訪就停下來
		}
		rel, err := filepath.Rel(dir, path)
		if err != nil {
			return err
		}
		rel = filepath.ToSlash(rel)

		if d.IsDir() {
			if d.Name() == "draft" {
				fmt.Println("跳過", rel+"/")
				return filepath.SkipDir
			}
			fmt.Println(rel + "/")
			return nil
		}
		info, err := d.Info()
		if err != nil {
			return err
		}
		fmt.Println(rel, info.Size(), "byte")
		return nil
	})
	fmt.Println("錯誤：", err)
}

輸出

./
2026-10/
2026-10/A01.txt 2 byte
2026-10/A02.txt 3 byte
2026-11/
2026-11/A03.txt 2 byte
跳過 2026-11/draft/
notes.md 13 byte
錯誤： <nil>
  • 走訪的順序是字典順序，每次都一樣，輸出也就固定。代價是 WalkDir 要先把一整個目錄讀進記憶體，再往下走。
  • 函式收到的 err 一定先檢查：根目錄不存在、某個目錄讀不了的時候，WalkDir 會帶著錯誤呼叫你，這時 d 可能是 nil。回傳 err 就停止，回傳 nil 就略過這個目錄繼續走。
  • fs.DirEntry 是讀目錄時順便拿到的資料，Name、IsDir 不用再問作業系統；要大小、修改時間才呼叫 d.Info()，那會多一次系統呼叫。舊的 filepath.Walk 對每個檔案都先拿完整資訊，所以比較慢，新程式用 WalkDir。
  • 找到要的東西就想整個停下來，回傳 filepath.SkipAll（Go 1.20 起）。WalkDir 不會跟著指向目錄的符號連結走進去。

6. fs.FS 與 embed

收目錄路徑的函式很難測試：每個測試都得真的建目錄、寫檔案。io/fs 套件定義了一個唯讀檔案系統的介面 fs.FS，只有一個方法 Open(name string) (fs.File, error)，再搭配一組用它做事的函式：fs.ReadFile、fs.ReadDir、fs.WalkDir、fs.Glob、fs.Sub。把第 5 節的走訪改成收 fs.FS，順便加總發票金額：

func receiptTotal(fsys fs.FS) (int, error) {
	total := 0
	err := fs.WalkDir(fsys, ".", func(p string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if d.IsDir() && d.Name() == "draft" {
			return fs.SkipDir
		}
		if d.IsDir() || path.Ext(p) != ".txt" {
			return nil
		}

		data, err := fs.ReadFile(fsys, p)
		if err != nil {
			return err
		}
		n, err := strconv.Atoi(strings.TrimSpace(string(data)))
		if err != nil {
			return fmt.Errorf("%s：%w", p, err)
		}
		total += n
		return nil
	})
	return total, err
}

func fsDemo() {
	dir, done := scratch()
	defer done()
	if err := makeTree(dir); err != nil {
		fmt.Println("建立失敗：", err)
		return
	}

	total, err := receiptTotal(os.DirFS(dir))
	fmt.Println("磁碟上的發票合計：", total, err)
}

  • fs.FS 裡的路徑在每個系統上都用 / 分隔、不能用 / 開頭、不能有 . 或 ..，根目錄寫成 "."。所以這裡用 path.Ext，不用 filepath。
  • 走訪的 callback 拿到的就是相對路徑，不用再 Rel、ToSlash，比第 5 節乾淨。
  • 錯誤用 %w 包上檔名，呼叫的人知道是哪一張發票有問題，也還能用 errors.Is 判斷原因。

測試時不必碰磁碟，testing/fstest 的 MapFS 就是一個用 map 做的檔案系統，key 是路徑、value 是內容：

第三種來源是 embed：用 //go:embed 指示，在編譯時把檔案內容放進執行檔。部署時只要帶一個執行檔，網頁範本、預設設定、SQL migration 都跟著走。單一檔案可以放進 string 或 []byte，整個目錄放進 embed.FS，而 embed.FS 也是一個 fs.FS：

package main

import (
	"embed"
	"fmt"
	"io/fs"
)

// 下面兩個變數的內容在編譯時就放進執行檔：部署時只要帶一個執行檔，不用另外帶資料夾。
// //go:embed 寫在變數的正上方，路徑相對於這個 .go 檔所在的目錄。

//go:embed welcome.txt
var welcome string

//go:embed receipts
var receipts embed.FS

// embedDemo 讀 embed 進來的檔案。receipts 是一個 fs.FS，可以直接交給 receiptTotal。
func embedDemo() {
	fmt.Print(welcome)

	total, err := receiptTotal(receipts)
	fmt.Println("embed 進來的發票合計：", total, err)

	names, err := fs.Glob(receipts, "receipts/*/*.txt")
	fmt.Println(names, err)

  • //go:embed 要緊貼在套件層級的變數宣告上面，中間只能有空行或 // 註解。型別只能是 string、[]byte 或 embed.FS。只用 string、[]byte 時要寫 import _ "embed"。
  • 路徑相對於這個 .go 檔所在的目錄，不能有 .、..，也不能用 / 開頭，所以上層目錄的檔案 embed 不到（常見錯誤 7）。
  • embed 整個目錄時，名稱以 . 或 _ 開頭的檔案不會被放進去；要包含它們，寫成 //go:embed all:receipts。
  • embed.FS 裡的路徑包含目錄名稱本身（receipts/2026-12/B01.txt）。想讓 receipts 變成根，用 fs.Sub(receipts, "receipts")。
  • 內容在編譯時就固定了，執行時改磁碟上的檔案不會影響它；改了檔案要重新編譯。

深入：第一次讀可以先跳過

os.DirFS 不是保險箱

os.DirFS(dir) 會拒絕帶 .. 的名稱（那不是合法的 fs.FS 路徑），看起來像是把存取限制在 dir 裡。但它只保證開檔時的路徑以 dir 開頭；dir 裡如果有指向外面的符號連結，照樣打得開。官方文件特別說明它不能拿來當安全機制。目錄的內容不是你能控制的（例如使用者上傳的東西），改用 os.OpenRoot(dir) 再呼叫 root.FS()。

自己實作 fs.FS（例如把 zip 檔或資料庫包成檔案系統）時，用 fstest.TestFS 檢查實作有沒有符合介面的各種約定。

7. 暫存檔與安全覆寫

需要一個用完就丟的檔案或目錄時，不要自己取名字（兩個程式同時跑就會撞名），交給 os.CreateTemp(dir, pattern) 和 os.MkdirTemp(dir, pattern)：pattern 裡的 * 會換成亂數，保證是新的。dir 是空字串時用系統的暫存目錄。這一章每個示範都用這個小工具開自己的暫存目錄：

func scratch() (dir string, done func()) {
	dir, err := os.MkdirTemp("", "ch20-*")
	if err != nil {
		panic(err) // 連暫存目錄都開不了，示範沒辦法繼續
	}
	return dir, func() { os.RemoveAll(dir) }
}

測試裡更簡單：t.TempDir() 回傳一個新目錄，測試結束時自動刪掉（練習題就是這樣用的）。

暫存檔最重要的用途是安全覆寫。WriteFile 先清空舊檔再寫，寫到一半程式當掉、磁碟滿了、或產生內容的程式出錯，檔案就只剩一半。正確的做法是先寫到同一個目錄的暫存檔，全部成功才用 os.Rename 換過去：

func saveAtomic(path string, write func(io.Writer) error) (err error) {
	tmp, err := os.CreateTemp(filepath.Dir(path), filepath.Base(path)+".*.tmp")
	if err != nil {
		return err
	}
	defer func() {
		if err != nil {
			tmp.Close()
			os.Remove(tmp.Name())
		}
	}()

	if err = write(tmp); err != nil {
		return err
	}
	if err = tmp.Sync(); err != nil { // 確定資料真的寫到磁碟上，再換名字
		return err
	}
	if err = tmp.Close(); err != nil {
		return err
	}
	return os.Rename(tmp.Name(), path)
}

func atomicDemo() {
	dir, done := scratch()
	defer done()
	path := filepath.Join(dir, "prices.txt")

	err := saveAtomic(path, func(w io.Writer) error {
		_, err := io.WriteString(w, "排骨飯 90\n雞腿飯 100\n")
		return err
	})
	fmt.Println("第一次存檔：", err)

	err = saveAtomic(path, func(w io.Writer) error {
		if _, err := io.WriteString(w, "排骨飯 95\n"); err != nil {
			return err
		}
		return errors.New("第二行的價格不是數字")
	})
	fmt.Println("第二次存檔：", err)

	data, err := os.ReadFile(path)
	fmt.Printf("檔案內容：%q %v\n", data, err)

	entries, err := os.ReadDir(dir)
	for _, e := range entries {
		fmt.Println("目錄裡有：", e.Name())
	}
	fmt.Println("錯誤：", err)
}

輸出

第一次存檔： <nil>
第二次存檔： 第二行的價格不是數字
檔案內容："排骨飯 90\n雞腿飯 100\n" <nil>
目錄裡有： prices.txt
錯誤： <nil>
  • 在 macOS、Linux 這類 Unix 系統上，Rename 取代既有的檔案是一次完成的：別的程式去讀，看到的不是舊的就是新的，不會看到一半。官方文件說明在非 Unix 系統（例如 Windows）上，Rename 即使在同一個目錄也不保證是一次完成的。
  • 暫存檔一定要和目標放在同一個目錄：Rename 不能跨檔案系統，系統的暫存目錄和你的資料常常不在同一個檔案系統上。
  • 出錯時 defer 會關掉並刪除暫存檔，目錄裡只剩原本的 prices.txt。成功時暫存檔已經改名，不需要刪。
  • write 參數是一個函式，saveAtomic 不在乎內容怎麼產生：可以是 Fprintf、json 編碼、io.Copy。這種「把動作當參數傳進來」的設計，讓「安全覆寫」這件事只要寫一次。

常見錯誤

1. 用 ReadFile 讀不知道多大的檔案

log、上傳的檔案、使用者給的輸入，大小都不是你能控制的。ReadFile 和 io.ReadAll 會把它整個放進記憶體。用 Scanner 一行一行讀、用 io.Copy 串流，或至少用 LimitReader 設上限（第 3 節）。

2. 寫入的檔案只寫 defer f.Close()

Close 的錯誤被丟掉，呼叫的人以為存好了。寫入的檔案用具名回傳值加 errors.Join（第 2 節、11 章）。

3. 處理很多檔案時，在迴圈裡 defer Close

defer 要等整個函式結束才執行，迴圈跑一萬圈就同時開著一萬個檔案，很快就會碰到「too many open files」。把每一圈的工作抽成一個函式，讓 defer 在那個函式結束時執行（04 章）。只有像練習 2 那樣，所有檔案本來就要同時開著的時候，迴圈裡 defer 才是對的。

4. 用字串相加組路徑

dir + "/" + name 在 Windows 上分隔符號不對，dir 結尾已經有 / 時還會多一個。用 filepath.Join；處理 fs.FS、網址的路徑才用 path（第 4 節）。

5. 直接用使用者給的檔名開檔

filepath.Join(uploads, name) 擋不住 ../，也擋不住符號連結。用 os.Root 把操作關在目錄裡（第 4 節、練習 5）。

6. 用了 bufio.Writer 卻忘了 Flush

資料還在 bufio 的緩衝區裡，檔案就關了，內容少了最後一段，小檔案甚至整個是空的（練習 6、02 章）。

7. embed 上層目錄的檔案

embed 的路徑不能有 ..。把要 embed 的檔案搬進套件的目錄（或子目錄），或是在上層目錄開一個專門 embed 的套件，再 import 它。

package main

import (
	_ "embed"
	"fmt"
)

//go:embed ../menu.txt
var menu string

func main() {
	fmt.Print(menu)
}

go build

main.go:8:12: pattern ../menu.txt: invalid pattern syntax

8. 用 WriteFile 直接覆寫重要的檔案

寫到一半出錯，舊內容已經被清空了。設定檔、資料檔、任何壞掉會很麻煩的檔案，用暫存檔加 Rename（第 7 節）。

重點回顧

  • 小檔案用 os.ReadFile、os.WriteFile；WriteFile 會先清空舊檔。
  • 判斷檔案不存在用 errors.Is(err, fs.ErrNotExist)，不要比對字串，也不要用 os.IsNotExist。
  • os.Open 只讀、os.Create 清空重寫、os.OpenFile 自己組旗標；寫日誌用 O_WRONLY|O_CREATE|O_APPEND。
  • 寫入的檔案一定要檢查 Close 的錯誤；只讀的檔案 defer f.Close() 就好。
  • 大檔案用 io.Copy 和 Scanner 串流處理；MultiReader、TeeReader、LimitReader 可以自由組合。
  • 路徑用 filepath.Join；使用者給的檔名用 os.Root 開，擋住 ..、絕對路徑和符號連結。
  • filepath.WalkDir 照字典順序走訪，SkipDir 跳過目錄；callback 先檢查 err。
  • 函式收 fs.FS：磁碟用 os.DirFS 或 root.FS()，執行檔裡用 embed.FS，測試用 fstest.MapFS。
  • 重要的檔案先寫暫存檔，Sync、Close 之後再 Rename 換上去。
