1. 發出請求、讀回應

送出請求的是 *http.Client。它的 Get、Post 是方便的寫法，完整的寫法是先建立 *http.Request，再交給 client.Do。拿到的 *http.Response 有狀態碼、標頭，以及一個 io.Reader 形式的 Body：

func getDemo() {
	client := newDemoClient()

	resp, err := client.Get("http://shop.test/menu")
	if err != nil {
		fmt.Println("送不出去：", err)
		return
	}
	defer resp.Body.Close()
	body, err := io.ReadAll(resp.Body)
	if err != nil {
		fmt.Println("讀內容失敗：", err)
		return
	}
	fmt.Println(resp.StatusCode, resp.Header.Get("Content-Type"))
	fmt.Println(string(body))

	resp2, err := client.Get("http://shop.test/orders/99")
	if err != nil {
		fmt.Println("送不出去：", err)
		return
	}
	defer resp2.Body.Close()
	fmt.Printf("err 是 %v，狀態是 %s\n", err, resp2.Status)
}

  • 先檢查 err，再 defer resp.Body.Close()。err 不是 nil 的時候 resp 是 nil，順序反過來就是 nil 指標的 panic。
  • resp.StatusCode 是數字，resp.Status 是「404 Not Found」這種給人看的文字。判斷用前者，比較時用 http.StatusNotFound 這類常數。
  • Body 是一邊從網路讀一邊交給你的串流，不是已經在記憶體裡的字串。io.ReadAll 會讀到結束為止，所以要先確定對方不會送來無限多的資料（第 3 節）。
  • http.Get(url) 用的是 http.DefaultClient，它沒有逾時。只適合寫小工具，正式的程式要自己建立 Client（下一節）。

2. 逾時與取消

每個 Client 都要設 Timeout：從開始連線，到 body 讀完的總時間。個別請求需要更短的期限，或要跟著上層一起取消時，用 18 章的 context 建立請求：http.NewRequestWithContext(ctx, …)。

逾時要怎麼測？店家真的等 5 秒，測試就要跑 5 秒。下面的測試用 26 章介紹的 httptest.NewTestServer（記憶體裡的網路）搭配 synctest（假的時間），測試一瞬間就跑完，而且時間可以檢查到剛好 2 秒：

func TestClientTimeout(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		start := time.Now()
		gaveUp := make(chan time.Duration, 2)
		srv := httptest.NewTestServer(t, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			select {
			case <-time.After(5 * time.Second):
				io.WriteString(w, "便當好了")
			case <-r.Context().Done(): // 客人走了，店家這邊也收到通知
				gaveUp <- time.Since(start)
			}
		}))
		client := srv.Client()
		client.Timeout = 2 * time.Second

		_, err := client.Get("http://shop.test/slow")
		if !errors.Is(err, context.DeadlineExceeded) || time.Since(start) != 2*time.Second {
			t.Fatalf("Client.Timeout：%v 之後拿到 %v，want 2s 之後 DeadlineExceeded", time.Since(start), err)
		}
		if got := <-gaveUp; got != 2*time.Second {
			t.Errorf("店家在 %v 才知道客人走了，want 2s", got)
		}

		// 單一請求的期限用 context：1 秒，比 Client.Timeout 短，先到的那個生效。
		ctx, cancel := context.WithTimeout(t.Context(), time.Second)
		defer cancel()
		req, err := http.NewRequestWithContext(ctx, http.MethodGet, "http://shop.test/slow", nil)
		if err != nil {
			t.Fatal(err)
		}
		before := time.Now()
		if _, err := client.Do(req); !errors.Is(err, context.DeadlineExceeded) || time.Since(before) != time.Second {
			t.Errorf("context：%v 之後拿到 %v，want 1s 之後 DeadlineExceeded", time.Since(before), err)
		}
		<-gaveUp
	})
}
  • 逾時的錯誤包了好幾層（*url.Error 裡面是 context.DeadlineExceeded），用 errors.Is 判斷，不要比對錯誤訊息的文字。
  • 客人放棄時，店家那邊 r.Context() 也被取消。26 章說要把它傳給資料庫查詢，就是為了這種時候能停下來。
  • DefaultTransport 另外有連線階段的逾時（建立 TCP 連線 30 秒、TLS 握手 10 秒），但沒有限制等回應的時間，所以 Client.Timeout 還是必要的。
  • 逾時要多長，看對方平常多快、你的呼叫者能等多久。不知道的話先量測，不要隨便抄一個數字。

網址裡有使用者輸入的部分（站名、菜名、備註）時，用 net/url 組，不要用字串相加：

呼叫 JSON API 的步驟每次都一樣：編碼、設標頭、送出、檢查狀態碼、解碼、關 body。把它們集中在 do，再用泛型包成 getJSON 和 postJSON（12 章）：

type APIError struct {
	Status  int
	Message string
}

func (e *APIError) Error() string {
	return fmt.Sprintf("HTTP %d：%s", e.Status, e.Message)
}

const maxResponse = 1 << 20

func do(client *http.Client, req *http.Request, out any) error {
	resp, err := client.Do(req)
	if err != nil {
		return err
	}
	defer func() {
		io.Copy(io.Discard, io.LimitReader(resp.Body, maxResponse))
		resp.Body.Close()
	}()
	body := io.LimitReader(resp.Body, maxResponse)

	if resp.StatusCode < 200 || resp.StatusCode > 299 {
		apiErr := &APIError{Status: resp.StatusCode, Message: http.StatusText(resp.StatusCode)}
		var e struct {
			Error string `json:"error"`
		}
		if json.UnmarshalRead(body, &e) == nil && e.Error != "" {
			apiErr.Message = e.Error
		}
		return apiErr
	}
	if out == nil {
		return nil
	}
	return json.UnmarshalRead(body, out)
}

func getJSON[T any](ctx context.Context, client *http.Client, u string) (T, error) {
	var out T
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, u, nil)
	if err != nil {
		return out, err
	}
	req.Header.Set("Accept", "application/json")
	err = do(client, req, &out)
	return out, err
}

func postJSON[T any](ctx context.Context, client *http.Client, u string, in any) (T, error) {
	var out T
	b, err := json.Marshal(in)
	if err != nil {
		return out, err
	}
	req, err := http.NewRequestWithContext(ctx, http.MethodPost, u, bytes.NewReader(b))
	if err != nil {
		return out, err
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Accept", "application/json")
	err = do(client, req, &out)
	return out, err
}

  • APIError 帶著狀態碼，呼叫的一方用 errors.AsType 取出來決定怎麼處理（11 章）：409 換一道菜，404 告訴使用者沒有這筆訂單。
  • 錯誤的內容不一定是 JSON：前面的閘道器、負載平衡器可能回一頁 HTML。解不開時用 http.StatusText 當訊息，不要把整頁 HTML 放進錯誤裡。
  • io.LimitReader 限制最多讀多少。對方出錯送來 1 GB 的內容時，解析會在 1 MB 處失敗，而不是把記憶體吃光。
  • json/v2 解析失敗時，out 可能已經被填了一部分。err 不是 nil 時，不要使用回傳的值。
  • POST 的內容先 Marshal 成 []byte 再用 bytes.NewReader 送出：編碼失敗時請求還沒送出，而且 Client 知道內容的長度。

4. 關掉 body 與連線池

Client 不是每次都重新連線。它的 Transport 把用完的連線留在池子裡，下一個送到同一個主機的請求直接拿來用。但只有在 body 讀到結束並關掉之後，連線才會還回去。下面的測試數 server 接受了幾條連線：

func countConns(t *testing.T) (*httptest.Server, *atomic.Int64) {
	var conns atomic.Int64
	srv := httptest.NewTestServer(t, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		io.WriteString(w, "排骨飯 90")
	}))
	srv.Config.ConnState = func(_ net.Conn, s http.ConnState) {
		if s == http.StateNew {
			conns.Add(1)
		}
	}
	return srv, &conns
}

func TestConnReuse(t *testing.T) {
	t.Run("讀完並關掉", func(t *testing.T) {
		srv, conns := countConns(t)
		for range 5 {
			resp, err := srv.Client().Get("http://shop.test/menu")
			if err != nil {
				t.Fatal(err)
			}
			io.Copy(io.Discard, resp.Body)
			resp.Body.Close()
		}
		if n := conns.Load(); n != 1 {
			t.Errorf("5 個請求用了 %d 條連線，want 1", n)
		}
	})
	t.Run("沒有關掉", func(t *testing.T) {
		srv, conns := countConns(t)
		var open []io.Closer
		for range 5 {
			resp, err := srv.Client().Get("http://shop.test/menu")
			if err != nil {
				t.Fatal(err)
			}
			open = append(open, resp.Body) // 沒讀也沒關：這條連線一直被佔著
		}
		if n := conns.Load(); n != 5 {
			t.Errorf("5 個請求用了 %d 條連線，want 5（每次都要開新的）", n)
		}
		for _, b := range open {
			b.Close()
		}
	})
}
  • 只關不讀時，net/http 不一定能重用那條連線（剩下的內容還在路上）。不需要內容時，先 io.Copy(io.Discard, resp.Body) 再關，第 3 節的 do 就是這樣寫的。
  • 在迴圈裡 defer resp.Body.Close()，要等整個函式結束才會關，迴圈跑多少圈就佔著多少條連線（04 章，練習 6）。
  • srv.Config.ConnState 是 http.Server 的欄位，連線狀態改變時呼叫。測試用它就能看到「連線有沒有被重用」這種平常看不到的行為。

連線池在 Transport 裡，所以 整個程式共用一個 Client（它可以被很多 goroutine 同時使用）。每個請求都建一個新的 Transport，池子就沒有意義，舊的連線也不會被關掉。正式用的 Client 從 DefaultTransport 複製一份再調整：

func newClient() *http.Client {
	t := http.DefaultTransport.(*http.Transport).Clone()
	t.MaxIdleConnsPerHost = 10 // 預設是 2：同一個主機最多留 2 條閒置的連線
	return &http.Client{
		Timeout:   10 * time.Second, // 從送出到讀完 body 的總時間
		Transport: t,
	}
}
  • Clone 保留 DefaultTransport 的 Proxy、連線逾時、HTTP/2 這些設定，只改你要改的。自己用 &http.Transport{} 從零開始，這些都會變成零值。
  • MaxIdleConnsPerHost 預設是 2：同一個主機最多留 2 條閒置的連線。對同一個 API 的並發請求很多時，多出來的連線用完就被關掉，下次又要重新建立。

5. 重試與退避

網路和對方都可能暫時出問題：連線被切斷、對方正在重新部署回 503、被限流回 429。這種失敗等一下再試通常就好了。但不是每種失敗都值得重試：

func retryable(resp *http.Response, err error) bool {
	if err != nil {
		// ctx 被取消或到期，是呼叫的一方不要了，再試也沒有用；其他的網路錯誤可能是暫時的。
		return !errors.Is(err, context.Canceled) && !errors.Is(err, context.DeadlineExceeded)
	}
	switch resp.StatusCode {
	case http.StatusTooManyRequests, http.StatusBadGateway,
		http.StatusServiceUnavailable, http.StatusGatewayTimeout:
		return true
	}
	return false // 2xx 成功了；其他 4xx 是請求本身的問題，再送一次結果也一樣
}

func getWithRetry(ctx context.Context, client *http.Client, u string, attempts int, base time.Duration) (*http.Response, error) {
	var resp *http.Response
	var err error
	for i := range attempts {
		if i > 0 {
			wait := base << (i - 1)
			wait += rand.N(wait/2 + 1)
			select {
			case <-time.After(wait):
			case <-ctx.Done():
				return nil, ctx.Err()
			}
		}
		req, reqErr := http.NewRequestWithContext(ctx, http.MethodGet, u, nil)
		if reqErr != nil {
			return nil, reqErr
		}
		resp, err = client.Do(req)
		if !retryable(resp, err) || i == attempts-1 {
			break
		}
		if resp != nil {
			// 要再試一次，這個回應用不到了：讀完並關掉，連線才能重用。
			io.Copy(io.Discard, resp.Body)
			resp.Body.Close()
		}
	}
	return resp, err
}
func flaky() http.Handler {
	calls := 0
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		calls++
		fmt.Printf("店家收到第 %d 次請求\n", calls)
		if calls <= 2 {
			http.Error(w, "太忙了", http.StatusServiceUnavailable)
			return
		}
		fmt.Fprint(w, "今天的便當：排骨飯")
	})
}

  • 重試哪些：網路錯誤，以及 429、502、503、504。其他 4xx 是請求本身有問題（格式錯、沒權限、找不到），再送一次結果也一樣。
  • 不重試 ctx 的錯誤：Canceled 或 DeadlineExceeded 表示呼叫的一方已經不要了。
  • 只重試冪等的請求：GET 送幾次都一樣。POST 下單時，可能是店家已經收到、只是回應在路上掉了，重送就變成兩張訂單。真的要重試 POST，要和對方約定一個 idempotency key，讓對方認出重複的請求。
  • 對方說了要等多久：429 和 503 的回應可能帶著 Retry-After 標頭，有的話照它的時間等（練習 4）。
  • 等待用 select 同時看 time.After 和 ctx.Done()（16 章），ctx 到期時不用把剩下的時間等完。

等待的時間有隨機的抖動，用真的時間測試會又慢又不穩定。synctest 讓測試檢查「總共等了 7 到 10.5 秒」，實際上一瞬間就跑完：

func TestGetWithRetry(t *testing.T) {
	tests := []struct {
		name             string
		status           int
		deadline         time.Duration // 0 表示 ctx 沒有期限
		wantCalls        int64
		wantErr          error
		minWait, maxWait time.Duration
	}{
		// 等 1 + 2 + 4 = 7 秒，每次再加上最多一半的抖動，最多 10.5 秒
		{"一直 503：試 4 次", 503, 0, 4, nil, 7 * time.Second, 10500 * time.Millisecond},
		{"404 不重試", 404, 0, 1, nil, 0, 0},
		{"等待時 ctx 到期", 503, 2 * time.Second, 2, context.DeadlineExceeded, 2 * time.Second, 2 * time.Second},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			synctest.Test(t, func(t *testing.T) {
				var calls atomic.Int64
				srv := httptest.NewTestServer(t, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
					calls.Add(1)
					http.Error(w, http.StatusText(tt.status), tt.status)
				}))
				ctx := t.Context()
				if tt.deadline > 0 {
					var cancel context.CancelFunc
					ctx, cancel = context.WithTimeout(ctx, tt.deadline)
					defer cancel()
				}

				start := time.Now()
				resp, err := getWithRetry(ctx, srv.Client(), "http://shop.test/today", 4, time.Second)
				waited := time.Since(start)
				if resp != nil {
					resp.Body.Close()
				}

				if !errors.Is(err, tt.wantErr) || (tt.wantErr == nil && resp.StatusCode != tt.status) {
					t.Errorf("err = %v，want %v", err, tt.wantErr)
				}
				if calls.Load() != tt.wantCalls {
					t.Errorf("店家收到 %d 次請求，want %d", calls.Load(), tt.wantCalls)
				}
				if waited < tt.minWait || waited > tt.maxWait {
					t.Errorf("總共等了 %v，want %v 到 %v", waited, tt.minWait, tt.maxWait)
				}
			})
		})
	}
}

6. RoundTripper

Client 負責逾時、轉址、cookie；真正把請求送出去、拿回回應的是它的 Transport 欄位，型別是 http.RoundTripper，一個只有 RoundTrip(*Request) (*Response, error) 方法的 interface。換掉它，就能在不改呼叫端的情況下，加上記錄、驗證、指標，或者完全不經過網路。本章的示範都靠這一個：

type handlerTransport struct {
	h http.Handler
}

func (t handlerTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	if req.Body != nil {
		defer req.Body.Close() // RoundTripper 一定要關掉請求的 body，不管成功或失敗
	}
	rec := httptest.NewRecorder()
	t.h.ServeHTTP(rec, req)
	return rec.Result(), nil
}

包住另一個 RoundTripper，就能在前後加上自己的處理，和 26 章的 middleware 是同一個想法：

type logTransport struct {
	next   http.RoundTripper
	logger *slog.Logger
}

func (t logTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	start := time.Now()
	resp, err := t.next.RoundTrip(req)
	if err != nil {
		t.logger.WarnContext(req.Context(), "request failed", "method", req.Method, "url", req.URL.Redacted(), "err", err)
		return nil, err
	}
	t.logger.InfoContext(req.Context(), "request", "method", req.Method, "url", req.URL.Redacted(),
		"status", resp.StatusCode, "took", time.Since(start))
	return resp, nil
}

func transportDemo() {
	logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{ReplaceAttr: dropVolatile}))
	client := &http.Client{
		Timeout:   5 * time.Second,
		Transport: logTransport{next: handlerTransport{fakeShop()}, logger: logger},
	}
	for _, u := range []string{"http://shop.test/menu", "http://amei:s3cret@shop.test/orders/7"} {
		resp, err := client.Get(u)
		if err != nil {
			continue
		}
		io.Copy(io.Discard, resp.Body)
		resp.Body.Close()
	}
}

RoundTripper 有幾條規則，寫錯了不會編譯失敗，只會在奇怪的時候出問題：

  • 不要修改傳進來的請求。要加標頭，先用 req.Clone(req.Context()) 複製一份，改複本（練習 3）。呼叫的一方可能會重用原本的請求，例如重試。
  • 一定要關掉請求的 body，成功或失敗都要。交給下一層 RoundTripper 時，由下一層負責。
  • 只有拿不到回應才回傳 error。404、500 照樣回傳 Response，判斷狀態碼是呼叫端的事。
  • 記錄網址用 req.URL.Redacted()，網址裡的密碼會變成 xxxxx。Authorization 這類標頭更不能記錄。
  • 逾時、轉址、cookie 是 Client 處理的，不要在 RoundTripper 裡重做一次。

7. 測試

要測的是「我的 client 程式碼對各種回應的反應」，所以假的對方要能隨意回出 200、404、502、壞掉的 JSON、超大的內容。handlerTransport 讓這些都只是一個 handler：

func TestDo(t *testing.T) {
	h := http.NewServeMux()
	h.HandleFunc("GET /gateway", func(w http.ResponseWriter, r *http.Request) {
		http.Error(w, "<html>upstream down</html>", http.StatusBadGateway)
	})
	h.HandleFunc("GET /huge", func(w http.ResponseWriter, r *http.Request) {
		io.WriteString(w, `["`+strings.Repeat("滷", maxResponse)+`"]`)
	})
	client := &http.Client{Transport: handlerTransport{h}}
	ctx := t.Context()

	_, err := getJSON[[]string](ctx, client, "http://shop.test/gateway")
	if apiErr, ok := errors.AsType[*APIError](err); !ok || apiErr.Status != 502 || apiErr.Message != "Bad Gateway" {
		t.Errorf("不是 JSON 的錯誤內容：err = %v，want HTTP 502：Bad Gateway", err)
	}

	// 只讀前 1 MB，JSON 在中間被截斷，所以解析失敗，而不是把整個回應讀進記憶體。
	if _, err := getJSON[[]string](ctx, client, "http://shop.test/huge"); err == nil {
		t.Errorf("超過 %d bytes 的回應應該解析失敗", maxResponse)
	}
}
  • 假的 RoundTripper 不經過連線，所以測不到逾時和連線重用；那些行為用第 2、4、5 節的 NewTestServer 測。
  • 測試用 NewTestServer 時一定要用 srv.Client()。用 http.Get 或自己的 Client，請求會真的送上網路（26 章）。
  • 假的 RoundTripper 也能檢查呼叫端有沒有做對：把回應的 body 包一層，記錄有沒有被關掉。練習的測試就是這樣檢查練習 2、5、6 的。
  • 讓函式接受 *http.Client 參數（或放在 struct 欄位），不要在函式裡用 http.DefaultClient，測試才換得掉。

常見錯誤

1. 用 http.Get 或 http.DefaultClient 上線

DefaultClient 沒有逾時，對方卡住時你的 goroutine 也跟著卡住。自己建立 Client，設 Timeout（第 2 節）。

2. 以為 404、500 會是 error

只要拿到回應，err 就是 nil。一定要檢查 StatusCode（第 1 節）。

3. 沒有讀完、關掉 body

連線還不回池子，請求一多就用光連線和檔案描述符。先檢查 err，再 defer 讀完並關掉（第 4 節）。

4. 在迴圈裡 defer resp.Body.Close()

defer 要等整個函式結束才執行，迴圈跑幾圈就佔著幾條連線。把一圈的工作抽成一個函式，defer 寫在裡面（練習 6）。

5. 每個請求建一個新的 Client 或 Transport

連線池在 Transport 裡，每次新建就沒有重用，舊的閒置連線也不會被關。整個程式共用一個 Client（第 4 節）。

6. 用字串相加組網址

使用者輸入的 &、#、/、空白會改變網址的意思。用 url.Values 和 url.PathEscape（第 3 節）。

7. 什麼都重試

重試 400 只是浪費；重試 POST 可能下兩次單；不等待就重試會把對方壓垮。只重試暫時性的失敗和冪等的請求，並且退避（第 5 節）。

8. 在 RoundTripper 裡修改傳進來的請求

呼叫的一方可能還在用那個請求。先 Clone 再改（第 6 節）。

重點回顧

  • err 不是 nil 表示沒拿到回應；拿到回應時一定要檢查 StatusCode。
  • 自己建立 Client 並設 Timeout；單一請求的期限和取消用 NewRequestWithContext。
  • 網址用 url.Values 和 url.PathEscape 組，不要用字串相加。
  • 呼叫 JSON API 的步驟集中在一個函式：送出、檢查狀態碼、限制大小、解碼、讀完並關掉 body。
  • body 讀完並關掉，連線才能重用；不要在迴圈裡 defer。
  • 整個程式共用一個 Client；調整 Transport 時從 DefaultTransport 複製。
  • 只重試暫時性的失敗和冪等的請求，指數退避加抖動，ctx 決定最多等多久。
  • RoundTripper 是 client 這一側的 middleware：不改原本的請求，只有拿不到回應才回傳 error。
  • 測試用假的 RoundTripper 或 NewTestServer，加上 synctest 就不用真的等。
