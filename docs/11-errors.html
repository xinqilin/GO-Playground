錯誤處理

錯誤是一個普通的值：函式把它交給你，你決定要處理還是往上交。

看圖

最小範例

var ErrNotFound = errors.New("找不到")

func find(name string) error {
	return fmt.Errorf("查詢 %q：%w", name, ErrNotFound)
}

func main() {
	err := fmt.Errorf("下單失敗：%w", find("香蕉"))
	fmt.Println(err)
	fmt.Println(errors.Is(err, ErrNotFound))
}

輸出

下單失敗：查詢 "香蕉"：找不到
true

工程師筆記

  • if err != nil { return … } 是日常。每一層補上自己的說明再往上傳，最後的錯誤訊息就是完整的路徑。
  • 包裝用 %w，呼叫端才能用 errors.Is / errors.As 找到原本的錯誤；用 %v 只會變成一段文字。
  • 呼叫端需要分辨的狀況用 sentinel error（var ErrNotFound = errors.New(…)）；需要帶資料就用自訂錯誤型別。
  • Go 1.26 起有 errors.AsType[*T](err)，不用先宣告一個變數；多個錯誤可以用 errors.Join 合在一起。
  • 一個錯誤只處理一次：要嘛處理掉（記 log、降級），要嘛往上傳，不要兩件事都做。
  • panic 留給程式寫錯的狀況；recover 只在 defer 裡有效，通常只放在 goroutine 或 HTTP handler 的最外層。
