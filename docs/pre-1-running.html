程式怎麼跑起來

程式是一份寫給電腦的食譜。電腦非常聽話，但完全不會變通：它從第一行開始，一行一行照著做，寫錯一個字就做不下去。

1. 程式是什麼

電腦能做的事其實很單純：算數學、比大小、把資料搬來搬去、照條件決定下一步。它厲害的地方是做得非常快，而且不會累。程式（program）就是一串指令，告訴電腦依序要做哪些事。寫程式，就是把你想完成的事情，拆成電腦聽得懂的小步驟。

電腦聽不懂中文，所以要用程式語言來寫。程式語言是一種規則很嚴格的文字：每個符號、每個括號都有固定的意思。Go 是其中一種，它的規則少、錯誤訊息清楚，很適合當第一個學的語言。下面就是一段 Go 程式：

func hello() {
	fmt.Println("你好，Go")
}

輸出

你好，Go

現在先不用懂每個字的意思，只要知道：fmt.Println(…) 是「把括號裡的東西印在螢幕上」，雙引號 "…" 裡的文字會原樣印出來。func hello() { … } 把大括號裡的幾行包成一組，取名叫 hello，之後的章節會一直用這種寫法來分開每個示範。

2. 終端機

寫 Go 時，大部分的操作都在終端機（terminal）裡進行：一個只能打字的視窗，你輸入一行指令、按 Enter，電腦執行完再把結果印出來。macOS 打開「終端機」（Terminal）這個 App；Windows 打開「PowerShell」；Linux 打開 Terminal。

終端機隨時都「站在」某一個資料夾裡，這叫目前的目錄（current directory）。剛打開時通常站在你的家目錄，也就是存放你個人檔案的那一層，用 ~ 表示。最常用的三個指令，在 macOS、Linux 和 Windows PowerShell 裡都能用：

指令意思例子
pwd我現在站在哪裡（print working directory）pwd
ls列出這裡有哪些檔案和資料夾（list）ls、ls chapters
cd換到另一個資料夾（change directory）cd GO-Playground、cd ..、cd ~

資料夾的位置用路徑（path）表示，各層之間用 / 分開（Windows 也接受 /，顯示時用 \）。chapters/pre-1-running 的意思是「目前位置底下的 chapters，再底下的 pre-1-running」，這種從目前位置出發的寫法叫相對路徑。兩個點 .. 代表上一層，一個點 . 代表目前這一層；所以後面會常看到 ./chapters/… 這種寫法。

例如在本手冊的資料夾裡執行 ls chapters/pre-1-running，會列出 crash、main.go、main_test.go 三項，就是這一章的程式。

三個好用的按鍵

Tab：資料夾或檔案名稱打幾個字就按 Tab，終端機會自動補完，不用打完整，也不會打錯。上方向鍵：叫出上一個指令，改一改再執行。Ctrl-C：停止正在執行的程式，程式卡住或跑不停的時候用（先修 3 會遇到）。

3. 安裝 Go 和編輯器

到官方網站的 安裝頁面 下載你的系統對應的安裝檔，照著畫面一路按「下一步」即可。裝好之後重新打開終端機（已經開著的視窗不會知道你剛裝了新東西），輸入：

go version

輸出（版本號和系統依你的電腦而不同）

go version go1.27.4 darwin/arm64

看到 go version go1. 開頭的一行，就代表安裝成功。如果看到「找不到指令」（command not found 或 is not recognized），通常是終端機沒有重新打開，或安裝沒有完成。

程式碼是純文字，但不要用 Word 這類文書軟體來寫：它們會偷偷加上格式，或把直的引號換成彎的引號，Go 就看不懂了。請用寫程式專用的編輯器，例如免費的 VS Code，再裝上 Go 的擴充功能。官方的編輯器說明列出了各種選擇。好的編輯器會幫你上色、在打錯字時畫紅線、存檔時自動排版。

最後，把這本手冊的程式碼下載到電腦上。00 章的「這本手冊怎麼用」有完整的步驟；之後所有指令都假設終端機站在手冊的資料夾（GO-Playground）裡。

4. 從原始碼到執行

你寫的 .go 檔案叫原始碼（source code）。電腦的處理器其實看不懂原始碼，只看得懂一連串的機器指令。把原始碼翻譯成機器指令的工具叫編譯器（compiler），翻譯的過程叫編譯，翻譯出來的檔案叫執行檔。Go 的編譯器就是你剛裝好的 go 指令。

練習時最常用的是 go run：它編譯完馬上執行，不會留下執行檔：

go run ./chapters/pre-1-running

這一章的程式會依序執行五個示範，第一行印出「你好，Go」。go build 則只編譯，產生一個執行檔，之後可以直接執行它，不需要原始碼，也不需要再裝 Go：

go build -o hello ./chapters/pre-1-running   # 產生執行檔 hello（Windows 上請用 hello.exe）
./hello                                      # 執行它

寫好的程式要交給別人用時，給的就是執行檔。這也是 Go 受歡迎的原因之一：編譯出來的一個檔案就能在對方的電腦上跑。

5. 一行一行照順序

func cookRice() {
	fmt.Println("1. 量米")
	fmt.Println("2. 洗米")
	fmt.Println("3. 按下煮飯鍵")
}

輸出

1. 量米
2. 洗米
3. 按下煮飯鍵

這聽起來理所當然，卻是寫程式最重要的觀念之一：電腦不會自己調整順序。如果把「按下煮飯鍵」寫在「量米」前面，電腦就會先按鍵，鍋子裡什麼都沒有，它也不會覺得奇怪。先修 2 的「追蹤表」就是一行一行模擬電腦的做法，用來找出這類問題。練習 5 是一個順序寫錯的泡茶程式。

讓電腦算數學

func calculate() {
	fmt.Println(85 * 3)
	fmt.Println("85 * 3")
	fmt.Println("三個排骨便當：", 85*3, "元")
}

輸出

255
85 * 3
三個排骨便當： 255 元

第一行沒有雙引號，85 * 3 是一個算式，電腦先算出 255 再印。第二行有雙引號，是一段文字，原樣印出 85 * 3。第三行用逗號分開好幾個東西，Println 會依序印出來，中間自動加一個空白。程式裡的乘號是 *，除號是 /，和數學課一樣先乘除後加減。

6. 讀懂錯誤訊息

寫程式一定會遇到錯誤訊息，就連寫了幾十年的人也一樣。錯誤訊息不是在罵你，而是電腦盡力告訴你它卡在哪裡。下面這支程式把 Println 少打了一個 t：

package main

import "fmt"

func main() {
	fmt.Prinln("你好")
}

編譯錯誤

./main.go:6:6: undefined: fmt.Prinln

讀法：在 main.go 的第 6 行、第 6 個字的位置，fmt.Prinln 是 undefined（沒有定義，也就是「不認識這個名字」）。照著行號回到程式，就會看到打錯的字。錯誤訊息是英文，但常見的就那幾種，多看幾次就熟了：

訊息意思常見原因
undefined: …不認識這個名字打錯字、大小寫錯、忘了 import
syntax error: …文法錯誤，看不懂這一行少了括號、引號、逗號
declared and not used: …宣告了卻沒用到寫到一半的程式（先修 2）
newline in string字串還沒結束就換行了少了結尾的雙引號

有時候一個錯誤會引發好幾則訊息，先看第一則，改好之後重新執行，後面的往往就跟著消失了。例如少了結尾的雙引號：

package main

import "fmt"

func main() {
	fmt.Println("你好)
}

編譯錯誤

./main.go:6:22: newline in string
./main.go:6:22: syntax error: unexpected newline in argument list; possibly missing comma or )

第一則已經說中了：字串在第 6 行還沒結束就換行了。第二則是連帶的結果：Go 以為右括號也還在字串裡，所以說少了 )。補上雙引號，兩則訊息都會消失。

7. 三種錯誤

編譯錯誤：上一節看到的那種，程式寫得不合規則，編譯器拒絕翻譯，程式根本跑不起來。它最容易處理，因為訊息會直接指出位置。

執行時錯誤：程式符合規則、編譯成功了，但執行到某一行時遇到做不到的事，例如除以 0。這時程式會印出 panic 開頭的訊息然後停止，後面的程式都不會執行：

func main() {
	total := 300
	people := 0
	fmt.Println("開始分帳")
	fmt.Println(total / people)
	fmt.Println("這一行不會執行")
}
go run ./chapters/pre-1-running/crash

輸出（檔案路徑的前半段以 … 代替）

開始分帳
panic: runtime error: integer divide by zero

goroutine 1 [running]:
main.main()
	…/chapters/pre-1-running/crash/main.go:13 +0x50
exit status 2

第一行證明程式確實開始執行了；接著是 panic 的原因「整數除以 0」，下面告訴你出事的是 main.go 的第 13 行。「這一行不會執行」沒有印出來。

邏輯錯誤：程式順利跑完，但答案是錯的。電腦不會抱怨，因為它只是忠實地照你寫的做。這是最難發現的一種：

func wrongAverage() {
	fmt.Println(80 + 90/2)
}

func rightAverage() {
	fmt.Println((80 + 90) / 2)
}

輸出

125
85

想算 80 和 90 的平均，但先乘除後加減，80 + 90/2 先算 90/2 = 45，再加 80 得到 125，比兩個分數都高。加上括號讓加法先算才是 85。找邏輯錯誤的方法是先想好正確答案，再和程式的結果比對：平均一定介於最低和最高之間，125 一看就知道不對。這本手冊的每一題練習都附有自動檢查答案的測試，做的就是這件事（練習 4）。

8. 在瀏覽器裡試：Go Playground

還沒裝好 Go，或只是想快速試一小段程式時，可以用官方的 Go Playground：在網頁上貼上程式，按 Run，結果就顯示在下方。它很適合試一個想法、或把程式分享給別人看（按 Share 會產生一個連結）。

但它有一些限制：不能讀鍵盤輸入、不能存取你電腦上的檔案、執行時間和記憶體有上限。做這本手冊的練習時，還是請在自己的電腦上執行，因為練習需要用到 go test。

常見錯誤

1. 終端機站錯資料夾

執行 go run ./chapters/pre-1-running 時看到「找不到」的錯誤，多半是終端機不在手冊的資料夾裡。先用 pwd 確認位置，再用 cd 移過去。

2. 大小寫打錯

Go 分大小寫：fmt.println、Fmt.Println、fmt.PrintLn 都是錯的，只有 fmt.Println 是對的。錯誤訊息會是 undefined。

3. 用了全形符號或彎引號

程式裡的括號、引號、逗號都要用半形：( ) " ,。中文輸入法打出來的 （）“”， 是不同的字元，Go 看不懂。雙引號裡面的文字可以是中文，符號本身不行。從網頁或文件複製程式碼時也要注意，有些軟體會把直的引號換成彎的。

4. 忘了 import

用到 fmt.Println，程式開頭就要有 import "fmt"，否則會看到 undefined: fmt。好的編輯器存檔時會自動幫你加上。

5. 改了程式卻沒存檔

go 讀的是存在磁碟上的檔案。改完沒存檔就執行，跑的還是舊的版本，看起來就像「怎麼改都沒用」。

練習

題目在 exercises/pre-1-running/exercises.go。用編輯器打開它，照著每一題的說明修改，存檔後執行測試：

go test ./exercises/pre-1-running/                    # 跑全部練習
go test ./exercises/pre-1-running/ -run TestMotto     # 只跑一題
go test -tags solution ./exercises/pre-1-running/     # 跑參考解答

還沒作答時，測試會失敗，並告訴你得到什麼、應該要是什麼：

輸出（還沒作答時）

--- FAIL: TestMotto (0.00s)
    exercises_test.go:10: Motto() = "", want "我會寫 Go 了"
FAIL

= 後面是你的程式回傳的東西（現在是空的），want 後面是正確答案。全部答對時，最後一行會變成 ok。

  1. 入門練習 1：第一句話

    把 return "" 的 "" 換成那句話，雙引號要留著。

    func Motto() string {
	// TODO: 把 "" 換成答案
	return ""
}

    測試：TestMotto。

    提示

    答案寫成 return "我會寫 Go 了"。注意 Go 和「了」之間各有一個空白，要和題目一模一樣，電腦會逐字比對。

  2. 入門練習 2：三行收據

    回傳三行的收據。字串裡的 \n 代表換行。

    func Receipt() string {
	// TODO: 把 "" 換成答案
	return ""
}

    測試：TestReceipt。

    提示

    三行寫在同一個字串裡："排骨便當 85\n雞腿便當 90\n合計 175"。

  3. 入門練習 3：讓電腦算

    回傳 4 個雞腿便當的總價。把 0 換成一個算式。

    func Total() int {
	// TODO: 把 0 換成算式
	return 0
}

    測試：TestTotal。

    提示

    乘號是 *，算式不用加雙引號。

  4. 找錯練習 4：平均分數

    三次考試的平均怎麼會比滿分還高？

    func Average() int {
	return 72 + 85 + 91/3
}

    測試：TestAverage。

    提示

    第 7 節的邏輯錯誤。電腦先算了哪一個？

  5. 找錯練習 5：泡茶

    泡茶的步驟都在，但順序錯了。

    func Steps() []string {
	return []string{
		"放茶葉",
		"倒熱水",
		"燒開水",
		"等三分鐘",
	}
}

    這裡用到的 []string{…} 是一份文字的清單，先修 4 會介紹；現在只要調整清單裡各行的順序。測試：TestSteps。

    提示

    沒有熱水，就不能倒熱水。題目的說明列出了正確的順序。

  6. 動手做練習 6：跑起來

    1. 打開終端機，用 cd 移到手冊的資料夾，用 pwd 確認位置。
    2. 執行 go version，確認 Go 已經安裝。
    3. 執行 go run ./chapters/pre-1-running，對照第 1、5、7 節的輸出。
    4. 用 go build 產生執行檔並執行它，再用 ls 看看資料夾裡多了什麼。看完可以刪掉它（macOS、Linux 用 rm hello，Windows 用 del hello.exe）。

  7. 動手做練習 7：故意寫錯

    打開 chapters/pre-1-running/main.go，每次只做下面一種修改，執行 go run ./chapters/pre-1-running，讀錯誤訊息，然後改回來：

    1. 把 Println 改成 println。
    2. 刪掉某一行結尾的右括號 )。
    3. 把某個雙引號換成中文的「”」。
    4. 刪掉 import "fmt" 那一行。

    每一次都找出訊息裡的行號，確認它指向你改的地方。全部改回來之後，執行 go test ./chapters/pre-1-running，應該看到 ok。

參考解答：先自己寫完再看。

重點回顧

  • 程式是給電腦的一串指令，電腦從上到下一行一行照做，不會自己調整順序。
  • 終端機隨時站在某個資料夾裡：pwd 看位置、ls 列內容、cd 換位置，.. 是上一層。
  • Tab 自動補完、上方向鍵叫出上一個指令、Ctrl-C 停止程式。
  • 原始碼經過編譯變成執行檔；go run 編譯完馬上執行，go build 留下執行檔。
  • 錯誤訊息的格式是「檔案:行:字: 說明」，先看第一則。
  • 三種錯誤：編譯錯誤跑不起來、執行時錯誤會 panic、邏輯錯誤跑完但答案錯。
  • 找邏輯錯誤要先想好正確答案再比對，這本手冊的測試就是在做這件事。
