1. 位址與指標

每個變數都住在記憶體的某個位置，這個位置叫做位址（address）。指標（pointer）就是一個存放位址的變數。Go 用兩個符號操作指標：

  • &x：取得 x 的位址，結果是一個指向 x 的指標。
  • *p：照著 p 的位址找到那個變數，可以讀，也可以寫。這叫做解參考（dereference）。
func addressAndDeref() {
	stock := 5
	p := &stock // p 的型別是 *int：「指向 int 的指標」
	fmt.Println("stock =", stock)
	fmt.Println("*p =", *p)
	fmt.Println("p == &stock:", p == &stock)
	fmt.Printf("%T\n", p)
}

輸出

stock = 5
*p = 5
p == &stock: true
*int

p 的型別是 *int，讀作「指向 int 的指標」。型別前面的 * 是型別的一部分，運算式前面的 * 是解參考，兩者長得一樣但意思不同。指標本身也有型別：*int 只能指向 int，不能指向 string。

直接印出指標會得到 0xc000012345 這種十六進位的位址，但每次執行都不一樣，所以本書的範例只比較位址，不印出來。

透過指標修改

func modifyThroughPointer() {
	stock := 5
	p := &stock
	*p = 10 // 改的是 p 指向的那一格，也就是 stock
	*p += 3
	fmt.Println("stock =", stock)
}

輸出

stock = 13

*p = 10 不是改 p，而是改「p 指向的那個變數」，也就是 stock。*p += 3 也一樣。從頭到尾 p 裡面的位址都沒變過。

兩張紙條，同一間房子

func aliasing() {
	stock := 5
	a := &stock
	b := &stock
	*a = 8
	fmt.Println(*b, a == b)

	other := 8
	c := &other
	fmt.Println(*a == *c, a == c) // 值相等，但指向不同的變數
}

輸出

8 true
true false

a 和 b 指向同一個變數，從 a 改，從 b 讀得到新值。比較兩個指標 a == b，比的是「是不是同一個位址」，不是值；要比值就要先解參考：*a == *c。好幾個指標指向同一個變數，在程式裡很常見，也是 bug 的來源：改了一個地方，遠處的另一段程式跟著變了。

沒有指標運算

C 語言可以對指標加減，走到隔壁的記憶體。Go 不允許，p++ 對指標是編譯錯誤（常見錯誤 5）。指標只能取位址、解參考、比較、指定。這讓 Go 的指標安全得多：一個指標要嘛是 nil，要嘛指向一個真正存在的變數。

2. 傳值與傳指標

第 04 章說過，Go 的參數一律傳值。傳指標其實也是傳值，只是複製的是「位址」：函式拿到一張抄了同樣門牌的紙條，照著它就能改到呼叫端的變數。

func addOneValue(n int) { n++ }

func addOnePointer(n *int) { *n++ }

func passValueVsPointer() {
	a, b := 1, 1
	addOneValue(a)
	addOnePointer(&b)
	fmt.Println("a =", a, "b =", b)
}

輸出

a = 1 b = 2

呼叫時寫 &b，呼叫端一看就知道「這個函式可能會改 b」。這是 Go 刻意的設計：會不會被修改，從呼叫的地方就看得出來。

struct 也是值

type bento struct {
	name  string
	price int
}

func raiseCopy(b bento) { b.price += 5 }

func raisePointer(b *bento) { b.price += 5 }

func structCopy() {
	pork := bento{"排骨", 85}
	copied := pork
	copied.price = 999
	fmt.Println(pork.price, copied.price)

	raiseCopy(pork)
	fmt.Println(pork.price)
	raisePointer(&pork)
	fmt.Println(pork.price)
}

輸出

85 999
85
90

和 Java 的物件不同，Go 的 struct 是值：copied := pork 會把每個欄位都複製一份，改 copied 不影響 pork。傳給函式也一樣，raiseCopy 漲價的是複本，只有傳指標的 raisePointer 才改到原本的便當。第 09 章的方法也會遇到同樣的選擇：receiver 用值還是用指標。

指標欄位會被共用

type order struct {
	id   int
	note *string
}

func shallowCopy() {
	note := "不要香菜"
	first := order{id: 1, note: &note}
	second := first
	second.id = 2
	*second.note = "加辣"
	fmt.Println(first.id, *first.note)
	fmt.Println(second.id, *second.note)
}

輸出

1 加辣
2 加辣

複製 struct 時，指標欄位被複製的是「門牌」，不是房子。所以 second 改了備註，first 的備註也變了，id 則各自獨立。這叫做淺複製（shallow copy）。slice 和 map 欄位也是同樣的情況（第 06 章、第 07 章）。需要完全獨立的複本時，要替指標欄位另外配置新的變數，練習 7 就是這個題目。

3. 指向 struct 的指標

實務上最常見的指標，是指向 struct 的指標。存取欄位時不用先解參考，Go 會自動處理：

func structPointer() {
	b := bento{"雞腿", 90}
	p := &b
	p.price = 95 // 等於 (*p).price = 95
	fmt.Println(b.price, (*p).price)
}

輸出

95 95

p.price 和 (*p).price 完全一樣，前者只是簡寫。所以在 Go 裡，手上是 struct 還是指向 struct 的指標，用起來幾乎沒有差別，-> 這種 C 的符號也不需要。

new 和 &T{}

func newVsLiteral() {
	p := new(bento) // 配置一個零值的 bento，回傳它的位址
	p.name = "素食"
	q := &bento{name: "素食"} // 複合字面值加上 &，可以順便填欄位
	fmt.Println(*p == *q, p == q)
}

輸出

true false

兩種寫法都會建立一個新的變數，回傳指向它的指標。new(T) 得到零值的 T；&T{…} 可以同時填欄位，所以 struct 幾乎都用後者。兩個指標指向不同的變數（p == q 是 false），只是內容剛好一樣（*p == *q 是 true）。

注意 & 只能用在「有位置的東西」上：變數、struct 的欄位、slice 的元素、複合字面值。數字常數沒有位置，&85 是編譯錯誤：

package main

import "fmt"

func main() {
	discount := &85
	fmt.Println(*discount)
}

編譯錯誤

./main.go:6:15: invalid operation: cannot take address of 85 (untyped int constant)

new(值)：Go 1.26 起

func newWithValue() {
	discount := new(15)
	fmt.Println(*discount)
	o := order{id: 3, note: new("少飯")}
	fmt.Println(*o.note)
}

輸出

15
少飯

Go 1.26 起，new 的參數可以是一個值，建立一個以它為初始值的新變數。以前要寫兩行：先宣告 d := 15，再取 &d；現在 new(15) 一個運算式就完成。這在填「用指標表示可有可無」的欄位時特別方便，第 4 節會看到。如果你的 Go 比 1.26 舊，這兩行會編譯失敗，改回先宣告變數再取位址的寫法即可。

4. nil 指標

指標的零值是 nil：一張還沒寫門牌的紙條。對 nil 解參考會在執行時 panic：

func nilPointer() {
	var p *int
	fmt.Println(p == nil)
	defer func() {
		fmt.Println("panic:", recover())
	}()
	fmt.Println(*p)
}

輸出

true
panic: runtime error: invalid memory address or nil pointer dereference

這就是 Go 版的 NullPointerException，是 Go 程式最常見的 panic。對策很直接：指標可能是 nil 的地方，使用前先檢查 if p != nil；函式的文件寫清楚參數能不能是 nil、回傳值會不會是 nil。透過 nil 的 struct 指標讀欄位（p.price）也一樣會 panic，因為它本質上就是 (*p).price。

用指標表示「可以沒有值」

nil 也有正面的用途。int 的零值是 0，但有時候「0」和「沒有填」是兩回事：折扣 0% 是明確的設定，沒有設定折扣則可能要套用預設規則。用 *int 就分得出來：

func priceAfter(price int, discount *int) string {
	if discount == nil {
		return fmt.Sprintf("%d 元（沒有設定折扣）", price)
	}
	return fmt.Sprintf("%d 元（折扣 %d%%）", price*(100-*discount)/100, *discount)
}

func optionalField() {
	zero := 0
	fmt.Println(priceAfter(100, nil))
	fmt.Println(priceAfter(100, &zero))
	fmt.Println(priceAfter(100, new(20)))
}

輸出

100 元（沒有設定折扣）
100 元（折扣 0%）
80 元（折扣 20%）

這個模式在之後的 JSON（欄位可能不存在）和資料庫（欄位可能是 NULL）都很常見。new(20) 讓呼叫的地方保持簡潔。練習 3 用同樣的想法做「部分更新」：只有非 nil 的欄位才更新。

5. 回傳區域變數的指標

在 C 語言裡，回傳區域變數的位址是嚴重的錯誤：函式結束後那塊記憶體就被收回了。在 Go 裡這樣寫完全安全：

type counter struct{ n int }

func newCounter() *counter {
	c := counter{n: 1}
	return &c
}

func returnLocalPointer() {
	a := newCounter()
	b := newCounter()
	a.n++
	fmt.Println(a.n, b.n, a == b)
}

輸出

2 1 false

每次呼叫 newCounter 都會得到一個新的變數，所以 a 和 b 各自獨立。Go 的編譯器會做逃逸分析（escape analysis）：如果一個變數的位址在函式結束後還可能被用到，就把它放到 heap（由垃圾回收器 GC 管理，沒有人用了才回收）；否則放在 stack（函式結束就自動收回，非常便宜）。放哪裡由編譯器決定，和你寫 new、& 還是一般的宣告無關。

深入：第一次讀可以先跳過

5.1 用 -gcflags=-m 看編譯器的決定

chapters/05-pointers/escape 是一支專門給逃逸分析看的小程式：

// escape 是給逃逸分析看的小程式。用下面的指令看編譯器把哪些變數放到 heap：
//
//	go build -gcflags=-m ./chapters/05-pointers/escape
package main

import "os"

type counter struct{ n int }

func newCounter() *counter {
	c := counter{n: 1} // 位址被回傳出去，離開函式後還會被用到：放到 heap
	return &c
}

func localOnly() int {
	c := counter{n: 1} // 位址只在函式裡用：留在 stack
	p := &c
	p.n++
	return c.n
}

func main() {
	c := newCounter()
	c.n += localOnly()
	os.Exit(c.n - 3) // 結果是 3，所以結束碼是 0
}
go build -gcflags=-m ./chapters/05-pointers/escape

輸出（不同的 Go 版本可能略有不同）

# github.com/xinqilin/GO-Playground/chapters/05-pointers/escape
chapters/05-pointers/escape/main.go:10:6: can inline newCounter
chapters/05-pointers/escape/main.go:15:6: can inline localOnly
chapters/05-pointers/escape/main.go:23:17: inlining call to newCounter
chapters/05-pointers/escape/main.go:24:18: inlining call to localOnly
chapters/05-pointers/escape/main.go:11:2: moved to heap: c

-gcflags=-m 讓編譯器說出它做的最佳化決定。moved to heap: c 指的是 newCounter 裡的 c（第 11 行），因為它的位址被回傳了。localOnly 裡的 c 也被取了位址，但位址沒有離開函式，所以留在 stack 上，沒有出現在報告裡。can inline 和 inlining call 是另一種最佳化：編譯器把小函式的內容直接嵌進呼叫的地方，省掉呼叫的成本。

heap 配置比 stack 貴，因為要由 GC 追蹤和回收。但不要因此刻意避免指標：先寫出清楚的程式，等效能量測（效能與 profiling那一章）顯示配置是瓶頸，再用 -gcflags=-m 找原因。

6. 什麼時候該用指標

指標不是越多越好。每多一個指標，就多一個可能是 nil 的地方、多一條「遠處的程式可能改到這裡」的路徑。下面是實務上的判斷方式：

情況用指標？原因
函式要修改呼叫端的變數要傳值只會改到複本
需要分辨「沒有值」和「零值」要nil 代表沒有值（第 4 節）
struct 裡有不能複製的東西，例如 sync.Mutex要複製會讓鎖失效，go vet 會警告（第 17 章）
很大的 struct，而且會頻繁傳遞看量測複製有成本，但小 struct 複製通常比 heap 配置便宜
int、bool、小 struct 這類小值不用直接傳值更簡單，也不會是 nil
slice、map、channel、函式、string幾乎不用它們本身就是指向底層資料的小結構，傳值就能共用資料

slice 的情況稍微特殊：函式改 slice 的元素，呼叫端看得到；但函式用 append 讓 slice 變長，呼叫端看不到。Go 的慣例不是傳 *[]int，而是讓函式回傳新的 slice，像 s = append(s, x) 一樣，第 06 章會解釋原因。

同一個型別最好統一：如果它有一些方法需要指標，就讓所有方法都用指標，傳遞時也一律傳指標。第 09 章會把這件事和方法一起講清楚。

常見錯誤

1. 對 nil 指標解參考

錯誤訊息是 invalid memory address or nil pointer dereference（第 4 節）。常見的來源：宣告了 var p *T 卻忘了給值、函式在錯誤時回傳 nil 而呼叫端沒檢查 err、struct 裡的指標欄位沒有初始化。看到這個 panic，往回找是哪個指標在那一行是 nil。

2. 取到 range 複本的位址

for _, it := range items { … &it … } 取到的是複本的位址，透過它改不到 items 裡的資料。要指向 slice 裡的元素，用索引：&items[i]。練習 4 就是這個 bug，原理見第 03 章 range 的複本。

3. 以為複製 struct 就是完整的複本

struct 裡的指標、slice、map 欄位，複製後兩邊共用同一份資料（第 2 節）。需要獨立的複本，就要自己替這些欄位建立新的資料。

4. 取 map 元素的位址

package main

import "fmt"

func main() {
	stock := map[string]int{"排骨": 10}
	p := &stock["排骨"]
	fmt.Println(*p)
}

編譯錯誤

./main.go:7:8: invalid operation: cannot take address of stock["排骨"] (map index expression of type int)

map 長大時會把元素搬到新的位置，舊的位址就失效了，所以 Go 不讓你取 map 元素的位址。要修改就直接寫 stock["排骨"] = 9；需要共用的話，讓 map 的值本身是指標，例如 map[string]*Item（第 07 章）。

5. 對指標做運算

package main

import "fmt"

func main() {
	prices := [3]int{85, 90, 15}
	p := &prices[0]
	p++
	fmt.Println(*p)
}

編譯錯誤

./main.go:8:2: invalid operation: p++ (non-numeric type *int)

Go 沒有指標運算。要走過陣列或 slice，用索引或 for range。

6. 到處都用指標

「用指標比較快」是常見的誤解。小的值複製很便宜，指標反而可能讓變數逃逸到 heap、增加 GC 的負擔，還多了 nil 檢查。預設傳值，有明確的理由才用指標（第 6 節的表格）。

    回傳的指標應該指向 items 裡最便宜的那一項，讓呼叫端可以直接改它的庫存。但透過回傳的指標改庫存，items 卻沒有變。

		}

    測試：TestCheapest。

	return dup

重點回顧

  • &x 取位址，*p 解參考；*int 是「指向 int 的指標」這個型別。
  • 指標比較的是位址；Go 沒有指標運算。
  • 參數一律傳值，傳指標是複製位址，所以函式能改到呼叫端的變數。
  • struct 是值，指定和傳參數都會整個複製；指標欄位只複製位址，兩邊共用資料。
  • 指向 struct 的指標可以直接用 p.field。
  • struct 用 &T{…} 建立；Go 1.26 起 new(值) 能直接建立有初始值的變數。
  • 指標的零值是 nil，解參考會 panic；可能是 nil 的地方先檢查。
  • 用 *T 表示「可以沒有值」，分辨「沒有填」和「零值」。
  • 回傳區域變數的指標是安全的；變數放 stack 還是 heap 由逃逸分析決定，用 -gcflags=-m 看。
  • 預設傳值；要修改、要表示沒有值、或不能複製時才用指標。slice、map 不需要再包一層指標。
