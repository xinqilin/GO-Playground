1. 安裝 Go 並確認版本

到 go.dev 的下載頁選擇你的作業系統：

  • macOS：下載 .pkg 安裝檔，一路按下一步；有用 Homebrew 的話也可以 brew install go。
  • Windows：下載 .msi 安裝檔。裝完之後要重新開一個終端機視窗，新的 PATH 才會生效。
  • Linux：下載 .tar.gz，解壓縮到 /usr/local/go，再把 /usr/local/go/bin 加進 PATH。發行版套件庫裡的 Go 常常比較舊，建議直接用官方版本。

裝好之後開一個新的終端機，確認 go 指令找得到：

go version

輸出（以本書寫作時的 macOS 為例，版本和平台依你的電腦而定）

go version go1.27.4 darwin/arm64

輸出依序是 Go 的版本、作業系統和 CPU 架構。darwin 是 macOS，arm64 是 Apple 晶片；Windows 會顯示 windows/amd64 之類的組合。

版本不夠新也沒關係

這個 repo 的 go.mod 寫的是 go 1.27。只要你的 Go 是 1.21 以上，遇到要求更新版本的專案時，go 指令會自動下載對應版本的工具鏈（toolchain）來用，這個行為由環境變數 GOTOOLCHAIN 控制，預設值是 auto。第一次會花一點下載時間，之後就直接用快取。

Go 會在你的家目錄底下建立一個 go 資料夾（可以用 go env GOPATH 查實際位置）。下載的套件放在它的 pkg/mod，go install 裝的程式放在它的 bin。把這個 bin 加進 PATH，之後裝的工具就能直接在終端機執行。

2. 建立第一個 module

Go 的程式碼以 module 為單位管理。一個 module 就是一個資料夾，最上層有一個 go.mod 檔。建立 module 只要一個指令：

mkdir hello
cd hello
go mod init example.com/hello

輸出

go: creating new go.mod: module example.com/hello

產生的 go.mod

module example.com/hello

go 1.27.4

只有兩行，但都很重要：

  • module example.com/hello 是 module 的路徑，也就是它的全名。別人要用你的程式碼時，import 的就是這個路徑開頭的名字。只在自己電腦上練習的話，名字隨便取都可以；要放上 GitHub 讓別人用的話，習慣寫成 github.com/你的帳號/repo 名稱。
  • go 1.27.4 表示這個 module 至少需要哪個版本的 Go。go mod init 會填入你目前用的版本。它也決定了語言的行為：例如第 03 章提到的「每一圈都是新的迴圈變數」，只在這一行寫 1.22 以上時才生效。

以後用到第三方套件時，go.mod 會多出 require 區塊，旁邊也會出現記錄檢查碼的 go.sum，package 與 module 那一章會詳細介紹。現在只用標準庫，go.mod 就保持這兩行。

3. 一支程式的結構

這是本章程式的 main.go，完整的檔案長這樣：

// 第 00 章：第一支 Go 程式。
//
// 一支可以執行的 Go 程式需要 package main 和 func main()。
// 這一章的程式分成 main.go 和 greet.go 兩個檔案，它們屬於同一個 package。
//
// 執行：go run ./chapters/00-hello
package main

import "fmt"

// main 是程式的入口：它跑完，整支程式就結束。
func main() {
	fmt.Println("哈囉，Go！")

	// Println 可以一次印好幾個值，值和值之間自動補一個空白，最後換行。
	fmt.Println("便當", 3, "個，共", 255, "元，已付款：", true)

	// greeting 寫在 greet.go，同一個 package 裡的函式可以直接呼叫。
	fmt.Println(greeting("小明"))
}

輸出

哈囉，Go！
便當 3 個，共 255 元，已付款： true
哈囉，小明！

由上往下看：

  • 最上面的註解：緊貼在 package 上方的註解是這個 package 的說明文件，go doc 會把它顯示出來（第 8 節）。註解有兩種寫法：// 到行尾，或 /* … */ 包住一段；實務上幾乎都用 //。
  • package main：每個 .go 檔的第一行（註解除外）都要宣告它屬於哪個 package。名字叫 main 的 package 很特別：它會被編譯成可以執行的程式，其他名字的 package 則是給別人 import 的函式庫。
  • import "fmt"：把標準庫的 fmt 套件借進來用，fmt 負責格式化輸出。import 的是路徑，用的時候寫路徑的最後一段當前綴，也就是 fmt.Println。要 import 好幾個時，用括號包成一組：import ( "fmt" "os" )，每個路徑各佔一行。
  • func main()：程式的入口，沒有參數，也沒有回傳值。main 跑完，整支程式就結束；命令列參數要從 os.Args 拿（21 章 命令列工具）。
  • 每一行敘述的結尾不用分號：編譯器會自動補上，所以 Go 程式碼幾乎看不到分號（規則在第 03 章常見錯誤 1）。

fmt.Println 可以一次印好幾個值，不管是字串、整數還是布林值，它會在值和值之間補一個空白，最後換行。所以第二行輸出的「已付款：」和 true 中間多了一個空白。想精準控制格式時，要用 fmt.Printf，第 02 章會介紹。

字串和中文

Go 的原始碼一律是 UTF-8 編碼，字串可以直接放中文，不需要任何設定。用雙引號 "…" 寫的是字串；單引號 'a' 是一個字元（rune），兩者是不同的型別，第 08 章會細講。

大寫開頭才能給別人用

注意 fmt.Println 的 P 是大寫。Go 沒有 public、private 這些關鍵字，而是用名字的第一個字母決定：大寫開頭的名字會被匯出（exported），其他 package 可以使用；小寫開頭的只有自己的 package 看得到。所以標準庫給你用的函式全都是大寫開頭，而我們的 greeting 是小寫，只在這個 package 裡使用。寫成 fmt.println 會發生什麼事，第 7 節會看到。

4. 一個 package，好幾個檔案

main.go 呼叫的 greeting 不在 main.go 裡，而是寫在同一個資料夾的 greet.go：

package main

// greeting 回傳一句打招呼的話。
func greeting(name string) string {
	return "哈囉，" + name + "！"
}

Go 的規則是：一個資料夾就是一個 package。同一個資料夾裡的 .go 檔都要宣告同一個 package 名稱，編譯時會被當成一個整體，彼此的函式、變數、型別可以直接使用，不用 import，也不用管哪個檔案先寫。程式變大時，就照主題把程式拆成幾個檔案，例如第 03 章把 if、for、switch 的示範分別放在 if.go、loops.go、switch.go。

正因為如此，執行時要指定「整個資料夾」，而不是單一檔案：

go run .          # 編譯目前資料夾裡的整個 package
go run main.go    # 只編譯 main.go 這一個檔案

go run main.go 的輸出

# command-line-arguments
./main.go:6:14: undefined: greeting

只給 main.go 時，go 指令會把這一個檔案當成一個臨時的 package（名字叫 command-line-arguments），greet.go 不在裡面，所以找不到 greeting。養成用 go run . 或 go run ./路徑 的習慣，就不會遇到這個問題。

5. go run、go build、go install

Go 是編譯式語言：原始碼要先被編譯器翻譯成機器碼，才能執行。三個指令都會編譯，差別在編譯出來的執行檔放到哪裡：

指令做什麼什麼時候用
go run .編譯到暫存資料夾，馬上執行，跑完就刪掉開發中，改一下、跑一下
go build在目前資料夾產生執行檔，名字取 module 路徑的最後一段（例如 hello，Windows 是 hello.exe）；用 -o 可以指定名稱和位置要把程式交給別人或部署到伺服器
go install編譯後放進 go env GOPATH 底下的 bin（有設定 GOBIN 的話放那裡）安裝自己常用的命令列工具
 
go build -o bin/hello ./chapters/00-hello   # 在 bin/ 產生執行檔
./bin/hello                                 # 直接執行，不需要 go 指令

有幾件事值得知道：

  • 編譯很快：go 指令有 build cache，沒改過的 package 不會重新編譯，所以 go run 第二次之後幾乎是立刻執行。
  • 產物是單一執行檔：在大多數情況下，Go 會把程式需要的東西全部打包進一個執行檔，目標機器不需要安裝 Go，也不需要額外的 runtime。部署就是把這個檔案複製過去。
  • 交叉編譯只要設兩個環境變數：在 Mac 上執行 GOOS=linux GOARCH=amd64 go build，就能產生 Linux 伺服器用的執行檔，工具鏈那一章會細講。
  • 路徑寫法：. 是目前資料夾，./chapters/00-hello 是相對路徑；./... 代表目前資料夾和底下所有子資料夾，例如 go build ./... 會檢查整個 repo 都能編譯。

6. gofmt 與 go vet

gofmt：排版只有一種

Go 的程式碼排版是由工具決定的，不是由團隊爭論出來的。gofmt 會把縮排統一成 tab、在運算子兩側補空白、把大括號放到固定的位置。用 -d 可以先看它打算怎麼改。下面這個檔案排版很亂，但可以編譯：

gofmt -d messy.go

輸出

diff messy.go.orig messy.go
--- messy.go.orig
+++ messy.go
@@ -1,6 +1,10 @@
 package main
+
 import "fmt"
-func main(){
-    total:=85*3
-  if total>200 {fmt.Println("超過預算")}
+
+func main() {
+	total := 85 * 3
+	if total > 200 {
+		fmt.Println("超過預算")
+	}
 }

開頭是 - 的是原本的行，+ 是排版後的行。確認沒問題就用 gofmt -w messy.go 直接改寫檔案，或在 module 裡用 go fmt ./... 一次處理所有檔案。實務上不需要手動執行：設定好編輯器（第 9 節），存檔時就會自動排版。因為大家的程式都長得一樣，讀別人的 Go 程式碼會輕鬆很多，code review 也不用再討論空白和換行。

go vet：能編譯，不代表沒問題

編譯器只檢查「合不合法」，go vet 則會找出「合法但很可疑」的寫法。最常抓到的是格式字串和參數對不上。下面這支程式可以編譯，因為它沒有違反任何語法規則；但 %d 是整數的格式，卻配了一個字串：

package main

import "fmt"

func main() {
	name := "小明"
	fmt.Printf("%d 你好\n", name)
}
go vet .

輸出

main.go:7:14: fmt.Printf format %d has arg name of wrong type string

vet 的訊息很具體：第 7 行第 14 欄，%d 配到了 string 型別的 name。go test 在跑測試之前也會自動執行一部分 vet 檢查（printf 就是其中之一），本 repo 的 CI 則會對所有程式完整跑一次 go vet ./...。

7. 看懂編譯錯誤

初學時遇到的編譯錯誤大多是下面幾種。每個例子都是一支完整的程式，錯誤訊息是實際執行 go build 的結果（省略了第一行的 package 名稱）。遇到很多個錯誤時，先修第一個：後面的錯誤常常是第一個錯誤連帶造成的。

宣告了變數卻沒用

package main

import "fmt"

func main() {
	total := 85 * 3
	fmt.Println("便當三個")
}

編譯錯誤

./main.go:6:2: declared and not used: total

在其他語言這只是警告，在 Go 是錯誤。沒用到的變數通常代表程式寫到一半、或者算出來的值忘了用，編譯器直接擋下來，可以少掉一整類 bug。暫時還不想用的值可以指定給 _（空白識別字）：_ = total。

import 了卻沒用

package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Println("哈囉")
}

編譯錯誤

./main.go:5:2: "os" imported and not used

沒用到的 import 也是錯誤，這讓每個檔案的相依關係保持乾淨，編譯也更快。設定好編輯器之後，存檔時會自動移除沒用到的 import、補上缺少的 import，這個錯誤幾乎不會再遇到。

名字打錯

package main

import "fmt"

func main() {
	fmt.Println(greting("小明"))
}

func greeting(name string) string {
	return "哈囉，" + name
}

編譯錯誤

./main.go:6:14: undefined: greting

undefined 表示編譯器找不到這個名字。常見原因有三個：打錯字、忘了 import、或者定義寫在另一個檔案卻只編譯了一個檔案（第 4 節）。

用到沒有匯出的名字

package main

import "fmt"

func main() {
	fmt.println("哈囉")
}

編譯錯誤

./main.go:6:6: undefined: fmt.println (but have Println)

小寫開頭的名字不會匯出，所以從 fmt 外面看不到 println。編譯器還很貼心地提示「但是有 Println」。Go 的錯誤訊息通常都寫得很直接，耐心讀完，答案常常就在裡面。

8. 查文件：go doc 與 pkg.go.dev

寫 Go 的時候會一直查標準庫的用法。有兩個地方可以查：

  • 網頁：pkg.go.dev 有標準庫和所有公開套件的文件，可以搜尋，也有範例。
  • 終端機：go doc 不用開瀏覽器。go doc strings 列出整個套件，go doc strings.Repeat 只看一個函式，go doc -all strings 看完整內容。

go doc 顯示的內容來自原始碼裡的註解。所以我們自己寫的程式也能用它查，例如本章的程式：

go doc ./chapters/00-hello

輸出

第 00 章：第一支 Go 程式。

一支可以執行的 Go 程式需要 package main 和 func main()。 這一章的程式分成 main.go 和 greet.go 兩個檔案，它們屬於同一個 package。

執行：go run ./chapters/00-hello

這就是 main.go 最上面那段註解。Go 的慣例是：寫在宣告正上方、以那個名字開頭的註解，就是它的文件，例如 // greeting 回傳一句打招呼的話。。不需要特別的標記語法，寫成通順的句子就好。練習 4、5 會需要你用 go doc 查 strings 和 strconv 的函式。

9. 編輯器

Go 官方維護一個語言伺服器 gopls，大部分編輯器都透過它支援 Go：

  • VS Code：安裝 Go 官方的擴充套件，第一次開 .go 檔時它會提示安裝 gopls 等工具，按下安裝就好。
  • GoLand：JetBrains 的 Go IDE，裝好就能用。習慣 IntelliJ 的人會很熟悉。
  • Vim、Neovim、Emacs、Zed、Helix：設定它們的 LSP 功能去使用 gopls。

設定好之後，你會得到：存檔自動排版、自動整理 import、自動完成、跳到定義、找出所有使用的地方、安全地重新命名，以及在你打字時就標出編譯錯誤和 vet 的警告。這些功能在練習時非常有幫助，值得花十分鐘設定好。

10. 這本手冊怎麼用

先把整個 repo 下載到你的電腦：

git clone https://github.com/xinqilin/GO-Playground.git
cd GO-Playground

repo 裡有四個主要的資料夾：

  • chapters/：每一章的示範程式。頁面上的程式碼和輸出都是從這裡同步過去的，用 go run ./chapters/03-control-flow 就能看到同樣的輸出。
  • exercises/：每一章的練習題。exercises.go 是題目，exercises_test.go 是檢查答案的測試，solution.go 是參考解答。
  • projects/：把多章的內容組合起來的專題。
  • docs/：你正在讀的這些網頁。

做練習的流程是：打開 exercises.go，把 TODO 換成你的程式，然後執行測試。還沒寫的時候，測試會失敗，並告訴你哪裡不對：

go test ./exercises/00-hello/ -run TestGreeting

輸出（還沒作答時）

--- FAIL: TestGreeting (0.00s)
    exercises_test.go:15: Greeting("小明") = "", want "哈囉，小明！"
    exercises_test.go:15: Greeting("Go") = "", want "哈囉，Go！"
    exercises_test.go:15: Greeting("") = "", want "哈囉，陌生人！"
FAIL
FAIL	github.com/xinqilin/GO-Playground/exercises/00-hello	0.315s
FAIL

每一行失敗訊息都是同一個格式：用什麼參數呼叫、實際得到什麼（= 後面）、期望得到什麼（want 後面）。這裡三次呼叫都得到空字串，因為題目還沒寫。全部寫對之後，最後一行會變成 ok。-run 後面接測試名稱，只跑那一題；不加就跑整章的練習。卡住的時候可以加 -tags solution 跑參考解答，或直接讀 solution.go，但建議先自己試過。

不要在根目錄跑 go test ./...

根目錄的 go test ./... 會連同所有還沒寫的練習一起跑，一定會看到一堆紅燈。只想確認示範程式時，用 go test ./chapters/... ./projects/...。

常見錯誤

1. 在沒有 go.mod 的資料夾執行

go run .

輸出

go: go.mod file not found in current directory or any parent directory; see 'go help modules'

go 指令會從目前的資料夾往上找 go.mod，一路找到根目錄都找不到就會報這個錯誤。可能是忘了 go mod init，或者終端機不在專案資料夾裡。用 pwd（Windows 用 cd）確認目前的位置。

2. 同一個資料夾放了兩種 package

main.go 寫 package main，greet.go 卻寫了 package hello：

go run . 的輸出

found packages hello (greet.go) and main (main.go) in …/mixed

一個資料夾只能有一個 package，所有檔案的 package 名稱必須一致（測試檔的 _test 後綴是唯一的例外，測試那一章會介紹）。

3. 用 go run main.go 漏掉其他檔案

package 拆成好幾個檔案之後，go run main.go 只會編譯 main.go，其他檔案定義的名字都會變成 undefined。改用 go run .，見第 4 節。

4. 把警告當成可以忽略的東西

沒用到的變數和 import 在 Go 是編譯錯誤，不能先放著。這不是刁難，而是讓程式一直保持乾淨。暫時不用的值指定給 _，或乾脆刪掉。

5. 裝好之後找不到 go 指令

終端機說找不到 go，通常是 PATH 還沒更新：關掉終端機再開一個新的。還是不行的話，確認安裝路徑底下的 bin（macOS 和 Linux 預設是 /usr/local/go/bin）有加進 PATH。

練習

前五題在 exercises/00-hello/exercises.go，每題都有測試；最後兩題是在自己的電腦上動手做，沒有自動測試。你還沒學到變數、if 和字串處理也沒關係，提示會告訴你要用什麼，也可以先跳過，讀完第 01–03 章再回來寫。

go test ./exercises/00-hello/                     # 跑全部練習
go test ./exercises/00-hello/ -run TestGreeting   # 只跑一題
go test -tags solution ./exercises/00-hello/      # 跑參考解答

  1. 入門練習 1：打招呼

    回傳 "哈囉，<name>！"；name 是空字串時回傳 "哈囉，陌生人！"。

    func Greeting(name string) string {
	// TODO: 實作
	return ""
}

    測試：TestGreeting，第 10 節有它還沒作答時的失敗訊息。

    提示

    字串用 + 接起來，和本章的 greeting 一樣。空字串的判斷寫成 if name == "" { name = "陌生人" }，放在組字串之前。

  2. 入門練習 2：便當總價

    一個便當 85 元，買 10 個以上每個算 80 元。qty 小於 1 時回傳 0。

    func BentoTotal(qty int) int {
	// TODO: 實作
	return 0
}

    例如 BentoTotal(3) 是 255，BentoTotal(10) 是 800。測試：TestBentoTotal。

    提示

    先用 price := 85 宣告單價，數量夠多時改成 80，最後回傳 qty * price。

  3. 入門練習 3：秒數轉時鐘

    把秒數轉成 "時:分:秒"，每一段都是兩位數；負數當成 0，時數超過 99 就照實寫出。

    func Clock(seconds int) string {
	// TODO: 實作
	return ""
}

    例如 Clock(3725) 是 "01:02:05"。測試：TestClock。

    提示

    整數除法會捨去小數：seconds / 3600 是時，seconds % 3600 / 60 是分，seconds % 60 是秒。用 go doc fmt.Sprintf 查格式化的寫法，%02d 表示「至少兩位，不足補 0」。

  4. 進階練習 4：ASCII 框

    用 +、-、| 把文字框起來，三列之間用換行分開。框的內寬是文字長度加 2，文字左右各留一個空白。text 只會有 ASCII 字元。

    func Box(text string) string {
	// TODO: 實作
	return ""
}

    例如 Box("Go") 是 "+----+\n| Go |\n+----+"。測試：TestBox。

    提示

    執行 go doc strings.Repeat，它可以把一個字串重複 n 次。上下兩條邊框一樣，先算好存在一個變數裡。len(text) 是字串的 byte 數，ASCII 字元一個就是 1 byte。

  5. 進階練習 5：讀 go.mod 的版本

    讀取 go.mod 的 go 那一行（例如 "go 1.27.4" 或 "go 1.27"），回傳主版號和次版號。格式不對時，例如不是 "go " 開頭、少了次版號，或版號不是數字，就回傳 0, 0, false。

    func GoVersion(line string) (major, minor int, ok bool) {
	// TODO: 實作
	return 0, 0, false
}

    例如 GoVersion("go 1.27.4") 是 1, 27, true，GoVersion("go 1") 是 0, 0, false。測試：TestGoVersion。

    提示

    用 go doc 查這三個函式：strings.CutPrefix 拿掉開頭的 "go "，strings.Split 用 "." 切開，strconv.Atoi 把字串轉成整數，失敗時會回傳錯誤。只看切出來的前兩段，第三段（修訂版號）不用管。

  6. 動手做練習 6：自己的 module

    在 repo 以外的地方建立一個新資料夾，從零做出一支程式：

    1. 用 go mod init 建立 module，名稱自己取。
    2. 寫一個 main.go，印出你的名字和今天的日期（日期先寫死在字串裡）。
    3. 把印名字的部分抽成一個函式，放到另一個檔案。
    4. 用 go run . 執行，再用 go build 產生執行檔，直接執行它。
    5. 執行 go doc .，看看你寫的註解有沒有出現。

  7. 動手做練習 7：故意寫錯

    在練習 6 的程式裡，一次製造一個錯誤，先猜編譯器會說什麼，再執行 go build 對答案，最後修好它：

    1. 宣告一個變數但不使用。
    2. import "strings" 但不使用。
    3. 把 fmt.Println 寫成 fmt.println。
    4. 把 { 換到下一行。
    5. 用 fmt.Printf("%d\n", "文字")，這次改用 go vet . 檢查。

參考解答：先自己寫完再看。測試通過的寫法都是對的。

重點回顧

  • go version 確認安裝；Go 1.21 以上會自動下載專案需要的版本。
  • go mod init 路徑 建立 module；go.mod 記錄 module 路徑和需要的 Go 版本。
  • 可以執行的程式是 package main 加上 func main()。
  • 一個資料夾就是一個 package，裡面的檔案一起編譯；執行時用 go run .。
  • 大寫開頭的名字才會匯出給其他 package 使用。
  • go run 編譯後馬上執行，go build 留下執行檔，go install 放進 GOPATH 的 bin。
  • 排版交給 gofmt，可疑的寫法交給 go vet。
  • 錯誤訊息的格式是「檔案:行:欄: 原因」，先修第一個。
  • 沒用到的變數和 import 是編譯錯誤。
  • 用 go doc 或 pkg.go.dev 查文件；宣告上方的註解就是文件。
  • 練習題用 go test ./exercises/章節/ 檢查，失敗訊息會告訴你得到什麼、期望什麼。
