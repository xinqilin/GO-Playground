1. Print 家族

fmt 套件的輸出函式有九個，但只要記兩件事：字首決定寫到哪裡，字尾決定怎麼排。字尾沒有東西的版本（Print）把參數接在一起；ln 版本在參數之間補空白、最後換行；f 版本第一個參數是格式字串，後面的值依序填進去。

Print 和 Println 補空白的規則不同

func printSpacing() {
	fmt.Print("便當", 3, 85, "元", "\n")
	fmt.Println("便當", 3, 85, "元")
}

輸出

便當3 85元
便當 3 85 元

Println 一律在參數之間補一個空白。Print 則只在「兩邊都不是字串」的時候補：「便當」和 3 之間沒有空白，3 和 85 之間有，85 和「元」之間又沒有。這個規則很容易忘，實務上要控制格式時直接用 Printf，最不會出錯。

S 開頭：回傳字串

func sprintDemo() {
	label := fmt.Sprintf("%s x%d", "排骨飯", 2)
	total := fmt.Sprint(170)
	fmt.Println(label + "：" + total + " 元")
}

輸出

排骨飯 x2：170 元

Sprintf 是 Go 最常用的「組字串」方法，相當於 Java 的 String.format。錯誤訊息也常用同樣的格式字串來組：fmt.Errorf 的用法和 Sprintf 一樣，只是回傳一個 error，第 11 章會細講。

F 開頭：寫到指定的地方

func fprintDemo() {
	fmt.Fprintln(os.Stdout, "寫到標準輸出")

	var sb strings.Builder
	fmt.Fprintf(&sb, "%d 號請到 %d 號櫃台", 42, 3)
	fmt.Println("Builder 裡有：" + sb.String())
}

輸出

寫到標準輸出
Builder 裡有：42 號請到 3 號櫃台

Fprintf 的第一個參數是一個 io.Writer，任何「可以寫入」的東西都行：os.Stdout、打開的檔案、網路連線，或者存在記憶體裡的 strings.Builder。其實 fmt.Println(x) 就是 fmt.Fprintln(os.Stdout, x) 的簡寫。&sb 的 & 是取位址，讓 Fprintf 寫進的是 sb 本身而不是一份複本，第 05 章介紹。io.Writer 是什麼，第 7 節會說明。

2. 格式化動詞

格式字串裡 % 開頭的部分叫做動詞（verb），它決定對應的值要怎麼印。動詞很多，但最常用的只有十幾個。

萬用的 %v 和印型別的 %T

type item struct {
	Name  string
	Price int
}

func verbsGeneral() {
	it := item{"排骨飯", 85}
	fmt.Printf("%v | %+v\n", it, it)
	fmt.Printf("%#v\n", it)
	fmt.Printf("%T\n", it)

	menu := map[string]int{"雞腿": 90, "排骨": 85, "滷蛋": 15}
	fmt.Printf("%v\n", menu)
	queue := []string{"A01", "A02"}
	fmt.Printf("%v %q\n", queue, queue)
}

輸出

{排骨飯 85} | {Name:排骨飯 Price:85}
main.item{Name:"排骨飯", Price:85}
main.item
map[排骨:85 滷蛋:15 雞腿:90]
[A01 A02] ["A01" "A02"]
  • %v（value）用預設的格式印出任何值，Println 內部用的就是它。
  • %+v 印 struct 時會加上欄位名稱，除錯時最好用。
  • %#v 印出 Go 語法的寫法，貼回程式碼就能用；字串會加上引號，型別也寫出來。
  • %T 印出值的型別。main.item 表示 main 這個 package 裡的 item 型別。
  • 印 map 時，fmt 會先把 key 排序，所以每次印出來的順序都一樣。這是 fmt 特地做的；直接用 for range 走訪 map 時順序是隨機的（第 07 章）。
  • %q 用在字串 slice 上，每個元素都加上引號，看得出空字串和前後的空白。

fmt 印得出 struct 的所有欄位，不管大寫還是小寫開頭。這裡的欄位寫成大寫的 Name、Price，是先為之後的 JSON 編碼養成習慣：encoding/json 只看得到大寫開頭（匯出）的欄位。

整數和字元

func verbsInt() {
	n := 255
	fmt.Printf("%d %+d %b %o %x %X %#x\n", n, n, n, n, n, n, n)
	r := '飯'
	fmt.Printf("%c %q %U %d\n", r, r, r, r)
}

輸出

255 +255 11111111 377 ff FF 0xff
飯 '飯' U+98EF 39151

%d 十進位，%+d 一定帶正負號，%b 二進位，%o 八進位，%x、%X 十六進位（小寫、大寫），加上 # 旗標會帶前綴 0x。字元（rune）本質是整數，所以 %d 印出它的編號 39151；%c 印出字元本身，%q 加上單引號，%U 印出 Unicode 的標準寫法 U+98EF。

浮點數

func verbsFloat() {
	f := 1234.5678
	fmt.Printf("%f | %.2f | %.0f\n", f, f, f)
	fmt.Printf("%e | %g\n", f, f)
	fmt.Printf("%g | %g\n", 0.000012345, 1e21)
}

輸出

1234.567800 | 1234.57 | 1235
1.234568e+03 | 1234.5678
1.2345e-05 | 1e+21

%f 預設印到小數第六位，%.2f 指定兩位（會四捨五入），%.0f 不要小數。%e 是科學記號。%g 是「看情況」：用最少的位數精確表示這個值，數字太大或太小時自動換成科學記號。Println 印浮點數時用的就是 %g 的規則，所以第 01 章才會看到 0.30000000000000004 這種長尾巴。要給人看的數字，例如金額和百分比，用 %.1f 或 %.2f 固定位數。

字串、布林與百分比符號

func verbsString() {
	s := "Go語"
	fmt.Printf("%s | %q | %x | % x\n", s, s, s, s)
	fmt.Printf("%t | %v\n", true, false)
	fmt.Printf("%d%%\n", 85)
}

輸出

Go語 | "Go語" | 476fe8aa9e | 47 6f e8 aa 9e
true | false
85%

%s 印字串本身，%q 加上雙引號並把特殊字元（換行、tab、不可見字元）寫成跳脫序列，除錯時很好用，看得出字串裡藏了什麼。%x 把字串的每個 byte 寫成十六進位，% x（中間有空白）會在 byte 之間加空白：「語」佔了 e8 aa 9e 三個 byte，這就是 UTF-8，第 08 章會細講。%t 印布林值。要印出 % 本身，寫兩個 %%。

動詞和值對不上時

Printf 不會因為格式錯誤而停下來，而是把錯誤寫進輸出裡。下面三行分別是型別不對、參數不夠、參數太多：

package main

import "fmt"

func main() {
	fmt.Printf("%d 個便當\n", "三")
	fmt.Printf("%s 點 %d 分\n", "十二")
	fmt.Printf("合計 %d 元\n", 255, 15)
}

執行結果

%!d(string=三) 個便當
十二 點 %!d(MISSING) 分
合計 255 元
%!(EXTRA int=15)

看到 %! 開頭的奇怪文字，就是格式字串寫錯了。好消息是這三個錯誤 go vet 全部抓得到，存檔時編輯器也會標出來：

main.go:7:21: fmt.Printf format %d reads arg #2, but call has 1 arg
main.go:8:2: fmt.Printf call needs 1 arg but has 2 args
動詞用途例子
%v %+v %#v預設格式、加欄位名、Go 語法{排骨飯 85}
%T型別main.item
%d %b %o %x整數：十、二、八、十六進位255 11111111 377 ff
%c %U字元、Unicode 編號飯 U+98EF
%f %.2f %e %g浮點數1234.57

%t布林true

3. 寬度、精度與對齊

在 % 和動詞之間，可以加上寬度、精度和旗標，排出對齊的輸出：

func widthBasics() {
	fmt.Printf("|%6d|%-6d|%06d|\n", 85, 85, 85)
	fmt.Printf("|%8.2f|%-8.2f|%.1f|\n", 3.14159, 3.14159, 3.14159)
	fmt.Printf("|%6s|%-6s|%.2s|\n", "Go", "Go", "Golang")
	fmt.Printf("|%*d|\n", 6, 85)
}

輸出

|    85|85    |000085|
|    3.14|3.14    |3.1|
|    Go|Go    |Go|
|    85|
  • 寬度：%6d 至少佔 6 格，不夠就在左邊補空白，也就是靠右對齊。值比寬度長時照樣完整印出，不會被截斷。
  • 旗標 -：改成靠左對齊，空白補在右邊。
  • 旗標 0：用 0 取代空白來補，常用在編號，例如 %03d 印出 007。
  • 精度：對浮點數是小數位數；對字串是「最多印幾個字元」，所以 %.2s 把 Golang 截成 Go。
  • *：寬度或精度要執行時才知道時，寫成 *，再多傳一個整數參數。

排一張表

func fareTable() {
	fmt.Println("票價  目的地")
	fmt.Printf("%4d  %s\n", 20, "台北車站")
	fmt.Printf("%4d  %s\n", 35, "南港展覽館")
	fmt.Printf("%4d  %s\n", 65, "淡水")
}

輸出

票價  目的地
  20  台北車站
  35  南港展覽館
  65  淡水

數字靠右對齊，個位數就會對在同一欄，比較大小一目了然。中文站名長短不一，所以放在最後一欄，讓它自由延伸，前面的欄位就不受影響。

3.1 中文為什麼對不齊

func widthCJK() {
	fmt.Printf("|%-6s|\n", "Go")
	fmt.Printf("|%-6s|\n", "排骨飯")
}

輸出

|Go    |
|排骨飯   |

兩行都補到 6 個字元：Go 後面補 4 個空白，排骨飯後面補 3 個。但在終端機和大部分等寬字型裡，一個中文字佔兩個英文字母的寬度，所以排骨飯那一行實際上是 9 格，右邊的 | 就歪了。fmt 只會數「字元」（rune），不知道每個字顯示出來有多寬。

簡單的解法就是上面票價表的做法：中文放最後一欄。真的需要對齊中文時，要自己算顯示寬度，再用 strings.Repeat(" ", n) 補空白，第 08 章會實作這件事。

4. Stringer：型別自己決定怎麼印

第 01 章用 iota 定義的列舉，印出來只是數字。只要替型別加上一個 String() string 方法，fmt 就會改印這個方法回傳的文字：

type Size int

const (
	Small Size = iota
	Medium
	Large
)

func (s Size) String() string {
	switch s {
	case Small:
		return "小份"
	case Medium:
		return "中份"
	case Large:
		return "大份"
	}
	return "Size(" + strconv.Itoa(int(s)) + ")"
}

func stringerDemo() {
	s := Large
	fmt.Println(s)
	fmt.Printf("%v %s %d\n", s, s, s)
	fmt.Println(Size(7))
	fmt.Println([]Size{Small, Large})
}

輸出

大份
大份 大份 2
Size(7)
[小份 大份]

func (s Size) String() string 是方法的寫法：函式名稱前面多了一個 (s Size)，叫做 receiver，表示這個函式屬於 Size 型別，呼叫時寫成 s.String()。方法在第 09 章正式介紹，這裡只要會照著寫就好。switch 依序比對 case，第 03 章會細講。

fmt 印每個值之前，都會檢查它有沒有 String() string 方法，有的話就呼叫它。這個「有某個方法」的條件，在 Go 裡叫做實作了 fmt.Stringer 這個 interface（第 10 章）。所以 Println、%v、%s 都印出「大份」，連印 slice 時裡面的每個元素也一樣。只有 %d 這種明確要求數字格式的動詞，才會印出底層的 2。

注意最後的 return：份量不在三個合法值裡時，印出 Size(7) 這種形式，看到就知道是哪個值出了問題。這裡用 strconv.Itoa(int(s)) 而不是 fmt.Sprint(s)，原因在下面。

深入：第一次讀可以先跳過

4.1 String 裡面不能再用 %v 印自己

package main

import "fmt"

type Size int

func (s Size) String() string {
	return fmt.Sprintf("Size(%v)", s)
}

func main() {
	fmt.Println(Size(2))
}

go vet 的輸出

main.go:8:27: fmt.Sprintf format %v with arg s causes recursive (example.com/size.Size).String method call

%v 印 s 時，fmt 發現它有 String 方法，就去呼叫 String；String 裡又用 %v 印 s……無限遞迴，直到程式的堆疊用完而當掉。解法是先把值轉成底層型別：int(s) 沒有 String 方法，fmt 就會乖乖印數字。所以寫成 fmt.Sprintf("Size(%d)", int(s)) 或上面的 strconv.Itoa(int(s)) 都可以。

另一個常見的坑是把 String 寫在指標上：func (s *Size) String() string。這時只有 *Size 有這個方法，直接印 Size 的值不會用到它。方法的 receiver 該用值還是指標，第 09 章會說明；String 這種不修改內容的方法，一般用值。

5. 標準輸入、輸出與錯誤

每支程式一啟動，作業系統就幫它接好三條管道，在 Go 裡是 os 套件的三個變數：

  • os.Stdin：標準輸入。預設是鍵盤，也可以是管線（|）或檔案（<）。
  • os.Stdout：標準輸出，放程式的結果。fmt.Println 寫的就是這裡。
  • os.Stderr：標準錯誤，放給人看的訊息：提示、進度、警告、錯誤。

兩個出口預設都印在終端機上，看起來沒有差別，但它們可以分開導向：

func streams() {
	fmt.Fprintln(os.Stderr, "提示：這一行寫到 stderr")
	fmt.Fprintln(os.Stdout, "結果：這一行寫到 stdout")
}

輸出

結果：這一行寫到 stdout

終端機上會看到兩行，但測試只比對 stdout，所以 Example 的輸出只有一行。用一支完整的程式來看分工：chapters/02-input-output/sum 從 stdin 讀整數，算出總和與平均。它的主體是一個收 io.Reader 和 io.Writer 的 run 函式（第 7 節會說明為什麼這樣寫），main 只負責把真正的 stdin、stdout 接上去：

func main() {
	fmt.Fprintln(os.Stderr, "請輸入整數，每行一個，Ctrl-D 結束：")
	if err := run(os.Stdin, os.Stdout); err != nil {
		fmt.Fprintln(os.Stderr, "錯誤：", err)
		os.Exit(1)
	}
}

先編譯，再用 printf 和管線餵資料給它（Windows 的 PowerShell 寫法不同，可以改成直接執行、用鍵盤輸入，最後按 Ctrl-Z 再按 Enter 結束）：

go build -o sum ./chapters/02-input-output/sum
printf '3\n4\n5\n' | ./sum

輸出

請輸入整數，每行一個，Ctrl-D 結束：
共 3 個數字，總和 12，平均 4.00

提示和結果都出現了。把 stderr 丟掉（2>/dev/null），就只剩結果；把 stdout 導到檔案（> result.txt），終端機上就只剩提示，檔案裡只有乾淨的結果，可以直接交給下一支程式處理：

printf '3\n4\n5\n' | ./sum 2>/dev/null
printf '3\n4\n5\n' | ./sum > result.txt
cat result.txt

輸出

共 3 個數字，總和 12，平均 4.00
請輸入整數，每行一個，Ctrl-D 結束：
共 3 個數字，總和 12，平均 4.00

第一行來自第一個指令；第二行是第二個指令的提示（stderr 還是印在終端機上）；第三行是 cat 印出檔案的內容。如果提示也寫到 stdout，result.txt 的第一行就會混進「請輸入整數」，下一支程式讀到它就壞了。

結束碼

程式結束時會回傳一個整數給作業系統，叫做結束碼：0 代表成功，其他值代表失敗。main 正常跑完就是 0；要回報失敗，呼叫 os.Exit(1)：

printf '1\nabc\n' | ./sum
echo "exit=$?"

輸出

請輸入整數，每行一個，Ctrl-D 結束：
錯誤： 第 2 行 "abc" 不是整數
exit=1

$? 是 shell 裡「上一個指令的結束碼」。shell 腳本、Makefile 和 CI 都靠它判斷有沒有成功，所以出錯時一定要回傳非 0 的值。注意 os.Exit 會立刻結束程式，連 defer 都不會執行（第 04 章）；習慣的寫法是像這裡一樣，只在 main 的最後呼叫它，其他函式一律回傳 error。

6. 一行一行讀：bufio.Scanner

讀輸入最常用的工具是 bufio.Scanner。它包住一個 io.Reader，每呼叫一次 Scan 就往下讀一行，讀到了回傳 true，讀完或出錯時回傳 false：

func scanLines() {
	input := "排骨飯 85\n雞腿飯 90\n\n滷蛋 15\n"
	sc := bufio.NewScanner(strings.NewReader(input))
	n := 0
	for sc.Scan() {
		n++
		fmt.Printf("第 %d 行：%q\n", n, sc.Text())
	}
	if err := sc.Err(); err != nil {
		fmt.Println("讀取失敗：", err)
	}
}

輸出

第 1 行："排骨飯 85"
第 2 行："雞腿飯 90"
第 3 行：""
第 4 行："滷蛋 15"

這是讀取的標準寫法，三個部分缺一不可：

  1. for sc.Scan()：迴圈條件就是「還有沒有下一行」。
  2. sc.Text()：取出這一行，不含換行字元。Windows 的 \r\n 也會一起去掉，空白行則得到空字串。
  3. sc.Err()：迴圈結束後一定要檢查。Scan 回傳 false 有兩種可能：正常讀完，或者讀取出錯。只看 Scan 分不出來，要問 Err；正常讀完時它回傳 nil。

strings.NewReader 把一個字串包成 io.Reader，示範和測試時用它取代真正的 stdin 或檔案。換成 bufio.NewScanner(os.Stdin)，同樣的迴圈就能讀鍵盤或管線。

改成一個字一個字讀

func scanWords() {
	sc := bufio.NewScanner(strings.NewReader("  排骨飯   2\n滷蛋 3 "))
	sc.Split(bufio.ScanWords)
	var words []string
	for sc.Scan() {
		words = append(words, sc.Text())
	}
	if err := sc.Err(); err != nil {
		fmt.Println("讀取失敗：", err)
	}
	fmt.Println(len(words), words)
}

輸出

4 [排骨飯 2 滷蛋 3]

Split 可以換掉切割的方式。bufio.ScanWords 以空白為界，連續的空白、tab、換行都算一個分隔，頭尾的空白也會略過。另外還有 ScanRunes（一個字元一個字元）和 ScanBytes。要讀的資料是「一行一筆紀錄」時，通常還是用預設的逐行讀，再用 strings.Fields 把一行切成欄位，這樣才知道每個欄位屬於哪一行。

太長的行

func scanTooLong() {
	long := strings.Repeat("x", 70_000)
	sc := bufio.NewScanner(strings.NewReader("短的一行\n" + long + "\n最後一行\n"))
	for sc.Scan() {
		fmt.Println("讀到", len(sc.Text()), "bytes")
	}
	fmt.Println("Err:", sc.Err())
}

輸出

讀到 12 bytes
Err: bufio.Scanner: token too long

Scanner 的緩衝區預設最大 64 KB（bufio.MaxScanTokenSize），一行超過這個長度時，Scan 回傳 false，Err 回傳 token too long，後面的「最後一行」再也讀不到了。如果沒有檢查 Err，程式會以為輸入只有一行，而且不會有任何警告。一般的文字檔很少有這麼長的行，但壓縮過的 JSON、log 或 CSV 一整行好幾 MB 並不少見。需要時用 Buffer 放寬上限：

func scanBigBuffer() {
	long := strings.Repeat("x", 70_000)
	sc := bufio.NewScanner(strings.NewReader(long + "\n最後一行\n"))
	sc.Buffer(make([]byte, 0, 64*1024), 1024*1024) // 一行最多 1 MB
	for sc.Scan() {
		fmt.Println("讀到", len(sc.Text()), "bytes")
	}
	fmt.Println("Err:", sc.Err())
}

輸出

讀到 70000 bytes
讀到 12 bytes
Err: <nil>

Buffer 的第一個參數是一開始用的緩衝區，第二個是上限。要在第一次 Scan 之前呼叫。上限是整個緩衝區的大小，換行字元也要放得下，所以設定時要比預期最長的一行再多一點：上限設成剛好 1 MB，遇到剛好 1 MB 的一行仍然會失敗。如果資料根本沒有「行」的概念，或者一行可能無限長，就不要用 Scanner，改用 bufio.Reader 或直接處理串流。

fmt.Sscan：用空白切開再轉型

func sscanDemo() {
	var name string
	var qty, price int
	n, err := fmt.Sscan("排骨飯 2 85", &name, &qty, &price)
	fmt.Println(n, err, name, qty*price)

	n, err = fmt.Sscan("滷蛋 三 15", &name, &qty, &price)
	fmt.Println(n, err)
}

輸出

3 <nil> 排骨飯 170
1 expected integer

fmt 也有一組讀取函式：Scan 從 stdin 讀、Sscan 從字串讀、Fscan 從 io.Reader 讀。它們用空白切開輸入，依照變數的型別自動轉換，回傳成功填了幾個。第二次呼叫時「三」不是整數，所以只填了 name 一個，錯誤是 expected integer。它們用在格式很固定的小工具很方便，但錯誤訊息不夠清楚，也不容易知道錯在第幾行。一般的程式建議用 Scanner 逐行讀，再用 strings.Fields 和 strconv.Atoi 自己處理每一行，像上面的 sum 程式一樣。

7. io.Reader 與 io.Writer

前面已經用了好幾次 io.Reader 和 io.Writer。它們是 Go 標準庫裡最重要的兩個 interface，定義非常小：

  • io.Reader：有一個 Read(p []byte) (n int, err error) 方法，意思是「把資料讀進 p，告訴我讀了幾個 byte」。讀完時回傳 io.EOF 這個錯誤。
  • io.Writer：有一個 Write(p []byte) (n int, err error) 方法，意思是「把 p 寫出去，告訴我寫了幾個 byte」。

任何型別只要有這個方法，就「是」一個 Reader 或 Writer，不用特別宣告（第 10 章）。所以 os.Stdin、檔案、網路連線、strings.Reader、壓縮串流都是 Reader；os.Stdout、檔案、HTTP 回應、strings.Builder、bytes.Buffer 都是 Writer。你幾乎不會自己呼叫 Read 和 Write，而是把它們交給 Scanner、Fprintf、io.Copy 這些工具去用。

讓函式收 Reader 和 Writer

func numberLines(r io.Reader, w io.Writer) error {
	sc := bufio.NewScanner(r)
	n := 0
	for sc.Scan() {
		n++
		if _, err := fmt.Fprintf(w, "%02d %s\n", n, sc.Text()); err != nil {
			return err
		}
	}
	return sc.Err()
}

func numberLinesDemo() {
	if err := numberLines(strings.NewReader("排骨飯\n雞腿飯\n滷蛋\n"), os.Stdout); err != nil {
		fmt.Println("錯誤：", err)
	}

	var sb strings.Builder
	if err := numberLines(strings.NewReader("紅茶\n綠茶\n"), &sb); err != nil {
		fmt.Println("錯誤：", err)
	}
	fmt.Printf("%q\n", sb.String())
}

輸出

01 排骨飯
02 雞腿飯
03 滷蛋
"01 紅茶\n02 綠茶\n"

同一個 numberLines，一次寫到 stdout，一次寫進記憶體裡的 Builder。如果它直接寫死 os.Stdin 和 os.Stdout，要測試就得真的打字或接管線；改收 interface 之後，測試只要準備一個字串，再檢查 Builder 裡的結果就好。這就是 sum 程式把邏輯放在 run(in, out)、main 只負責接線的原因，本書後面的命令列程式和 HTTP 程式都會照這個模式寫。

注意 Fprintf 也會回傳錯誤：寫到檔案或網路時，磁碟可能滿了、連線可能斷了。印到終端機的小程式通常忽略它，但寫檔案或寫網路的函式應該把錯誤傳回去，練習 4 會要求你這樣做。

bufio.Writer：記得 Flush

func bufferedWriter() {
	var sb strings.Builder
	bw := bufio.NewWriter(&sb)
	fmt.Fprint(bw, "叫號：A01")
	fmt.Printf("Flush 前：%q\n", sb.String())
	if err := bw.Flush(); err != nil {
		fmt.Println("錯誤：", err)
	}
	fmt.Printf("Flush 後：%q\n", sb.String())
}

輸出

Flush 前：""
Flush 後："叫號：A01"

每次 Write 都直接寫到檔案或網路，代價很高。bufio.Writer 先把資料累積在記憶體裡（預設 4 KB），滿了才一次寫出去，大量的小寫入會快很多。代價是：還沒滿的資料會一直待在緩衝區裡，一定要在最後呼叫 Flush，並檢查它回傳的錯誤，不然最後一段資料就消失了。另外，用了 bufio.Writer 之後，所有的輸出都要經過它，直接寫到底層 Writer 的資料會「插隊」跑到前面，練習 6 就是這個 bug。

io.Copy

func copyDemo() {
	n, err := io.Copy(os.Stdout, strings.NewReader("整份菜單原封不動地複製過去\n"))
	fmt.Println(n, err)
}

輸出

整份菜單原封不動地複製過去
40 <nil>

io.Copy(dst, src) 把 Reader 的內容全部搬到 Writer，回傳搬了多少 byte。13 個中文字各 3 個 byte，加上換行，共 40 個。它內部會分批搬，不會把整個來源一次讀進記憶體，所以複製一個好幾 GB 的檔案也沒問題。檔案的讀寫在之後的「檔案與 I/O」那一章會細講。

常見錯誤

1. 沒有檢查 Scanner 的 Err

只寫 for sc.Scan() { … } 就結束，遇到太長的行或讀取錯誤時，程式會安靜地少讀資料，沒有任何訊息（第 6 節的 scanTooLong）。迴圈後面一定要接 if err := sc.Err(); err != nil。

2. 忘了 Flush，或繞過了 bufio.Writer

錯誤寫法：結尾直接寫到 w，會跑到最前面

func CallNumbers(w io.Writer, names []string) error {
	bw := bufio.NewWriter(w)
	for _, name := range names {
		fmt.Fprintf(bw, "請 %s 到櫃台\n", name)
	}
	fmt.Fprintln(w, "== 以上 ==")
	return bw.Flush()
}

正確寫法：所有輸出都經過 bw，最後 Flush 並回傳錯誤

func bufferedWriter() {
	var sb strings.Builder
	bw := bufio.NewWriter(&sb)
	fmt.Fprint(bw, "叫號：A01")
	fmt.Printf("Flush 前：%q\n", sb.String())
	if err := bw.Flush(); err != nil {
		fmt.Println("錯誤：", err)
	}
	fmt.Printf("Flush 後：%q\n", sb.String())
}

左邊是練習 6 的題目：名字還在 bw 的緩衝區裡排隊，「== 以上 ==」卻直接寫進了 w，所以最先出現。修法留給你。

3. 格式動詞和參數對不上

輸出裡出現 %!d(string=…)、%!d(MISSING)、%!(EXTRA …)，就是動詞和值不合、參數太少或太多（第 2 節）。執行 go vet，或讓編輯器幫你檢查。

4. 把提示和錯誤寫到 stdout

「請輸入…」「處理中…」「錯誤：…」這些訊息寫到 stdout，結果導到檔案或接到下一支程式時就會混在一起。給人看的訊息寫 os.Stderr，stdout 只放結果（第 5 節）。

5. String 方法裡印自己

在 String 裡寫 fmt.Sprintf("%v", s) 會無限遞迴。先轉成底層型別再印：int(s)（第 4.1 節）。

6. 出錯了卻回傳結束碼 0

只把錯誤印出來就讓 main 結束，shell 和 CI 會以為成功了。失敗時呼叫 os.Exit(1)（或其他非 0 的值），而且只在 main 裡呼叫。

重點回顧

  • 字首決定去向：Print 印到 stdout，Sprint 回傳字串，Fprint 寫到任何 io.Writer。
  • Println 一律補空白；Print 只在兩邊都不是字串時補；要控制格式就用 Printf。
  • %v 萬用，%+v 加欄位名，%#v 印 Go 語法，%T 印型別，%q 看得出字串裡藏了什麼。
  • 寬度靠右、- 靠左、0 補零、.n 是精度；fmt 用字元數補空白，中文會對不齊。
  • 有 String() string 方法的型別，fmt 會用它來印；String 裡要先轉成底層型別再印自己。
  • 結果寫 stdout，提示和錯誤寫 stderr；失敗時用 os.Exit(1) 回傳非 0 的結束碼。
  • 讀取的標準寫法：for sc.Scan()、sc.Text()、迴圈後檢查 sc.Err()。
  • Scanner 一行預設最多 64 KB，用 Buffer 放寬，上限要比最長一行再大一點。
  • 函式收 io.Reader 和 io.Writer，測試時就能用 strings.NewReader 和 strings.Builder 取代 stdin、stdout。
  • bufio.Writer 用完一定要 Flush 並檢查錯誤，而且所有輸出都要經過它。
