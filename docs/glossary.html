工具與專案

package
同一個目錄裡、開頭宣告同一個 package 名稱的 .go 檔案，是組織和匯入程式的單位。名稱大寫開頭的識別字才會匯出給其他 package 使用。→ 29 章 package 與 import
module
一組一起發佈、一起管理版本的 package，根目錄有一個 go.mod。import 路徑的開頭就是 module 的路徑。→ 00 章 建立第一個 module、29 章 go.mod 與 go.sum
go.mod、go.sum
go.mod 記錄 module 的路徑、Go 的版本和依賴的版本；go.sum 記錄依賴內容的雜湊，用來確認下載到的程式沒有被改過。兩個檔案都要 commit。→ 29 章 go.mod 與 go.sum
最小版本選擇（MVS）
Go 決定依賴版本的規則：每個 module 取所有 go.mod 要求裡最高的那個版本，而不是自動升到最新版。同樣的 go.mod，任何時候建置都得到同樣的版本。→ 29 章 版本與最小版本選擇
internal
路徑裡有 internal 這一段的 package，只能被 internal 上一層目錄底下的程式匯入，用來放不打算給外面用的程式。→ 29 章 internal 與 package 的設計
go.work
工作區檔案，讓本機的好幾個 module 一起開發，不用在 go.mod 裡寫 replace。→ 29 章 replace 與 go.work
init 函式
package 裡名稱是 init、沒有參數也沒有回傳值的函式，在 main 之前自動執行，不能被呼叫。一個 package 可以有好幾個。→ 29 章 初始化的順序
gofmt
Go 官方的格式化工具。縮排、空白、對齊都由它決定，所以每個人寫的 Go 程式碼看起來都一樣。→ 00 章 gofmt 與 go vet
go vet
檢查「編譯得過，但幾乎一定是錯的」寫法，例如 Printf 的動詞和參數對不上、複製了含有 Mutex 的值。→ 32 章 go vet
build tag
檔案開頭的 //go:build 條件，決定這個檔案在哪些平台或標籤下才編譯。檔名結尾是 _windows.go 這種寫法也有同樣的效果。→ 32 章 build tag 與檔名
交叉編譯
設定 GOOS、GOARCH 兩個環境變數，在一台電腦上編出其他作業系統或 CPU 的執行檔。→ 32 章 交叉編譯
編譯錯誤、執行時錯誤、邏輯錯誤
編譯錯誤讓程式根本跑不起來；執行時錯誤讓程式跑到一半停下來（Go 裡叫 panic）；邏輯錯誤最難找，程式正常結束，只是答案不對。→ 先修 1 三種錯誤

值與資料

零值
宣告了但沒有給值的變數，會是它型別的零值：數字是 0、字串是空字串、bool 是 false，指標、slice、map、channel、函式和 interface 是 nil。→ 01 章 零值
untyped 常數
沒有寫型別的常數，例如 const n = 10。用到的地方才決定型別，計算時的精度也比一般的變數高。→ 01 章 為什麼常數要分有沒有型別
iota
const 區塊裡的計數器，從 0 開始，每一行加 1，常用來定義一組列舉值。→ 01 章 常數與 iota
遮蔽（shadowing）
內層的作用域用 := 宣告了和外層同名的變數，之後改到的是內層那一個，外層的不受影響。→ 01 章 作用域與遮蔽、03 章 常見錯誤
slice
指向一段底層陣列的一扇窗，記著起點、長度和容量。複製 slice 只複製這扇窗，兩個 slice 看到的是同一份資料。→ 06 章 slice 是一扇窗
len、cap
len 是 slice 現在有幾個元素；cap 是從起點到底層陣列結尾還有幾格。append 超過 cap 時，才會配置一個新的陣列。→ 06 章 append
nil slice
slice 的零值，len 和 cap 都是 0，可以直接 append 和 range。和空 slice 幾乎可以互換，平常只有和 nil 比較、用 %#v 印出時看得出差別；判斷是不是空的，用 len(s) == 0。→ 06 章 nil slice 與空 slice
map
key 對應到 value 的雜湊表。讀不存在的 key 會得到零值；走訪的順序每次都可能不同。→ 07 章 建立與基本操作
comma-ok
第二個回傳值是 bool 的慣用寫法：v, ok := m[k]。用在 map 讀取、type assertion，以及從可能已經關閉的 channel 收值。→ 07 章 讀取：零值與 comma-ok
byte、rune、UTF-8
Go 的字串是一串 byte，內容通常是 UTF-8，常用的中文字一個佔 3 個 byte。rune 是一個 Unicode 碼位（int32 的別名），range 字串時一次拿到一個 rune。→ 08 章 UTF-8：byte 與 rune
Stringer
有 String() string 方法的型別。fmt 印它的時候，會改用這個方法回傳的文字。→ 02 章 Stringer
指標
存著另一個變數位址的值。*T 是指向 T 的指標型別，&x 取得 x 的位址，*p 讀寫 p 指向的值。→ 05 章 位址與指標
逃逸分析
編譯器判斷一個值能不能放在 stack 上；函式結束後還會被用到的值，會「逃逸」到 heap，由 GC 回收。用 -gcflags=-m 可以看到它的決定。→ 05 章 -gcflags=-m、31 章 逃逸分析

函式、型別與錯誤

closure
用到外層變數的函式值。它捕獲的是變數本身，不是當下的值；外層的變數之後改了，它看到的也會跟著變。→ 04 章 closure
defer
讓一個呼叫在函式結束時才執行，常用來關檔、解鎖。參數在 defer 那一行就先算好；好幾個 defer 由後往前執行。→ 04 章 defer
panic、recover
panic 讓目前的 goroutine 停下正常的流程，一路執行 defer 往上退；在 defer 的函式裡呼叫 recover 可以接住它。預期中的錯誤要用 error 回傳，不用 panic。→ 04 章 panic 與 recover、11 章 什麼時候用 panic
receiver
方法名稱前面的那個參數，決定方法屬於哪個型別。值 receiver 拿到的是複本；要修改欄位就用指標 receiver。→ 09 章 方法與 receiver
method set
一個型別擁有的方法，決定它能不能滿足某個 interface。T 的 method set 只有值 receiver 的方法，*T 則兩種都有。→ 09 章 method set
嵌入
在 struct 裡只寫型別、不寫欄位名稱，外層就能直接使用它的欄位和方法。這是組合，不是繼承：方法收到的 receiver 仍然是裡面那一個。→ 09 章 嵌入
struct tag
欄位後面用反引號寫的字串，例如 `json:"name"`，給 encoding/json 這類套件讀取，改變它們處理這個欄位的方式。→ 09 章 struct tag、23 章 名稱與省略
interface
一份方法清單。任何型別只要有這些方法，就自動滿足它，不需要宣告「我實作了它」。→ 10 章 interface 是一份方法清單
any
interface{} 的別名，可以裝任何值；取出來時要用 type assertion 或 type switch。→ 10 章 type switch 與 any
type assertion
從 interface 值取出具體型別：v, ok := x.(T)。不帶 ok 的寫法，型別不對時會 panic。→ 10 章 type assertion
type switch
依 interface 值的具體型別走不同的分支：switch v := x.(type)。→ 10 章 type switch 與 any
nil interface 陷阱
interface 值同時記著型別和值；裝著 nil 指標的 interface 有型別，所以不等於 nil。函式沒有錯誤時，要直接回傳 nil。→ 10 章 nil interface 陷阱
泛型、型別參數
函式或型別在名稱後面用方括號宣告型別參數，例如 func Max[T cmp.Ordered](a, b T) T，同一份程式碼可以用在不同的型別上。→ 12 章 型別參數與限制
限制、型別集合
型別參數的限制本身是一個 interface，描述哪些型別可以用。~int 表示「底層型別是 int 的所有型別」。→ 12 章 型別集合與 ~
comparable
能用 == 和 != 比較的型別都滿足這個限制。map 的 key 必須是 comparable 的型別，slice、map、函式都不是。→ 07 章 key 的型別
疊代器（iter.Seq）
形如 func(yield func(V) bool) 的函式，可以直接寫在 for range 後面。yield 回傳 false 表示迴圈提早結束，疊代器就要停下來。→ 13 章 range 一個函式、13 章 yield 的約定
error
只有 Error() string 一個方法的 interface。Go 用回傳值表示失敗，呼叫的人檢查 err != nil。→ 11 章 錯誤是一個值
sentinel error
事先宣告好、用 errors.Is 比對的錯誤值，例如 io.EOF。→ 11 章 sentinel error
錯誤鏈（%w）
fmt.Errorf 用 %w 包裝錯誤，加上脈絡，同時保留原本的錯誤；errors.Is 和 errors.As 會沿著這條鏈往下找。→ 11 章 包裝：%w 與錯誤鏈
errors.As、errors.AsType
在錯誤鏈裡找某個型別的錯誤並取出來。AsType（Go 1.26 起）是泛型的版本，不用先宣告一個變數。→ 11 章 自訂錯誤型別

並行

goroutine
由 Go runtime 管理的輕量執行單位，用 go f() 啟動。stack 從幾 KB 開始、不夠時自動長大，同時開上萬個也沒問題。→ 14 章 go 敘述、14 章 goroutine 很便宜
並行與平行
並行（concurrency）是程式的結構：同時處理好幾件事；平行（parallelism）是執行的方式：同一瞬間真的有好幾個 CPU 在跑。並行的程式在單核心上也能執行。→ 14 章 排程器：並行與平行
G、M、P
Go 排程器的三個角色：G 是 goroutine，M 是作業系統的執行緒，P 是執行 Go 程式碼需要的資源；P 的數量就是 GOMAXPROCS。→ 14 章 G、M、P
WaitGroup
等一群 goroutine 都結束。wg.Go(f)（Go 1.25 起）開一個 goroutine 並計數，wg.Wait() 等到全部做完。→ 14 章 sync.WaitGroup
channel
goroutine 之間傳值的管道。無緩衝的 channel，送和收的兩邊都準備好才會完成；有緩衝的可以先放幾個值。→ 15 章 無緩衝的 channel、15 章 有緩衝的 channel
close
送的一方表示「不會再送了」。收的一方的 range 會在 channel 關閉、值都收完之後結束。只有送的一方該 close，close 兩次會 panic。→ 15 章 close 與 range
select
同時等好幾個 channel 的送或收，哪一個先準備好就執行哪一個；好幾個同時準備好時，隨機挑一個。→ 16 章 同時等好幾個 channel
死結
每個 goroutine 都在等別人，誰都動不了。所有 goroutine 都卡住時，runtime 會印出 all goroutines are asleep - deadlock! 並結束程式。→ 15 章 死結與洩漏
goroutine 洩漏
goroutine 卡在永遠等不到的 channel 或鎖上，一直不會結束，也一直佔著記憶體。→ 15 章 死結與洩漏、14 章 常見錯誤
data race
兩個 goroutine 同時存取同一個變數，至少一個是寫，而且沒有同步。結果無法預測；go test -race 能抓到實際執行時發生的 race。→ 17 章 data race
Mutex、RWMutex
Mutex 是互斥鎖，Lock 和 Unlock 之間同時只有一個 goroutine 能進去。RWMutex 允許好幾個讀的人同時進去，寫的人則獨佔。→ 17 章 Mutex、17 章 RWMutex
atomic
sync/atomic 的型別（例如 atomic.Int64）用不可分割的指令讀寫，適合計數器、旗標這種單一的變數。→ 17 章 atomic
happens-before
記憶體模型描述「保證先發生，而且結果看得到」的關係。同一個 goroutine 裡照程式的順序；不同 goroutine 之間，只有 channel 的送收、鎖、WaitGroup 這類同步操作能建立它。→ 17 章 happens-before
context
在函式之間傳遞取消的訊號、期限，以及少量和這個請求有關的資料。習慣上是函式的第一個參數，名稱叫 ctx。→ 18 章 為什麼需要 context
取消樹
從一個 context 衍生出來的子 context，會跟著它一起被取消；子 context 被取消，則不會影響上層。→ 18 章 取消樹
worker pool
固定數量的 goroutine 從同一個 channel 拿工作，限制同時進行的工作量。→ 19 章 worker pool
semaphore
限制同時進行的數量。常用有緩衝的 channel 實作：送進去算佔用一個名額，收出來算還回去。→ 19 章 semaphore
fan-out、fan-in
fan-out 是把工作分給好幾個 goroutine；fan-in 是把好幾個 channel 的結果合成一個。→ 15 章 fan-out 與 fan-in
管線
一站接一站的 goroutine，用 channel 把上一站的輸出交給下一站。→ 15 章 管線、19 章 可以取消的管線
synctest
testing/synctest（Go 1.25 起）讓測試在一個「泡泡」裡執行，泡泡裡的時間是假的：所有 goroutine 都在等的時候，時間直接跳到下一個計時器。→ 30 章 時間與並行的測試

標準庫與服務

io.Reader、io.Writer
各只有一個方法（Read、Write）的 interface。檔案、網路連線、壓縮、記憶體裡的緩衝區都實作它們，所以可以像水管一樣接在一起。→ 02 章 io.Reader 與 io.Writer、20 章 串流
bufio
在 Reader、Writer 外面加一層緩衝。Scanner 一行一行讀，結束後要檢查 Err；bufio.Writer 寫完要 Flush。→ 02 章 bufio.Scanner
os.Root
（Go 1.24 起）把開檔限制在某個目錄裡，路徑裡的 .. 或符號連結都跑不出去，適合處理使用者給的檔名。→ 20 章 路徑與 os.Root
embed
用 //go:embed 在編譯時把檔案放進執行檔，執行時就不用再帶著那些檔案。→ 20 章 fs.FS 與 embed
flag
解析命令列旗標的套件，例如 -top 10。→ 21 章 flag 套件
結束碼（exit code）
程式結束時交給作業系統的數字：0 表示成功，其他表示失敗。shell 腳本和 CI 靠它判斷結果。→ 21 章 結束碼與 stderr
time.Duration
兩個時間點之間的長度，內部是奈秒的整數。寫成 5 * time.Second 才清楚，直接寫 5 是 5 奈秒。→ 22 章 Time 與 Duration
版面（layout）
Go 用一個參考時間 2006 年 1 月 2 日 15:04:05 的樣子描述格式，例如 2006-01-02，而不是 YYYY-MM-DD。→ 22 章 格式化與解析
單調時鐘
time.Now() 除了日期時間，還帶著一個只會往前走的讀數。兩個 Time 相減或比較時用它，系統時間被調整也不受影響。→ 22 章 比較、單調時鐘與 Unix 時間
encoding/json/v2
這本手冊使用的 JSON 套件。和舊的 encoding/json 比，欄位名稱預設分大小寫比對、nil slice 輸出成 []，map 的輸出順序也不固定。→ 23 章 Marshal 與 Unmarshal、23 章 現有程式碼裡的 encoding/json
omitzero
struct tag 的選項：欄位是零值（或它的 IsZero 方法回傳 true）時就不輸出。→ 23 章 名稱與省略
RE2
Go 的 regexp 採用的語法和比對方式，保證比對時間和輸入的長度成正比；代價是不支援往回參照和環視（lookahead）。→ 24 章 為什麼 Go 不支援 lookahead
html/template
用法和 text/template 一樣，但會依照內容出現在 HTML 的位置自動跳脫，使用者的輸入不會變成網頁上的程式碼（XSS）。→ 24 章 html/template
slog
log/slog，結構化的日誌：一則訊息加上 key-value 的屬性，可以輸出成文字或 JSON，方便用欄位查詢。→ 25 章 slog
Handler（HTTP）
有 ServeHTTP(ResponseWriter, *Request) 方法的 interface，每一個 HTTP 請求都交給一個 Handler 處理。→ 26 章 Handler 與 ResponseWriter
ServeMux
HTTP 的路由器，依方法和路徑把請求交給對應的 Handler；Go 1.22 起，路徑裡可以有 {id} 這種萬用字元。→ 26 章 ServeMux 的路由
middleware
包住 Handler 的 Handler，在請求的前後做共同的事，例如記錄 log、接住 panic、檢查身分。→ 26 章 middleware
優雅關機
停止接受新的請求，等進行中的做完再結束。http.Server 用 Shutdown 做這件事。→ 26 章 優雅關機、專題 6 關機
RoundTripper
http.Client 實際送出請求的那一層。換成自己的實作，就能在測試裡不碰網路。→ 27 章 RoundTripper
連線池
重複使用已經建立好的連線。http.Client（實際上是它的 Transport）和 database/sql 的 DB 都有，所以它們都應該建立一次、一直重複使用。→ 27 章 關掉 body 與連線池、28 章 連線池與 context
SQL injection、placeholder
把使用者的輸入直接拼進 SQL 字串，對方就能改掉整句 SQL。用 ? 這種佔位符號把值另外交給資料庫，值就不會被當成 SQL。→ 28 章 參數與 SQL injection
交易
一組要嘛全部生效、要嘛全部不算的資料庫操作：Begin 開始，Commit 確定，Rollback 取消。→ 28 章 交易

測試與效能

table-driven test
把輸入和預期的結果列成一張表，用迴圈逐一測試；每一列通常用 t.Run 跑成一個子測試。→ 30 章 table-driven 與子測試
測試替身
在測試裡代替真的依賴（網路、資料庫、時間）的東西。fake 是能用的簡化實作，是這本手冊最常用的一種。→ 30 章 測試替身
golden file
把預期的完整輸出存成 testdata 裡的檔案，測試時逐字比對；輸出改了就用 -update 重新產生，再檢查差異。→ 30 章 golden file 與 testdata
Example 函式
名稱以 Example 開頭、最後有 // Output: 註解的函式。go test 會比對它的輸出，pkg.go.dev 也會把它當成範例顯示在文件裡。→ 30 章 Example、覆蓋率與 benchmark
fuzz
go test -fuzz 自動產生大量的輸入，找出讓程式出錯的情況；找到的輸入存進 testdata/fuzz，成為之後的回歸測試。→ 30 章 fuzz
覆蓋率
測試執行到了哪些程式碼，用 go test -cover 查看。執行到不代表測對了。→ 30 章 Example、覆蓋率與 benchmark
benchmark
名稱以 Benchmark 開頭的函式，用 go test -bench 執行，量出每次操作的時間和配置次數。Go 1.24 起用 b.Loop() 寫迴圈。→ 31 章 先確認正確，再量測
pprof
Go 內建的效能分析工具，看 CPU 時間和記憶體配置花在哪些函式上。→ 31 章 用 pprof 找出瓶頸
配置（allocation）
