map

1. 建立與基本操作

map 把 key 對應到 value，型別寫成 map[K]V：map[string]int 是「用字串查整數」，例如品名查價格。可以用字面值建立：

func mapBasics() {
	menu := map[string]int{
		"排骨": 85,
		"雞腿": 90,
	}
	menu["素食"] = 70 // 新增
	menu["排骨"] = 95 // key 已經存在：覆寫
	delete(menu, "雞腿")
	delete(menu, "魚排") // 刪除不存在的 key，什麼都不會發生
	fmt.Println(menu, len(menu))
	fmt.Println(menu["排骨"])
}

輸出

map[排骨:95 素食:70] 2
95
  • m[k] = v：key 不存在就新增，存在就覆寫。map 裡同一個 key 只會有一份。
  • delete(m, k)：刪除 key；key 不存在時什麼都不做，不會出錯。
  • len(m)：目前有幾個 key。map 沒有 cap。
  • 多行的字面值，每一行最後都要有逗號，包括最後一行。
  • fmt.Println 印 map 時會把 key 排序，方便閱讀和測試；這不代表 map 本身有順序（第 3 節）。

make 與 nil map

func makeMap() {
	stock := make(map[string]int)
	stock["排骨"] = 10
	stock["雞腿"] = 6
	fmt.Println(stock, len(stock))
}

func nilMap() {
	var stock map[string]int
	fmt.Println(stock == nil, len(stock), stock["排骨"])
	defer func() {
		fmt.Println("panic:", recover())
	}()
	stock["排骨"] = 10
}

輸出

map[排骨:10 雞腿:6] 2
true 0 0
panic: assignment to entry in nil map

map 的零值是 nil。nil map 可以讀（讀到零值）、可以取長度、可以 range（一圈都不跑），但寫入會 panic。這和 nil slice 可以直接 append 不同，是新手很常踩到的坑：宣告了 var m map[string]int 卻忘了 make。要放資料的 map，一定先用 make(map[K]V) 或字面值 map[K]V{} 建立。struct 裡的 map 欄位也一樣，零值是 nil，要在建構函式裡初始化（第 09 章）。

2. 讀取：零值與 comma-ok

func commaOK() {
	stock := map[string]int{"排骨": 0, "雞腿": 3}
	fmt.Println(stock["排骨"], stock["魚排"]) // 都是 0，分不出來

	n, ok := stock["排骨"]
	fmt.Println(n, ok)
	n, ok = stock["魚排"]
	fmt.Println(n, ok)

	if _, ok := stock["雞腿"]; ok {
		fmt.Println("有賣雞腿")
	}
}

輸出

0 0
0 true
0 false
有賣雞腿

讀取不存在的 key，Go 不會丟例外，也不會回傳 nil，而是回傳值型別的零值。這在多數情況下很方便，但也代表 stock["排骨"] 和 stock["魚排"] 都是 0 時分不出來：排骨是賣完了，魚排是根本沒賣。

這時用兩個變數接收：n, ok := m[k]，第二個值 ok 是 bool，表示 key 存不存在。這個寫法叫 comma-ok，之後的 type assertion（第 10 章）和從 channel 接收（第 15 章）也會用到。只想知道存不存在時，搭配 if 的初始化敘述：if _, ok := m[k]; ok { … }。

利用零值：計數

func countOrders() {
	orders := []string{"排骨", "雞腿", "排骨", "素食", "排骨"}
	counts := make(map[string]int)
	for _, o := range orders {
		counts[o]++
	}
	fmt.Println(counts)
}

輸出

map[排骨:3 素食:1 雞腿:1]

counts[o]++ 第一次遇到某個品項時，讀到的是 0，加一後存回去；不需要先檢查 key 存不存在。在 Java 裡要寫 getOrDefault 或 merge，在 Go 零值就幫你處理好了。

利用零值：分組

func groupOrders() {
	type order struct {
		table int
		item  string
	}
	orders := []order{{1, "排骨"}, {3, "雞腿"}, {1, "素食"}, {2, "排骨"}, {3, "滷蛋"}}
	byTable := make(map[int][]string)
	for _, o := range orders {
		byTable[o.table] = append(byTable[o.table], o.item)
	}
	fmt.Println(byTable)
	fmt.Println(byTable[1], len(byTable[9]))
}

輸出

map[1:[排骨 素食] 2:[排骨] 3:[雞腿 滷蛋]]
[排骨 素食] 0

值是 slice 時，不存在的 key 讀到 nil slice，而 nil slice 可以直接 append（第 06 章），所以分組也只要一行。注意 append 的結果要存回 map：byTable[o.table] = append(byTable[o.table], …)。最後一行顯示，讀不存在的桌號只會得到長度 0 的 nil slice，不會出錯。

3. 走訪與刪除

func rangeMap() {
	menu := map[string]int{"排骨": 85, "雞腿": 90, "素食": 70}
	total := 0
	for _, price := range menu {
		total += price
	}
	fmt.Println(total)
}

輸出

245

for k, v := range m 走過每一組 key 和 value，只要 key 時寫 for k := range m。走訪的順序沒有定義，而且 Go 的 runtime 會刻意打亂，讓同一個程式每次執行的順序都可能不同。這是為了逼你不要依賴順序：如果某個版本剛好有固定順序，程式就會在不知不覺中依賴它，換版本時才出問題。所以這個範例只做加總，和順序無關。

固定順序：先排序 key

func sortedRange() {
	menu := map[string]int{"排骨": 85, "雞腿": 90, "素食": 70, "魚排": 100}
	for _, name := range slices.Sorted(maps.Keys(menu)) {
		fmt.Println(name, menu[name])
	}

	// Go 1.23 以前的寫法：自己收集 key 再排序
	names := make([]string, 0, len(menu))
	for name := range menu {
		names = append(names, name)
	}
	slices.Sort(names)
	fmt.Println(names)
}

輸出

排骨 85
素食 70
雞腿 90
魚排 100
[排骨 素食 雞腿 魚排]

Go 1.23 起，maps.Keys(m) 回傳一個疊代器，slices.Sorted 把它收集成排好序的 slice，一行就完成。疊代器在第 13 章介紹，現在只要記得這個組合。舊的程式碼常見下半段的寫法：自己 range 收集 key，再排序。中文字串的排序依照 UTF-8 的 byte 順序，不是筆畫或注音，所以「排骨」排在「雞腿」前面只是編碼的結果。

依照值排序

func sortByValue() {
	sold := map[string]int{"排骨": 12, "雞腿": 30, "素食": 12, "魚排": 7}
	names := slices.Collect(maps.Keys(sold))
	slices.SortFunc(names, func(a, b string) int {
		return cmp.Or(
			cmp.Compare(sold[b], sold[a]), // 賣得多的排前面
			cmp.Compare(a, b),
		)
	})
	for _, name := range names {
		fmt.Println(name, sold[name])
	}
}

輸出

雞腿 30
排骨 12
素食 12
魚排 7

map 本身不能排序，排序的永遠是從 map 取出來的 key。比較函式查 sold[a] 和 sold[b] 來比較銷量。排骨和素食都賣了 12 個，如果只比銷量，兩者的先後就取決於 map 的走訪順序，每次執行可能不同；cmp.Or 回傳第一個不是 0 的比較結果，銷量相同時再比名稱，結果才會固定。

在 range 裡刪除

func deleteWhileRange() {
	stock := map[string]int{"排骨": 0, "雞腿": 3, "素食": 0, "魚排": 5}
	for name, n := range stock {
		if n == 0 {
			delete(stock, name)
		}
	}
	fmt.Println(stock)

	maps.DeleteFunc(stock, func(name string, n int) bool { return n < 4 })
	fmt.Println(stock)

	clear(stock)
	fmt.Println(stock, len(stock))
}

輸出

map[雞腿:3 魚排:5]
map[魚排:5]
map[] 0

規格明確保證：走訪時刪除還沒走到的 key，它就不會被走到；刪除目前的 key 也是安全的。所以「把賣完的品項刪掉」可以直接在 range 裡做。maps.DeleteFunc 是同一件事的簡寫，條件成立的就刪除。clear(m)（Go 1.21 起的內建函式）一次刪除所有 key，map 本身還在，可以繼續使用。

反過來，在走訪時新增 key，新的 key 可能被走到、也可能不會，規格不保證。需要邊走邊新增時，先把要新增的收集起來，走完再加。

4. key 的型別

key 的型別必須可以用 == 比較，因為 map 要判斷兩個 key 是不是同一個。可以當 key 的：數字、字串、bool、指標、channel、陣列，以及欄位全都可以比較的 struct。不能當 key 的：slice、map、函式。

package main

import "fmt"

func main() {
	combos := map[[]string]int{}
	fmt.Println(len(combos))
}

編譯錯誤

./main.go:6:16: invalid map key type []string

struct 和陣列當 key

type seat struct {
	row, col int
}

func structKey() {
	booked := map[seat]string{
		{1, 2}: "小明",
		{3, 4}: "小華",
	}
	fmt.Println(booked[seat{1, 2}], len(booked))
	_, taken := booked[seat{2, 2}]
	fmt.Println(taken)

	trips := make(map[[2]string]int) // 起點和終點組成的路段
	trips[[2]string{"甲站", "乙站"}]++
	trips[[2]string{"甲站", "乙站"}]++
	trips[[2]string{"乙站", "甲站"}]++
	fmt.Println(trips[[2]string{"甲站", "乙站"}], len(trips))
}

輸出

小明 2
false
2 2

需要用「好幾個值的組合」當 key 時，不必把它們拼成字串（例如 "1,2"），直接用 struct：座位的列和行、日期和分店、起點和終點。兩個 struct 的每個欄位都相等，就是同一個 key。陣列也一樣，[2]string{"甲站", "乙站"} 和 [2]string{"乙站", "甲站"} 是不同的 key。在字面值裡，key 的型別名稱可以省略，直接寫 {1, 2}。

4.1 NaN 當 key

func nanKey() {
	m := make(map[float64]string)
	m[math.NaN()] = "a"
	m[math.NaN()] = "b"
	_, ok := m[math.NaN()]
	fmt.Println(len(m), ok)
}

輸出

2 false

浮點數的 NaN（Not a Number）不等於任何值，包括它自己（第 01 章的浮點數）。所以每次用 NaN 寫入都會新增一個 key，而且用 NaN 永遠查不到。這些 key 只能靠 range 走訪或 clear 清掉。實務上避免用浮點數當 key：金額用整數的「分」，座標轉成整數格子。

另外，key 的型別是 interface（例如 map[any]int）時，編譯器沒辦法事先檢查，放進一個 slice 當 key 會在執行時 panic。interface 在第 10 章。

5. 值是 struct

map 的值是 struct 時，直接修改欄位是編譯錯誤：

package main

import "fmt"

type item struct {
	price int
	stock int
}

func main() {
	menu := map[string]item{"排骨": {price: 85, stock: 10}}
	menu["排骨"].stock--
	fmt.Println(menu)
}

編譯錯誤

./main.go:12:2: cannot assign to struct field menu["排骨"].stock in map

原因和第 05 章「不能取 map 元素的位址」一樣：map 長大時會把資料搬到新的位置，map 裡的元素沒有固定的位址，也就沒有辦法「就地」修改它的某個欄位。有兩種解法：

type item struct {
	price int
	stock int
}

func structValue() {
	menu := map[string]item{"排骨": {price: 85, stock: 10}}
	it := menu["排骨"] // 拿到的是複本
	it.stock--
	fmt.Println(menu["排骨"].stock, it.stock)
	menu["排骨"] = it // 放回去
	fmt.Println(menu["排骨"].stock)
}

輸出

10 9
9

第一種：拿出來、改完、放回去。it := menu["排骨"] 是複本，只改 it 的時候 map 裡還是 10；存回去之後才變成 9。練習 4 就是忘了存回去的 bug。

func pointerValue() {
	menu := map[string]*item{"排骨": {price: 85, stock: 10}}
	menu["排骨"].stock--
	fmt.Println(menu["排骨"].stock)

	if it, ok := menu["魚排"]; ok {
		it.stock--
	} else {
		fmt.Println("沒有魚排", it == nil)
	}
}

輸出

9
沒有魚排 true

第二種：值改成指標 map[string]*item。map 裡存的是位址，menu["排骨"] 拿到指標，透過指標修改的是同一個 item。代價是 key 不存在時讀到的是 nil 指標，直接 menu["魚排"].stock-- 會 panic，所以要先用 comma-ok 檢查。struct 小、偶爾修改時用第一種；struct 大、經常修改，或其他地方也要共用同一個 item 時用第二種。

6. map 是參考

func raisePrices(menu map[string]int, n int) {
	for name := range menu {
		menu[name] += n
	}
}

func mapIsReference() {
	menu := map[string]int{"排骨": 85, "雞腿": 90}
	alias := menu
	alias["素食"] = 70
	fmt.Println(len(menu))

	raisePrices(menu, 5)
	fmt.Println(menu)

	snapshot := maps.Clone(menu)
	snapshot["排骨"] = 0
	fmt.Println(menu["排骨"], snapshot["排骨"])
	fmt.Println(maps.Equal(menu, snapshot))
}

輸出

3
map[排骨:90 素食:75 雞腿:95]
90 0
false

map 變數裡存的其實是一個指向內部資料結構的指標，所以：

  • alias := menu 之後，從 alias 新增的素食，menu 也看得到。
  • 把 map 傳給函式，函式裡的新增、修改、刪除，呼叫端都看得到。不需要傳 *map[K]V。這和 slice 不同：slice 的 append 呼叫端看不到，map 的新增看得到。
  • 要一份獨立的複本就用 maps.Clone。它是淺複製：值如果是指標或 slice，複本和原本還是共用那些資料（第 05 章）。
  • map 不能用 == 比較（只能和 nil 比），比較內容用 maps.Equal。

這也代表：把內部的 map 直接回傳給呼叫端，呼叫端就能改到你的資料。需要保護內部狀態時，回傳 maps.Clone 的結果。

7. 當成集合

func mapAsSet() {
	soldOut := map[string]struct{}{} // struct{} 不佔空間，只用來表示「有這個 key」
	soldOut["雞腿"] = struct{}{}
	soldOut["魚排"] = struct{}{}
	_, out := soldOut["雞腿"]
	fmt.Println(out, len(soldOut))
	fmt.Println(slices.Sorted(maps.Keys(soldOut)))

	seen := make(map[string]bool) // 用 bool 寫起來比較直覺：不存在的 key 讀到 false
	var dup []string
	for _, t := range []string{"A01", "A02", "A01", "A03", "A02"} {
		if seen[t] {
			dup = append(dup, t)
		}
		seen[t] = true
	}
	fmt.Println(dup)
}

輸出

true 2
[雞腿 魚排]
[A01 A02]

Go 沒有內建的 set，用 map 的 key 代替：只在乎 key 在不在，值不重要。常見兩種寫法：

  • map[string]struct{}：struct{} 是沒有欄位的 struct，大小是 0，不佔額外空間。缺點是寫起來囉唆，判斷要用 comma-ok。
  • map[string]bool：多花一個 byte，但不存在的 key 讀到 false，可以直接寫 if seen[t]，比較好讀。

資料量不大時，選好讀的 map[string]bool 就好。集合的典型用途：找重複（上面的號碼牌）、去除重複、求交集和差集（練習 6）。

8. 預先配置與並行

func buildIndex(names []string) map[string]int {
	idx := make(map[string]int, len(names))
	for i, name := range names {
		idx[name] = i
	}
	return idx
}

func indexByName() {
	idx := buildIndex([]string{"排骨", "雞腿", "素食"})
	fmt.Println(idx["素食"], len(idx))
}

輸出

2 3

make(map[K]V, n) 的第二個參數是「大概會放幾個 key」的提示。map 放滿時要擴充，把所有資料重新安排一次，和 slice 的 append 換陣列類似。事先知道數量時給這個提示，就能省掉中間的擴充。它只是提示，放超過 n 個也沒問題，len 一開始還是 0。

map 不能同時寫

map 不是並行安全的：一個 goroutine 在寫入時，其他 goroutine 不能同時讀或寫同一個 map。chapters/07-maps/concurrent 讓兩個 goroutine 同時寫入（goroutine 在第 14 章）：

func main() {
	counts := make(map[int]int)
	var wg sync.WaitGroup
	for g := range 2 {
		wg.Go(func() {
			for i := range 1_000_000 {
				counts[i%100] = g
			}
		})
	}
	wg.Wait()
	fmt.Println("沒有被偵測到，這次運氣好", len(counts))
}
go run ./chapters/07-maps/concurrent

輸出（後面的 goroutine 堆疊省略）

fatal error: concurrent map writes

goroutine 19 [running]:
…
exit status 2

runtime 偵測到時會直接結束程式。注意這是 fatal error，不是 panic，recover 接不住。偵測是盡力而為的，沒被偵測到不代表沒問題，資料可能已經壞掉了。需要在多個 goroutine 之間共用 map 時，用 sync.Mutex 保護它，或改用 sync.Map（第 17 章）；測試時加上 -race，執行過程中實際發生的這類衝突都會被回報。

8.1 map 裡面長什麼樣子

map 是一個雜湊表（hash table）：用 key 算出一個雜湊值，依照雜湊值決定資料放在哪一群格子裡，所以查詢、新增、刪除的平均成本都是常數時間，不會隨資料量變慢。資料太滿時會配置更大的表，重新安排所有資料，這就是元素沒有固定位址的原因。

Go 1.24 起，內建 map 改用一種叫 Swiss Tables 的設計，整體效能比以前好。這是 runtime 內部的改變，程式的寫法完全不受影響；也正因為 Go 沒有保證走訪順序，才能這樣替換實作。

常見錯誤

1. 寫入 nil map

錯誤訊息是 assignment to entry in nil map（第 1 節）。最常見的情況是 struct 裡有 map 欄位，卻沒有初始化。寫入前確認 map 已經用 make 或字面值建立。

2. 用讀到的值判斷 key 存不存在

if stock["魚排"] == 0 分不出「沒有這個品項」和「庫存是 0」。需要分辨時用 comma-ok：n, ok := stock["魚排"]。

3. 依賴走訪順序

直接 range map 產生輸出、測試期望值或 API 回應，順序每次都可能不同，結果就是時好時壞的測試。需要固定順序就先排序 key（第 3 節），練習 5 就是這個 bug。依照值排序時，值相同的要再比 key，順序才會固定。

4. 改了 struct 的複本卻沒存回去

it := m[k]; it.stock-- 只改到複本（第 5 節）。改完要 m[k] = it，或者改用 map[K]*V。

5. 以為指定會複製 map

backup := menu 不是備份，兩個變數是同一份資料（第 6 節）。要備份用 maps.Clone(menu)。

6. 多個 goroutine 同時讀寫

會造成 fatal error: concurrent map writes，或是更糟的，沒被偵測到的資料損毀（第 8 節）。用 mutex 保護，並在測試加上 -race。

重點回顧

  • m[k] = v 新增或覆寫，delete(m, k) 刪除，len(m) 是 key 的個數。
  • nil map 可以讀、不能寫；要放資料先 make 或用字面值建立。
  • 讀不存在的 key 得到零值；要分辨存不存在用 v, ok := m[k]。
  • 零值讓計數 m[k]++ 和分組 m[k] = append(m[k], v) 都只要一行。
  • 走訪順序不固定；要固定順序就 slices.Sorted(maps.Keys(m))，依值排序時平手要再比 key。
  • 在 range 裡刪除是安全的；clear(m) 清空，maps.DeleteFunc 依條件刪除。
  • key 必須可以用 == 比較；多個值的組合用 struct 當 key。
  • 不能直接改 map 裡 struct 的欄位：拿出來改完存回去，或用指標當值。
  • map 是參考，指定和傳參數都共用資料；複本用 maps.Clone，比較用 maps.Equal。
  • 集合用 map[T]bool 或 map[T]struct{}。
  • 知道數量時 make(map[K]V, n)；多個 goroutine 共用 map 要加鎖。
