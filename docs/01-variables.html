1. 宣告變數

Go 是靜態型別語言：每個變數在編譯時就有固定的型別，放錯型別的值會直接編譯失敗。宣告變數有兩種寫法，第一種是 var：

func declareVar() {
	var price int = 85 // 名稱、型別、初始值都寫出來
	var qty = 3        // 省略型別，由右邊的值推斷成 int
	var paid bool      // 省略初始值，得到零值 false
	fmt.Println(price, qty, paid)
}

輸出

85 3 false

三種寫法差在寫出多少資訊。型別寫在名稱後面，和 C、Java 相反，讀起來就是「變數 price，型別 int，值是 85」。有給初始值時可以省略型別，編譯器會從右邊的值推斷；沒給初始值時，變數會是那個型別的零值（第 2 節）。

第二種是在函式裡最常用的簡短宣告 :=，它同時做「宣告」和「指定」，型別一律推斷：

func declareShort() {
	item := "排骨便當"
	price := 85
	price = 90 // 之後要改值用 =，不是 :=
	fmt.Println(item, price)
}

輸出

排骨便當 90

記住一個分工：:= 是建立新變數，= 是修改已經存在的變數。第三行要改價錢，用的是 =。

一次宣告好幾個

func declareMulti() {
	var (
		opens  = 10
		closes = 20
	)
	name, qty := "雞腿便當", 2
	fmt.Println(opens, closes, name, qty)

	first, second := "A01", "A02"
	first, second = second, first // 右邊先全部算好，再一起指定，不需要暫存變數
	fmt.Println(first, second)
}

輸出

10 20 雞腿便當 2
A02 A01

var ( … ) 把相關的宣告放成一組，常用在套件層級。first, second = second, first 是 Go 交換兩個變數的慣用寫法：右邊的值會先全部算好，再一起指定給左邊，所以不需要暫存變數。

:= 左邊只要有一個新變數

函式常常同時回傳結果和錯誤（第 04 章）。連續呼叫好幾個這種函式時，每次都要接一個 err。:= 的規則是：左邊至少要有一個新變數，已經存在的變數就只是被重新指定：

func redeclare() {
	price, err := strconv.Atoi("85")
	fmt.Println(price, err)
	qty, err := strconv.Atoi("三") // qty 是新的，err 沿用上面那一個
	fmt.Println(qty, err)
}

輸出

85 <nil>
0 strconv.Atoi: parsing "三": invalid syntax

第二個 := 的 qty 是新的，err 沿用第一行宣告的那一個。strconv.Atoi 把字串轉成整數，第 5 節會再看到它。如果左邊全部都是舊變數，編譯器會報 no new variables on left side of :=（常見錯誤 2）。

推斷出來的型別

func typeInference() {
	a := 85
	b := 85.0
	c := 'A'
	d := "A"
	e := true
	fmt.Printf("%T %T %T %T %T\n", a, b, c, d, e)
}

輸出

int float64 int32 string bool

整數推斷成 int，有小數點就是 float64，單引號的字元是 int32（也就是 rune，代表一個 Unicode 字元，第 08 章細講）。想要其他型別，例如 int64 或 float32，就要用 var x int64 = 85 明寫。

套件層級的變數

寫在所有函式外面的變數屬於整個 package，同一個 package 的每個函式都能使用。套件層級只能用 var，不能用 :=：

var shopName = "阿姨便當"

func packageLevel() {
	fmt.Println("店名：" + shopName)
}

輸出

店名：阿姨便當

套件層級的變數任何函式都能改，程式一大就很難追是誰改的。實務上它多半用來放設定好就不再改的值，或者乾脆用常數（第 6 節）。

2. 零值

Go 的每個變數一宣告就有值。沒有給初始值時，會自動填入那個型別的零值（zero value）：

func zeroValues() {
	var i int
	var f float64
	var ok bool
	var s string
	var p *int
	fmt.Printf("int=%d float64=%g bool=%t string=%q pointer=%v\n", i, f, ok, s, p)
}

輸出

int=0 float64=0 bool=false string="" pointer=<nil>

數字是 0，布林是 false，字串是空字串 ""，指標是 nil（第 05 章）。之後會學到的 slice、map、channel、函式、interface，零值也都是 nil；struct 的零值則是每個欄位各自的零值。

零值的好處是可以直接拿來用。計數器不用先寫 = 0，字串不用先寫 = ""：

func zeroUsable() {
	var count int    // 0
	var order string // ""
	count++
	order += "排骨"
	count++
	order += "、雞腿"
	fmt.Printf("%d 個：%s\n", count, order)
}

輸出

2 個：排骨、雞腿
「讓零值有用」是 Go 的設計習慣

標準庫的很多型別，宣告完不用呼叫建構函式就能用，例如 strings.Builder 和 sync.Mutex。設計自己的型別時，也盡量讓零值代表一個合理的狀態。第 09 章會再談這件事。第 6 節的 Priority 從 1 開始編號，也是為了讓零值 0 有「還沒設定」的意思。

3. 整數

Go 的整數型別依照「有沒有負數」和「佔幾個位元」區分：

  • 有號：int8、int16、int32、int64，以及 int。
  • 無號（沒有負數）：uint8、uint16、uint32、uint64，以及 uint。
  • 別名：byte 就是 uint8，用來表示原始的位元組；rune 就是 int32，用來表示一個 Unicode 字元。
  • 大小跟著平台走：int 和 uint 在 64 位元系統上是 64 位元，在 32 位元系統上是 32 位元。

math 套件為每一種型別都準備了上下限常數：

func intRanges() {
	fmt.Printf("%-6s %d ~ %d\n", "int8", math.MinInt8, math.MaxInt8)
	fmt.Printf("%-6s %d ~ %d\n", "uint8", 0, math.MaxUint8)
	fmt.Printf("%-6s %d ~ %d\n", "int16", math.MinInt16, math.MaxInt16)
	fmt.Printf("%-6s %d ~ %d\n", "int32", math.MinInt32, math.MaxInt32)
	fmt.Printf("%-6s %d ~ %d\n", "int64", int64(math.MinInt64), int64(math.MaxInt64))
	fmt.Printf("%-6s %d ~ %d\n", "uint64", 0, uint64(math.MaxUint64))
}

輸出

int8   -128 ~ 127
uint8  0 ~ 255
int16  -32768 ~ 32767
int32  -2147483648 ~ 2147483647
int64  -9223372036854775808 ~ 9223372036854775807
uint64 0 ~ 18446744073709551615

沒有特別理由時就用 int：它是 len() 的回傳型別，也是 slice 索引的型別，用 int 可以少寫很多轉換。需要固定大小時才挑其他型別，例如檔案格式規定 4 個 byte、要和外部系統交換資料，或者要放進大量資料、需要省記憶體的時候。

溢位會繞回來

func overflowWrap() {
	var level int8 = 127
	level++
	fmt.Println(level)

	var stock uint8 = 0
	stock--
	fmt.Println(stock)
}

輸出

-128
255

執行時的整數運算超出範圍時，Go 不會報錯，也不會 panic，而是像里程表一樣從另一端繞回來：int8 的 127 加 1 變成 -128，uint8 的 0 減 1 變成 255。這個行為在語言規格裡有明確定義，每台機器的結果都一樣，但它幾乎都代表 bug。uint 系列特別要小心：「庫存減一」減到 0 以下會變成一個超大的正數，而不是負數。所以就算數值不可能是負的，一般計數也習慣用 int。練習 6 會讓你寫一個不會繞回來的加法。

如果超出範圍的是常數，編譯器在編譯時就能算出來，會直接報錯，例如 var level int8 = 128（常見錯誤 4）。

整數除法和餘數

func integerDivision() {
	fmt.Println(7/2, 7%2)
	fmt.Println(-7/2, -7%2)
	fmt.Println(7.0 / 2)

	total, people := 1000, 3
	fmt.Println("每人", total/people, "元，剩", total%people, "元")
}

輸出

3 1
-3 -1
3.5
每人 333 元，剩 1 元

兩個整數相除，結果還是整數，小數部分直接捨去，方向是往 0（所以 -7/2 是 -3，不是 -4）。% 是餘數，它的正負號跟著被除數：-7 % 2 是 -1。這兩條規則保證 (a/b)*b + a%b == a 永遠成立。想要有小數的結果，至少要有一邊是浮點數，例如 7.0 / 2。

整數除法加上餘數很適合處理「分組」的問題：1000 元分給 3 個人，每人 333 元，剩 1 元。練習 1、2 都會用到它。

除以 0

func divide(a, b int) int {
	return a / b
}

func divideByZero() {
	defer func() {
		fmt.Println("panic:", recover())
	}()
	fmt.Println(divide(10, 0))
}

輸出

panic: runtime error: integer divide by zero

整數除以 0 會在執行時 panic，程式會停下來並印出錯誤。這裡用 defer 和 recover 把 panic 接住，才能把訊息印出來，這兩個在第 04 章介紹。如果除數是常數 0，例如 10 / 0，編譯器會直接拒絕：invalid operation: division by zero。除數來自使用者輸入時，記得先檢查是不是 0。

深入：第一次讀可以先跳過

3.1 int 到底是幾位元

int 的大小由編譯目標決定：GOARCH=amd64 或 arm64 是 64 位元，386 或 arm 是 32 位元。程式裡可以用 strconv.IntSize 查。現在的伺服器和個人電腦幾乎都是 64 位元，但如果你的程式可能跑在 32 位元的嵌入式裝置上，或者要存的值可能超過 21 億（例如以毫秒計的時間戳、金額的累計），就直接用 int64，不要賭平台。

這也是為什麼上面的 intRanges 寫成 int64(math.MinInt64)：沒有型別的常數傳給 Printf 時會變成 int，在 32 位元平台上放不下，會編譯失敗。先轉成 int64 就不受平台影響。

4. 浮點數

Go 有兩種浮點數：float64 和 float32。float64 有大約 15–16 位有效數字，是預設的選擇；float32 精度只有 6–7 位，除非要省記憶體或配合外部格式，不然不要用。標準庫的 math 套件也全部以 float64 為準。

浮點數最重要的一件事是：它只是近似值。

func floatError() {
	a, b := 0.1, 0.2
	fmt.Println(a+b, a+b == 0.3)

	sum := 0.0
	for range 10 {
		sum += 0.1
	}
	fmt.Println(sum)
}

輸出

0.30000000000000004 false
0.9999999999999999

浮點數用二進位存小數，而 0.1 在二進位是無限循環小數，就像 1/3 在十進位寫不完一樣，只能存一個最接近的值。0.1 和 0.2 各有一點點誤差，加起來就不等於 0.3 存起來的那個值。加十次 0.1 也到不了 1。這不是 Go 的問題，Java 的 double、JavaScript 的 number 都一樣。

比較時允許一點誤差

因為有誤差，浮點數很少用 == 比較，而是看兩者的差距夠不夠小：

func floatCompare() {
	a, b := 0.1, 0.2
	const epsilon = 1e-9
	fmt.Println(math.Abs(a+b-0.3) < epsilon)
}

輸出

true

math.Abs 是絕對值。誤差範圍 epsilon 要多小，取決於你的數字有多大、需要多精確，沒有萬用的值。

金額用整數存

func moneyInTenths() {
	rate := 2.1
	fmt.Println(3 * rate)

	rateTenths := 21
	total := 3 * rateTenths
	fmt.Printf("%d.%d 元\n", total/10, total%10)
}

輸出

6.300000000000001
6.3 元

用浮點數算錢，誤差會跑進帳單。常見的做法是用整數存最小單位：台幣通常整數就夠，有小數時改存「角」或「分」，美金存「cent」。要顯示時再用整數除法和餘數拆成整數部分和小數部分。如果需要任意精度的小數運算，標準庫有 math/big，但大多數情況下整數就夠了。

深入：第一次讀可以先跳過

4.1 無限大與 NaN

整數除以 0 會 panic，浮點數除以 0 卻不會：

func floatSpecial() {
	var zero float64
	fmt.Println(1/zero, -1/zero)
	nan := zero / zero
	fmt.Println(nan, nan == nan, math.IsNaN(nan))
}

輸出

+Inf -Inf
NaN false true

依照 IEEE 754 浮點數標準，正數除以 0 得到正無限大，0 除以 0 得到 NaN（Not a Number）。NaN 有一個怪特性：它和任何值都不相等，包括它自己，所以 nan == nan 是 false，要判斷 NaN 只能用 math.IsNaN。NaN 會一路傳染下去，任何運算碰到它結果都是 NaN；算出一堆 NaN 時，往回找第一個除以 0 或 math.Sqrt(-1) 的地方。

5. 型別轉換

Go 從不自動轉換型別。int 不會自動變成 float64，連 int 和 int64 都不能直接相加，兩邊型別不同就是編譯錯誤（常見錯誤 3）。要轉換時，把型別名稱當成函式來用，寫成 型別(值)：

func convertNumbers() {
	bill, people := 200, 3
	fmt.Println(bill/people, float64(bill)/float64(people))

	price := 85.9
	fmt.Println(int(price), int(-price)) // 直接截掉小數，往 0 的方向

	big := 300
	fmt.Println(int8(big)) // 放不下時只留下最低的 8 個位元
}

輸出

66 66.66666666666667
85 -85
44

一行一行看：

  • 整數轉浮點數：bill/people 是整數除法，得到 66；兩邊都轉成 float64 再除，才有小數。要注意轉換的時機：float64(bill/people) 是先做整數除法、再把 66 轉成 66.0，小數早就不見了。練習 3 就是這個 bug。
  • 浮點數轉整數：直接截掉小數，往 0 的方向，不是四捨五入。要四捨五入就用 math.Round。
  • 大的整數轉小的整數：放不下時只留下最低的幾個位元。300 的二進位是 1 0010 1100，int8 只留下最後 8 位 0010 1100，也就是 44。編譯器和執行時都不會警告你。

為什麼這麼囉嗦？因為自動轉換是 bug 的溫床：精度在哪裡掉的、數值在哪裡被截斷的，在會自動轉型的語言裡很難看出來。Go 要求每一次轉換都寫出來，讀程式的人一眼就知道這裡可能會失去資訊。

數字和字串

數字和字串之間的轉換不是「型別轉換」，而是「解析」和「格式化」，要用 strconv 套件：

func convertStrings() {
	fmt.Println(strconv.Itoa(85) + " 元")

	n, err := strconv.Atoi("120")
	fmt.Println(n+1, err)

	_, err = strconv.Atoi("12a")
	fmt.Println(err)

	fmt.Println(string(rune(65)), strconv.Itoa(65))
}

輸出

85 元
121 <nil>
strconv.Atoi: parsing "12a": invalid syntax
A 65
  • strconv.Itoa（integer to ASCII）把整數變成十進位的字串。
  • strconv.Atoi 反過來把字串解析成整數。字串不一定是合法的數字，所以它會多回傳一個錯誤，成功時錯誤是 nil。錯誤處理在第 11 章詳細介紹，現在只要記得：一定要檢查 err。
  • string(rune(65)) 得到的是 "A"，不是 "65"：把整數轉成字串，Go 會把它當成 Unicode 字元的編號。這個行為太容易誤用，go vet 會在你寫 string(n) 時提出警告（常見錯誤 5）。

需要浮點數或其他進位時，strconv 還有 ParseFloat、FormatFloat、ParseInt、FormatInt 等函式，用 go doc strconv 可以看到完整清單。要把數字嵌進一段文字裡，fmt.Sprintf 通常更方便，第 02 章會介紹。

6. 常數與 iota

常數用 const 宣告，值在編譯時就決定，執行時不能修改。它只能是數字、字串、布林這類基本的值，不能是函式的回傳結果，也不能是 slice 或 struct：

func constBasics() {
	const shop = "阿姨便當"
	const bentoPrice = 85
	const taxRate = 0.05
	fmt.Println(shop, bentoPrice, bentoPrice*taxRate)
}

輸出

阿姨便當 85 4.25

注意最後一個值：整數常數 85 乘上浮點常數 0.05，直接得到 4.25，不需要任何轉換。如果 bentoPrice 是一個 int 變數，這樣寫就會編譯失敗。差別在於這兩個常數沒有型別。

沒有型別的常數

func untypedConst() {
	const n = 3
	var qty int = n
	var weight float64 = n
	var small int8 = n
	fmt.Println(qty, weight, small)

	const huge = 1 << 100 // 遠超過 int64，但只要最後用到的結果放得進去就好
	fmt.Println(huge >> 98)
}

輸出

3 3 3
4

const n = 3 沒寫型別，它只是一個「整數 3」，要等到被用到的時候才決定型別：指定給 int 就是 int，指定給 float64 就是 float64，指定給 int8 也可以，只要放得下。所以同一個常數可以用在很多種型別的地方，不用一直轉換。沒有型別的常數用在不需要特定型別的地方，例如 x := n，就會用它的預設型別：整數是 int，小數是 float64。

沒有型別的常數在編譯時用很高的精度計算。1 << 100 遠超過 int64 能放的範圍，但只要最後真正用到的值放得下（huge >> 98 是 4），就沒問題。直接印 huge 的話，它要變成 int 才能傳給 Println，就會編譯失敗：

./main.go:8:14: cannot use huge (untyped int constant 1267650600228229401496703205376) as int value in argument to fmt.Println (overflows)

也可以寫成有型別的常數：const limit int8 = 100。這時它就和 int8 變數一樣，不能和其他型別混用。大部分時候不寫型別比較方便；需要配合自訂型別時才寫，例如下面的 Weekday。

iota：自動編號

Go 沒有 enum 關鍵字。要表示「星期幾」這種一組固定的選項，慣例是先定義一個自訂型別，再用 const 區塊搭配 iota 編號：

type Weekday int

const (
	Sunday  Weekday = iota // 0
	Monday                 // 1：沒寫的話沿用上一行的寫法，iota 自動加 1
	Tuesday                // 2
	Wednesday
	Thursday
	Friday
	Saturday
)

func iotaWeekday() {
	fmt.Println(Sunday, Monday, Saturday)
	today := Friday
	fmt.Println(today+1 == Saturday) // 可以和沒有型別的常數 1 運算
}

輸出

0 1 6
true

iota 在每個 const 區塊裡從 0 開始，每多一行就加 1。區塊裡沒寫等號的行，會沿用上一行的寫法（型別和運算式），只是 iota 換成新的值，所以只要第一行寫 Weekday = iota，後面的常數就自動變成 1、2、3……，型別也都是 Weekday。

type Weekday int 定義了一個新型別，它的底層是 int，但它和 int 是不同的型別：一個 Weekday 變數和一個 int 變數不能直接相加。和沒有型別的常數 1 運算則沒問題，所以 today+1 可以編譯。自訂型別讓編譯器幫你擋住「把數量當成星期幾」這類錯誤。第 02 章會介紹 Stringer，讓自訂型別印出有意義的文字，而不是一個數字。

iota 的兩種常見寫法

type Priority int

const (
	Low Priority = iota + 1
	Normal
	High
)

type Note uint8

const (
	Spicy     Note = 1 << iota // 0001
	NoOnion                    // 0010
	ExtraRice                  // 0100
	Takeout                    // 1000
)

func iotaPatterns() {
	var p Priority
	fmt.Println(p, Low, Normal, High)
	fmt.Println(Spicy, NoOnion, ExtraRice, Takeout)
}

輸出

0 1 2 3
1 2 4 8
  • 從 1 開始：iota + 1。這樣零值 0 不會是任何一個合法的選項，看到 0 就知道「還沒設定」。
  • 位元旗標：1 << iota 得到 1、2、4、8，每個常數只佔一個位元，可以用 | 組合起來，一個變數就能記住好幾個備註。第 8 節會用位元運算操作它們。
  • 跳過某個值：在區塊裡寫 _ = iota，那一行的編號就被丟掉。練習 4 會用到這個技巧，搭配 1 << (10 * iota) 做出 KB、MB、GB。

深入：第一次讀可以先跳過

6.1 為什麼常數要分有沒有型別

Go 一方面嚴格禁止自動轉型，另一方面又希望 x * 2、price * 0.05、time.Second * 3 這種寫法不用到處加轉換。沒有型別的常數就是兩者之間的折衷：常數的值在編譯時就知道，編譯器可以確認它放進目標型別時不會失真；放不下（例如把 128 放進 int8，或把 3.5 放進 int）就直接報錯。所以常數的「自動轉換」是安全的，變數的則不是。

規格要求編譯器至少用 256 位元表示整數常數，浮點常數的精度也很高，所以常數之間的運算是精確的：0.1 + 0.2 這兩個常數相加剛好等於 0.3，只有存進 float64 變數之後才會出現第 4 節看到的誤差。

7. 作用域與遮蔽

一個名字（變數、常數、函式、型別）在哪裡可以使用，叫做它的作用域（scope）。Go 的作用域由大括號決定，由外到內是：

  • 全域（universe）：Go 內建的名字，例如 int、string、true、nil、len、append，在任何地方都能用。
  • 套件：寫在函式外面的宣告，整個 package 都看得到，不管在哪個檔案。
  • 檔案：import 進來的套件名稱，只在那個檔案有效。所以每個檔案都要自己寫 import。
  • 函式與區塊：函式裡宣告的變數，從宣告那一行開始，到所在的大括號結束為止有效。if、for、switch 的大括號也都是區塊，第 03 章會看到 if 的初始化敘述也有自己的作用域。
func scopeLevels() {
	fmt.Println("套件層級：", shopName)
	qty := 3 // 函式層級
	{
		price := 85 // 區塊層級：只在這對大括號裡有效
		fmt.Println("區塊裡：", qty*price)
	}
	// 這裡已經看不到 price
	fmt.Println("函式裡：", qty)
}

輸出

套件層級： 阿姨便當
區塊裡： 255
函式裡： 3

一對單獨的大括號也能開一個新的區塊。price 只在裡面有效，在大括號外面使用它會編譯失敗：undefined: price。變數的作用域越小越好，讀程式的人需要記住的東西就越少。

遮蔽

內層可以宣告一個和外層同名的變數。這時內層的名字會遮蔽（shadow）外層的，在內層的範圍裡，外層那個就看不到了：

func shadowPackage() {
	shopName := "阿姨便當 二號店"
	fmt.Println(shopName)
	printShopName()
}

func printShopName() {
	fmt.Println(shopName)
}

輸出

阿姨便當 二號店
阿姨便當

shadowPackage 裡的 shopName 是一個新的區域變數，它沒有改到套件層級的 shopName，所以 printShopName 印出來的還是原本的店名。遮蔽本身是合法的，問題在於它常常不是故意的：在 if 裡用 := 想改外面的變數，結果宣告了一個新的，外面的值根本沒變。第 03 章的常見錯誤有完整的例子。

全域的名字也能被遮蔽。把變數取名為 len、new、string 是合法的，但之後在同一個範圍裡就不能再用那個內建函式或型別了（常見錯誤 7）。

8. 運算子

Go 的運算子和 C、Java 大致相同，這一節整理幾個容易出錯或比較特別的地方。

優先順序只有五級

優先順序運算子
5（最先算）*　/　%　<<　>>　&　&^
4+　-　|　^
3==　!=　<　<=　>　>=
2&&
1（最後算）||

同一級由左往右算。記法很簡單：乘除類比加減類先算，算完才比較，比較完才做邏輯運算。

func precedence() {
	fmt.Println(2+3*4, (2+3)*4)
	fmt.Println(1 + 2<<1) // << 和 * 同一級，比 + 先算
	n := 6
	fmt.Println(n%2 == 0 && n > 5)
	fmt.Println(n&1 == 0) // & 也比 == 先算
}

輸出

14 20
5
true
true

和 C、Java 不同的是位元運算的位置：<< 和 * 同一級，所以 1 + 2<<1 是 1 + 4 = 5（在 Java 是 (1+2)<<1 = 6）；& 比 == 先算，所以 n&1 == 0 就是「n 是偶數」，不需要括號。gofmt 會用空白提示優先順序：2+3*4 寫成 2 + 3*4，緊貼在一起的先算。不確定的時候加括號，讀的人也會感謝你。

&& 和 || 會短路

func expensive(total, qty int) bool {
	return qty > 0 && total/qty > 100
}

func shortCircuit() {
	fmt.Println(expensive(450, 3), expensive(0, 0))
}

輸出

true false

&& 左邊是 false 時，整個結果一定是 false，右邊根本不會執行；|| 左邊是 true 時也一樣。所以把「先決條件」放在左邊，就能保護右邊不出錯：qty > 0 擋住了除以 0。Go 的布林值只能是 bool，不能拿整數或指標當條件，if qty 是編譯錯誤，要寫 if qty != 0。

++ 是敘述，不是運算式

func incDec() {
	queue := 5
	queue++    // 來了一位
	queue--    // 叫走一位
	queue += 3 // 一次來三位
	price := 85
	price *= 2
	fmt.Println(queue, price)
}

輸出

8 170

queue++ 和 queue-- 只能自己寫成一行，不能放進其他運算式，也沒有 ++queue 這種前置寫法。這樣就不用再爭論 i++ + ++i 是多少：

package main

import "fmt"

func main() {
	i := 1
	j := i++
	fmt.Println(i, j)
}

編譯錯誤

./main.go:7:8: syntax error: unexpected ++ at end of statement

+=、-=、*=、/=、%=，以及位元運算的 &=、|=、^=、&^=、<<=、>>= 都有。Go 也沒有三元運算子 a ? b : c，要用 if 寫。

位元運算

func bitFlags() {
	order := Spicy | ExtraRice
	fmt.Printf("%04b\n", order)
	fmt.Println(order&Spicy != 0, order&NoOnion != 0)
	order |= Takeout
	order &^= Spicy
	fmt.Printf("%04b\n", order)
	order ^= NoOnion
	fmt.Printf("%04b\n", order)
}

輸出

0101
true false
1100
1110
運算子名稱在旗標上的用途
a | bOR打開 b 的位元（加上備註）
a & bAND只留下兩邊都有的位元；a&b != 0 表示 a 有 b 的某個位元
a &^ bAND NOT（bit clear）關掉 b 的位元（拿掉備註），Go 特有
a ^ bXOR切換 b 的位元：開的關掉、關的打開
^aNOT每個位元都反過來（Java 的 ~a）
a << n、a >> n位移往左移 n 位等於乘 2ⁿ，往右移等於除以 2ⁿ

%04b 是 Printf 的格式，意思是「以二進位印出，至少 4 位，不足補 0」。Go 沒有 Java 的 >>>：右移時，有號整數補符號位，無號整數補 0，由型別決定。位元旗標在實務上很常見，例如檔案權限 0644、網路協定的標頭欄位。練習 5 會用它做員工權限。

常見錯誤

1. 在函式外面用 :=

package main

	fmt.Println(count)

編譯錯誤

函式外面只能寫宣告，而 := 在語法上是一個敘述。改成 var count = 0，或者更簡單的 var count int（零值就是 0）。

編譯錯誤

第二次只是要改值，用 =。反過來的情況更危險：在內層區塊用 :=，編譯器不會報錯，而是悄悄宣告一個新的變數（第 7 節的遮蔽）。

3. 不同型別直接運算

package main

import "fmt"

func main() {
	qty := 3
	price := 85.5
	fmt.Println(qty * price)
}

編譯錯誤

./main.go:8:14: invalid operation: qty * price (mismatched types int and float64)

改成 float64(qty) * price。同樣的錯誤在使用自訂型別時也會出現，最常見的是 time.Duration：

package main

	"fmt"
	"time"
)

func main() {
	n := 3
	fmt.Println(n * time.Second)
}

編譯錯誤

./main.go:10:14: invalid operation: n * time.Second (mismatched types int and time.Duration)

3 * time.Second 可以編譯，因為 3 是沒有型別的常數；換成 int 變數就不行了，要寫 time.Duration(n) * time.Second。這正是第 6 節說的「常數可以自動轉換，變數不行」。

4. 常數放不進型別

package main

import "fmt"

	var level int8 = 128
	fmt.Println(level)
}

編譯錯誤

./main.go:6:19: cannot use 128 (untyped int constant) as int8 value in variable declaration (overflows)

常數的值在編譯時就知道，放不下會直接報錯；換成浮點常數轉整數，例如 int(3.99)，也會得到 cannot convert 3.99 (untyped float constant) to type int。但同樣的事情發生在執行時（變數的運算或轉換），就是第 3 節的「繞回來」，不會有任何錯誤。挑型別時要先想清楚值的範圍。

5. 用 string(n) 把數字轉成文字

輸出

這支程式可以編譯，執行會印出 A，而不是 65。vet 的訊息說得很清楚：結果是一個字元，不是一串數字。要數字的文字就用 strconv.Itoa(n)；真的想要字元，就明寫 string(rune(n))，vet 就不會再警告。

錯誤寫法

    例如 Ticket(999, 1) 是 1，Ticket(1, -1) 是 999，Ticket(5, -2000) 是 3。測試：TestTicket。

    先把號碼換成從 0 開始的位置（減 1），算完再加回 1，循環就是取 % 999。麻煩在負數：Go 的 % 正負號跟著被除數，-1 % 999 是 -1，不是 998（第 3 節）。得到負的餘數時，再加上 999 就回到正確的範圍。

參考解答：先自己寫完再看。測試通過的寫法都是對的。

重點回顧

  • var 哪裡都能用；:= 只能在函式裡，左邊至少要有一個新變數。
  • := 建立新變數，= 修改已存在的變數。
  • 沒給初始值的變數是零值：0、false、""、nil，可以直接使用。
  • 沒有特別理由就用 int 和 float64；byte 是 uint8，rune 是 int32。
  • 執行時的整數溢位會繞回來，不會報錯；常數溢位是編譯錯誤。
  • 整數除法往 0 捨去，% 的正負號跟著被除數；整數除以 0 會 panic。
  • 浮點數是近似值：不要用 == 比較，金額用整數存最小單位。
  • 型別轉換一律明寫成 T(v)；浮點轉整數直接截斷；數字和字串互轉用 strconv。
  • 沒有型別的常數用到時才決定型別，所以可以安全地和各種數字型別搭配。
  • 列舉用自訂型別加上 iota；1 << iota 做位元旗標。
  • 內層的同名變數會遮蔽外層，包括 len 這類內建名字。
  • <<、& 和 * 同一級；&&、|| 會短路；++ 是敘述；沒有三元運算子。
