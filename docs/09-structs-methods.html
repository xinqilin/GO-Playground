1. 自訂型別

type 名稱 底層型別 定義一個新型別（defined type）。它和底層型別長得一樣（同樣的值、同樣的運算），卻是不同的型別，而且可以有自己的方法：

type Gram float64

type Jin float64

func (j Jin) Grams() Gram {
	return Gram(j * 600)
}

func (g Gram) String() string {
	return fmt.Sprintf("%.0f 公克", float64(g))
}

func definedTypes() {
	pork := Jin(1.5)
	fmt.Println(pork)
	fmt.Println(pork.Grams())

	var raw float64 = 300
	rice := Gram(raw)
	fmt.Println(rice + 50)
	fmt.Println(float64(rice))
}

輸出

1.5
900 公克
350 公克
300
  • Jin(1.5)、Gram(raw)：底層型別相同就能轉換。rice + 50 不用轉換，因為 50 是 untyped 常數，會自動變成 Gram（01 章的常數）。
  • Jin 沒有 String 方法，就照 float64 的樣子印出 1.5；Gram 有，所以 pork.Grams() 印出「900 公克」。float64(rice) 轉回去之後，String 方法也跟著不見了：方法屬於型別，不屬於值。
  • 新型別最大的用處是讓編譯器幫你檢查。把公克和台斤直接加在一起，在菜市場是算錯錢，在 Go 裡是編譯錯誤：
package main

import "fmt"

type Gram float64

type Jin float64

func main() {
	rice := Gram(300)
	pork := Jin(1.5)
	fmt.Println(rice + pork)
}

編譯錯誤

./main.go:12:14: invalid operation: rice + pork (mismatched types Gram and Jin)

標準庫到處都是這種用法：time.Duration 的底層型別是 int64，但它有 Hours()、String() 等方法，也不會和一般的整數搞混。

type alias

type Score = int

type Points int

func aliasDemo() {
	var s Score = 90
	var p Points = 90
	var n int = s
	fmt.Printf("%T %T %d\n", s, p, n)
}

輸出

int main.Points 90

多了一個等號，意思就完全不同：type Score = int 是別名（alias），Score 和 int 是同一個型別，%T 印出來就是 int，互相指定不用轉換，也不能替 Score 加方法（那等於替 int 加方法）。你已經用過好幾個別名：byte 是 uint8 的別名、rune 是 int32 的別名（08 字串與 rune）、any 是 interface{} 的別名。自己的程式很少需要 alias，它主要用在大型重構時，把型別從一個 package 搬到另一個 package，讓舊名字還能繼續用。想要一個新的型別，就用沒有等號的寫法。

2. struct

type Bento struct {
	Name  string
	Price int
	Spicy bool
}

func structLiterals() {
	var zero Bento
	a := Bento{Name: "排骨飯", Price: 85}
	b := Bento{"雞腿飯", 95, true}
	fmt.Printf("%v\n", zero)
	fmt.Printf("%+v\n", a)
	fmt.Printf("%#v\n", b)

	a.Price = 90
	fmt.Println(a.Name, a.Price, a.Spicy)
}

輸出

{ 0 false}
{Name:排骨飯 Price:85 Spicy:false}
main.Bento{Name:"雞腿飯", Price:95, Spicy:true}
排骨飯 90 false
  • var zero Bento：每個欄位都是零值。%v 印出 { 0 false}，開頭那個空白是空字串。
  • Bento{Name: "排骨飯", Price: 85}：寫出欄位名稱，順序隨意，沒寫的欄位是零值。平常都用這種寫法。
  • Bento{"雞腿飯", 95, true}：依照欄位順序填，每個欄位都要填。struct 之後多一個欄位或調換順序，這種寫法就會編譯失敗或填錯欄位，所以只適合欄位很少、而且不會改的型別。
  • %+v 加上欄位名稱，%#v 印成 Go 的語法，除錯時很好用（02 章）。
  • 欄位用 . 讀寫：a.Price = 90。
func structPointer() {
	p := &Bento{Name: "素食餐", Price: 80}
	p.Price += 5
	fmt.Println(p.Price)
	fmt.Printf("%+v\n", p)
}

輸出

85
&{Name:素食餐 Price:85 Spicy:false}

&Bento{…} 建立 struct 並直接拿到它的指標，這個寫法非常常見。透過指標存取欄位時不用寫 (*p).Price，Go 會自動解參考，寫 p.Price 就好（05 章）。印出指標時，fmt 會在前面加一個 &。

匿名 struct

func anonymousStruct() {
	stats := []struct {
		Day   string
		Sales int
	}{
		{"一", 3200},
		{"二", 4100},
	}
	for _, s := range stats {
		fmt.Println(s.Day, s.Sales)
	}
}

輸出

一 3200
二 4100

只用一次的資料不必替它取名字，直接寫 struct{ … } 當型別。最常見的地方是表格測試：tests := []struct{ in, want int }{ … }，本書每一章的練習測試都是這樣寫的。

3. 複製與比較

func copyStruct() {
	a := Bento{Name: "排骨飯", Price: 85}
	b := a
	b.Price = 100
	fmt.Println(a.Price, b.Price)
}

輸出

85 100

struct 是值。b := a 把每個欄位都複製一份，改 b 不影響 a；傳給函式、從函式回傳、放進 slice、用 range 拿出來，也都是複製。這讓 struct 用起來很安全，但要注意「複製一份」只複製到欄位這一層：

type Combo struct {
	Name  string
	Sides []string
}

func shallowCopy() {
	a := Combo{Name: "A 餐", Sides: []string{"滷蛋", "青菜"}}
	b := a
	b.Name = "B 餐"
	b.Sides[0] = "豆干"
	fmt.Println(a.Name, a.Sides)
	fmt.Println(b.Name, b.Sides)
}

輸出

A 餐 [豆干 青菜]
B 餐 [豆干 青菜]

改 b.Name 只影響 b，因為字串欄位被複製了；改 b.Sides[0] 卻連 a 也變了，因為兩個 Sides 共用同一個底層陣列（06 章的共用底層陣列、05 章的淺複製）。需要完全獨立的複本時，要自己複製 slice：b.Sides = slices.Clone(a.Sides)。

比較與當成 map 的 key

func compareStructs() {
	a := Bento{Name: "排骨飯", Price: 85}
	b := Bento{Name: "排骨飯", Price: 85}
	c := Bento{Name: "排骨飯", Price: 90}
	fmt.Println(a == b, a == c)

	sold := map[Bento]int{}
	sold[a]++
	sold[b]++
	sold[c]++
	fmt.Println(len(sold), sold[a])
}

輸出

true false
2 2

每個欄位都可以比較時，struct 就能用 ==：逐一比較每個欄位，全部相等才是 true。可以比較的 struct 也能當 map 的 key（07 章的 key 的型別），a 和 b 內容一樣，所以是同一個 key，map 裡只有兩筆。只要有一個欄位是 slice、map 或函式，整個 struct 就不能比較：

package main

import "fmt"

type Combo struct {
	Name  string
	Sides []string
}

func main() {
	a := Combo{Name: "A 餐", Sides: []string{"滷蛋"}}
	b := Combo{Name: "A 餐", Sides: []string{"滷蛋"}}
	fmt.Println(a == b)
}

編譯錯誤

./main.go:13:14: invalid operation: a == b (struct containing []string cannot be compared)

這種 struct 要自己寫比較的方法，例如比 Name 再用 slices.Equal 比 Sides。

4. 方法與 receiver

方法（method）是在 func 和名稱之間多寫一個 receiver 的函式：func (s *StampCard) Stamp()。receiver 就像一個特別的參數，呼叫時寫在點的前面：card.Stamp()。方法可以掛在同一個 package 裡定義的任何型別上，不只是 struct，第 1 節的 Gram 就是一例。

type StampCard struct {
	Stamps int
}

func (s StampCard) StampCopy() {
	s.Stamps++
}

func (s *StampCard) Stamp() {
	s.Stamps++
}

func receiverDemo() {
	card := StampCard{}
	card.StampCopy()
	fmt.Println(card.Stamps)
	card.Stamp()
	card.Stamp()
	fmt.Println(card.Stamps)
}

輸出

0
2

receiver 和一般參數一樣是傳值的（05 章）。StampCopy 的 receiver 是 StampCard，它拿到的是 card 的複本，蓋章蓋在複本上，函式結束複本就丟了，所以 card 還是 0 點。Stamp 的 receiver 是 *StampCard，拿到的是 card 的地址，改的就是 card 本身。

func (s *StampCard) Free() bool {
	return s.Stamps >= 10
}

func autoAddress() {
	card := StampCard{Stamps: 9}
	p := &card
	p.Stamp()
	card.Stamp()
	fmt.Println(p.Free(), card.Stamps)
}

輸出

true 11

card 是一般的變數，卻可以直接呼叫指標 receiver 的方法：card.Stamp() 會自動變成 (&card).Stamp()。反過來，指標也可以呼叫值 receiver 的方法，Go 會自動補上 *。所以呼叫的時候不用管 receiver 是哪一種，只有定義的時候要選。

自動取地址有一個前提：那個值要可以取地址（addressable）。變數、slice 的元素、指標指向的欄位都可以；map 的元素、函式的回傳值、字面值都不行：

package main

import "fmt"

type StampCard struct {
	Stamps int
}

func (s *StampCard) Stamp() {
	s.Stamps++
}

func main() {
	cards := map[string]StampCard{"小明": {Stamps: 3}}
	cards["小明"].Stamp()
	fmt.Println(cards)
}

編譯錯誤

./main.go:15:18: cannot call pointer method Stamp on StampCard

map 的元素沒有固定的位址（map 長大時會搬家），所以不能取地址。解法和 07 章的「值是 struct」一樣：取出來、改、放回去，或者讓 map 存指標 map[string]*StampCard。

選哪一種 receiver

  • 要修改 receiver：一定用指標。
  • struct 很大：用指標，避免每次呼叫都複製整個 struct。
  • struct 裡有不能複製的東西，例如 sync.Mutex：一定用指標，否則每次呼叫都會複製一把新的鎖，go vet 會報錯（常見錯誤 4）。
  • 小而且不會變的值，例如 Gram、time.Time：用值 receiver，用起來就像數字一樣。
  • 保持一致：一個型別只要有一個方法用了指標 receiver，其他方法通常也全部用指標，讀的人不用一個一個想。拿不定主意時，用指標。

深入：第一次讀可以先跳過

4.1 method set

呼叫時的自動 &、* 只是語法上的方便。型別本身真正「擁有」哪些方法，由 method set 決定：型別 T 的 method set 只有值 receiver 的方法；*T 的 method set 則包含值 receiver 和指標 receiver 的全部方法。

這條規則平常感覺不到，一遇到 interface 就很重要。fmt.Println 印一個值時，會檢查它有沒有 String 方法（也就是有沒有實作 fmt.Stringer）：

type Ticket struct {
	No int
}

func (t *Ticket) String() string {
	return fmt.Sprintf("第 %d 號", t.No)
}

func methodSetDemo() {
	t := Ticket{No: 7}
	fmt.Println(t)
	fmt.Println(&t)
}

輸出

{7}
第 7 號

String 掛在 *Ticket 上，所以 Ticket 這個型別沒有 String 方法。把 t 傳給 Println，fmt 找不到 String，只好照 struct 的樣子印出 {7}；傳 &t 才印出「第 7 號」。這不是編譯錯誤，很容易沒注意到。明確地把 Ticket 當成 Stringer 用，編譯器就會說出原因：

package main

import "fmt"

type Ticket struct {
	No int
}

func (t *Ticket) String() string {
	return fmt.Sprintf("第 %d 號", t.No)
}

func main() {
	t := Ticket{No: 7}
	var s fmt.Stringer = t
	fmt.Println(s)
}

編譯錯誤

./main.go:15:23: cannot use t (variable of struct type Ticket) as fmt.Stringer value in variable declaration: Ticket does not implement fmt.Stringer (method String has pointer receiver)

為什麼 T 不能擁有指標方法？因為放進 interface 的是值的複本，而複本不一定能取地址；如果允許，指標方法改到的會是那個看不到的複本。10 interface 會再回到這條規則。

5. 建構函式與零值

Go 沒有建構子（constructor）。建立 struct 有兩種常見的設計：讓零值就能直接用，或者提供一個 NewX 函式。

讓零值就能用

type Queue struct {
	next    int // 最後發出的號碼
	serving int // 目前叫到的號碼
}

func (q *Queue) Take() int {
	q.next++
	return q.next
}

func (q *Queue) Call() (int, bool) {
	if q.serving >= q.next {
		return 0, false
	}
	q.serving++
	return q.serving, true
}

func (q *Queue) Waiting() int {
	return q.next - q.serving
}

func zeroValueDemo() {
	var q Queue
	a := q.Take()
	b := q.Take()
	fmt.Println(a, b, q.Waiting())

	n, ok := q.Call()
	fmt.Println(n, ok, q.Waiting())

	q.Call()
	n, ok = q.Call()
	fmt.Println(n, ok)
}

輸出

1 2 2
1 true 1
0 false

排隊叫號機的兩個計數都從 0 開始，正好就是 int 的零值，所以 var q Queue 宣告完就能用，不需要任何初始化。這是 Go 很推崇的設計：bytes.Buffer、strings.Builder、sync.Mutex 的零值都能直接用。設計型別時，先想想「零值代表什麼」，讓它是一個合理的初始狀態。

欄位用小寫開頭（next、serving），其他 package 就讀不到也改不到，只能透過 Take、Call 操作，叫號機的狀態不會被弄亂。大寫開頭才會被匯出，這條規則在package 與 module 那一章會詳細說明。

欄位是 map 時，零值是 nil map，讀取沒問題，寫入會 panic（07 章）。讓零值也能用的技巧是第一次寫入時才建立：

type Tally struct {
	counts map[string]int
}

func (t *Tally) Add(name string) {
	if t.counts == nil {
		t.counts = map[string]int{}
	}
	t.counts[name]++
}

func (t *Tally) Count(name string) int {
	return t.counts[name]
}

func tallyDemo() {
	var t Tally
	fmt.Println(t.Count("排骨飯"))
	t.Add("排骨飯")
	t.Add("排骨飯")
	t.Add("雞腿飯")
	fmt.Println(t.Count("排骨飯"), t.Count("雞腿飯"))
}

輸出

0
2 1

NewX 建構函式

有些型別必須有合理的初始值，或者要檢查輸入才能建立。慣例是寫一個 NewX 函式，回傳 *X，可能失敗時再多回傳一個 error：

type Reservation struct {
	Name   string
	People int
}

func NewReservation(name string, people int) (*Reservation, error) {
	if name == "" {
		return nil, errors.New("訂位要留名字")
	}
	if people < 1 || people > 12 {
		return nil, fmt.Errorf("人數 %d 不在 1 到 12 之間", people)
	}
	return &Reservation{Name: name, People: people}, nil
}

func constructorDemo() {
	r, err := NewReservation("王先生", 4)
	fmt.Println(r.Name, r.People, err)

	_, err = NewReservation("林小姐", 20)
	fmt.Println(err)

	_, err = NewReservation("", 2)
	fmt.Println(err)
}

輸出

王先生 4 <nil>
人數 20 不在 1 到 12 之間
訂位要留名字
  • 失敗時回傳 nil, err，呼叫的人要先檢查 err 才能用結果（錯誤處理的細節在 11 錯誤處理）。
  • 回傳指標 &Reservation{…} 是安全的，Go 會把它放在 heap 上（05 章）。
  • 只要欄位是匯出的，別人還是可以繞過 NewReservation 直接寫 Reservation{People: 99}。真的要保證不變量，就把欄位改成小寫，再提供讀取用的方法。
  • 只有一個主要型別的 package，建構函式常常直接叫 New，例如 errors.New、list.New。

6. 嵌入

struct 的欄位只寫型別、不寫名稱，就是嵌入（embedding）。被嵌入型別的欄位和方法會被提升（promote）到外層，可以直接用：

type Shop struct {
	Name  string
	Phone string
}

func (s Shop) Contact() string {
	return s.Name + " " + s.Phone
}

type BentoShop struct {
	Shop
	Menu []string
}

func embedDemo() {
	b := BentoShop{
		Shop: Shop{Name: "阿姨便當", Phone: "02-2345-6789"},
		Menu: []string{"排骨飯", "雞腿飯"},
	}
	fmt.Println(b.Name)
	fmt.Println(b.Contact())
	fmt.Println(b.Shop.Name)
}

輸出

阿姨便當
阿姨便當 02-2345-6789
阿姨便當

嵌入的欄位仍然是一個普通的欄位，它的名稱就是型別名稱 Shop，所以 b.Shop.Name 這種完整的寫法也一直可以用。建立時，傳統的寫法是替這個欄位寫 key：Shop: Shop{…}。Go 1.27 起，也可以直接用被提升的欄位當 key：

func promotedKeys() {
	b := BentoShop{Name: "巷口便當", Phone: "02-8765-4321"}
	fmt.Println(b.Contact())
}

輸出

巷口便當 02-8765-4321

這個新寫法有兩個限制：通往那個欄位的路上不能經過指標型別的嵌入欄位（例如嵌入的是 *Shop 就不行），而且同一個字面值裡不能同時寫 Shop: … 又寫 Name: …。本章的 embedDemo 和下面的 shadowDemo 故意保留傳統寫法來對照，go fix 會建議把它們改成新寫法。

遮蔽

type DrinkShop struct {
	Shop
	LineID string
}

func (d DrinkShop) Contact() string {
	return d.Shop.Contact() + " LINE:" + d.LineID
}

func shadowDemo() {
	d := DrinkShop{Shop: Shop{Name: "手搖飲", Phone: "02-1111-2222"}, LineID: "@drink"}
	fmt.Println(d.Contact())
	fmt.Println(d.Shop.Contact())
}

輸出

手搖飲 02-1111-2222 LINE:@drink
手搖飲 02-1111-2222

外層自己有同名的欄位或方法時，外層的優先，被嵌入的那一個被遮蔽（shadow），要用完整路徑 d.Shop.Contact() 才拿得到。DrinkShop.Contact 就是先呼叫 Shop.Contact，再加上自己的東西。注意它必須寫 d.Shop.Contact()，寫成 d.Contact() 就是呼叫自己，永遠停不下來。

兩個被嵌入的型別有同名的欄位，而外層沒有時，直接用那個名字是模稜兩可的，編譯器不會替你選：

package main

import "fmt"

type Shop struct {
	Name string
}

type Bento struct {
	Name  string
	Price int
}

type ShopBento struct {
	Shop
	Bento
}

func main() {
	var x ShopBento
	fmt.Println(x.Name)
}

編譯錯誤

./main.go:21:16: ambiguous selector x.Name

只要不去用 x.Name 就不會出錯；要用的時候寫清楚是 x.Shop.Name 還是 x.Bento.Name。

嵌入不是繼承

type Greeter struct{}

func (Greeter) Title() string { return "客人" }

func (g Greeter) Welcome() string { return "歡迎光臨，" + g.Title() }

type VIPGreeter struct {
	Greeter
}

func (VIPGreeter) Title() string { return "貴賓" }

func notInheritance() {
	v := VIPGreeter{}
	fmt.Println(v.Title())
	fmt.Println(v.Welcome())
}

輸出

貴賓
歡迎光臨，客人

在有繼承的語言裡，子類別覆寫 Title 之後，父類別的 Welcome 也會改呼叫新的 Title。Go 的嵌入不是這樣：v.Welcome() 只是 v.Greeter.Welcome() 的簡寫，Welcome 收到的 receiver 是裡面那個 Greeter，它根本不知道外面還包著一個 VIPGreeter。嵌入是組合（composition）：「BentoShop 有一個 Shop」，不是「BentoShop 是一種 Shop」。需要「同一個呼叫、依型別做不同的事」時，Go 用的是 interface，下一章的主題。

7. struct tag

type Member struct {
	Name   string `json:"name"`
	Phone  string `json:"phone,omitempty"`
	Points int    `json:"points"`
	note   string // 小寫開頭：其他 package（包括 encoding/json）看不到
}

func tagsDemo() {
	m := Member{Name: "小明", Points: 120, note: "常客"}
	data, err := json.Marshal(m)
	fmt.Println(string(data), err)

	f, _ := reflect.TypeFor[Member]().FieldByName("Phone")
	fmt.Println(f.Tag.Get("json"))
}

輸出

{"name":"小明","points":120} <nil>
phone,omitempty

欄位後面用反引號包起來的字串叫 struct tag。它對程式本身沒有任何作用，是寫給其他套件在執行時讀的說明。encoding/json 讀 json:"…" 這個 key：

  • json:"name"：輸出成 JSON 時，欄位名稱用 name，而不是 Go 的 Name。
  • json:"phone,omitempty"：逗號後面是選項，omitempty 表示值是空的就整個省略，所以輸出裡沒有 phone。
  • note 是小寫開頭的未匯出欄位，encoding/json 在另一個 package，看不到它，所以也不會輸出。想輸出一定要大寫開頭，tag 救不了小寫的欄位。

tag 的格式是用空白隔開的 key:"value"，例如 json:"name" db:"member_name"。冒號兩邊不能有空白、值一定要雙引號，寫錯不會編譯失敗，只會默默地沒有作用；還好 go vet 會檢查常見的格式錯誤。讀取 tag 用的是 reflect 套件，自己的程式很少需要；JSON 的完整用法留到「JSON 與資料編碼」那一章。

常見錯誤

1. 想修改欄位，卻用了值 receiver

錯誤寫法：改的是複本

func (s StampCard) StampCopy() {
	s.Stamps++
}

正確寫法

func (s *StampCard) Stamp() {
	s.Stamps++
}

能編譯、能執行，就是沒有效果（第 4 節）。練習 6 就是這個 bug。

2. 在 range 裡改 struct 的複本

for _, e := range staff { e.Salary += 1000 } 改的是 e 這個複本，slice 裡的元素沒變。要改就用索引：staff[i].Salary += 1000（06 章、練習 7）。

3. 直接改 map 裡的 struct

cards["小明"].Stamps++ 和 cards["小明"].Stamp() 都是編譯錯誤，因為 map 的元素不能取地址（第 4 節）。取出來、改、放回去，或者讓 map 存指標。

4. 複製含有 Mutex 的 struct

package main

import (
	"fmt"
	"sync"
)

type SafeTally struct {
	mu sync.Mutex
	n  int
}

func (t SafeTally) Add() {
	t.mu.Lock()
	t.n++
	t.mu.Unlock()
}

func main() {
	var t SafeTally
	t.Add()
	fmt.Println(t.n)
}

go vet

main.go:13:9: Add passes lock by value: example.com/tally.SafeTally contains sync.Mutex

值 receiver 每次都複製整個 struct，連鎖也複製了一把新的，鎖了等於沒鎖，而且 n 也加在複本上。含有 sync.Mutex 的型別，方法一律用指標 receiver，也不要把它當值傳來傳去。（訊息裡的 example.com/tally 是這支程式的 module 路徑。）

5. 把嵌入當成繼承

外層定義了同名方法，被嵌入型別裡的其他方法不會改呼叫它（第 6 節）。要依型別改變行為，用 interface。

6. String 用了指標 receiver，印值時沒有效果

func (t *Ticket) String() 只對 *Ticket 有效，fmt.Println(t) 還是印出 {7}（4.1 節）。String 這類「只讀」的方法通常用值 receiver，除非型別的其他方法都是指標 receiver，那就記得傳指標給 fmt。

7. 用位置寫 struct 字面值

Bento{"雞腿飯", 95, true} 要依序填滿每個欄位。之後在 Bento 裡加一個欄位，所有這種寫法都要改；調換兩個同型別欄位的順序，甚至不會編譯失敗，只是值填錯了位置。一律寫出欄位名稱。

重點回顧

  • type A B 定義新型別，可以有方法，和 B 之間要明確轉換；type A = B 只是別名。
  • 方法屬於型別：轉換成別的型別，方法就不見了。
  • struct 字面值寫出欄位名稱；沒寫的欄位是零值。
  • struct 是值，指定和傳參數都會複製；但 slice、map、指標欄位複製的只是參考，內容仍然共用。
  • 欄位都能比較的 struct 可以用 ==，也能當 map 的 key。
  • 要修改、struct 很大、含有 Mutex 時用指標 receiver；同一個型別的 receiver 保持一致。
  • 呼叫時 Go 會自動補 & 或 *，但 map 的元素不能取地址。
  • T 的 method set 只有值 receiver 的方法，*T 兩種都有。
  • 設計成零值就能用；需要檢查輸入時，寫 NewX 回傳 *X 和 error。
  • 嵌入會提升欄位和方法，外層同名的會遮蔽裡面的；嵌入是組合，不是繼承。
  • struct tag 是給其他套件讀的說明，只對匯出的欄位有用。
