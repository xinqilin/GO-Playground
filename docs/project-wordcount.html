字詞統計

便當店貼了一整年的公告，老闆想知道最常出現的是哪幾個字。英文用空白就切得開，中文卻一個空白都沒有。這個專題寫一個命令列工具：讀好幾個檔案、算出行數和字數、把中英文切成字詞，最後排出前幾名。

1. 檔案或標準輸入

func run(args []string, stdin io.Reader, stdout, stderr io.Writer) int {
	fs := flag.NewFlagSet("wordcount", flag.ContinueOnError)
	fs.SetOutput(stderr)
	top := fs.Int("top", 5, "列出出現最多次的前幾個字詞")
	mode := HanChar
	fs.TextVar(&mode, "han", HanChar, "中文的切法：char（單字）或 bigram（雙字）")
	if err := fs.Parse(args); err != nil {
		return 2
	}

	files := fs.Args()
	if len(files) == 0 {
		files = []string{"-"}
	}
	var total Stats
	status := 0
	for _, name := range files {
		s, err := countFile(name, stdin, mode)
		if err != nil {
			fmt.Fprintf(stderr, "wordcount：%v\n", err)
			status = 1
			continue
		}
		printStats(stdout, name, s)
		total.Add(s)
	}
	if len(files) > 1 {
		printStats(stdout, "合計", total)
	}
	printTop(stdout, Top(total.Counts, *top))
	return status
}

func countFile(name string, stdin io.Reader, mode HanMode) (Stats, error) {
	if name == "-" {
		return Count(stdin, mode)
	}
	f, err := os.Open(name)
	if err != nil {
		return Stats{}, err
	}
	defer f.Close()
	s, err := Count(f, mode)
	if err != nil {
		return s, fmt.Errorf("%s：%w", name, err)
	}
	return s, nil
}
testdata/notice.txt：3 行，25 個字詞，29 個字元，90 bytes
wordcount：open testdata/nosuch.txt: no such file or directory
合計：3 行，25 個字詞，29 個字元，90 bytes
exit code 1
  • 每個檔案一個函式：countFile 裡的 defer f.Close() 在這個函式結束時就執行。如果把 Open 和 defer 直接寫在 run 的迴圈裡，所有檔案要等 run 結束才會關，檔案一多就會用完可以開的檔案數（20 章）。
  • exit code：0 是成功，1 是有檔案讀不到，2 是旗標用錯。錯誤一律寫到 stderr，stdout 只放結果，接在管線後面的程式才不會收到錯誤訊息（21 章）。
  • "-" 代表標準輸入：這是 Unix 工具的慣例。沒有給檔名時，files 就是 ["-"]，兩種情況走同一條路。
  • run 的參數是 args、stdin、stdout、stderr，回傳 exit code；main 只有一行。測試和 Example 都直接呼叫 run，上面的 Example 把 stderr 也接到 stdout，才看得到錯誤那一行。

2. 一行一行讀

type Stats struct {
	Lines  int
	Words  int
	Runes  int // 不含行尾的換行
	Bytes  int // 含換行，和檔案大小相同
	Counts map[string]int
}

func Count(r io.Reader, mode HanMode) (Stats, error) {
	s := Stats{Counts: map[string]int{}}
	br := bufio.NewReader(r)
	for {
		line, err := br.ReadString('\n')
		if line != "" {
			s.Lines++
			s.Bytes += len(line)
			text := strings.TrimSuffix(strings.TrimSuffix(line, "\n"), "\r")
			s.Runes += utf8.RuneCountInString(text)
			for w := range Tokens(text, mode) {
				s.Words++
				s.Counts[w]++
			}
		}
		if err == io.EOF {
			return s, nil
		}
		if err != nil {
			return s, err
		}
	}
}
  • Bytes 和檔案大小一樣：ReadString 回傳的 line 包含換行，len(line) 加起來就是檔案的 byte 數，TestCountMatchesFileSize 用 os.ReadFile 比對過。字元數則去掉行尾的 \n 和 Windows 的 \r。
  • 為什麼不用 bufio.Scanner：Scanner 很方便（02 章），但一行超過 64KB 就會停下來。壓縮過的 JSON、log 檔很容易碰到：
func Example_scannerLimit() {
	long := strings.Repeat("飯", 30_000) // 90,000 bytes
	sc := bufio.NewScanner(strings.NewReader(long + "\n"))
	for sc.Scan() {
		fmt.Println("讀到一行")
	}
	fmt.Printf("錯誤：%v\n", sc.Err())
	// Output:
	// 錯誤：bufio.Scanner: token too long
}
錯誤：bufio.Scanner: token too long
  • 迴圈一次都沒有印出「讀到一行」：Scan 直接回傳 false，原因要看 Err。只檢查 Scan 而忘了檢查 Err，就會以為檔案是空的。用 Scanner 時可以呼叫 sc.Buffer(buf, max) 把上限調高；bufio.Reader 的 ReadString 沒有這個限制，TestLongLine 讀了一行 30 萬 byte。

3. 切成字詞

func Tokens(line string, mode HanMode) iter.Seq[string] {
	return func(yield func(string) bool) {
		rest := line
		for rest != "" {
			r, size := utf8.DecodeRuneInString(rest)
			switch {
			case isHan(r):
				end := runEnd(rest, isHan)
				if !yieldHan(rest[:end], mode, yield) {
					return
				}
				rest = rest[end:]
			case isWordRune(r):
				end := runEnd(rest, isWordRune)
				if !yield(strings.ToLower(rest[:end])) {
					return
				}
				rest = rest[end:]
			default:
				rest = rest[size:]
			}
		}
	}
}

func isHan(r rune) bool { return unicode.Is(unicode.Han, r) }

func isWordRune(r rune) bool {
	return !isHan(r) && (unicode.IsLetter(r) || unicode.IsDigit(r))
}

func runEnd(s string, keep func(rune) bool) int {
	for i, r := range s {
		if !keep(r) {
			return i
		}
	}
	return len(s)
}
["today" "s" "便" "當" "排" "骨" "飯" "x2"]
["today" "s" "便當" "排骨" "骨飯" "x2"]
  • 疊代器：Tokens 回傳 iter.Seq[string]，Count 用 for range 一個一個拿，不必先建一個 slice。測試裡用 slices.Collect 收成 slice 來比對。TestTokensStop 確認呼叫端 break 之後不會再呼叫 yield（13 章）。
  • unicode.Han 是一張 Unicode 範圍表，涵蓋繁體、簡體和日文漢字。unicode 套件裡還有 Hiragana、Katakana、Hangul 等表。
  • 切片不複製：rest[:end] 是原本字串的一段，不會配置新的記憶體；只有 ToLower 在需要改大小寫時才產生新字串。
  • 限制：撇號是分隔，所以 Today's 變成 today 和 s；1.27 會變成 1 和 27。要不要保留，看你的用途（延伸挑戰 2）。
  • fuzz 測試：FuzzTokens 用隨機的字串檢查兩件事：不會產生空字串或含空白的字詞；單字模式下漢字字詞的數量等於原文的漢字數。連不合法的 UTF-8 也要能處理（30 章）。

4. 中文：單字還是雙字

type HanMode int

func yieldHan(run string, mode HanMode, yield func(string) bool) bool {
	runes := []rune(run)
	if mode == HanChar || len(runes) == 1 {
		for _, r := range runes {
			if !yield(string(r)) {
				return false
			}
		}
		return true
	}
	for i := range len(runes) - 1 {
		if !yield(string(runes[i : i+2])) {
			return false
		}
	}
	return true
}

同一張公告，單字模式下（本頁開頭的輸出）排在前面的是「飯」「排」「骨」，看不出在說什麼；換成雙字：

go run . -han bigram -top 3 testdata/notice.txt
testdata/notice.txt：3 行，21 個字詞，29 個字元，90 bytes
出現最多的字詞：
  排骨  2
  骨飯  2
  今天  1
  • []rune 才能依字切：yieldHan 先把這一段漢字轉成 []rune，runes[i:i+2] 才是兩個字；直接切 string 的話，一個漢字是 3 個 byte，會切壞（08 章）。
  • 只有一個字的段落（例如「飯，好吃」的「飯」）在雙字模式下保留那一個字，不然它就消失了。
  • yieldHan 回傳 bool，把「呼叫端已經 break」往外傳，Tokens 收到 false 就立刻 return。拆出來的小函式也要遵守 yield 的規則。

5. 合計與排行

func (s *Stats) Add(other Stats) {
	s.Lines += other.Lines
	s.Words += other.Words
	s.Runes += other.Runes
	s.Bytes += other.Bytes
	if s.Counts == nil {
		s.Counts = map[string]int{}
	}
	for w, c := range other.Counts {
		s.Counts[w] += c
	}
}

type WordCount struct {
	Word  string
	Count int
}

func Top(counts map[string]int, n int) []WordCount {
	all := make([]WordCount, 0, len(counts))
	for w, c := range counts {
		all = append(all, WordCount{w, c})
	}
	slices.SortFunc(all, func(a, b WordCount) int {
		return cmp.Or(
			cmp.Compare(b.Count, a.Count), // 次數多的在前
			strings.Compare(a.Word, b.Word),
		)
	})
	return all[:min(max(n, 0), len(all))]
}
  • 零值也能 Add：run 裡的 var total Stats 沒有初始化 Counts，Add 第一次寫入前才建立 map。nil map 可以讀、不能寫（07 章）。
  • 排序要有第二個條件：map 的走訪順序每次都不一樣，次數相同的字詞如果不再依字詞排序，每次執行的結果會不同，Example 也就沒辦法比對。cmp.Or 回傳第一個不是 0 的比較結果，寫多個排序條件很簡潔。
  • Top 先全部排序再切：m 個字詞要 O(m log m)。一份公告只有幾百個字詞，這樣最簡單。真的要從幾百萬個字詞挑前 10 名，用大小為 n 的 heap 只要 O(m log n)（延伸挑戰 3）。
  • min(max(n, 0), len(all))：n 是負數時當成 0，超過字詞數時全部回傳，切片不會越界。

6. 中文的對齊

func Example_padRight() {
	for _, w := range []string{"go", "排骨飯", "rice"} {
		fmt.Printf("|%-6s|%s|\n", w, padRight(w, 6))
	}
	// Output:
	// |go    |go    |
	// |排骨飯   |排骨飯|
	// |rice  |rice  |
}
|go    |go    |
|排骨飯   |排骨飯|
|rice  |rice  |

在等寬字型下，第二欄的直線對齊，第一欄的不對齊。printTop 先算出前幾名裡最寬的字詞，再用 padRight 把每個字詞補到同樣的寬度：

func printTop(w io.Writer, top []WordCount) {
	if len(top) == 0 {
		return
	}
	col := 0
	for _, wc := range top {
		col = max(col, displayWidth(wc.Word))
	}
	fmt.Fprintln(w, "出現最多的字詞：")
	for _, wc := range top {
		fmt.Fprintf(w, "  %s  %d\n", padRight(wc.Word, col), wc.Count)
	}
}

func displayWidth(s string) int {
	w := 0
	for _, r := range s {
		w++
		if unicode.In(r, unicode.Han, unicode.Hiragana, unicode.Katakana, unicode.Hangul) ||
			r >= 0x3000 && r <= 0x303F || r >= 0xFF01 && r <= 0xFF60 {
			w++
		}
	}
	return w
}

func padRight(s string, width int) string {
	return s + strings.Repeat(" ", max(width-displayWidth(s), 0))
}
  • displayWidth 是簡化的規則，涵蓋中日韓文字和全形符號；完整的規則（Unicode 的 East Asian Width）在標準庫以外的 golang.org/x/text/width。08 章有更完整的說明。
  • 對齊只在終端機上有意義。輸出要給其他程式讀時，改用 tab 分隔或 JSON（延伸挑戰 4）。

7. 自己的旗標型別

-han 只接受 char 和 bigram 兩個值。與其收一個字串、到處比對，不如定義一個型別，讓 flag 套件在解析時就檢查：

func (m HanMode) MarshalText() ([]byte, error) {
	switch m {
	case HanChar:
		return []byte("char"), nil
	case HanBigram:
		return []byte("bigram"), nil
	}
	return nil, fmt.Errorf("不認得的 HanMode %d", int(m))
}

func (m *HanMode) UnmarshalText(text []byte) error {
	switch string(text) {
	case "char":
		*m = HanChar
	case "bigram":
		*m = HanBigram
	default:
		return fmt.Errorf("要用 char 或 bigram，收到 %q", text)
	}
	return nil
}

run 裡用 fs.TextVar(&mode, "han", HanChar, "…") 註冊。任何實作 encoding.TextUnmarshaler 的型別都可以當旗標，預設值則用 MarshalText 顯示在說明裡。給一個不認得的值：

go run . -han word testdata/notice.txt

輸出（stderr）

invalid value "word" for flag -han: 要用 char 或 bigram，收到 "word"
Usage of wordcount:
  -han value
    	中文的切法：char（單字）或 bigram（雙字） (default char)
  -top int
    	列出出現最多次的前幾個字詞 (default 5)
exit status 2
  • 前幾行是 flag 套件印的：錯誤訊息裡包含 UnmarshalText 回傳的錯誤，接著是自動產生的說明。最後一行是 go run 印的，表示程式以 exit code 2 結束。TestRunExitCodes 檢查了這個 exit code 和錯誤訊息。
  • 同一個型別也能用在 JSON、環境變數等任何「從文字解析」的地方：encoding/json 也認得 TextUnmarshaler（23 章）。
  • 另一個做法是 fs.Func，傳一個解析字串的函式。值只在一個地方用時比較輕便；值有自己的型別、會在多個地方傳遞時，TextVar 比較清楚（21 章）。

延伸挑戰

這些題目沒有附測試。先寫測試描述你要的行為，再改程式；改完 go test 和 Example 都要通過。

  1. 入門挑戰 1：停用詞

    加一個 -stop 旗標，指向一個檔案，每行一個不要計入排行的字詞（例如「的」「是」「the」）。

    提示

    讀進一個 map[string]bool 當成集合；Count 不用改，在 Top 之前把這些字詞從合計裡刪掉，或在 printTop 時跳過。想一想：停用詞要不要影響「字詞數」？

  2. 進階挑戰 2：保留縮寫和小數

    讓 don't、Today's、1.27 各自是一個字詞：撇號和小數點夾在兩個英數字元中間時，算在字詞裡。

    提示

    改 runEnd 的停止條件：遇到 ' 或 . 時往後看一個字元，如果還是英數就繼續。先把新的期望加進 TestTokens，FuzzTokens 不用改也應該繼續通過。

  3. 進階挑戰 3：用 heap 挑前幾名

    用 container/heap 維護一個大小為 n 的 min-heap，走過一次 map 就得到前 n 名，結果要和現在的 Top 完全相同（包括次數相同時的順序）。

    提示

    heap 的頂端放「目前前 n 名裡最差的那一個」，新的字詞比它好就替換掉。最後把 heap 裡的元素取出、再排序一次。寫一個 benchmark 用十萬個字詞比較兩種做法。

  4. 進階挑戰 4：JSON 輸出

    加一個 -json 旗標，輸出每個檔案的統計、合計和排行，讓其他程式可以讀。

    提示

    定義輸出用的 struct 並加上 json tag，用 encoding/json/v2 的 MarshalWrite 寫到 stdout（23 章）。map 的輸出順序記得加 json.Deterministic(true)，或直接輸出排序好的 slice。

  5. 挑戰挑戰 5：同時讀好幾個檔案

    檔案很多時，每個檔案用一個 goroutine 統計，但輸出的順序要和命令列的檔名順序相同，錯誤的處理也要和現在一樣。

    提示

    先建立和檔名一樣長的結果 slice，每個 goroutine 只寫自己那一格，就不需要鎖；用 WaitGroup 等全部完成後再依序輸出。同時開的檔案數用 buffered channel 當 semaphore 限制（19 章）。用 -race 跑測試。

重點回顧

  • 一個檔案出錯就回報到 stderr、繼續處理其他檔案，最後用 exit code 表示結果。
  • 每個檔案用一個函式處理，defer Close 才會在每個檔案結束時執行。
  • io.Reader 可能同時回傳資料和 io.EOF：先處理資料，再處理錯誤。
  • bufio.Scanner 預設一行最多 64KB；要讀任意長的行用 bufio.Reader，或調高 Buffer。
  • 漢字也是 Letter：分類字元時先判斷 unicode.Han。依字切中文要先轉成 []rune。
  • 排序加上第二個條件，讓 map 產生的結果固定。
  • fmt 的寬度以字元計算；中文的對齊要依顯示寬度補空白。
  • 有固定選項的旗標，定義一個實作 TextUnmarshaler 的型別，用 flag.TextVar 註冊。

延伸閱讀

  • 套件文件：bufio.Reader.ReadString、bufio.Scanner.Buffer、unicode 的範圍表、flag.TextVar、encoding.TextUnmarshaler、container/heap。
  • Go 語言規格：字串和 []rune 的轉換。
