疊代器

疊代器是一台叫號機：你要下一號，它就叫下一號；你說不用了，它就關機收工，不會繼續叫下去。

1. range 一個函式

03 章的 range 可以走過 slice、map、字串、channel 和整數。Go 1.23 起，range 後面也可以接一個函式，只要它長成這個樣子：

func callNumbers(from, to int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := from; n <= to; n++ {
			if !yield(n) {
				return
			}
		}
	}
}

func rangeFuncDemo() {
	for n := range callNumbers(17, 19) {
		fmt.Println("請", n, "號")
	}
}

輸出

請 17 號
請 18 號
請 19 號

callNumbers 回傳的是一個函式，它的參數叫 yield（「交出」），型別是 func(int) bool。這種「收一個 yield 函式當參數」的函式，就叫疊代器（iterator）。標準庫的 iter 套件替它取了名字：

  • iter.Seq[V] 就是 func(yield func(V) bool)，每次交出一個值，range 時寫 for v := range seq。
  • iter.Seq2[K, V] 就是 func(yield func(K, V) bool)，每次交出兩個值，range 時寫 for k, v := range seq，像走過 map 一樣。

兩個都是用函式型別定義的泛型型別，不是 interface，不需要實作任何方法。yield 也可以不收參數（func(yield func() bool)），range 時只寫 for range f，很少用到。

range 一個函式時，Go 會把迴圈本體包成一個 yield 函式，再把它傳給疊代器。疊代器裡每呼叫一次 yield，迴圈本體就執行一次，執行完 yield 回傳 true，表示「繼續」。下面這段程式不用 range，自己動手把迴圈本體包成函式傳進去，印出來的東西一模一樣：

func byHand() {
	seq := callNumbers(17, 19)
	seq(func(n int) bool {
		fmt.Println("請", n, "號")
		return true
	})
}

輸出

請 17 號
請 18 號
請 19 號

所以疊代器是「推」（push）的模式：值由疊代器推給你，什麼時候推、推幾個，由疊代器的程式決定。寫疊代器的人只要寫一個普通的 for 迴圈，在要交出值的地方呼叫 yield，「目前走到哪裡」就留在區域變數 n 裡，不需要另外記狀態。

yield 一定要回傳 bool，range 才接受。少了 bool 的函式就不是疊代器：

package main

import "fmt"

func numbers(yield func(int)) {
	for n := 1; n <= 3; n++ {
		yield(n)
	}
}

func main() {
	for n := range numbers {
		fmt.Println(n)
	}
}

編譯錯誤

./main.go:12:17: cannot range over numbers (value of type func(yield func(int))): func must be func(yield func(...) bool): yield func does not return bool

注意 range 後面接的是函式本身 numbers，不是呼叫它。callNumbers 寫成「回傳疊代器的函式」，是為了能帶參數 17、19 進去；range 的是它回傳的那個函式。

2. yield 的約定：提早結束

使用端可以隨時 break。這時迴圈本體不會再執行，但疊代器還在它自己的 for 迴圈裡，它得知道要停。所以 yield 會回傳一個 bool：

  • 回傳 true：迴圈本體正常跑完這一圈，還要下一個值。
  • 回傳 false：使用端已經離開迴圈了（break、return，或用 goto 跳出去）。疊代器必須立刻停止，不可以再呼叫 yield。

這就是每個疊代器都寫 if !yield(v) { return } 的原因。它帶來一個好處：疊代器可以在結束時收尾，例如關檔案、釋放資源，不管使用端是全部跑完還是中途離開：

func receipts() iter.Seq[string] {
	return func(yield func(string) bool) {
		fmt.Println("打開收據匣")
		defer fmt.Println("關上收據匣")
		for _, r := range []string{"A-001", "A-002", "A-003"} {
			if !yield(r) {
				return
			}
		}
	}
}

func earlyStopDemo() {
	for r := range receipts() {
		fmt.Println("處理", r)
		if r == "A-002" {
			break
		}
	}
	fmt.Println("迴圈結束")
}

輸出

打開收據匣
處理 A-001
處理 A-002
關上收據匣
迴圈結束

注意順序：「關上收據匣」印在「迴圈結束」之前。break 之後，yield 回傳 false，疊代器 return，它的 defer 執行，然後 range 才結束，程式繼續往下走。收尾一定在迴圈結束時已經完成。

不理會 yield 的回傳值，就違反了約定。使用端都已經 break 了，疊代器還繼續交出下一個值，Go 會直接 panic，不會讓迴圈本體在 break 之後又被執行：

func rudeNumbers() iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := 1; n <= 3; n++ {
			yield(n)
		}
	}
}

func ignoreYieldDemo() {
	defer func() {
		fmt.Println("panic:", recover())
	}()
	for n := range rudeNumbers() {
		fmt.Println(n)
		break
	}
}

輸出

1
panic: runtime error: range function continued iteration after function for loop body returned false

這個錯誤只有在使用端提早離開時才會出現，全部跑完的時候看不出來。所以測試疊代器時，一定要有一個「取幾個就 break」的案例，本章的練習測試都有。

深入：第一次讀可以先跳過

2.1 迴圈本體 panic 的時候

迴圈本體是被 yield 呼叫的，所以本體裡的 panic 會從 yield 冒出來，往上經過疊代器，再傳到外面。panic 往上傳的路上，疊代器的 defer 一樣會執行（04 章），收據匣照樣會關上。疊代器不應該用 recover 把它吞掉，那個 panic 不是疊代器造成的。

另外，迴圈本體裡的 return 會讓 yield 回傳 false、疊代器收尾，然後外層的函式才真的 return。對使用端來說，range 一個函式和 range 一個 slice 寫起來沒有兩樣，break、continue、return 都照常使用。

3. 替自己的型別寫疊代器

疊代器最常見的用途，是讓使用端可以 range 你自己的資料結構，不必知道裡面怎麼存。習慣上，型別提供一個回傳疊代器的方法，最常用的名字是 All：

type Menu struct {
	names  []string
	prices map[string]int
}

func (m *Menu) Add(name string, price int) {
	if m.prices == nil {
		m.prices = map[string]int{}
	}
	if _, ok := m.prices[name]; !ok {
		m.names = append(m.names, name)
	}
	m.prices[name] = price
}

func (m *Menu) All() iter.Seq2[string, int] {
	return func(yield func(string, int) bool) {
		for _, n := range m.names {
			if !yield(n, m.prices[n]) {
				return
			}
		}
	}
}

func seq2Demo() {
	var m Menu
	m.Add("排骨飯", 85)
	m.Add("雞腿飯", 95)
	m.Add("紅茶", 25)
	for name, price := range m.All() {
		fmt.Println(name, price)
	}
}

輸出

排骨飯 85
雞腿飯 95
紅茶 25

Menu 裡其實有一個 slice 和一個 map，用 slice 記住加入的順序。如果直接開放這兩個欄位，使用端得自己知道「要走 names、再拿名字去查 prices」。All 把這件事藏起來，回傳一個 iter.Seq2[string, int]，使用端只要寫 for name, price := range m.All()。以後內部改成別的存法，使用端的程式一行都不用改。

方法的命名可以參考標準庫的習慣：交出全部內容的叫 All，只交出 key 或 value 的叫 Keys、Values，倒著走的叫 Backward。疊代器有其他順序或條件時，用描述性的名字，例如下面的 Walk。

遞迴的資料結構（樹、巢狀的分類）用疊代器特別順手，因為寫疊代器的人可以用遞迴，使用端卻只看到一個普通的 range。唯一要小心的是：使用端喊停時，每一層遞迴都要停下來：

type Category struct {
	Name     string
	Children []*Category
}

func (c *Category) Walk() iter.Seq[string] {
	return func(yield func(string) bool) {
		c.walk("", yield)
	}
}

func (c *Category) walk(prefix string, yield func(string) bool) bool {
	path := prefix + c.Name
	if !yield(path) {
		return false
	}
	for _, child := range c.Children {
		if !child.walk(path+"/", yield) {
			return false
		}
	}
	return true
}

func treeDemo() {
	menu := &Category{Name: "菜單", Children: []*Category{
		{Name: "便當", Children: []*Category{{Name: "排骨飯"}, {Name: "雞腿飯"}}},
		{Name: "飲料", Children: []*Category{{Name: "紅茶"}}},
	}}
	for path := range menu.Walk() {
		fmt.Println(path)
	}
	for path := range menu.Walk() {
		if path == "菜單/便當/雞腿飯" {
			fmt.Println("找到", path)
			break
		}
	}
}

輸出

菜單
菜單/便當
菜單/便當/排骨飯
菜單/便當/雞腿飯
菜單/飲料
菜單/飲料/紅茶
找到 菜單/便當/雞腿飯
  • Walk 本身只是把遞迴的 walk 包成 iter.Seq[string]。
  • walk 多了一個 bool 回傳值，意思是「還要繼續嗎」。yield 回傳 false 時，walk 回傳 false；上一層看到子分類回傳 false，自己也立刻回傳 false。這樣 false 會一路傳回最上層，不會有任何一層再呼叫 yield。
  • 如果 walk 不回傳 bool，只在自己這層檢查 yield，那麼 break 之後，上一層的迴圈會繼續走到「飲料」，再呼叫一次 yield，結果就是第 2 節看過的 panic。
  • 第二個 range 找到雞腿飯就 break，所以第二次只印出一行「找到」，飲料那一支完全沒有走。

4. 標準庫的疊代器

Go 1.23 加入疊代器時，slices 和 maps 套件也一起加了一批回傳或接收疊代器的函式，Go 1.24 再補上 strings 和 bytes 的：

func stdlibDemo() {
	stock := map[string]int{"雞腿飯": 0, "排骨飯": 10, "滷蛋": 25}
	fmt.Println(slices.Sorted(maps.Keys(stock)))

	queue := []int{17, 18, 19}
	for i, n := range slices.Backward(queue) {
		fmt.Println(i, n)
	}

	receipt := "排骨飯 x2\n紅茶 x1\n合計 195\n"
	for line := range strings.Lines(receipt) {
		fmt.Printf("%q\n", line)
	}

	for batch := range slices.Chunk([]int{1, 2, 3, 4, 5}, 2) {
		fmt.Println(batch)
	}
}

輸出

[排骨飯 滷蛋 雞腿飯]
2 19
1 18
0 17
"排骨飯 x2\n"
"紅茶 x1\n"
"合計 195\n"
[1 2]
[3 4]
[5]
  • maps.Keys 交出 map 的所有 key，順序和走訪 map 一樣不固定（07 章）。slices.Sorted 把疊代器的值收集成 slice 並排序，兩個接起來就是「排好序的 key」，這是最常見的組合。
  • slices.Backward 從最後一個往前走，索引也是原本的索引。
  • strings.Lines 一行一行交出字串的內容，每一行都包含結尾的換行，最後一行沒有換行就不含。用 %q 印出來就看得到 \n。
  • slices.Chunk 每 n 個切成一段。交出的子 slice 和原本的 slice 共用底層陣列，但容量被切到剛好，對它 append 不會蓋到下一段。

常用的整理成一張表。左半邊產生疊代器，右半邊把疊代器收集回 slice 或 map：

函式做什麼版本
slices.All(s)交出索引和元素（Seq2）1.23
slices.Values(s)只交出元素1.23
slices.Backward(s)從尾巴往前交出索引和元素1.23
slices.Chunk(s, n)每 n 個一段的子 slice1.23
maps.All、Keys、Values交出 map 的內容，順序不固定1.23
strings.Lines(s)每一行，含結尾的換行1.24
strings.SplitSeq、FieldsSeq和 Split、Fields 一樣切字串，但不先建 slice1.24
slices.Collect(seq)收集成 slice1.23
slices.Sorted(seq)收集成 slice 並排序1.23
maps.Collect(seq2)收集成新的 map1.23
maps.Insert(m, seq2)加進現有的 map，key 重複就覆蓋1.23

這些函式讓 slice、map 和疊代器可以互相轉換。例如 maps.Collect(m.All()) 就能把第 3 節的 Menu 轉成一個普通的 map。只是要對每一個值做點事時，直接 range 就好，不必先 Collect 成 slice。

5. 串成管線

疊代器可以接收疊代器、再回傳疊代器，一層包一層，就成了管線（pipeline）。這三個轉接函式都只有幾行，而且因為是泛型，任何型別都能用：

func Filter[T any](seq iter.Seq[T], keep func(T) bool) iter.Seq[T] {
	return func(yield func(T) bool) {
		for v := range seq {
			if keep(v) && !yield(v) {
				return
			}
		}
	}
}

func Map[T, U any](seq iter.Seq[T], f func(T) U) iter.Seq[U] {
	return func(yield func(U) bool) {
		for v := range seq {
			if !yield(f(v)) {
				return
			}
		}
	}
}

func Take[T any](seq iter.Seq[T], n int) iter.Seq[T] {
	return func(yield func(T) bool) {
		if n <= 0 {
			return
		}
		count := 0
		for v := range seq {
			if !yield(v) {
				return
			}
			count++
			if count == n {
				return
			}
		}
	}
}

每一個都是同樣的形狀：回傳一個新的疊代器，裡面 range 上游的疊代器，處理之後交給自己的 yield，yield 回傳 false 就 return。Take 多做了一件事：數到 n 個就主動 return。它一 return，裡面那個 for v := range seq 就結束了，對上游來說，這跟使用端 break 一模一樣，上游的 yield 也收到 false。

所以上游可以是無限的：

func naturals() iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := 1; ; n++ {
			if !yield(n) {
				return
			}
		}
	}
}

func pipelineDemo() {
	nums := Filter(naturals(), func(n int) bool { return n%10 != 4 })
	labels := Map(nums, func(n int) string { return fmt.Sprintf("%03d", n) })
	fmt.Println(slices.Collect(Take(labels, 5)))
}

輸出

[001 002 003 005 006]

naturals 永遠不會自己結束，但整條管線只跑到需要的地方。Filter、Map 那兩行執行時什麼也沒算，只是把疊代器包起來；直到最後 slices.Collect 開始 range，值才一個一個被拉出來。這叫惰性求值（lazy evaluation）。把每一步印出來就看得很清楚：

func lazyDemo() {
	src := func(yield func(int) bool) {
		for n := 1; n <= 3; n++ {
			fmt.Println("產生", n)
			if !yield(n) {
				return
			}
		}
	}
	doubled := Map(src, func(n int) int {
		fmt.Println("加倍", n)
		return n * 2
	})
	for v := range doubled {
		fmt.Println("拿到", v)
		if v == 4 {
			break
		}
	}
}

輸出

產生 1
加倍 1
拿到 2
產生 2
加倍 2
拿到 4

「產生、加倍、拿到」是交錯出現的：一個值走完整條管線，下一個值才產生。拿到 4 就 break，所以第 3 個值根本沒有產生，也沒有加倍。如果改用 slice 一步一步做（先產生全部、再全部加倍），每一步都要多一個完整的中間 slice，而且算了用不到的值。

標準庫目前沒有提供 Map、Filter 這類轉接函式。需要時自己寫，就像上面這樣；也別把所有迴圈都改寫成管線，一個普通的 for 迴圈裡寫 if 和 continue，常常更好讀。管線的價值在資料量大、來源無限，或是要重複組合同一套步驟的時候。

6. iter.Pull

range 很方便，但它一次只能走一個疊代器，而且節奏由疊代器決定。有時候你需要自己決定什麼時候拿下一個值，例如同時從兩個疊代器交錯取值。這時用 iter.Pull：

func pullBasics() {
	next, stop := iter.Pull(slices.Values([]string{"A-001", "A-002"}))
	defer stop()

	v1, ok1 := next()
	v2, ok2 := next()
	v3, ok3 := next()
	fmt.Println(v1, ok1, v2, ok2)
	fmt.Printf("%q %v\n", v3, ok3)
}

輸出

A-001 true A-002 true
"" false
  • iter.Pull(seq) 回傳兩個函式：next 和 stop（Seq2 用 iter.Pull2）。
  • 每呼叫一次 next()，就拿到下一個值和一個 ok。用完了 ok 是 false，值是零值。這和 map 的 comma-ok 是同一個習慣。
  • stop() 告訴疊代器「不要了」，就像 range 時的 break：疊代器的 yield 收到 false，執行它的 defer。沒拿完就不要了的時候一定要呼叫 stop，否則疊代器會一直停在那裡等，它的收尾永遠不會執行。最保險的寫法是拿到之後馬上 defer stop()，多呼叫幾次也沒關係。
  • next 和 stop 不能同時從好幾個 goroutine 呼叫。

實際的例子：叫號機的號碼和空出來的櫃台，是兩個各自的來源，要一個配一個。range 號碼，每拿到一個號碼，就用 next 向櫃台要一個：

func assign(nums iter.Seq[int], counters iter.Seq[string]) iter.Seq2[int, string] {
	return func(yield func(int, string) bool) {
		next, stop := iter.Pull(counters)
		defer stop()
		for n := range nums {
			c, ok := next()
			if !ok || !yield(n, c) {
				return
			}
		}
	}
}

func pullDemo() {
	nums := slices.Values([]int{17, 18, 19, 20})
	counters := slices.Values([]string{"1 號櫃台", "2 號櫃台", "3 號櫃台"})
	for n, c := range assign(nums, counters) {
		fmt.Println(n, "→", c)
	}
}

輸出

17 → 1 號櫃台
18 → 2 號櫃台
19 → 3 號櫃台

櫃台只有 3 個，next 第 4 次回傳 ok 為 false，assign 就 return，20 號沒有被配到。assign 本身也是一個疊代器，所以它也遵守 yield 的約定，而且用 defer 確保櫃台那邊的 stop 一定會被呼叫。

Pull 比直接 range 多了一層轉換。能用 range 寫的，就用 range；只有需要「自己控制節奏」，例如同時從兩個以上的疊代器取值、比較或合併時，才用 Pull。練習 6 會用它合併兩條排好序的資料。

7. 疊代器、slice 與 channel

函式要交出一串值時，有三種選擇，怎麼選：

  • 回傳 slice：資料本來就在記憶體裡、數量不大，或是使用端需要索引、長度、排序、讀好幾次。這是最簡單的選擇，不確定的時候先用它。
  • 回傳疊代器：資料量大或無限、每個值的計算有成本、使用端常常只要前幾個，或是你想把內部的資料結構藏起來（第 3 節）。疊代器在使用端的 goroutine 裡執行，沒有並行，也沒有同步的成本。
  • 回傳 channel：值由另一個 goroutine 產生，真的需要並行，例如一邊下載一邊處理。channel 每傳一個值都要同步，而且要有人負責 close、要處理 goroutine 洩漏，詳見 14 goroutine 和 15 channel。在 Go 1.23 以前，有人會用 goroutine 加 channel 來寫「產生器」，現在這種用途應該改用疊代器。

疊代器還有一個 slice 沒有的性質要注意：有些疊代器只能用一次：

func reuseDemo() {
	seq := callNumbers(1, 3)
	fmt.Println(slices.Collect(seq), slices.Collect(seq))

	sc := bufio.NewScanner(strings.NewReader("排骨飯\n紅茶\n"))
	once := func(yield func(string) bool) {
		for sc.Scan() {
			if !yield(sc.Text()) {
				return
			}
		}
	}
	fmt.Println(slices.Collect(once), slices.Collect(once))
}

輸出

[1 2 3] [1 2 3]
[排骨飯 紅茶] []

callNumbers 的疊代器每次被 range，都從 1 重新數起，所以兩次 Collect 結果一樣。once 讀的是一個 bufio.Scanner，第一次就把資料讀完了，Scanner 不會倒帶，第二次什麼都拿不到。從檔案、網路、標準輸入這類「資料流」讀的疊代器，通常都是這樣。標準庫的文件會寫明「It returns a single-use iterator」，例如 strings.Lines 和 strings.SplitSeq。自己寫的單次疊代器，也應該在註解裡說清楚。

深入：第一次讀可以先跳過

7.1 會失敗的疊代器

從檔案一行一行讀時，讀到一半可能出錯，但 yield 沒有地方放 error。常見的做法有兩種：

  • 回傳 iter.Seq2[T, error]，每一圈都交出值和錯誤，使用端在迴圈裡檢查 err。錯誤跟著出錯的位置走，但每一圈都得寫檢查。
  • 學 bufio.Scanner：疊代器只交出值，出錯就停止，另外提供一個方法讓使用端在迴圈結束後查詢錯誤。迴圈本體比較乾淨，但使用端很容易忘了查。

兩種都有人用，挑一種，並在文件裡寫清楚（11 錯誤處理）。

常見錯誤

1. 不理會 yield 的回傳值

錯：使用端 break 之後還繼續交出值，執行期 panic

func rudeNumbers() iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := 1; n <= 3; n++ {
			yield(n)
		}
	}
}

對：yield 回傳 false 就 return

func callNumbers(from, to int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := from; n <= to; n++ {
			if !yield(n) {
				return
			}
		}
	}
}

全部跑完時兩者看起來一樣，只有 break 時才會 panic “range function continued iteration after function for loop body returned false”（第 2 節）。測試一定要有提早離開的案例。

2. 遞迴時沒有把 false 往上傳

只在最底層檢查 yield 不夠，每一層遞迴都要知道「使用端喊停了」，否則上一層的迴圈會繼續走下一個子節點，再呼叫一次 yield，一樣 panic。讓遞迴的輔助函式回傳 bool，見第 3 節的 walk。

3. 以為 maps.Keys 有固定順序

maps.Keys、maps.Values、maps.All 的順序和 range map 一樣，每次都可能不同。要固定的順序就用 slices.Sorted(maps.Keys(m))。

4. 用了 iter.Pull 卻沒有呼叫 stop

沒拿完就不要了，疊代器會一直停在 yield 那裡等，它的 defer 永遠不會執行，檔案不會關、資源不會釋放。拿到 next 和 stop 之後，下一行就寫 defer stop()。

5. 把單次疊代器 range 兩次

第二次什麼都拿不到，或從上次停下來的地方繼續，不會報錯（第 7 節）。需要讀好幾次，就先 slices.Collect 成 slice。

6. 交出去的 slice 被下一輪改掉

疊代器每次交出一個 slice 時，如果重複使用同一個底層陣列（例如每次都 buf = buf[:0]），使用端把前一個 slice 留下來，內容會被下一輪蓋掉（06 章）。要嘛每次交出新的 slice，要嘛在文件裡寫明「只在這一圈有效」。練習 5 就是要你處理這件事。

題目在 exercises/13-iterators/exercises.go。每一題的測試都會「取幾個就 break」，所以每個疊代器都要遵守 yield 的約定。

go test ./exercises/13-iterators/                  # 跑全部練習
go test ./exercises/13-iterators/ -run TestEvery  # 只跑一題
go test -tags solution ./exercises/13-iterators/   # 跑參考解答

  1. 入門練習 1：發車時刻

    公車從某個時間開始，每隔固定的分鐘數發一班車。時間用「從午夜起算的分鐘數」表示。

    func Every(from, to, step int) iter.Seq[int] {
	// TODO: 實作
	return func(yield func(int) bool) {}
}

    Every(360, 420, 15) 是早上 6 點到 7 點每 15 分鐘一班。測試：TestEvery。

    提示

    和第 1 節的 callNumbers 一樣，只是每次加 step。step 小於等於 0 時要先 return，否則迴圈永遠不會結束。

  2. 入門練習 2：加上行號

    把收據的每一行加上行號交出去，交出的是 iter.Seq2。

    func Numbered(s string) iter.Seq2[int, string] {
	// TODO: 實作
	return func(yield func(int, string) bool) {}
}

    測試：TestNumbered。

    提示

    用 strings.Lines 拿到每一行（第 4 節），它包含結尾的換行，用 strings.TrimSuffix(line, "\n") 去掉。行號用一個計數器。

  3. 進階練習 3：叫號機按了兩次

    叫號機偶爾會重複送出同一個號碼，連續重複的只留一個。

    func Dedup[T comparable](seq iter.Seq[T]) iter.Seq[T] {
	// TODO: 實作
	return func(yield func(T) bool) {}
}

    測試：TestDedup。

    提示

    記住上一個交出去的值。第一個值沒有「上一個」，不能拿零值來比，測試的第一個值剛好就是空字串。多用一個 bool 記錄「是不是第一個」。

  4. 進階練習 4：捷運區間

    給一串站名，交出每一段相鄰兩站的區間。

    func Segments[T any](seq iter.Seq[T]) iter.Seq2[T, T] {
	// TODO: 實作
	return func(yield func(T, T) bool) {}
}

    測試：TestSegments。

    提示

    和練習 3 一樣記住上一個值和「有沒有上一個」。從第二個值開始，每拿到一個就交出（上一個, 這一個）。

  5. 進階練習 5：外送分批

    外送員一趟最多帶 n 份，把訂單每 n 份分成一批。

    func Batch[T any](seq iter.Seq[T], n int) iter.Seq[[]T] {
	// TODO: 實作
	return func(yield func([]T) bool) {}
}

    測試會把每一批都留下來再檢查，所以重用同一個 slice 會失敗。測試：TestBatch。

    提示

    用一個容量 n 的 slice 收集，收滿就 yield，然後 make 一個新的，不要用 buf[:0]（常見錯誤 6）。迴圈結束後，buf 裡還有剩的也要交出。

  6. 挑戰練習 6：合併兩家分店的發票

    兩家分店的發票號碼各自排好了序，合併成一條，結果也要排好序。

    func MergeSorted[T cmp.Ordered](a, b iter.Seq[T]) iter.Seq[T] {
	// TODO: 實作
	return func(yield func(T) bool) {}
}

    測試會檢查提早結束時，兩個來源都有被停止。測試：TestMergeSorted。

    提示

    兩邊各用一次 iter.Pull，拿到後馬上 defer stop()。先各拿一個值，只要還有一邊 ok 就繼續：交出比較小的那個（另一邊已經用完時，交出還有的那邊），再從交出的那一邊拿下一個（第 6 節）。

  7. 找錯練習 7：只要兩個座位

    全部取完沒問題，取兩個就 break 時 panic。

    func Seats(row string, n int) iter.Seq[string] {
	return func(yield func(string) bool) {
		for i := 1; i <= n; i++ {
			yield(fmt.Sprintf("%s%d", row, i))
		}
	}
}

    測試：TestSeats。

    提示

    常見錯誤 1。

重點回顧

  • 疊代器是收一個 yield 函式的函式；iter.Seq[V] 交出一個值，iter.Seq2[K, V] 交出兩個值。
  • range 一個函式時，迴圈本體被包成 yield，由疊代器呼叫；這是 push 的模式。
  • yield 回傳 false 表示使用端離開了迴圈，疊代器必須立刻 return，不然會 panic。
  • 疊代器的 defer 會在迴圈結束前執行，適合用來收尾。
  • 型別用 All、Keys、Values、Backward 這類方法交出疊代器；遞迴時要把 false 一層一層往上傳。
  • slices.Collect、slices.Sorted、maps.Keys、strings.Lines 等函式讓疊代器和 slice、map 互相轉換。
  • 疊代器可以串成惰性的管線，用不到的值不會被產生，來源可以是無限的。
  • iter.Pull 換成 next 和 stop，用來同時從多個來源取值；stop 一定要呼叫。
  • 不確定就回傳 slice；資料大、無限或要藏起內部結構就用疊代器；真的需要並行才用 channel。有些疊代器只能用一次。
