本章你會學到

  • shell 怎麼把一行指令切成 os.Args，引號和 *.txt 是誰處理的。
  • 用 flag.FlagSet 解析旗標，自訂用法說明，分辨「使用者要看說明」和「用錯了」。
  • 用一個 switch 加上每個子命令自己的 FlagSet，做出 tally total、tally top。
  • 沒給檔名就讀標準輸入，讓工具可以接在管線裡。
  • 結果寫 stdout、錯誤寫 stderr、用結束碼告訴 shell 成功或失敗；main 只呼叫 run。
  • 設定的優先順序：命令列旗標 > 環境變數 > 內建預設值。
  • 用 signal.NotifyContext 把 Ctrl-C 變成 ctx 的取消，收好尾再結束。

先備：02 章的標準輸入、輸出與錯誤、18 章的取消原因、20 章的開檔。

這一章的程式本身就是一個完整的工具 tally，加總便當店的營業額。每一行輸入是「品項 金額」。main 只把作業系統的東西接上 run，run 不碰 os.Args、os.Exit，所以測試可以像呼叫一般函式一樣呼叫它。頁面上的輸出都是測試用這個小工具跑出來的：

const sales = "排骨飯 90\n雞腿飯 100\n排骨飯 90\n滷肉飯 60\n"

func try(ctx context.Context, stdin string, env map[string]string, args ...string) {
	var stdout, stderr strings.Builder
	code := run(ctx, args, sys{
		stdin:  strings.NewReader(stdin),
		stdout: &stdout,
		stderr: &stderr,
		getenv: func(key string) string { return env[key] },
	})

	prompt := []string{"$"}
	for _, k := range slices.Sorted(maps.Keys(env)) {
		prompt = append(prompt, k+"="+env[k])
	}
	fmt.Println(strings.Join(slices.Concat(prompt, []string{"tally"}, args), " "))
	fmt.Print(stdout.String())
	for line := range strings.Lines(stderr.String()) {
		fmt.Println(strings.TrimRight("stderr｜"+line, " \n"))
	}
	fmt.Println("結束碼", code)
}

1. os.Args：shell 交給你的參數

在終端機打的一行指令，程式拿到的是 os.Args，一個 []string。第一個元素是程式本身的路徑，後面才是參數。用一個只會印出 os.Args 的小程式看看：

// args 把 os.Args 的每一個元素印出來，看 shell 把命令列切成了哪幾段。
//
// 執行（先編譯，os.Args[0] 才會是簡短的 ./args）：
//
//	go build -o args ./chapters/21-cli/args
//	./args total -tax 10 "週一 營業額.txt"
package main

import (
	"fmt"
	"os"
)

func main() {
	for i, a := range os.Args {
		fmt.Printf("os.Args[%d] = %q\n", i, a)
	}
}

在一個有 sales.txt 的目錄裡執行

$ ./args total -tax 10 "週一 營業額.txt"
os.Args[0] = "./args"
os.Args[1] = "total"
os.Args[2] = "-tax"
os.Args[3] = "10"
os.Args[4] = "週一 營業額.txt"
$ ./args *.txt
os.Args[0] = "./args"
os.Args[1] = "sales.txt"
  • 引號是給 shell 看的："週一 營業額.txt" 變成一個參數，引號本身不會傳進來。
  • *.txt 也是 shell 展開的，程式拿到的是展開後的檔名。在 Windows 的命令提示字元裡，萬用字元不會被展開，程式拿到的就是 *.txt 這個字串。
  • 用 go run 執行時，os.Args[0] 是 go 編譯在暫存目錄裡的執行檔路徑，又長又不固定，所以這裡先 go build -o args 再執行。
  • 除了把 os.Args[1:] 交給 run，程式的其他地方都不應該直接讀 os.Args：參數從函式的參數進來，測試才能換成自己的。

2. flag 套件

自己切 os.Args 很快就會變得一團亂：-tax 10、-tax=10、少給值、給了不認得的旗標，每一種都要處理。標準庫的 flag 套件都做好了。簡單的小程式可以直接用全域的 flag.Int 加 flag.Parse()；要測試、要子命令的工具，自己開一個 flag.FlagSet：

func total(ctx context.Context, args []string, s sys) int {
	fs := flag.NewFlagSet("tally total", flag.ContinueOnError)
	fs.SetOutput(s.stderr)

	tax, err := envInt(s.getenv, "TALLY_TAX", 5)
	if err != nil {
		fmt.Fprintf(s.stderr, "tally total：%v\n", err)
		return exitUsage
	}
	fs.IntVar(&tax, "tax", tax, "稅率（百分比），也可以用環境變數 TALLY_TAX 設定")
	fs.Usage = func() {
		fmt.Fprintln(fs.Output(), "用法：tally total [-tax 百分比] [檔案…]")
		fs.PrintDefaults()
	}
	if code, ok := parse(fs, args); !ok {
		return code
	}

	sum := 0
	err = readSales(ctx, fs.Args(), s.stdin, func(_ string, price int) {
		sum += price
	})
	if err != nil {
		return fail(ctx, s.stderr, "tally total", err)
	}

	withTax := (sum*(100+tax) + 50) / 100 // 四捨五入到整數元
	fmt.Fprintf(s.stdout, "合計 %d 元，含稅 %d%% 共 %d 元\n", sum, tax, withTax)
	return exitOK
}
func parse(fs *flag.FlagSet, args []string) (int, bool) {
	err := fs.Parse(args)
	switch {
	case err == nil:
		return exitOK, true
	case errors.Is(err, flag.ErrHelp):
		return exitOK, false // 使用者自己要看說明，不算失敗
	default:
		return exitUsage, false
	}
}
  • flag.ContinueOnError：解析失敗時回傳錯誤，讓 run 自己決定結束碼。全域的 flag.Parse 用的是 ExitOnError，會直接結束程式（-h 結束碼 0，其他錯誤 2），測試沒辦法呼叫。
  • fs.SetOutput(s.stderr)：flag 的錯誤訊息和用法說明寫到這裡。不設定的話會寫到真的 os.Stderr，測試抓不到。
  • fs.Usage 換成自己的說明，再呼叫 fs.PrintDefaults() 列出每個旗標、型別和預設值。
  • -tax 的預設值不是寫死的 5，而是 envInt 算出來的值，第 6 節會說明。

正常的用法：

$ tally total
合計 340 元，含稅 5% 共 357 元
結束碼 0
$ tally total -tax=10
合計 340 元，含稅 10% 共 374 元
結束碼 0

值的型別不對時，flag 寫出錯誤和用法說明，run 回傳 2。使用者自己要求 -h 時，說明一樣寫到 stderr，但結束碼是 0，因為這不是錯誤：

結束碼 2
$ tally top -h

flag 遇到第一個不是旗標的參數就停下來（這裡是代表標準輸入的 -），後面的 -tax 10 被當成兩個檔名：

$ tally total - -tax 10
stderr｜tally total：open -tax: no such file or directory
結束碼 1
  • 很多 Unix 工具允許旗標寫在檔名後面，Go 的 flag 不允許。旗標一定寫在前面；檔名本身以 - 開頭時，先寫 --，後面的就都不會被當成旗標。
  • 內建的型別有 Bool、Int、Int64、Uint、Float64、String、Duration（-timeout 1m30s）。其他型別用 fs.Func（Go 1.16 起）傳一個解析函式，或用 fs.TextVar（Go 1.19 起）接任何實作 encoding.TextUnmarshaler 的型別。

3. 子命令

go build、go test、git commit 都是子命令的設計：一個工具做好幾件相關的事。寫法很直接，run 用 switch 看第一個參數，把剩下的參數交給對應的函式：

const usage = `用法：tally <子命令> [旗標] [檔案…]

子命令：
  total   加總營業額
  top     列出賣最多的品項

沒有給檔案、或檔名是 - 時，從標準輸入讀。
每一行是「品項 金額」，例如：排骨飯 90
`

type sys struct {
	stdin          io.Reader
	stdout, stderr io.Writer
	getenv         func(string) string
}

func run(ctx context.Context, args []string, s sys) int {
	if len(args) == 0 {
		fmt.Fprint(s.stderr, usage)
		return exitUsage
	}
	switch cmd, rest := args[0], args[1:]; cmd {
	case "total":
		return total(ctx, rest, s)
	case "top":
		return top(ctx, rest, s)
	case "help", "-h", "-help", "--help":
		fmt.Fprint(s.stdout, usage)
		return exitOK
	default:
		fmt.Fprintf(s.stderr, "tally：不認得的子命令 %q\n\n%s", cmd, usage)
		return exitUsage
	}
}

top 和 total 的結構一樣：開 FlagSet、解析、讀輸入、輸出結果。份數一樣時照品項名稱排，輸出才會固定：

func top(ctx context.Context, args []string, s sys) int {
	fs := flag.NewFlagSet("tally top", flag.ContinueOnError)
	fs.SetOutput(s.stderr)
	n := fs.Int("n", 3, "列出幾個品項")
	fs.Usage = func() {
		fmt.Fprintln(fs.Output(), "用法：tally top [-n 個數] [檔案…]")
		fs.PrintDefaults()
	}
	if code, ok := parse(fs, args); !ok {
		return code
	}
	if *n < 1 {
		fmt.Fprintln(s.stderr, "tally top：-n 至少要是 1")
		return exitUsage
	}

	counts := map[string]int{}
	err := readSales(ctx, fs.Args(), s.stdin, func(item string, _ int) {
		counts[item]++
	})
	if err != nil {
		return fail(ctx, s.stderr, "tally top", err)
	}

	items := slices.Collect(maps.Keys(counts))
	slices.SortFunc(items, func(a, b string) int {
		return cmp.Or(cmp.Compare(counts[b], counts[a]), strings.Compare(a, b))
	})
	for i, item := range items[:min(*n, len(items))] {
		fmt.Fprintf(s.stdout, "%d. %s %d 份\n", i+1, item, counts[item])
	}
	return exitOK
}

  • 不認得的子命令：說明哪裡錯，附上完整的用法，回傳 2。
  • tally help、tally -h 是使用者主動要看說明，寫到 stdout、回傳 0；被動的錯誤說明才寫 stderr。
  • 要讓所有子命令共用的旗標（例如 tally -v total），先用一個最上層的 FlagSet 解析，再拿它的 fs.Args() 選子命令。
  • 子命令再多，結構還是一樣：一個 switch 加上每個子命令一個函式。標準庫的 flag 已經足夠寫出完整的工具，Go 自己的 go 指令就是用它做的。

4. 標準輸入與管線

Unix 工具的傳統：給了檔名就讀檔，沒給就讀標準輸入，檔名是 - 也代表標準輸入。這樣一個工具可以單獨用，也可以接在管線中間，和 grep、sort 這些工具組合：

func readSales(ctx context.Context, names []string, stdin io.Reader, add func(item string, price int)) error {
	if len(names) == 0 {
		names = []string{"-"}
	}
	for _, name := range names {
		if err := readSalesFrom(ctx, name, stdin, add); err != nil {
			return err
		}
	}
	return nil
}

func readSalesFrom(ctx context.Context, name string, stdin io.Reader, add func(string, int)) error {
	r, label := stdin, "標準輸入"
	if name != "-" {
		f, err := os.Open(name)
		if err != nil {
			return err
		}
		defer f.Close()
		r, label = f, name
	}

	sc := bufio.NewScanner(r)
	for line := 1; sc.Scan(); line++ {
		if ctx.Err() != nil {
			return context.Cause(ctx)
		}
		text := strings.TrimSpace(sc.Text())
		if text == "" {
			continue
		}
		i := strings.LastIndexByte(text, ' ')
		price, err := strconv.Atoi(text[i+1:])
		if i < 0 || err != nil {
			return fmt.Errorf("%s 第 %d 行：看不懂「%s」", label, line, text)
		}
		add(text[:i], price)
	}
	return sc.Err()
}

  • 每個檔案在 readSalesFrom 裡開、在 readSalesFrom 結束時關。如果把 defer 寫在 readSales 的迴圈裡，所有檔案要等全部讀完才關（20 章）。
  • 品項名稱裡可能有空白（「排骨 便當 90」），所以用 LastIndexByte 找最後一個空白，最後一段才是金額。
  • 沒接管線、也沒給檔名時，程式在等你從鍵盤輸入，看起來像是當掉了。輸入完按 Ctrl-D（Windows 是 Ctrl-Z 再按 Enter）表示結束。想在這種情況印提示，可以檢查 os.Stdin.Stat() 的 Mode 有沒有 os.ModeCharDevice：有的話，標準輸入是終端機，不是管線或檔案。

5. 結束碼與 stderr

程式結束時交給作業系統一個整數，叫結束碼（exit code）：0 代表成功，其他值代表失敗。shell 的 &&、||、CI 的每一個步驟都看它。tally 用的慣例：

const (
	exitOK          = 0   // 成功
	exitError       = 1   // 執行時出錯，例如檔案打不開
	exitUsage       = 2   // 用法錯誤，例如旗標的值不對
	exitInterrupted = 130 // 被 Ctrl-C 中斷：128 加上 SIGINT 的編號 2
)

func fail(ctx context.Context, stderr io.Writer, prog string, err error) int {
	fmt.Fprintf(stderr, "%s：%v\n", prog, err)
	if ctx.Err() != nil {
		return exitInterrupted
	}
	return exitError
}

結束碼只能在 main 裡交出去：os.Exit(code)。它會立刻結束程式，連 defer 都不執行。所以 main 寫得越短越好，所有工作都在 run 裡做完、defer 都在 run 裡跑完，main 拿到結束碼再呼叫 os.Exit：

// 第 21 章：命令列工具。
//
// 這一章的程式本身就是一個完整的命令列工具 tally，加總便當店的營業額：
//
//	printf '排骨飯 90\n雞腿飯 100\n' | go run ./chapters/21-cli total -tax 5
//
// main 只負責把作業系統的東西（參數、標準輸入輸出、環境變數、訊號）接上 run；
// run 不碰 os.Args、os.Exit，所以 main_test.go 可以用 Example 呼叫它，
// 鎖住每一種用法的輸出和結束碼，頁面上的輸出就是從那裡同步過去的。
package main

import (
	"context"
	"os"
	"os/signal"
	"syscall"
)

func main() {
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	go func() {
		<-ctx.Done()
		stop() // 第一次 Ctrl-C 之後恢復預設行為：再按一次就直接結束
	}()

	code := run(ctx, os.Args[1:], sys{
		stdin:  os.Stdin,
		stdout: os.Stdout,
		stderr: os.Stderr,
		getenv: os.Getenv,
	})
	stop()
	os.Exit(code) // os.Exit 不會執行 defer，所以 main 裡不放任何 defer
}

在 shell 裡實際看看結束碼和兩個出口（$? 是上一個指令的結束碼）：

$ ./tally total nope.txt; echo "結束碼 $?"

結束碼 1
$ ./tally total < sales.txt > result.txt; echo "結束碼 $?"; cat result.txt

$ ./tally total nope.txt 2> errors.txt; echo "結束碼 $?"; cat errors.txt

$ ./tally total < sales.txt && echo 成功才會印這行

成功才會印這行
$ ./tally total nope.txt || echo "失敗時改做這行"

失敗時改做這行
  • > 只導走 stdout，錯誤訊息照樣出現在終端機；2> 導走的是 stderr。結果和錯誤分開，下一個程式才不會把錯誤訊息當成資料。
  • log.Fatal 等於印出訊息再 os.Exit(1)，一樣不執行 defer。它和 os.Exit 都只該出現在 main 裡；在其他函式裡回傳錯誤。
  • 常見的慣例：1 是一般錯誤，2 是用法錯誤（flag 自己也這樣用），被訊號中斷時是 128 加上訊號編號，所以 Ctrl-C（SIGINT 是 2）是 130。

注意：go run 會把程式的非 0 結束碼一律變成 1，另外印一行 exit status N。要檢查真正的結束碼，先 go build 再執行：

exit status 2
結束碼 1
$ ./tally top -n 0; echo "結束碼 $?"
tally top：-n 至少要是 1
結束碼 2

6. 旗標、環境變數、預設值

同一個設定常常有三個來源。慣例是越靠近這一次執行的越優先：這次在命令列寫的，蓋過這台機器設定的環境變數，再蓋過程式內建的值。用 flag 做起來只要一個小技巧：用環境變數算出旗標的預設值。命令列有給，flag 會蓋掉它；沒給，就留著環境變數或內建的值：

func envInt(getenv func(string) string, key string, def int) (int, error) {
	v := getenv(key)
	if v == "" {
		return def, nil
	}
	n, err := strconv.Atoi(v)
	if err != nil {
		return 0, fmt.Errorf("環境變數 %s=%q 不是整數", key, v)
	}
	return n, nil
}
$ TALLY_TAX=10 tally total
合計 340 元，含稅 10% 共 374 元
結束碼 0
$ TALLY_TAX=10 tally total -tax 0
合計 340 元，含稅 0% 共 340 元
結束碼 0
$ TALLY_TAX=十 tally total
stderr｜tally total：環境變數 TALLY_TAX="十" 不是整數
結束碼 2
  • run 讀環境變數用的是傳進來的 getenv，main 接上 os.Getenv，測試接上一個 map。另一種做法是在測試裡用 t.Setenv，但它會改到整個程式的環境，不能和 t.Parallel 一起用。
  • os.Getenv 分不出「沒設定」和「設成空字串」，需要分的話用 os.LookupEnv，它多回傳一個 bool。
  • 環境變數的值看不懂時，錯誤訊息要說出變數名稱和值：使用者通常早就忘了自己設過它。
  • 密碼、token 這類秘密不要用旗標傳：同一台機器的其他使用者可能用 ps 看到完整的指令。用環境變數或檔案。
  • 設定很多時，常見的第四層是設定檔，放在環境變數和預設值之間。讀 JSON 設定檔見「JSON 與資料編碼」那一章。

7. Ctrl-C 與 os/signal

按下 Ctrl-C，作業系統送給程式一個 SIGINT 訊號。Go 程式預設收到它就立刻結束，defer 不會執行，暫存檔留在那裡、寫到一半的檔案停在一半。signal.NotifyContext（Go 1.16 起）把訊號換成 ctx 的取消，程式就能自己決定怎麼收尾。第 5 節的 main 已經這樣做了：

  • 監聽 os.Interrupt（Ctrl-C）和 syscall.SIGTERM（kill 指令、容器平台要關閉程式時送的訊號）。SIGKILL 沒辦法攔截，程式一定會被砍掉。
  • 第一次收到訊號之後呼叫 stop，恢復預設行為：收尾卡住時，使用者再按一次 Ctrl-C 還是能結束程式。
  • Go 1.26 起，NotifyContext 取消時會附上原因，context.Cause(ctx) 的訊息是 interrupt signal received，說明收到的是哪個訊號（18 章）。

ctx 被取消不會讓任何程式碼自動停下來，要有人去看它。readSalesFrom 每讀一行先看一次 ctx（第 4 節），取消之後回傳原因，fail 看到 ctx 已經取消，回傳 130。在 Example 裡用一個已經取消的 ctx 模擬：

$ tally total
stderr｜tally total：interrupt signal received
結束碼 130

真的訊號也測得到：測試對自己的程式送一個 SIGINT，NotifyContext 把它攔下來，run 讀下一行時發現，回傳 130：

func TestInterruptSignal(t *testing.T) {
	ctx, stop := signal.NotifyContext(t.Context(), os.Interrupt)
	defer stop()

	stdin, w := io.Pipe()
	var stderr strings.Builder
	done := make(chan int)
	go func() {
		done <- run(ctx, []string{"total"}, sys{
			stdin: stdin, stdout: io.Discard, stderr: &stderr,
			getenv: func(string) string { return "" },
		})
	}()

	fmt.Fprintln(w, "排骨飯 90") // 等 run 讀走第一行才會回來
	if err := syscall.Kill(syscall.Getpid(), syscall.SIGINT); err != nil {
		t.Fatal(err)
	}
	<-ctx.Done()
	fmt.Fprintln(w, "雞腿飯 100") // run 讀到這一行之前先看 ctx，就停下來了
	w.Close()

	if code := <-done; code != exitInterrupted || !strings.Contains(stderr.String(), "interrupt signal received") {
		t.Errorf("結束碼 %d，stderr %q；want 130 而且說明收到 interrupt", code, stderr.String())
	}
}
  • 這個測試檔開頭寫了 //go:build unix，只在 Unix 系統上編譯。Windows 也會把 Ctrl-C 送成 os.Interrupt，但沒有 syscall.Kill 可以在測試裡模擬。
  • io.Pipe 是同步的：寫進去的一行要等 run 讀走才回來，所以送訊號的時間點是確定的，測試不會時好時壞。

常見錯誤

1. 在 main 以外呼叫 os.Exit 或 log.Fatal

defer 不會執行，檔案沒關、暫存檔沒刪；而且呼叫它的函式沒辦法測試，一測整個測試程式就結束了。函式回傳錯誤，只有 main 決定結束碼（第 5 節）。

2. 錯誤訊息寫到 stdout

結果導到檔案或接到下一個程式時，錯誤訊息混進資料裡。stdout 只放結果（02 章、練習 5）。

3. 失敗了還回傳 0

腳本和 CI 以為成功了，繼續做下一步。每一條失敗的路都要回傳非 0 的結束碼；使用者自己要求的 -h 才回傳 0。

4. 旗標寫在檔名後面

Go 的 flag 遇到第一個不是旗標的參數就停，後面的 -tax 10 變成檔名（第 2 節）。說明文件裡的用法要把旗標寫在前面。

5. 用 go run 檢查結束碼

go run 把非 0 的結束碼都變成 1。檢查結束碼用編譯出來的執行檔（第 5 節）。

6. 在要測試的程式碼裡用全域的 flag

全域的 flag.CommandLine 整個程式只有一份：同一個旗標定義兩次會 panic（flag redefined），解析失敗會直接結束測試程式。用 flag.NewFlagSet 加 ContinueOnError，每次呼叫都是新的。

7. 攔了 Ctrl-C 卻沒有人檢查 ctx

NotifyContext 攔下訊號之後，預設的「立刻結束」就不會發生了。如果沒有任何地方檢查 ctx，按 Ctrl-C 等於沒按。長時間的迴圈、等待都要看 ctx（第 7 節、練習 3）。

重點回顧

  • os.Args[0] 是程式本身；引號、萬用字元是 shell 處理的。main 只把 os.Args[1:] 交給 run。
  • 用 flag.NewFlagSet 加 ContinueOnError、SetOutput，flag 才能測試；errors.Is(err, flag.ErrHelp) 分辨 -h。
  • flag 解析到第一個不是旗標的參數就停，旗標寫在前面。
  • 子命令：switch 看第一個參數，每個子命令一個 FlagSet。
  • 沒給檔名或檔名是 - 時讀標準輸入，工具就能接在管線裡。
  • 結果寫 stdout、錯誤寫 stderr；0 成功、1 錯誤、2 用法錯誤、130 被 Ctrl-C 中斷。
  • os.Exit 和 log.Fatal 不執行 defer，只在 main 裡用；go run 會改掉結束碼。
  • 設定的優先順序：旗標 > 環境變數 > 預設值，用環境變數算出旗標的預設值就做得到。
  • signal.NotifyContext 把 Ctrl-C 變成 ctx 的取消，程式裡要有人檢查 ctx。
