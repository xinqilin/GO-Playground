context

context 是一條往下傳的取消繩：上層一拉，拿著這條繩子的工作都知道該停了。

看圖

最小範例

func slowWork(ctx context.Context) error {
	select {
	case <-time.After(time.Hour):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()
	fmt.Println(slowWork(ctx))
}

輸出

context deadline exceeded

工程師筆記

  • context 一律當第一個參數傳：func Do(ctx context.Context, …)，不要存在 struct 裡。
  • 拿到 cancel 就 defer cancel()，逾時版本也一樣，否則計時器要等到時間到才會釋放。
  • 取消是請求不是強制：被呼叫的函式要自己檢查 ctx.Done()，或把 ctx 交給會檢查的函式（http.NewRequestWithContext、資料庫查詢等）。
  • ctx.Err() 只告訴你是取消還是逾時；想留下原因，用 WithCancelCause 搭配 context.Cause。
  • WithValue 只放 request 範圍的資料（request ID、登入資訊），不要拿來傳一般參數；key 用不匯出的型別。
  • 沒有上層 context 時用 context.Background()；還沒想好要傳什麼時用 context.TODO() 做記號。
