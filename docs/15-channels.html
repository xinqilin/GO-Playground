channel

channel 是 goroutine 之間的輸送帶：一邊放、一邊拿。

看圖

最小範例

func produce(n int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out) // 送完就關，range 才會結束
		for i := 1; i <= n; i++ {
			out <- i
		}
	}()
	return out
}

func main() {
	for v := range produce(3) {
		fmt.Println("收到", v)
	}
}

輸出

收到 1
收到 2
收到 3

工程師筆記

  • 送到已關閉的 channel 會 panic，關閉已關閉的 channel 也會 panic。慣例是送的一方負責 close。
  • 從已關閉的 channel 收，會先收完剩下的值，之後馬上拿到零值和 ok == false。
  • 不是每個 channel 都要 close；只有收的一方需要知道「沒有了」（例如用 range 收）時才要關。
  • 對 nil channel 送或收會永遠卡住。
  • 所有 goroutine 都卡住時，runtime 會直接結束程式：fatal error: all goroutines are asleep - deadlock!
  • 參數寫成 chan<- T（只能送）或 <-chan T（只能收），編譯器會擋下方向用錯的程式碼。
