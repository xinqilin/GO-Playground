1. 寫一個小解析器

很多文字格式根本不需要正規表示式。櫃台手打的點餐單，每一行是「品項 [x數量] [備註]」，用 08 章的 strings 函式一步一步拆就好：

type OrderLine struct {
	Dish string
	Qty  int
	Note string
}

func parseOrder(text string) ([]OrderLine, error) {
	var order []OrderLine
	n := 0
	for line := range strings.Lines(text) {
		n++
		line = strings.TrimSpace(line)
		if line == "" || strings.HasPrefix(line, "#") {
			continue
		}
		fields := strings.Fields(line)
		ol := OrderLine{Dish: fields[0], Qty: 1}
		rest := fields[1:]
		if len(rest) > 0 {
			if q, ok := strings.CutPrefix(rest[0], "x"); ok {
				qty, err := strconv.Atoi(q)
				if err != nil {
					return nil, fmt.Errorf("第 %d 行：數量 %q：%w", n, q, err)
				}
				if qty < 1 {
					return nil, fmt.Errorf("第 %d 行：數量至少是 1", n)
				}
				ol.Qty = qty
				rest = rest[1:]
			}
		}
		ol.Note = strings.Join(rest, " ")
		order = append(order, ol)
	}
	return order, nil
}
func parseDemo() {
	const ticket = `# 第 7 桌
排骨飯 x2 少飯
滷肉飯

珍珠奶茶 x1 微糖, 去冰
`
	order, err := parseOrder(ticket)
	if err != nil {
		fmt.Println(err)
		return
	}
	for _, ol := range order {
		fmt.Printf("%s %d 份 %q\n", ol.Dish, ol.Qty, ol.Note)
	}

	_, err = parseOrder("排骨飯\n雞腿飯 x二\n")
	fmt.Println(err)
}

滷肉飯 1 份 ""
珍珠奶茶 1 份 "微糖, 去冰"

  • strings.Lines（Go 1.24 起）一次給一行，每一行帶著結尾的換行，所以先 TrimSpace。最後一行沒有換行也一樣會給。
  • 行號自己數，錯誤訊息一定要帶著它。使用者看到「第 2 行：數量 "二"」就知道要改哪裡。
  • strings.Fields 依任意長度的空白切開，連續的空白、Tab 都當成一個分隔，比 Split(" ") 適合處理人打的字。
  • 用 %w 包住 strconv 的錯誤，呼叫的一方還能用 errors.Is 判斷原因。

strconv 的錯誤是 *strconv.NumError，裡面記著是哪個函式、哪個字串，以及原因：strconv.ErrSyntax（根本不是數字）或 strconv.ErrRange（是數字，但放不下）。這兩種通常要給使用者不同的訊息：

func numErrorDemo() {
	for _, s := range []string{"二", "99999999999999999999"} {
		_, err := strconv.Atoi(s)
		ne, _ := errors.AsType[*strconv.NumError](err)
		fmt.Println(ne.Func, ne.Num, errors.Is(err, strconv.ErrSyntax), errors.Is(err, strconv.ErrRange))
	}

	_, err := strconv.ParseInt("300", 10, 8) // 第三個參數是位元數：int8 放不下 300
	fmt.Println(err)

	for _, s := range []string{"true", "1", "T", "yes"} {
		b, err := strconv.ParseBool(s)
		fmt.Println(s, b, err == nil)
	}
}
Atoi 二 true false
Atoi 99999999999999999999 false true
strconv.ParseInt: parsing "300": value out of range
true true true
1 true true
T true true
yes false false
  • ParseInt(s, 進位, 位元數) 的第三個參數決定範圍：8 就是 int8 的 -128 到 127，結果還是 int64，確認放得下之後再轉型。
  • ParseBool 只認得 1、t、T、TRUE、true、True 和對應的 false 寫法，yes、on 都不算。設定檔要接受這些字，要自己對照。

2. regexp：比對與擷取

格式有規則、但不是固定的分隔符號時（發票號碼、日期、交易紀錄），用正規表示式描述比較清楚。Go 的 regexp 套件先把字串編譯成 *regexp.Regexp，之後重複使用。編譯有成本，所以放在套件層級用 MustCompile 編譯一次：寫錯時程式一啟動就 panic，不會等到某個使用者剛好用到才發現。

var (
	invoiceNo = regexp.MustCompile(`^[A-Z]{2}-\d{8}$`)
	looseNo   = regexp.MustCompile(`[A-Z]{2}-\d{8}`) // 沒有 ^ 和 $：只要字串裡「有一段」符合就算
)

func matchDemo() {
	for _, s := range []string{"AB-12345678", "AB-123456789", "發票 AB-12345678", "ab-12345678"} {
		fmt.Printf("%q：完整比對 %v，部分比對 %v\n", s, invoiceNo.MatchString(s), looseNo.MatchString(s))
	}
}
"AB-12345678"：完整比對 true，部分比對 true
"AB-123456789"：完整比對 false，部分比對 true
"發票 AB-12345678"：完整比對 false，部分比對 true
"ab-12345678"：完整比對 false，部分比對 false
  • 第二行是最常見的 bug：九位數字的號碼，在沒有錨點的版本裡「有一段」符合，就通過了（練習 6）。
  • 正規表示式寫在反引號的原始字串裡，\d 不用寫成 \\d（08 章）。
  • *regexp.Regexp 可以被很多 goroutine 同時使用，放在套件層級是安全的。

要的不只是「符不符合」，還要取出其中的幾段時，用括號分組。(?<name>…) 是有名字的群組（舊的程式碼常寫成 (?P<name>…)，意思一樣），FindStringSubmatch 回傳整段和每一個群組，SubexpIndex 用名字找出群組的位置。解析悠遊卡的交易紀錄：

var trip = regexp.MustCompile(`^(?<date>\d{4}/\d{2}/\d{2}) (?<time>\d{2}:\d{2}) (?<kind>進站|出站) (?<station>\S+)(?: 扣款 (?<fare>\d+) 元)?$`)

func submatchDemo() {
	for _, line := range []string{
		"2026/11/19 08:15 進站 台北車站",
		"2026/11/19 08:41 出站 市政府 扣款 25 元",
		"2026/11/19 08:41 轉乘 市政府",
	} {
		m := trip.FindStringSubmatch(line)
		if m == nil {
			fmt.Printf("看不懂：%s\n", line)
			continue
		}
		fmt.Printf("%s %s %s 車資=%q\n",
			m[trip.SubexpIndex("time")], m[trip.SubexpIndex("kind")],
			m[trip.SubexpIndex("station")], m[trip.SubexpIndex("fare")])
	}

	amounts := regexp.MustCompile(`NT\$[\d,]+`)
	fmt.Printf("%q\n", amounts.FindAllString("早餐 NT$85，午餐 NT$120，晚餐 NT$1,280", -1))
}
08:15 進站 台北車站 車資=""
08:41 出站 市政府 車資="25"
看不懂：2026/11/19 08:41 轉乘 市政府
["NT$85" "NT$120" "NT$1,280"]
  • 回傳的 slice 第 0 個是整段符合的文字，第 1 個起是各個群組。用名字取，比數「第幾個括號」不容易出錯，以後在中間加一個群組也不會全部錯位。
  • (?:…) 只分組、不擷取；後面的 ? 讓整段可有可無。進站的紀錄沒有扣款，fare 群組就是空字串。
  • 不符合時回傳 nil，一定要先檢查。
  • 名稱裡有 All 的函式找出全部，第二個參數是最多幾個，-1 表示不限。另外還有回傳位置的 Index 系列，以及處理 []byte 的版本（沒有 String 的那些）。

3. regexp：取代與限制

ReplaceAllString 把每一段符合的文字換掉，取代字串裡用 $1 或 ${1} 引用群組，有名字的群組用 ${name}。把斜線的日期換成其他格式：

var slashDate = regexp.MustCompile(`(\d{4})/(\d{2})/(\d{2})`)

func replaceDemo() {
	s := "訂位日期 2026/11/19，取消期限 2026/11/17"
	fmt.Println(slashDate.ReplaceAllString(s, "$1-$2-$3"))
	fmt.Printf("%q\n", slashDate.ReplaceAllString(s, "$1年$2月$3日"))
	fmt.Println(slashDate.ReplaceAllString(s, "${1}年${2}月${3}日"))
}
訂位日期 2026-11-19，取消期限 2026-11-17
"訂位日期 ，取消期限 "
訂位日期 2026年11月19日，取消期限 2026年11月17日

第二行：日期全部不見了，也沒有任何錯誤。取代的結果需要計算時（換算、查表、統一格式），用 ReplaceAllStringFunc，它把每一段符合的文字交給你的函式，用回傳值取代。民國年換成西元年：

var rocDate = regexp.MustCompile(`民國(\d+)年`)

func replaceFuncDemo() {
	s := "本店民國68年開幕，民國115年搬到現址"
	out := rocDate.ReplaceAllStringFunc(s, func(m string) string {
		y, err := strconv.Atoi(rocDate.FindStringSubmatch(m)[1])
		if err != nil {
			return m // 數字太大轉不過來時保留原文
		}
		return strconv.Itoa(y+1911) + "年"
	})
	fmt.Println(out)

	price := regexp.QuoteMeta("NT$1.5") // 使用者輸入的文字裡有 $ 和 .，要當成一般字元
	fmt.Println(price, regexp.MustCompile(price).MatchString("特價 NT$1.5 起"))
}
本店1979年開幕，2026年搬到現址
NT\$1\.5 true
  • 函式只拿到整段文字，要群組就在函式裡再呼叫一次 FindStringSubmatch。
  • regexp.QuoteMeta 把 $、.、( 這些特殊字元加上反斜線。要搜尋使用者輸入的文字時，一定要先 QuoteMeta，不然「NT$1.5」裡的 . 會符合任何字元。
  • 只是要換掉固定的文字，用 08 章的 strings.ReplaceAll 或 Replacer 就好，不需要 regexp。

Go 的正規表示式語法叫做 RE2，和 Java、JavaScript、Python 的大致相同，但少了兩樣：lookahead／lookbehind（(?=…)）和 backreference（\1）。寫了不會悄悄失效，而是在編譯時就回傳錯誤：

func re2Demo() {
	for _, expr := range []string{`\d+(?=元)`, `(\w)\1`, `[A-Z`} {
		_, err := regexp.Compile(expr)
		fmt.Println(err)
	}
}

為什麼 Go 不支援 lookahead？

多數語言的正規表示式用「回溯」來比對：一條路走不通就退回去試下一條。遇到 (a+)+$ 這種寫法和一個刻意構造的長字串，可能要試的路徑數量會隨著長度指數成長，一個請求就能讓伺服器的 CPU 卡住好幾秒，這種攻擊叫做 ReDoS。

RE2 不回溯，它保證比對的時間和輸入的長度成正比，不管正規表示式怎麼寫、輸入是什麼。代價就是放棄那些需要回溯才做得到的功能，lookahead 和 backreference 就是其中兩個。所以在 Go 裡，就算正規表示式或要比對的文字來自使用者，也不會因為回溯而被拖垮；正規表示式越長，比對越慢，但只是等比例變慢，不會指數成長。

真的需要那些功能時，通常換個寫法就好：\d+(?=元) 可以寫成 (\d+)元 再取群組；「兩個相同的字元」可以先比對再用程式檢查。

4. text/template

收據、通知信、設定檔、程式碼產生器，這類「格式固定、資料會變」的輸出用 text/template。範本裡的 .（dot）是目前的資料，{{.Shop}} 取欄位，沒有參數的方法也能直接寫成 {{.Total}}：

type ReceiptItem struct {
	Name  string
	Qty   int
	Price int
}

func (it ReceiptItem) Subtotal() int { return it.Qty * it.Price }

type Receipt struct {
	Shop  string
	Table int
	Items []ReceiptItem
	Paid  bool
	Note  string
}

func (r Receipt) Total() int {
	sum := 0
	for _, it := range r.Items {
		sum += it.Subtotal()
	}
	return sum
}
const receiptText = `{{.Shop}} 第 {{.Table}} 桌
{{range .Items -}}
{{.Name}} x{{.Qty}} {{.Subtotal}} 元
{{else -}}
（沒有品項）
{{end -}}
合計 {{.Total}} 元{{if .Paid}}（已付款）{{end}}
{{with .Note}}備註：{{.}}
{{end -}}
`

var receiptTmpl = template.Must(template.New("receipt").Parse(receiptText))

func receiptDemo() {
	receipts := []Receipt{
		{Shop: "阿嬤便當", Table: 7, Paid: true, Note: "統編 12345678",
			Items: []ReceiptItem{{"排骨飯", 2, 90}, {"滷蛋", 3, 15}}},
		{Shop: "阿嬤便當", Table: 3},
	}
	for _, r := range receipts {
		if err := receiptTmpl.Execute(os.Stdout, r); err != nil {
			fmt.Println(err)
		}
	}
}
阿嬤便當 第 7 桌
排骨飯 x2 180 元
滷蛋 x3 45 元
合計 225 元（已付款）
備註：統編 12345678
阿嬤便當 第 3 桌
（沒有品項）
合計 0 元
  • {{range .Items}} 裡面的 dot 變成每一個品項；{{else}} 是 slice 為空時的內容。
  • {{if .Paid}} 的條件是零值就不成立：false、0、""、nil、長度 0 的 slice 和 map。
  • {{with .Note}} 不是空的才執行，而且裡面的 dot 換成 Note 本身，所以寫 {{.}}。
  • {{- 和 -}} 吃掉那一側所有的空白和換行。範本可以照邏輯分行寫，輸出又不會多出空行。橫線的另一側一定要有空白：{{- .Name}} 才是去空白，{{-3}} 是數字 -3。
  • 其他常用的：{{printf "%05d" .Table}}、{{len .Items}}、{{index .Items 0}}、{{if eq .Table 7}}，以及用 | 把前一個結果當成下一個函式的最後一個參數。

範本在 Parse 時只檢查語法，欄位存不存在要到 Execute 才知道。map 少了 key 預設不算錯，印出 <no value>：

func execErrorDemo() {

	if err := loose.Execute(os.Stdout, data); err != nil {
		fmt.Println(err)
	}
	strict := template.Must(template.New("strict").Option("missingkey=error").Parse("{{.shop}} {{.phone}}\n"))
	var b strings.Builder
	err := strict.Execute(&b, data)

  • 錯誤訊息指出範本名稱、行號和位置（typo:1:2），以及是哪一個動作出錯。
  • 資料是 map 時，加上 Option("missingkey=error")，少了 key 才會變成錯誤。
  • Execute 出錯時，錯誤之前的內容已經寫出去了（這裡的「阿嬤便當 」）。直接寫到檔案或 HTTP 回應，使用者會拿到半張收據、半個網頁。先寫到 bytes.Buffer，成功了再一次寫出去（練習 5）。
  • 範本在套件層級用 template.Must 解析一次，和 regexp 的 MustCompile 一樣：寫錯了一啟動就知道，也不用每次都重新解析。

5. 函式與組合範本

範本變多之後，有三個工具：FuncMap 讓範本可以呼叫你的函式；define、block、template 把範本拆成有名字的小塊；embed 把範本檔編進執行檔（20 章）。店門口的公告，一般的版本和公休的版本共用同一個樣子：

{{define "notice" -}}
【{{.Shop}}】{{block "body" .}}今天正常營業。{{end}}
營業時間 {{join .Hours "、"}}，外送滿 {{money .MinOrder}} 元免運。
{{end}}
{{define "body"}}{{.Date}} 公休一天，造成不便請見諒。{{end}}
package main

import (
	"embed"
	"fmt"
	"os"
	"strconv"
	"strings"
	"text/template"
)

//go:embed templates/*.tmpl
var templateFS embed.FS

// money 把 1280 寫成 1,280：從個位數往前，每三位插一個逗號。
func money(n int) string {
	s := strconv.Itoa(n)
	var b strings.Builder
	for i, d := range s {
		if i > 0 && (len(s)-i)%3 == 0 {
			b.WriteByte(',')
		}
		b.WriteRune(d)
	}
	return b.String()
}

// funcs 是範本裡可以呼叫的函式，要在 Parse 之前用 Funcs 加進去。
var funcs = template.FuncMap{
	"money": money,
	"join":  strings.Join,
}

// base 是一般的公告；holiday 複製一份 base，再把 body 換成公休的內容。
var (
	base    = template.Must(template.New("").Funcs(funcs).ParseFS(templateFS, "templates/notice.tmpl"))
	holiday = template.Must(template.Must(base.Clone()).ParseFS(templateFS, "templates/holiday.tmpl"))
)

// Notice 是店門口的公告。
type Notice struct {
	Shop     string
	Hours    []string
	MinOrder int
	Date     string
}

func noticeDemo() {
	n := Notice{Shop: "阿嬤便當", Hours: []string{"10:30-14:00", "17:00-20:30"}, MinOrder: 1500, Date: "11/24（一）"}
	for _, t := range []*template.Template{base, holiday} {
		if err := t.ExecuteTemplate(os.Stdout, "notice", n); err != nil {
			fmt.Println(err)
		}
	}
}

營業時間 10:30-14:00、17:00-20:30，外送滿 1,500 元免運。

  • {{define "名稱"}}…{{end}} 定義一塊有名字的範本，{{template "名稱" .}} 在別的地方用它。{{block "body" .}}預設{{end}} 等於「定義 body，並且在這裡用它」。
  • Funcs 要在 Parse 之前呼叫：解析時遇到 money，範本要已經知道它是什麼，不然是語法錯誤。函式可以回傳一個值，或一個值加一個 error；回傳 error 時 Execute 會停下來。
  • Clone 複製整組範本，複本裡重新定義 body 不會影響原本的。網站的「共用版型，每一頁填自己的內容」就是這個做法（練習 5）。
  • 範本檔有好幾個時，ExecuteTemplate 用名稱指定要執行哪一個；ParseFS 解析的檔案，名稱是檔名（例如 notice.tmpl）。

6. html/template

產生 HTML 時，資料裡只要有使用者寫的字，就可能被塞進 <script>。這種攻擊叫做 XSS：別人的瀏覽器打開你的網頁，就會執行攻擊者寫的程式，偷走登入狀態。html/template 的 API 和 text/template 完全一樣，差別是它會依照位置自動跳脫。同一個範本、同一份惡意的評論，兩個套件各跑一次：

type Review struct {
	Name    string
	Website string
	Comment string
}

const reviewPage = `<p><a href="{{.Website}}">{{.Name}}</a>：{{.Comment}}</p>
<button onclick="reply({{.Name}})">回覆</button>
`

func escapeDemo() {
	r := Review{
		Name:    `<b>阿明</b>`,
		Website: `javascript:alert(1)`,
		Comment: `好吃<script>steal()</script>`,
	}

	fmt.Println("text/template：")
	t := template.Must(template.New("review").Parse(reviewPage))
	if err := t.Execute(os.Stdout, r); err != nil {
		fmt.Println(err)
	}

	fmt.Println("html/template：")
	h := htmltemplate.Must(htmltemplate.New("review").Parse(reviewPage))
	if err := h.Execute(os.Stdout, r); err != nil {
		fmt.Println(err)
	}
}
text/template：
<p><a href="javascript:alert(1)"><b>阿明</b></a>：好吃<script>steal()</script></p>
<button onclick="reply(<b>阿明</b>)">回覆</button>
html/template：
<p><a href="#ZgotmplZ">&lt;b&gt;阿明&lt;/b&gt;</a>：好吃&lt;script&gt;steal()&lt;/script&gt;</p>
<button onclick="reply(&#34;\u003cb\u003e阿明\u003c/b\u003e&#34;)">回覆</button>
  • text/template 把輸入原封不動放進去：<script> 會被瀏覽器執行，連結點下去會執行 javascript: 網址。
  • html/template 在 HTML 內容裡把 < 換成 &lt;；在 href 裡發現 javascript: 這種不安全的網址，換成 #ZgotmplZ（看到這個字串就表示有值被擋下來了）；在 onclick 裡把值寫成跳脫過的 JavaScript 字串。
  • 兩個套件的名稱都是 template，同一個檔案要同時用時，替其中一個取別名（這裡的 htmltemplate）。實際的程式裡，產生 HTML 一律用 html/template，就不會有這個問題。

有時候程式自己產生了一段 HTML，確定是安全的，不想被跳脫。把它轉成 template.HTML 型別，html/template 就會原樣輸出：

func trustedDemo() {
	h := htmltemplate.Must(htmltemplate.New("badge").Parse("<p>{{.}}</p>\n"))
	for _, v := range []any{"<em>招牌</em>", htmltemplate.HTML("<em>招牌</em>")} {
		if err := h.Execute(os.Stdout, v); err != nil {
			fmt.Println(err)
		}
	}
}
<p>&lt;em&gt;招牌&lt;/em&gt;</p>
<p><em>招牌</em></p>

template.HTML 等於關掉保護，只能用在完全由程式控制的內容。把使用者的輸入轉成 template.HTML，就是自己把 XSS 放了進來。同樣的型別還有 template.URL、template.JS、template.CSS。

常見錯誤

1. 驗證輸入的正規表示式沒有 ^ 和 $

MatchString 在字串裡找，只要有一段符合就回傳 true。九位數的號碼、前後夾著其他文字的輸入都會通過（第 2 節、練習 6）。

2. 每次呼叫都重新編譯正規表示式或範本

編譯比比對慢得多，放在迴圈或每個請求裡，效能就浪費在重複的工作上。在套件層級用 MustCompile、template.Must 編譯一次（第 2、4 節）。

3. 取代字串的 $1 後面接著文字

名稱會把後面的字母、數字、底線、中文字一起吃進去，結果是空字串。一律寫成 ${1}（第 3 節）。

4. 簡單的事也用正規表示式

固定的前綴、分隔符號，用 HasPrefix、Cut、Fields 更快也更好讀。正規表示式留給真的有模式的格式（第 1 節）。

5. 用 text/template 產生 HTML

它不會跳脫任何東西，使用者的輸入直接變成網頁的程式碼。產生 HTML 一律用 html/template（第 6 節、練習 2）。

6. 把使用者的輸入轉成 template.HTML

等於告訴 html/template「這段不用檢查」。這個型別只給程式自己產生、確定安全的內容（第 6 節）。

7. 範本直接寫到檔案或 HTTP 回應

Execute 出錯時，前半段已經寫出去，收不回來。先寫到 bytes.Buffer，成功了再寫出去（第 4 節、練習 5）。

8. 在 Parse 之後才呼叫 Funcs

Parse 遇到不認得的函式名稱就是語法錯誤。先 Funcs、再 Parse（第 5 節）。

重點回顧

  • 有固定分隔符號的格式，用 Lines、Fields、Cut 加 strconv 拆，錯誤帶上行號。
  • strconv 的錯誤是 *NumError，用 errors.Is 分辨 ErrSyntax 和 ErrRange。
  • 正規表示式在套件層級 MustCompile 一次；驗證輸入要有 ^ 和 $。
  • 命名群組加 SubexpIndex 取值；不符合時回傳 nil。
  • 取代字串寫 ${1}；結果要計算時用 ReplaceAllStringFunc；使用者的文字先 QuoteMeta。
  • RE2 沒有 lookahead 和 backreference，換來不會被輸入拖垮的線性時間。
  • text/template：dot 是目前的資料，range、if、with 會改變 dot；{{- -}} 控制空白。
  • 範本的錯誤在 Execute 才出現，先寫到 buffer 再送出。
  • FuncMap 在 Parse 之前加；block 留位置，Clone 之後重新定義。
  • HTML 一律用 html/template，template.HTML 只給程式自己產生的內容。
