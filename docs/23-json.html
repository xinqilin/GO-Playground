JSON 與資料編碼

外送平台和便當店之間傳的訂單單：雙方先說好每一格叫什麼名字、填什麼格式。看不懂的單子要退回去並說清楚是哪一格；格式自己定的欄位（辣度、金額），就由那一方負責寫和讀。

Go 1.27 在標準庫加入了 encoding/json/v2 和 encoding/json/jsontext。舊的 encoding/json 現在叫 v1，會繼續支援，而且底層已經改用 v2 實作；官方文件建議新的程式用 v2。本章用 v2 寫，第 7 節再對照 v1，因為你在現有的程式碼、函式庫和網路文章裡看到的幾乎都是 v1。兩者的函式名稱大多一樣，import 的路徑不同，套件名稱都是 json：

import "encoding/json/v2"     # 本章用的 v2，套件名稱是 json
import "encoding/json"        # 現有程式碼裡的 v1，套件名稱也是 json

1. Marshal 與 Unmarshal

json.Marshal(v) 把 Go 的值編碼成 JSON 的 []byte，json.Unmarshal(data, &v) 反過來把 JSON 解碼到 Go 的值裡。最常用的是 struct：每個匯出的欄位變成 JSON 物件的一個成員，名稱寫在欄位後面的 struct tag 裡（09 章）：

type MenuItem struct {
	Name  string   `json:"name"`
	Price int      `json:"price"`
	Tags  []string `json:"tags"`
	cost  int      // 成本：小寫開頭，不會出現在 JSON 裡
}

func marshalDemo() {
	item := MenuItem{Name: "排骨飯", Price: 90, Tags: []string{"招牌", "炸物"}, cost: 55}
	b, err := json.Marshal(item)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))

	b, err = json.Marshal(MenuItem{Name: "白飯", Price: 10}) // Tags 是 nil
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))

	b, err = json.Marshal(item, jsontext.WithIndent("  ")) // 給人看的時候加上縮排
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))
}
{"name":"排骨飯","price":90,"tags":["招牌","炸物"]}
{"name":"白飯","price":10,"tags":[]}
{
  "name": "排骨飯",
  "price": 90,
  "tags": [
    "招牌",
    "炸物"
  ]
}
  • 沒有 tag 的話，JSON 的名稱就是欄位名稱 Name。對外的 API 通常用小寫或底線，所以幾乎每個欄位都會寫 tag。
  • v2 把 nil slice 編成 []、nil map 編成 {}，前端拿到的永遠是陣列，不用另外判斷 null。v1 在這裡不一樣（第 7 節）。
  • Marshal 的第二個參數起是選項。jsontext.WithIndent(" ") 加上縮排，給人看的時候用；傳給程式的就用預設的緊湊格式。
  • 中文直接輸出，不會被跳脫成 排 這種格式。

Unmarshal 要傳指標，它才改得到你的變數；傳值會回傳錯誤。JSON 裡多出來的欄位（這裡的 calories）預設會被略過：

func unmarshalDemo() {
	data := []byte(`{"name":"雞腿飯","price":100,"tags":["招牌"],"calories":780}`)
	var item MenuItem
	if err := json.Unmarshal(data, &item); err != nil {
		fmt.Println(err)
		return
	}
	fmt.Printf("%+v\n", item)

	stock := map[string]int{"雞腿": 12, "排骨": 0, "滷蛋": 30}
	b, err := json.Marshal(stock, json.Deterministic(true)) // map 的順序不固定，要固定就加這個選項
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))
}
{Name:雞腿飯 Price:100 Tags:[招牌] cost:0}
{"排骨":0,"滷蛋":30,"雞腿":12}
  • map 的 key 要能編成字串，例如 string、整數，或第 5 節的 TextMarshaler。
  • v2 輸出 map 的順序不固定，和 range 一樣（07 章）。要固定的順序（測試、要比對內容、要算雜湊）就加 json.Deterministic(true)，或改用 struct。
  • Marshal 失敗時，回傳的 []byte 可能是寫到一半的內容，一定要先檢查 err。

2. struct tag：名稱與省略

tag 的第一段是 JSON 的名稱，後面用逗號接選項。外送訂單的每個欄位示範一種常用的寫法：

type Order struct {
	ID       int64     `json:"id,string"`         // 很大的整數用字串傳，JavaScript 那邊才不會失真
	Customer string    `json:"customer"`          // 一定會輸出
	Items    []string  `json:"items,omitempty"`   // JSON 是空的（[]）就省略
	Note     string    `json:"note,omitempty"`    // 空字串就省略
	Discount int       `json:"discount,omitzero"` // Go 的零值（0）就省略
	PaidAt   time.Time `json:"paid_at,omitzero"`  // 還沒付款（零值）就省略；time.Time 有 IsZero 方法
	Phone    string    `json:"-"`                 // 個資，永遠不輸出
}

func tagsDemo() {
	o := Order{ID: 2026111900000000123, Customer: "林小姐", Phone: "0912-345-678"}
	b, err := json.Marshal(o)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))

	o.Items = []string{"排骨飯", "滷蛋"}
	o.Note = "不要香菜"
	o.Discount = 10
	o.PaidAt = time.Date(2026, time.November, 19, 12, 5, 0, 0, time.UTC)
	b, err = json.Marshal(o)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(string(b))
}
{"id":"2026111900000000123","customer":"林小姐"}
{"id":"2026111900000000123","customer":"林小姐","items":["排骨飯","滷蛋"],"note":"不要香菜","discount":10,"paid_at":"2026-11-19T12:05:00Z"}
  • json:"-"：這個欄位永遠不輸出，也不會被解碼寫入。電話、密碼雜湊這類欄位就算是大寫開頭也不該出現在 API 的回應裡。
  • string：數字用字串包起來，例如 "2026111900000000123"。JavaScript 的數字是 float64，超過 253 的整數會失真，很多 API 都把 64 位元的 ID 用字串傳。
  • time.Time 預設編成 RFC3339 的字串（22 章）。它有 IsZero 方法，omitzero 會用它判斷「還沒設定」。

兩個省略選項的差別，用同一個 struct 實際跑一次：

func omitDemo() {
	type flags struct {
		CountZ int      `json:",omitzero"`
		CountE int      `json:",omitempty"` // 0 編成 JSON 的 0，不是「空的」，所以不會省略
		ListZ  []string `json:",omitzero"`  // 只有 nil 才省略
		ListE  []string `json:",omitempty"` // nil 和長度 0 都編成 []，都省略
	}
	for _, f := range []flags{{}, {ListZ: []string{}, ListE: []string{}}} {
		b, err := json.Marshal(f)
		if err != nil {
			fmt.Println(err)
			return
		}
		fmt.Println(string(b))
	}
}
{"CountE":0}
{"CountE":0,"ListZ":[]}

CountE 的 0 沒有被 omitempty 省略：v2 的 omitempty 只看編出來的 JSON，0 不是「空的」。這和 v1 不一樣，v1 的 omitempty 會省略 0；從 v1 搬過來的程式碼，數字欄位上的 omitempty 要改成 omitzero。omitzero 在 v1 也能用（Go 1.24 起）。

3. 解碼的規則與錯誤

JSON 只有六種值。解碼到 struct 時，欄位的型別決定 JSON 的值要變成什麼；解碼到 any 時沒有型別可以參考，json 套件就照上圖選一個：

func anyDemo() {
	data := []byte(`{"name":"滷肉飯","price":35,"tags":["古早味"],"vegan":false,"note":null,"shop":{"id":7}}`)
	var v any
	if err := json.Unmarshal(data, &v); err != nil {
		fmt.Println(err)
		return
	}
	m := v.(map[string]any)
	for _, k := range slices.Sorted(maps.Keys(m)) {
		fmt.Printf("%-5s %T\n", k, m[k])
	}

	var big map[string]any
	if err := json.Unmarshal([]byte(`{"id":2026111900000000123}`), &big); err != nil {
		fmt.Println(err)
		return
	}
	fmt.Printf("%.0f\n", big["id"]) // float64 只有 15 到 17 位有效數字，後面的位數變了
}
name  string
note  <nil>
price float64
shop  map[string]interface {}
tags  []interface {}
vegan bool
2026111900000000000

最後一行：JSON 裡的整數是 2026111900000000123，解到 any 變成 float64，後面三位就沒了。這種 ID 要解到 int64 的欄位，或照第 2 節用 string 選項傳。

接著是兩個預設的寬鬆行為：大小寫不同的名稱、不認得的欄位，都會被安靜地略過。客戶端把 name 打成 Name，你收到的是空字串，卻沒有任何錯誤：

func strictDemo() {
	data := []byte(`{"Name":"雞腿飯","price":100,"spicy":true}`)

	var item MenuItem
	err := json.Unmarshal(data, &item)
	fmt.Printf("%q %d %v\n", item.Name, item.Price, err)

	err = json.Unmarshal(data, &item, json.RejectUnknownMembers(true))
	fmt.Println(explain(err), errors.Is(err, json.ErrUnknownName))
}
"" 100 <nil>
[位置 /Name，JSON string，Go main.MenuItem，原因 unknown object member name] true
  • v2 比對名稱時分大小寫，Name 對不到 name，被當成不認得的欄位。
  • 從外部收進來的 JSON（API 的請求、設定檔），通常加上 json.RejectUnknownMembers(true)，打錯的欄位名稱才會變成錯誤，而不是一個默默變成零值的欄位（練習 1）。
  • 要判斷是不是「不認得的欄位」，用 errors.Is(err, json.ErrUnknownName)。

解碼失敗分兩種。語法錯誤是 JSON 本身寫錯，例如多一個逗號、名稱重複，錯誤來自 jsontext 套件，會說在第幾個位元組。語意錯誤是 JSON 沒錯，但放不進 Go 的型別，例如字串要放進 int，錯誤的型別是 *json.SemanticError，用 JSON Pointer（/1/price：第 1 個元素的 price）指出是哪一個值：

func decodeErrorsDemo() {
	inputs := []string{
		`[{"name":"排骨飯","price":90},{"name":"雞腿飯","price":"一百"}]`, // 型別不對
		`[{"name":"排骨飯","price":90.5}]`,                           // int 放不下小數
		`[{"name":"排骨飯","price":90},]`,                            // 語法錯誤：多一個逗號
		`[{"name":"排骨飯","name":"雞腿飯"}]`,                           // 名稱重複
	}
	for _, in := range inputs {
		var menu []MenuItem
		fmt.Println(explain(json.Unmarshal([]byte(in), &menu)))
	}
}
[位置 /1/price，JSON string，Go int]
[位置 /0/price，JSON number，Go int，原因 invalid syntax]
jsontext: invalid character ',' at start of value after offset 32
jsontext: duplicate object member name "name" within "/0"

輸出裡方括號的部分是本章的 explain 函式整理出來的：

func explain(err error) string {
	se, ok := errors.AsType[*json.SemanticError](err)
	if !ok {
		return fmt.Sprint(err)
	}
	var parts []string
	if se.JSONPointer != "" {
		parts = append(parts, "位置 "+string(se.JSONPointer))
	}
	if se.JSONKind != 0 {
		parts = append(parts, "JSON "+se.JSONKind.String())
	}
	if se.GoType != nil {
		parts = append(parts, "Go "+se.GoType.String())
	}
	if se.Err != nil {
		parts = append(parts, "原因 "+se.Err.Error())
	}
	return strings.Replace(err.Error(), se.Error(), "["+strings.Join(parts, "，")+"]", 1)
}

為什麼不直接印錯誤訊息？因為 v2 是故意的：同一個語意錯誤，這次執行可能寫成 json: cannot unmarshal JSON string into Go int within "/1/price"，下次執行可能把 cannot 換成 unable to。標準庫的原始碼註解說明這是為了讓沒有人能依賴訊息的文字。程式要判斷錯誤時，用 errors.AsType[*json.SemanticError] 取出它，看 JSONPointer、GoType 這些欄位，或用 errors.Is 比對 json.ErrUnknownName 這類錯誤值（11 章）；訊息文字只給人看。

4. 結構未知的 JSON

不知道 JSON 的結構時，可以解到 map[string]any，再一層一層用型別斷言取值（10 章）。每往下一層都要用 comma-ok 的寫法，欄位不存在或型別不對時才不會 panic：

func lookupDemo() {
	data := []byte(`{"shop":{"name":"阿嬤便當","rating":4.7},"open":true}`)
	var v map[string]any
	if err := json.Unmarshal(data, &v); err != nil {
		fmt.Println(err)
		return
	}

	shop, ok1 := v["shop"].(map[string]any)
	name, ok2 := shop["name"].(string)
	rating, ok3 := shop["rating"].(float64)
	fmt.Println(name, rating, ok1 && ok2 && ok3)

	_, ok := v["closed_on"].(string)
	fmt.Println("沒有的欄位：", ok)
}
阿嬤便當 4.7 true
沒有的欄位： false

這種寫法又長又容易出錯，只適合真的不知道結構、或只要其中一兩個值的情況（練習 3）。更常見的是「結構有好幾種，外層的某個欄位說明是哪一種」，例如外送平台的通知：type 不同，data 的欄位就不同。這時讓 data 的型別是 jsontext.Value，它會原封不動地保留那一段 JSON，看了 type 再解第二次：

type Event struct {
	Type string         `json:"type"`
	Data jsontext.Value `json:"data"` // 先原封不動留著，看了 type 再決定怎麼解
}

type OrderPlaced struct {
	OrderID string `json:"order_id"`
	Total   int    `json:"total"`
}

type RiderAssigned struct {
	OrderID string `json:"order_id"`
	Rider   string `json:"rider"`
	ETA     int    `json:"eta_minutes"`
}

func describe(msg []byte) (string, error) {
	var ev Event
	if err := json.Unmarshal(msg, &ev); err != nil {
		return "", err
	}
	switch ev.Type {
	case "order.placed":
		var p OrderPlaced
		if err := json.Unmarshal(ev.Data, &p); err != nil {
			return "", err
		}
		return fmt.Sprintf("新訂單 %s，共 %d 元", p.OrderID, p.Total), nil
	case "rider.assigned":
		var r RiderAssigned
		if err := json.Unmarshal(ev.Data, &r); err != nil {
			return "", err
		}
		return fmt.Sprintf("%s 由 %s 外送，約 %d 分鐘", r.OrderID, r.Rider, r.ETA), nil
	default:
		return "", fmt.Errorf("不認得的通知類型 %q", ev.Type)
	}
}
新訂單 A-1024，共 280 元
A-1024 由 王大哥 外送，約 25 分鐘
錯誤： 不認得的通知類型 "order.refunded"
  • 每一種通知都有自己的 struct，第二次解碼一樣能用 RejectUnknownMembers 等選項檢查。
  • 不認得的 type 要回傳錯誤，不要默默略過：平台加了新的通知類型時，你才會知道。
  • 通知類型一多，switch 會越來越長。練習 6 用 Go 1.27 的 generic method 做一個可以登記處理函式的 Router。

5. 自訂編碼

型別在 JSON 裡應該是一個字串的時候（辣度、杯型、金額、ID），實作 encoding.TextMarshaler 和 encoding.TextUnmarshaler 最簡單：回傳文字就好，json 套件負責加引號、跳脫。程式裡的辣度是可以比大小的整數，JSON 裡是看得懂的中文：

type Spice int

const (
	NotSpicy Spice = iota
	Mild
	Medium
	Hot
)

var spiceNames = [...]string{"不辣", "小辣", "中辣", "大辣"}

func (s Spice) MarshalText() ([]byte, error) {
	if s < NotSpicy || s > Hot {
		return nil, fmt.Errorf("辣度 %d 超出範圍", int(s))
	}
	return []byte(spiceNames[s]), nil
}

func (s *Spice) UnmarshalText(b []byte) error {
	i := slices.Index(spiceNames[:], string(b))
	if i < 0 {
		return fmt.Errorf("不認得的辣度 %q", b)
	}
	*s = Spice(i)
	return nil
}

type Bowl struct {
	Dish  string `json:"dish"`
	Spice Spice  `json:"spice"`
}

func textDemo() {
	b, err := json.Marshal([]Bowl{{"麻辣鴨血", Hot}, {"清燉牛肉麵", NotSpicy}})
	fmt.Println(string(b), err)

	var bowl Bowl
	err = json.Unmarshal([]byte(`{"dish":"酸辣湯","spice":"中辣"}`), &bowl)
	fmt.Println(bowl.Dish, int(bowl.Spice), bowl.Spice > Mild, err)

	err = json.Unmarshal([]byte(`{"dish":"酸辣湯","spice":"超辣"}`), &bowl)
	fmt.Println(explain(err))

	sold := map[Spice]int{Hot: 3, Mild: 5}
	b, err = json.Marshal(sold, json.Deterministic(true))
	fmt.Println(string(b), err)
}
[{"dish":"麻辣鴨血","spice":"大辣"},{"dish":"清燉牛肉麵","spice":"不辣"}] <nil>
酸辣湯 2 true <nil>
[位置 /spice，JSON string，Go main.Spice，原因 不認得的辣度 "超辣"]
{"大辣":3,"小辣":5} <nil>
  • UnmarshalText 的 receiver 一定要是指標，才改得到呼叫者的值（09 章）。寫成值 receiver 不會有任何錯誤，只是解完的值永遠是零值（練習 7）。
  • UnmarshalText 回傳的錯誤會被包進 SemanticError，位置和型別自動填好。
  • TextMarshaler 也讓型別可以當 map 的 key：key 一定是字串，json 套件就用 MarshalText 的結果。
  • 需要輸出數字、物件、陣列時，實作 MarshalJSON() ([]byte, error)，v1、v2 都認得；v2 另外有效率較好的 MarshalJSONTo(*jsontext.Encoder) error。

標準庫裡很多型別已經實作了這些方法，例如 time.Time 和 Go 1.27 新增的 uuid 套件。uuid.UUID 在 JSON 裡就是標準格式的字串：

type Ticket struct {
	ID    uuid.UUID `json:"id"`
	Table int       `json:"table"`
}

func uuidDemo() {
	t := Ticket{ID: uuid.MustParse("019a9b1c-3f00-7d2e-8a41-5c6d7e8f9012"), Table: 7}
	b, err := json.Marshal(t)
	fmt.Println(string(b), err)

	var back Ticket
	err = json.Unmarshal(b, &back)
	fmt.Println(back.ID == t.ID, err)

	err = json.Unmarshal([]byte(`{"id":"A-1024","table":7}`), &back)
	fmt.Println(explain(err))

	fmt.Println(len(uuid.New().String())) // 每次都不一樣，這裡只印長度
}
{"id":"019a9b1c-3f00-7d2e-8a41-5c6d7e8f9012","table":7} <nil>
true <nil>

  • uuid.New() 產生一個新的 UUID，用的是適合大多數用途的演算法；需要指定版本時用 NewV4（隨機）或 NewV7（開頭是時間，依產生的順序遞增，適合當資料庫的主鍵）。
  • 格式不對的字串解碼時就會被擋下來，不用另外檢查。

別人的型別不能加方法。v2 讓呼叫的一方指定某個型別怎麼編碼：json.WithMarshalers。time.Duration 在 v2 沒有預設的 JSON 格式（v1 編成奈秒數，很少是對方想要的），直接編碼會失敗；可以指定把它寫成 "3h30m0s"：

type Recipe struct {
	Dish string        `json:"dish"`
	Prep time.Duration `json:"prep"`
}

func durationDemo() {
	r := Recipe{Dish: "紅燒牛肉", Prep: 3*time.Hour + 30*time.Minute}
	_, err := json.Marshal(r)
	fmt.Println(explain(err))

	asText := json.MarshalFunc(func(d time.Duration) ([]byte, error) {
		return json.Marshal(d.String())
	})
	b, err := json.Marshal(r, json.WithMarshalers(asText))
	fmt.Println(string(b), err)
}

  • json.MarshalFunc 用泛型推論出它處理的是 time.Duration，所有 Duration 欄位都會用這個函式，不管在第幾層。
  • 解碼對應的是 json.WithUnmarshalers 和 json.UnmarshalFunc。
  • 如果 Duration 是你自己 struct 的欄位，也可以換成一個實作 MarshalText 的自訂型別，讓所有呼叫的人都不用記得加選項。

6. 串流：一次一筆

log、匯出的資料常用 JSON Lines 格式：每一行是一筆完整的 JSON。這種檔案可能有好幾 GB，不能整個讀進來再 Unmarshal。jsontext.NewDecoder(r) 從 io.Reader 一邊讀一邊解，json.UnmarshalDecode 每次只解出下一個值：

type Sale struct {
	Shop   string `json:"shop"`
	Amount int    `json:"amount"`
}

func sumJSONLines(r io.Reader) (map[string]int, error) {
	dec := jsontext.NewDecoder(r)
	totals := map[string]int{}
	for n := 1; ; n++ {
		var s Sale
		err := json.UnmarshalDecode(dec, &s)
		if errors.Is(err, io.EOF) {
			return totals, nil
		}
		if err != nil {
			return nil, fmt.Errorf("第 %d 筆：%w", n, err)
		}
		totals[s.Shop] += s.Amount
	}
}

func linesDemo() {
	const input = `{"shop":"台北店","amount":1280}
{"shop":"台中店","amount":960}

{"shop":"台北店","amount":450}
`
	totals, err := sumJSONLines(strings.NewReader(input))
	if err != nil {
		fmt.Println(err)
		return
	}
	for _, shop := range slices.Sorted(maps.Keys(totals)) {
		fmt.Println(shop, totals[shop])
	}

	_, err = sumJSONLines(strings.NewReader(input + `{"shop":"高雄店","amount":"三百"}`))
	fmt.Println(explain(err))
}

  • 值和值之間的空白、空行都會被略過。讀到結尾時回傳 io.EOF，用 errors.Is 判斷。
  • 錯誤加上「第幾筆」：JSON Pointer 只知道是那一筆裡的哪個欄位，不知道是第幾筆。
  • HTTP 的 request body 也是 io.Reader，json.UnmarshalRead(r.Body, &v) 一行就能解一個值（「HTTP 伺服器」那一章會用到）。

另一種大檔案是一個很大的 JSON 陣列。用 ReadToken 先讀掉開頭的 [，再用 PeekKind 偷看下一個是不是 ]，不是的話就解一個元素：

func countExpensive(r io.Reader, limit int) (int, error) {
	dec := jsontext.NewDecoder(r)
	tok, err := dec.ReadToken() // 先讀掉開頭的 [
	if err != nil {
		return 0, err
	}
	if tok.Kind() != '[' {
		return 0, fmt.Errorf("要的是陣列，開頭卻是 %v", tok.Kind())
	}
	n := 0
	for dec.PeekKind() != ']' {
		var item MenuItem
		if err := json.UnmarshalDecode(dec, &item); err != nil {
			return 0, err
		}
		if item.Price > limit {
			n++
		}
	}
	return n, nil
}

func arrayDemo() {
	menu := `[{"name":"滷肉飯","price":35},{"name":"雞腿飯","price":100},{"name":"牛肉麵","price":180}]`
	fmt.Println(countExpensive(strings.NewReader(menu), 90))
	fmt.Println(countExpensive(strings.NewReader(`{"name":"滷肉飯"}`), 90))

7. 現有程式碼裡的 encoding/json

你會在現有的程式碼裡看到大量的 encoding/json，也就是 v1。函式名稱和用法幾乎一樣，但有幾個預設的行為不同。同樣的 struct、同樣的輸入，兩邊各跑一次：

type Dish struct {

8. encoding/csv

CSV 是和試算表交換資料最常見的格式：會計要的發票明細、從後台匯出的菜單。標準庫的 encoding/csv 處理引號、逗號、換行這些細節，你只要處理 []string：

type InvoiceLine struct {
	Number string // 發票號碼
	Item   string
	Amount int
}

func writeInvoices(w io.Writer, lines []InvoiceLine) error {
	cw := csv.NewWriter(w)
	if err := cw.Write([]string{"發票號碼", "品項", "金額"}); err != nil {
		return err
	}
	for _, l := range lines {
		if err := cw.Write([]string{l.Number, l.Item, strconv.Itoa(l.Amount)}); err != nil {
			return err
		}
	}
	cw.Flush() // csv.Writer 有緩衝區，最後一定要 Flush，再用 Error 檢查寫入有沒有出錯
	return cw.Error()
}

func readInvoices(r io.Reader) ([]InvoiceLine, error) {
	cr := csv.NewReader(r)
	cr.FieldsPerRecord = 3
	if _, err := cr.Read(); err != nil { // 標題
		return nil, err
	}
	var lines []InvoiceLine
	for {
		rec, err := cr.Read()
		if errors.Is(err, io.EOF) {
			return lines, nil
		}
		if err != nil {
			return nil, err
		}
		amount, err := strconv.Atoi(rec[2])
		if err != nil {
			line, _ := cr.FieldPos(2)
			return nil, fmt.Errorf("第 %d 行：金額 %q 不是整數", line, rec[2])
		}
		lines = append(lines, InvoiceLine{Number: rec[0], Item: rec[1], Amount: amount})
	}
}

  • FieldsPerRecord = 3 要求每一行剛好 3 個欄位；預設值 0 的意思是「每一行都要和第一行一樣多」，設成負數則不檢查。
  • 錯誤訊息裡的行號用 FieldPos（Go 1.17 起）取得：欄位裡有換行時，「第幾筆」和「檔案的第幾行」不一樣，FieldPos 給的是檔案的行號（練習 5）。
  • CSV 沒有型別，所有欄位都是字串，數字要自己用 strconv 轉、自己檢查。
  • 欄位的分隔符號可以改：cr.Comma = '\t' 就能讀 TSV。

常見錯誤

1. 欄位小寫開頭，輸出裡沒有它

json 套件在另一個 package，看不到未匯出的欄位，加了 tag 也沒用。要輸出的欄位一定大寫開頭，JSON 的名稱用 tag 改（第 1 節）。

2. 欄位名稱打錯，被安靜地略過

大小寫不同、拼錯的欄位都不會報錯，你拿到的是零值。外部來的 JSON 加上 RejectUnknownMembers，再自己檢查必填的欄位（第 3 節、練習 1）。

3. 比對錯誤訊息的文字

v2 故意讓同一個錯誤的訊息每次執行可能不同。判斷錯誤用 errors.Is 比對 ErrUnknownName 這類值，或用 errors.AsType 取出 SemanticError 看欄位（第 3 節）。

4. 大整數解到 any 或 float64

float64 放不下 19 位數的 ID，後面的位數會變。解到 int64 欄位，或在雙方約定用字串傳（string 選項，第 2、3 節）。

5. 從 v1 搬過來，數字上的 omitempty 不再省略 0

v2 的 omitempty 看的是 JSON 是不是空的，0 不算空的。數字、bool、time.Time 要省略零值，改用 omitzero，它在 v1、v2 的意思一樣（第 2 節）。

6. 依賴 map 的輸出順序

v2 輸出 map 的順序每次都可能不同。測試要比對字串、或要計算雜湊時，加上 Deterministic(true)，或改用 struct（第 1 節）。

7. UnmarshalText、UnmarshalJSON 用值 receiver

方法改到的是複本，解碼沒有錯誤，值卻還是零值。解碼的方法 receiver 一定是指標（第 5 節、練習 7）。

8. csv.Writer 沒有 Flush，或沒有檢查 Error

最後幾行還在緩衝區裡，檔案少了一段；寫入失敗也不會有人知道（第 8 節）。

參考解答：先自己寫完再看。測試通過的寫法都是對的。

重點回顧

  • 新的程式用 encoding/json/v2；現有程式碼裡的 encoding/json 是 v1，用法相近，預設行為有幾個不同。
  • 只有匯出的欄位會變成 JSON，名稱用 struct tag 指定；Unmarshal 要傳指標。
  • omitzero 看 Go 的零值，omitempty 看 JSON 是不是空的；數字和時間用 omitzero。
  • 大整數 ID 用 string 選項傳，解到 any 的數字一律是 float64。
  • 不認得的欄位預設被略過，外部來的 JSON 加 RejectUnknownMembers，再檢查必填欄位。
  • 判斷錯誤看 SemanticError 的欄位或 errors.Is，不要比對訊息文字。
  • 結構有好幾種時，用 jsontext.Value 先保留一段，看了 type 再解。
  • 字串型的自訂格式實作 MarshalText 和指標 receiver 的 UnmarshalText；別人的型別用 WithMarshalers。
  • 大檔案用 jsontext.Decoder 一筆一筆解；JSON Lines 用 UnmarshalDecode，大陣列加上 ReadToken、PeekKind。
  • CSV 用 encoding/csv，不要自己切逗號；寫完 Flush 再檢查 Error。
