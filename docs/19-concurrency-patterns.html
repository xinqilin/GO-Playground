並行模式

把前幾章的零件組起來：固定人數的工班、匯流的輸送帶、有限的號碼牌。

看圖

最小範例

func main() {
	jobs := make(chan int)
	results := make(chan int)
	var wg sync.WaitGroup
	for range 3 { // 固定 3 個 worker
		wg.Go(func() {
			for n := range jobs {
				results <- n * n
			}
		})
	}
	go func() { // 派工，派完就關
		for n := range 5 {
			jobs <- n + 1
		}
		close(jobs)
	}()
	go func() { wg.Wait(); close(results) }() // worker 都結束才關結果
	sum := 0
	for r := range results {
		sum += r
	}
	fmt.Println(sum)
}

輸出

55

工程師筆記

  • worker 數量固定，工作再多 goroutine 也不會暴增；CPU 密集的工作用 CPU 數，I/O 密集可以多一些。
  • 誰關哪個 channel 要講清楚：派工的 goroutine 關 jobs，所有 worker 結束後再關 results。
  • 每個可能卡住的送出都要搭配 ctx.Done()，取消時 goroutine 才能收工，不會洩漏。
  • 並行結果的順序不固定；需要順序就帶著編號，最後再排序。
  • 需要「任何一個出錯就全部取消」時，用 golang.org/x/sync/errgroup，它的 SetLimit 也能限制同時數量。
  • 先寫循序版本，量過真的太慢再改成並行；並行版本一定要用 -race 測過。
