費氏數列

0、1、1、2、3、5、8……每一項是前兩項的和。題目短到一行就說完，但要寫對、寫快、算到很大的數字，會一路碰到遞迴的代價、整數溢位和任意精度。這個專題把同一個數列用五種方法寫一次，每一種都有測試互相對照。

這個專題做什麼

這個 repo 最早有一支 Exercise/fibonacci.go，裡面有三個問題：隨機抽到 n = 0 時會無限遞迴，最後 stack overflow；fibonacci(2) 回傳 2，整個數列錯開一格；還在呼叫 Go 1.20 起已經 deprecated 的 rand.Seed。這個專題從修好它開始，最後做出一個命令列工具：

1. 照定義寫：遞迴

最直接的寫法就是把定義翻成程式：

func Recursive(n int) int {
	if n <= 0 {
		return 0
	}
	if n == 1 {
		return 1
	}
	return Recursive(n-1) + Recursive(n-2)
}

兩個停止條件都很重要。舊版只寫了 n == 1 和 n == 2：從 F(0) 開始會呼叫 F(-1)、F(-2)，永遠碰不到停止條件；而且 F(2) 被寫成 2，整個數列錯開一格。新版用 n <= 0 一次擋下 0 和所有負數。

這個寫法正確，但非常慢。數一數它到底呼叫了自己幾次：

func countCalls(n int) int {
	calls := 0
	var f func(int) int
	f = func(n int) int {
		calls++
		if n <= 0 {
			return 0
		}
		if n == 1 {
			return 1
		}
		return f(n-1) + f(n-2)
	}
	f(n)
	return calls
}
Recursive(5) 呼叫了 15 次
Recursive(10) 呼叫了 177 次
Recursive(20) 呼叫了 21891 次
Recursive(30) 呼叫了 2692537 次
  • 呼叫次數剛好是 2·F(n+1) − 1，TestCountCalls 對 n = 0 到 25 驗證了這個關係。F(30) 只是 832040，卻要呼叫兩百多萬次。
  • countCalls 用一個 closure 改外面的 calls 變數。函式要遞迴呼叫自己的 closure 時，必須先宣告變數 var f func(int) int，再把函式指定給它，否則函式本體裡還看不到 f。
  • 遞迴的深度是 n，每一層都佔一點 stack。Go 的 goroutine stack 會自動長大，所以不會像 C 那樣很快就爆掉，但慢的問題還在。

2. 記住算過的：記憶化

func Memoized() func(int) int {
	memo := map[int]int{}
	var fib func(int) int
	fib = func(n int) int {
		if n <= 0 {
			return 0
		}
		if n == 1 {
			return 1
		}
		if v, ok := memo[n]; ok {
			return v
		}
		v := fib(n-1) + fib(n-2)
		memo[n] = v
		return v
	}
	return fib
}
  • Memoized 回傳一個函式，表 memo 是它捕獲的變數（04 章）。每次呼叫 Memoized() 都得到一張新的表，兩個呼叫端不會互相影響。
  • 寫法和 Recursive 幾乎一樣，只是在計算前查表、計算後存表。這是記憶化最大的優點：不用改演算法，就把重複的計算拿掉。
  • 表用 map 很直覺，但 n 是連續的小整數，用長度 n+1 的 slice 更省（延伸挑戰 1）。
  • 這個 closure 不能同時被多個 goroutine 使用：map 不是並行安全的（07 章）。

3. 只記兩個數：迴圈

func Iterative(n int) int {
	a, b := 0, 1
	for range max(n, 0) {
		a, b = b, a+b
	}
	return a
}
  • a, b = b, a+b 是 Go 的多重指定：右邊的值全部先算好，再一起指定給左邊（規格）。所以不需要暫存變數，也不會用到更新到一半的 a。
  • for range max(n, 0)：Go 1.22 起可以 range 一個整數；用 max 把負數當成 0，迴圈一次都不跑，回傳 F(0) = 0。
  • 時間和 n 成正比，記憶體固定只有兩個變數。這是 n 在 int 範圍內時最好的寫法。

4. 溢位：int 的上限

64 位元的 int 最大約 9.2 × 10¹⁸，F(92) 是最後一個放得下的項。Iterative(93) 不會失敗，只會默默給你一個錯的負數：

const maxN = 92

var ErrOverflow = errors.New("超過 int 的範圍")

func Checked(n int) (int, error) {
	if n <= 0 {
		return 0, nil
	}
	a, b := 0, 1 // F(0)、F(1)
	for range n - 1 {
		if a > math.MaxInt-b {
			return 0, fmt.Errorf("F(%d)：%w", n, ErrOverflow)
		}
		a, b = b, a+b
	}
	return b, nil
}
math.MaxInt   = 9223372036854775807
F(92)         = 7540113804746346429
F(93)         = 12200160415121876738
Iterative(93) = -6246583658587674878
F(93)：超過 int 的範圍
  • 先檢查再加：a > math.MaxInt-b 等於「a + b 會超過 MaxInt」，但這個比較本身不會溢位。等加完再檢查結果是不是負數也能抓到這次，但那是依賴溢位後的行為，意圖不清楚。
  • Checked 從 F(1) 開始只走 n−1 步，讓最後一步算出來的正好是 F(n)。如果照 Iterative 走 n 步，算 F(92) 時最後一步會多算一個用不到、而且會溢位的 F(93)，誤報錯誤。這種差一的問題，靠 TestAgreeWithBig 從 0 到 92 每一項都比對才抓得到。
  • 錯誤用 %w 包住 ErrOverflow，呼叫端用 errors.Is 判斷（11 章）。
  • int 在 32 位元的平台只有 32 位元，maxN 會小很多。需要固定大小時用 int64 或 uint64（01 章）。

5. 一項一項產生：疊代器

func Seq() iter.Seq[int] {
	return func(yield func(int) bool) {
		a, b := 0, 1
		nextFits := true // b 是正確的值嗎（之前的加法沒有溢位）
		for {
			if !yield(a) || !nextFits {
				return
			}
			nextFits = a <= math.MaxInt-b
			a, b = b, a+b
		}
	}
}
func printList(out io.Writer, count int) error {
	if count < 1 || count > maxN+1 {
		return fmt.Errorf("list 必須介於 1 到 %d，收到 %d", maxN+1, count)
	}
	var terms []string
	for v := range Seq() {
		terms = append(terms, strconv.Itoa(v))
		if len(terms) == count {
			break
		}
	}
	fmt.Fprintln(out, strings.Join(terms, " "))
	return nil
}
  • yield 回傳 false 就要停。呼叫端 break 之後還繼續 yield，執行時會 panic（13 章）。
  • nextFits：和 Checked 一樣的檢查，只是位置不同。算出 F(93) 會溢位時，F(92) 還是正確的，所以要先 yield 它再結束。結果是剛好 93 項：F(0) 到 F(92)，TestAgreeWithBig 檢查了數量和每一項。
  • 呼叫端想要幾項就拿幾項，-list 15 只算了 15 項。同一個 Seq 也可以搭配 slices.Collect 收集全部、或在 for range 裡找第一個超過一百萬的項。

6. 沒有上限：math/big

F(100) 有 21 位數，int 放不下。math/big 的 Int 可以表示任意大的整數，大小只受記憶體限制：

func Big(n int) *big.Int {
	a, b := big.NewInt(0), big.NewInt(1)
	for range max(n, 0) {
		a.Add(a, b)
		a, b = b, a
	}
	return a
}
F(1000) 有 209 位數，開頭是 4346655768…，結尾是 …6849228875
  • 結果寫進 receiver：a.Add(a, b) 把 a + b 的結果存進 a，並回傳 a。math/big 的方法都是這個形式（z.Op(x, y)），讓你重複使用同一個 Int，不用每一步都配置新的數字。
  • 交換指標：a, b = b, a 交換的是兩個 *big.Int 指標，不是數字本身，所以很便宜。加完之後 a 存的是新的一項，交換後它變成 b，舊的 b 變成 a。
  • *big.Int 不要直接複製值：x := *a 會讓兩個 Int 共用內部的陣列。要複製用 new(big.Int).Set(a)。
  • 代價是速度：每一次加法都要處理一個陣列，數字越大越慢。int 放得下時，用 int。

7. 比一比：benchmark

func BenchmarkFib(b *testing.B) {
	const n = 30
	b.Run("recursive", func(b *testing.B) {
		for b.Loop() {
			Recursive(n)
		}
	})
	b.Run("memoized", func(b *testing.B) {
		for b.Loop() {
			Memoized()(n)
		}
	})
	b.Run("iterative", func(b *testing.B) {
		for b.Loop() {
			Iterative(n)
		}
	})
	b.Run("seq", func(b *testing.B) {
		for b.Loop() {
			i := 0
			for range Seq() {
				if i == n {
					break
				}
				i++
			}
		}
	})
	b.Run("big", func(b *testing.B) {
		for b.Loop() {
			Big(n)
		}
	})
}

  • recursive：沒有配置任何記憶體，但呼叫了 269 萬次函式。演算法的複雜度一錯，再怎麼省記憶體都救不回來。
  • memoized：快了兩千多倍，但每次都建一張新的 map，map 長大時要配置好幾次（7 allocs）。benchmark 裡每一圈都呼叫 Memoized()，量的是「從空的表開始」的成本。
  • iterative：30 次加法，11 奈秒，沒有任何配置。
  • seq：同樣是 30 次加法，多了每一項一次的 yield 呼叫，慢了幾倍，但仍然不配置記憶體。換來的是呼叫端可以自由決定要幾項。
  • big：每次都配置兩個 big.Int，加法也比較重。F(30) 用不到它，F(100) 以上只能用它。
  • 結論不是「永遠用最快的」：F(n) 在 int 範圍內用迴圈；要一串數列用疊代器；超過範圍用 math/big；遞迴適合用來寫出第一個正確的版本，作為測試的對照組（31 章）。

8. 包成命令列工具

main 只做一件事：呼叫 run，把錯誤印到 stderr，用 exit code 2 結束。真正的邏輯在 run 裡，參數和輸出都從外面傳進來，所以 Example 和測試可以直接呼叫它（21 章）：

func run(args []string, out io.Writer) error {
	fs := flag.NewFlagSet("fibonacci", flag.ContinueOnError)
	fs.SetOutput(out)
	n := fs.Int("n", 10, "要算第幾項（0 以上）")
	list := fs.Int("list", 0, fmt.Sprintf("改成列出前幾項（1 到 %d）", maxN+1))
	if err := fs.Parse(args); err != nil {
		if errors.Is(err, flag.ErrHelp) {
			return nil // -h：用法已經印出來了，不是錯誤
		}
		return err
	}
	if *list != 0 {
		return printList(out, *list)
	}
	if *n < 0 {
		return fmt.Errorf("n 不能是負數，收到 %d", *n)
	}

	v, err := Checked(*n)
	if err != nil {
		fmt.Fprintf(out, "F(%d) = %s\n", *n, Big(*n))
		fmt.Fprintf(out, "超過 int 的範圍（最大到 F(%d)），只用 math/big 計算\n", maxN)
		return nil
	}
	fmt.Fprintf(out, "F(%d) = %d\n", *n, v)
	if *n <= slowN {
		fmt.Fprintf(out, "遞迴：%d（呼叫了 %d 次）\n", Recursive(*n), countCalls(*n))
	} else {
		fmt.Fprintf(out, "遞迴：略過（n 大於 %d 會跑很久）\n", slowN)
	}
	fmt.Fprintf(out, "記憶化：%d\n", Memoized()(*n))
	fmt.Fprintf(out, "迴圈：%d\n", Iterative(*n))
	fmt.Fprintf(out, "math/big：%s\n", Big(*n))
	return nil
}

func main() {
	if err := run(os.Args[1:], os.Stdout); err != nil {
		fmt.Fprintln(os.Stderr, "錯誤：", err)
		os.Exit(2)
	}
}
  • FlagSet 加 ContinueOnError：參數錯誤時回傳 error，而不是直接結束整個程式，測試才測得到。TestRunErrors 試了負數、不是數字、超出範圍的 -list。
  • 依 n 選方法：先用 Checked；溢位時改用 math/big，告訴使用者原因。n 大於 35 時不跑遞迴，因為它會跑好幾秒以上。
  • 每一種寫法互相對照：-n 30 的輸出同時印出四種方法的結果。測試裡也是同一個想法：TestAgreeWithBig 讓最慢但最可靠的 math/big 當標準答案，其他寫法都要和它一致。

延伸挑戰

這些題目沒有附測試，寫完用 go test 和 benchmark 自己驗證：先寫測試，再寫實作。

  1. 入門挑戰 1：用 slice 當記憶化的表

    把 Memoized 的 map 換成長度 n+1 的 slice，零值 0 代表「還沒算過」（F(0) 本來就是 0，不影響結果）。用 -benchmem 比較兩個版本的配置次數和時間。

    提示

    slice 的大小要在知道 n 之後才能決定，所以函式的形狀要改成 func MemoSlice(n int) int，或讓表在需要時用 append 長大。

  2. 進階挑戰 2：列出某一段

    加上 -from 和 -to 兩個旗標，例如 -from 10 -to 15 印出 F(10) 到 F(15)。用 Seq 實作，不要先算出整個 slice 再切。

    提示

    for range Seq() 時自己數 index，小於 from 的跳過，超過 to 就 break。別忘了檢查 from ≤ to，以及 to 不能超過 92。

  3. 進階挑戰 3：fuzz 測試

    寫一個 FuzzChecked：對任意的 n（限制在 0 到 200），Checked 沒有錯誤時結果要和 Big 相同；有錯誤時 Big(n) 一定放不進 int64（IsInt64() 是 false）。

    提示

    fuzz 的輸入可以是任意 int，先用 n = abs(n) % 201 之類的方式收斂到想要的範圍（30 章）。

  4. 挑戰挑戰 4：fast doubling

    利用 F(2k) = F(k)·(2F(k+1) − F(k)) 和 F(2k+1) = F(k)² + F(k+1)²，從 n 的二進位最高位往下算，只要 log₂ n 步。用 math/big 實作，和 Big 比較 F(100000) 的 benchmark。

    提示

    從 (F(0), F(1)) = (0, 1) 開始，n 的每一個位元都先「加倍」得到 (F(2k), F(2k+1))，如果這個位元是 1，再往前走一步得到 (F(2k+1), F(2k+2))。用 TestAgreeWithBig 的方式和 Big 比對前幾百項。

  5. 挑戰挑戰 5：任意起始的兩項

    寫一個泛型的 Sequence[T ~int | ~int64 | ~uint64](first, second T) iter.Seq[T]，從任意兩項開始產生「每項是前兩項的和」的數列。Lucas 數列就是從 2、1 開始的版本：2、1、3、4、7、11……

    提示

    型別參數讓同一份程式用在不同的整數型別（12 章）。溢位的檢查要依型別不同：可以先只支援由呼叫端決定要拿幾項，不檢查溢位，並在文件寫清楚。

重點回顧

  • 遞迴寫起來最像定義，但重複計算讓它是指數時間；停止條件要涵蓋 0 和負數。
  • 記憶化不改演算法，只加一張表；遞迴的 closure 要先宣告變數再指定。
  • a, b = b, a+b：右邊先全部算完再指定，迴圈版只需要兩個變數。
  • Go 的整數溢位不會報錯；用 a > math.MaxInt-b 在加之前檢查。
  • 疊代器把產生和使用分開；yield 回傳 false 就要停。
  • math/big 沒有上限，方法把結果寫進 receiver，可以重複使用同一個數字。
  • 用最簡單可靠的版本當標準答案，讓其他寫法和它逐項比對。
