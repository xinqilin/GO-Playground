1. if：依條件走不同的路

if 後面接一個結果是 bool 的運算式：成立就執行大括號裡的程式，不成立就跳過。後面可以接任意多個 else if，最後可以有一個 else。Go 會由上往下檢查，第一個成立的區塊執行完就離開整組 if，後面的條件連看都不看。

func ifElse() {
	for _, temp := range []int{33, 24, 12} {
		if temp >= 30 {
			fmt.Println(temp, "度：開冷氣")
		} else if temp >= 20 {
			fmt.Println(temp, "度：開窗就好")
		} else {
			fmt.Println(temp, "度：穿外套")
		}
	}
}

輸出

33 度：開冷氣
24 度：開窗就好
12 度：穿外套

寫法上有四條規則，從其他語言過來的人要特別注意：

  • 條件不用加括號。寫成 if (temp >= 30) 也能編譯，但 gofmt 會把多餘的括號拿掉。
  • 大括號一定要寫，即使區塊只有一行。這讓「以為第二行也在 if 裡，其實不在」這一類 bug 根本不會發生。
  • { 必須跟條件寫在同一行，換行會編譯錯誤，原因在常見錯誤 1。
  • 條件只能是 bool。整數 0、空字串、nil 都不會自動被當成 false，要明確寫出 n != 0、s != ""、p != nil。
沒有三元運算子

Go 刻意不提供 cond ? a : b，一律寫成 if/else。常見的寫法是先給預設值，再用 if 覆寫：label := "平日"，接著 if weekend { label = "假日" }。

1.2 if 前面先做一件事

if 的條件前面可以放一個簡短敘述，用分號和條件隔開。最常見的用途是「呼叫一個會回傳錯誤的函式，馬上檢查錯誤」。下面的 strconv.Atoi 把字串轉成 int，失敗時回傳錯誤（錯誤在第 11 章細講）：

func ifInit() {
	for _, input := range []string{"3", "三", "0"} {
		if n, err := strconv.Atoi(input); err != nil {
			fmt.Printf("%q 不是數字\n", input)
		} else if n <= 0 {
			fmt.Println("至少要訂 1 個")
		} else {
			fmt.Println("訂", n, "個便當，共", n*85, "元")
		}
		// 這裡已經看不到 n 和 err
	}
}

輸出

訂 3 個便當，共 255 元
"三" 不是數字
至少要訂 1 個

在這裡宣告的 n 和 err，作用域只有這一組 if / else if / else：每個分支都看得到它們，離開之後就消失。這樣變數的壽命剛好等於它被需要的範圍，下面的程式不會不小心用到「上一次留下來的 err」。如果 if 結束後還需要 n，就把 n, err := strconv.Atoi(input) 移到 if 前面單獨一行。

1.3 guard clause：先處理例外，主流程靠左

判斷條件一多，if 很容易越疊越深：每通過一個檢查就往右縮一層，真正要做的事被擠到最右邊，每個 else 又離它對應的 if 很遠。Go 社群偏好的寫法是 guard clause（防衛子句）：先檢查「不合格」的情況，處理完立刻 return，通過所有檢查之後的主流程就留在最外層。

巢狀寫法（難讀）

func canShipNested(o order) string {
	if o.paid {
		if o.address != "" {
			if o.items > 0 {
				return "可以出貨"
			} else {
				return "購物車是空的"
			}
		} else {
			return "缺少地址"
		}
	} else {
		return "還沒付款"
	}
}

guard clause（建議）

func canShip(o order) string {
	if !o.paid {
		return "還沒付款"
	}
	if o.address == "" {
		return "缺少地址"
	}
	if o.items == 0 {
		return "購物車是空的"
	}
	return "可以出貨"
}

用四筆訂單同時呼叫兩個版本，結果完全一樣，差別只在好不好讀：

type order struct {
	paid    bool
	address string
	items   int
}

func guardClause() {
	orders := []order{
		{paid: false},
		{paid: true},
		{paid: true, address: "台北市信義路 1 號"},
		{paid: true, address: "台北市信義路 1 號", items: 2},
	}
	for _, o := range orders {
		fmt.Println(canShipNested(o), "|", canShip(o))
	}
}

輸出

還沒付款 | 還沒付款
缺少地址 | 缺少地址
購物車是空的 | 購物車是空的
可以出貨 | 可以出貨

讀 Go 程式碼時你會一直看到這個形狀：if err != nil { return … } 一段接一段，主流程沿著左邊往下走。這是刻意的：眼睛沿著左邊掃下來，就知道正常情況做了什麼；縮排進去的都是例外處理。另外，return 之後的 else 是多餘的，一些 linter 會把它標出來。

1.4 作用域與 shadowing

Go 的變數作用域以大括號為界：在某個區塊裡宣告的變數，只有這個區塊和更內層的區塊看得到。如果內層用 := 宣告一個和外層同名的變數，產生的是一個全新的變數，把外層的「遮住」，這叫 shadowing。在內層區塊裡，這個名字指的是新變數；離開區塊之後，外層變數原封不動。

func shadowing() {
	limit := 100
	if limit > 50 {
		limit := 50 // 新的 limit，只活在這個區塊
		fmt.Println("區塊裡：", limit)
	}
	fmt.Println("區塊外：", limit)
}

輸出

區塊裡： 50
區塊外： 100
真實程式裡沒這麼明顯

在內層區塊裡，:= 左邊的名字全都算是這個區塊的新變數，即使外層已經有同名的變數。它最常和多個回傳值一起出現：theme, err := readSetting(…) 寫在 if 裡，就會不知不覺宣告出一個新的 theme。常見錯誤 2 有完整的例子。

2. for：Go 唯一的迴圈

其他語言有 for、while、do-while、for-each，Go 全部用 for 一個關鍵字表達，差別只在 for 後面寫了什麼。

2.1 三段式

寫法是 for 初始化; 條件; 後置敘述 { … }。初始化只在一開始做一次；每一圈開始前檢查條件，成立才進入；每一圈跑完之後執行後置敘述，再回去檢查條件。三段之間用分號隔開，和 if 一樣不加括號。

func forClassic() {
	for n := 1; n <= 3; n++ {
		fmt.Printf("請 %d 號到櫃台\n", n)
	}
}

輸出

請 1 號到櫃台
請 2 號到櫃台
請 3 號到櫃台

初始化裡用 := 宣告的 n 只活在這個 for 裡。後置敘述通常是 n++；要注意 Go 的 ++ 和 -- 是敘述，不是運算式：不能寫 x := n++，也沒有 ++n 這種寫法。

2.2 只寫條件：Go 的 while

func forCondition() {
	balance, months := 0, 0
	for balance < 10000 {
		balance += 3000
		months++
	}
	fmt.Println(months, "個月後存到", balance, "元")
}

輸出

4 個月後存到 12000 元

把初始化和後置敘述都拿掉、只留條件，就是其他語言的 while。目標是存到 10000 元，每個月存 3000：第 3 個月後是 9000，還不夠；第 4 個月後是 12000，條件不成立，迴圈結束。

2.3 什麼都不寫：無窮迴圈

func forInfinite() {
	queue := []string{"A01", "A02", "A03"}
	for {
		if len(queue) == 0 {
			fmt.Println("沒有人在排隊了")
			break
		}
		next := queue[0]
		queue = queue[1:]
		fmt.Println("叫號", next)
	}
}

輸出

叫號 A01
叫號 A02
叫號 A03
沒有人在排隊了

for { … } 會一直跑，直到遇到 break、return 或程式結束。伺服器的主迴圈、「一直讀到沒有資料為止」這類情境很常用它。Go 也沒有 do-while（先做一次再檢查），一樣用無窮迴圈表達：把檢查放在迴圈的最後面，條件不成立就 break。

2.4 range 一個整數

func forRangeInt() {
	for i := range 3 {
		fmt.Println("第", i, "圈")
	}
}

輸出

第 0 圈
第 1 圈
第 2 圈

Go 1.22 起，for i := range n 會讓 i 依序是 0、1、…、n-1，等同 for i := 0; i < n; i++，但更短，也不會打錯邊界。如果只是要重複 n 次、用不到 i，就寫 for range n。

2.5 continue：跳過這一圈

func forContinue() {
	for n := range 10 {
		if n%3 != 0 {
			continue
		}
		fmt.Println(n, "是 3 的倍數")
	}
}

輸出

0 是 3 的倍數
3 是 3 的倍數
6 是 3 的倍數
9 是 3 的倍數

continue 會跳過這一圈剩下的程式，直接進入下一圈；如果是三段式，會先執行後置敘述。這和 guard clause 是同一個道理：在迴圈開頭用 continue 濾掉不需要處理的情況，主要邏輯就可以少縮一層。

三段都可以省略

for ; i < 10; { 是合法的，但 gofmt 會把它改寫成 for i < 10 {。同樣地，for ;; { 會被改寫成 for {。

3. range：走過一整組資料

for 變數 := range 運算式 會依序走過運算式裡的每個元素。運算式的型別決定了每一圈給你什麼：

range 的對象第一個值第二個值
slice、陣列索引 int元素（複本）
字串字元起始的 byte 位置 int字元 rune
mapkeyvalue
channel收到的值沒有
整數 n0 到 n-1沒有
特定形狀的函式由函式決定，見 3.6 與第 13 章

不需要的值用 _ 丟掉：for _, v := range s 只要值；只要索引就寫 for i := range s，連 _ 都不用寫。

3.1 拿到的是複本

range 每一圈都會把元素複製到迴圈變數。元素是 int、string 這種小值時沒什麼差別，但當元素是 struct，又想透過迴圈變數修改欄位時就會出事：你改到的是複本。

type dish struct {
	name  string
	stock int
}

func rangeCopy() {
	menu := []dish{{"雞腿飯", 3}, {"排骨飯", 5}}
	for _, d := range menu {
		d.stock = 0 // 改到的是複本 d
	}
	fmt.Println(menu)

	for i := range menu {
		menu[i].stock = 0 // 透過索引才改得到 menu 裡的元素
	}
	fmt.Println(menu)
}

輸出

[{雞腿飯 3} {排骨飯 5}]
[{雞腿飯 0} {排骨飯 0}]

要修改 slice 裡的元素，必須透過索引 menu[i]。另一種做法是讓 slice 存指標（[]*dish），這時複製的是指標，透過它修改就會改到同一份資料；指標在第 05 章介紹。

深入：第一次讀可以先跳過

3.2 range 陣列會先整個複製一份

range 後面的運算式只在迴圈開始前求值一次。陣列在 Go 是「值」，求值一次就等於把整個陣列複製一份，迴圈走的是這份複本。slice 則只是一個指向底層陣列的小結構（第 06 章），複製它並不會複製底層資料。所以迴圈中途修改原本的資料，陣列版看不到，slice 版看得到：

func rangeArrayCopy() {
	arr := [3]string{"空", "空", "空"}
	var seen []string
	for i, s := range arr {
		if i == 0 {
			arr[2] = "有人"
		}
		seen = append(seen, s)
	}
	fmt.Println("陣列：", seen)

	sl := []string{"空", "空", "空"}
	seen = nil
	for i, s := range sl {
		if i == 0 {
			sl[2] = "有人"
		}
		seen = append(seen, s)
	}
	fmt.Println("slice：", seen)
}

輸出

陣列： [空 空 空]
slice： [空 空 有人]

大陣列每次 range 都整個複製，也很浪費記憶體和時間。需要時可以改成 range arr[:] 或 &arr，這樣只會複製一個 slice header 或一個指標。只寫索引（for i := range arr）時不需要元素的值，就不會複製。實務上很少直接用陣列，這個差異知道就好。

3.3 字串：一次一個字元

Go 的字串是一串以 UTF-8 編碼的 byte。英文字母一個字元佔 1 byte，中文字大多佔 3 bytes。range 字串時，Go 會幫你解碼 UTF-8：每一圈給你一個字元（型別是 rune，其實就是 int32）和它在字串裡的起始 byte 位置，所以位置會跳號。

func rangeString() {
	s := "Go語言"
	for i, r := range s {
		fmt.Printf("位置 %d：%c（%U）\n", i, r, r)
	}
	fmt.Printf("len = %d，字元數 = %d\n", len(s), utf8.RuneCountInString(s))
}

輸出

位置 0：G（U+0047）
位置 1：o（U+006F）
位置 2：語（U+8A9E）
位置 5：言（U+8A00）
len = 8，字元數 = 4

對照兩種走法：

  • for i := 0; i < len(s); i++ 用 s[i] 拿到的是 byte，一個中文字會被拆成三塊。
  • for i, r := range s 拿到的是完整的字元。

要處理「字」就用 range，要處理原始資料（例如計算雜湊值）才逐 byte 走。如果字串裡有不合法的 UTF-8，range 會在那個位置給出 U+FFFD（替換字元），並且只前進 1 byte。UTF-8 的細節在第 08 章。

3.4 map：順序不固定

range map 會給你 key 和 value，但順序沒有保證。Go 的規格沒有規定順序，實際上 runtime 每次 range 都會從不同的位置開始，同一個程式跑兩次，結果就可能不同。這是刻意的設計，讓「依賴順序」的程式在開發階段就露出問題。需要固定順序時，先把 key 排序再走：

func rangeMap() {
	stock := map[string]int{"排骨": 5, "雞腿": 3, "魚排": 0}
	for _, name := range slices.Sorted(maps.Keys(stock)) {
		fmt.Println(name, stock[name])
	}
}

輸出

排骨 5
雞腿 3
魚排 0

maps.Keys 回傳所有的 key（它是一個可以 range 的函式），slices.Sorted 把它收集成排好序的 slice，兩個都是 Go 1.23 加入的。字串排序比的是 byte，所以中文是依 Unicode 碼位排序，不是依筆畫或注音。

一邊走一邊改 map

在 range 的過程中刪除還沒走到的 key，它就不會出現；新增的 key 則可能出現，也可能不出現。想要結果可預期，就先收集要刪的 key，迴圈結束後再刪。

3.5 channel：收到 close 為止

func rangeChannel() {
	tickets := make(chan string, 3)
	tickets <- "A01"
	tickets <- "A02"
	tickets <- "A03"
	close(tickets) // 沒有 close，range 會一直等下去
	for t := range tickets {
		fmt.Println("叫號", t)
	}
}

輸出

叫號 A01
叫號 A02
叫號 A03

range channel 會一直從 channel 接收值，直到 channel 被 close、而且裡面的值都收完為止。忘了 close 的話，迴圈會永遠等下去；如果其他 goroutine 也都在等，程式會因為死結（deadlock）而停止。channel 在第 15 章介紹，這裡先記住：range channel 一定要有人負責 close。

3.6 函式：自己做一個可以 range 的東西

func countdown(from int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for n := from; n > 0; n-- {
			if !yield(n) {
				return
			}
		}
	}
}

func rangeFunc() {
	for n := range countdown(3) {
		fmt.Println(n)
	}
	fmt.Println("發射")
}

輸出

3
2
1
發射

Go 1.23 起，range 後面也可以接特定形狀的函式。這個函式會收到一個 yield 函式，每呼叫一次 yield 就產生一個值；yield 回傳 false 代表使用者用 break 提早離開了，函式就應該停止。前面用過的 maps.Keys 就是這種函式。現在看得懂用法就好，第 13 章會從頭講怎麼寫。

3.7 range 的對象只求值一次

func rangeOnce() {
	nums := []int{1, 2, 3}
	count := 0
	for _, n := range nums {
		nums = append(nums, n*10)
		count++
	}
	fmt.Println("跑了", count, "圈，nums =", nums)
}

輸出

跑了 3 圈，nums = [1 2 3 10 20 30]

range 後面的運算式在迴圈開始前就求值好了，圈數也跟著固定。迴圈裡對 nums 做 append 會產生新的 slice，但 range 手上拿的還是一開始那個長度 3 的 slice，所以只跑 3 圈。三段式就不一樣：for i := 0; i < len(nums); i++ 的條件每一圈都會重新計算，如果迴圈裡一直 append，len 每圈都在變大，迴圈就永遠不會結束。

深入：第一次讀可以先跳過

3.8 每一圈都是新的變數

Go 1.22 改變了迴圈變數的語意：在 for 裡用 := 宣告的迴圈變數（不論是 range 還是三段式），每一圈都是一個新的變數。只有當你把迴圈變數的位址或 closure 留到那一圈之後才使用時，才看得出差別：

func loopVarPerIteration() {
	var perIter, shared []func() int
	for i := range 3 {
		perIter = append(perIter, func() int { return i }) // 每一圈的 i 都是新的
	}

	var j int
	for j = 0; j < 3; j++ {
		shared = append(shared, func() int { return j }) // j 宣告在迴圈外，三個 closure 共用它
	}

	for k := range 3 {
		fmt.Println(perIter[k](), shared[k]())
	}
}

輸出

0 3
1 3
2 3

perIter 裡的三個 closure 各自抓住自己那一圈的 i，所以是 0、1、2。shared 用的 j 宣告在迴圈外面，三個 closure 抓住的是同一個 j，等到呼叫時 j 已經變成 3。在 Go 1.22 之前，for i := range 3 的 i 也是所有圈共用的，結果會和 shared 一樣；當時常見的修法是在迴圈裡多寫一行 i := i。

新語意只套用在 go.mod 宣告 go 1.22 以上的 module，本 repo 宣告的是 go 1.27。以後在舊文章或舊程式裡看到 i := i，知道它是在補這個洞就好，新程式不需要再寫。

4. break、continue 與標籤

break 會離開最內層的 for、switch 或 select；continue 會跳到最內層 for 的下一圈。如果想在內層找到答案後直接離開外層，或在 switch 裡想離開外面的 for，就要用標籤（label）：在迴圈前面寫 名稱:，再用 break 名稱 或 continue 名稱 指定作用的對象。

4.1 break 加標籤：一次跳出兩層

func labeledBreak() {
	prices := []int{45, 55, 35, 65}
	budget := 100
search:
	for i := range prices {
		for j := i + 1; j < len(prices); j++ {
			if prices[i]+prices[j] == budget {
				fmt.Println("第", i, "和第", j, "個加起來剛好", budget, "元")
				break search
			}
		}
	}
}

輸出

第 0 和第 1 個加起來剛好 100 元

這裡有兩組加起來剛好 100（45+55 和 35+65），找到第一組就 break search，所以只印一行。如果只寫 break，跳出的只有內層的 j 迴圈，外層會繼續找，第二組也會被印出來。

4.2 continue 加標籤：直接換下一組

func labeledContinue() {
	classes := [][]int{{88, 92, 75}, {90, 55, 80}, {60, 70, 65}}
nextClass:
	for c, scores := range classes {
		for _, s := range scores {
			if s < 60 {
				fmt.Println("第", c+1, "班有人不及格：", s)
				continue nextClass
			}
		}
		fmt.Println("第", c+1, "班全部及格")
	}
}

輸出

第 1 班全部及格
第 2 班有人不及格： 55
第 3 班全部及格

第 2 班一看到 55 分，就 continue nextClass：跳過這一班剩下的分數，也跳過「全部及格」那一行，直接檢查第 3 班。

4.3 switch 裡的 break 只跳出 switch

這是從其他語言轉過來最常踩的坑。在 C 或 Java 的傳統 switch 裡，case 結尾要寫 break 才不會往下掉，所以手很習慣在 case 裡寫 break。Go 的 switch 本來就不會往下掉，case 裡的 break 只會結束這個 switch，外面的 for 照樣跑下一圈：

錯誤寫法：以為 break 會離開迴圈

func countUntilStopBuggy(cmds []string) int {
	handled := 0
	for _, c := range cmds {
		switch c {
		case "stop":
			break
		default:
			handled++
		}
	}
	return handled
}

正確寫法：幫迴圈加上標籤

func countUntilStop(cmds []string) int {
	handled := 0
loop:
	for _, c := range cmds {
		switch c {
		case "stop":
			break loop
		default:
			handled++
		}
	}
	return handled
}
func breakInSwitch() {
	cmds := []string{"開燈", "開冷氣", "stop", "關門"}
	fmt.Println("沒有標籤：", countUntilStopBuggy(cmds))
	fmt.Println("有標籤：", countUntilStop(cmds))
}

輸出

沒有標籤： 3
有標籤： 2

沒有標籤的版本遇到 "stop" 只是離開 switch，接著處理了 "關門"，所以算出 3。修法有兩種：像 countUntilStop 一樣幫迴圈加標籤，或者把迴圈抽成函式，在 case 裡直接 return。select（第 16 章）裡的 break 也是同樣的規則。

深入：第一次讀可以先跳過

4.4 goto

Go 也有 goto，可以跳到同一個函式裡的標籤。它有兩條限制：不能跳過變數宣告，也不能從區塊外面跳進區塊裡面。違反時編譯器會直接拒絕：

package main

import "fmt"

func main() {
	goto done
	n := 1
done:
	fmt.Println(n)
}

編譯錯誤

./main.go:6:7: goto done jumps over declaration of n at ./main.go:7:4

這兩條限制保證了跳過去之後，用到的變數一定已經宣告過。一般的應用程式碼幾乎用不到 goto，用 for、break、return 能表達的，就不要用它。

5. switch：多選一

switch 拿一個值，依序和每個 case 比對，執行第一個相符的 case，然後整個 switch 就結束。它和 C、Java 傳統 switch 最大的不同是不會往下掉（fall through）：不需要、也不應該在每個 case 結尾寫 break。

5.1 比對一個值

func switchValue() {
	for _, day := range []string{"六", "二", "日"} {
		switch day {
		case "六", "日":
			fmt.Printf("星期%s：假日\n", day)
		default:
			fmt.Printf("星期%s：上班\n", day)
		}
	}
}

輸出

星期六：假日
星期二：上班
星期日：假日
  • 一個 case 可以列多個值，用逗號隔開，符合任何一個就執行。
  • default 是「都不符合」時的去處，可以放在任何位置，但放在最後最好讀。沒有 default、也沒有任何 case 相符時，switch 什麼都不做。
  • case 的值不一定要是常數，可以是任何運算式，只要能和比對的值用 == 比較。

5.2 switch 前面也能先做一件事

func switchInit() {
	for _, name := range []string{"王明", "陳小美", "歐陽靖文", "李"} {
		switch n := utf8.RuneCountInString(name); n {
		case 2, 3:
			fmt.Printf("%s：一般長度\n", name)
		case 4:
			fmt.Printf("%s：可能是複姓\n", name)
		default:
			fmt.Printf("%s：%d 個字，請再確認\n", name, n)
		}
	}
}

輸出

王明：一般長度
陳小美：一般長度
歐陽靖文：可能是複姓
李：1 個字，請再確認

和 if 一樣，switch 可以有一個初始化敘述，宣告的 n 只活在這個 switch 裡。utf8.RuneCountInString 計算的是字串有幾個字元，不是幾個 byte；用 len(name) 的話，「王明」會得到 6。

5.3 沒有比對值的 switch

func aqiLevel(aqi int) string {
	switch {
	case aqi <= 50:
		return "良好"
	case aqi <= 100:
		return "普通"
	case aqi <= 150:
		return "對敏感族群不健康"
	case aqi <= 200:
		return "對所有族群不健康"
	case aqi <= 300:
		return "非常不健康"
	default:
		return "危害"
	}
}

func switchTrue() {
	for _, v := range []int{35, 120, 320} {
		fmt.Printf("AQI %d：%s\n", v, aqiLevel(v))
	}
}

輸出

AQI 35：良好
AQI 120：對敏感族群不健康
AQI 320：危害

switch 後面不寫值，就等於 switch true：每個 case 都是一個 bool 運算式，第一個成立的會被執行。一長串 if … else if … else if 改寫成這個形式，排版整齊，每個區間也一目了然。因為 case 是由上往下判斷的，aqi <= 100 不需要再寫 aqi > 50：能走到這個 case，就代表上面的條件都不成立。

5.4 case 的求值順序

func check(label string, ok bool) bool {
	fmt.Println("檢查", label)
	return ok
}

func switchOrder() {
	n := 7
	switch {
	case check("n > 10", n > 10):
		fmt.Println("大於 10")
	case check("n > 5", n > 5):
		fmt.Println("大於 5")
	case check("n > 0", n > 0):
		fmt.Println("大於 0")
	}
}

輸出

檢查 n > 10
檢查 n > 5
大於 5

case 會依照書寫的順序一個一個求值，找到成立的就停。n 是 7：n > 10 不成立，n > 5 成立，所以第三個 case 的 check 根本沒被呼叫。如果某個 case 的判斷比較耗時（例如要查資料庫），就把便宜又常見的情況放前面。

5.5 fallthrough：真的要往下掉

func perks(level string) []string {
	var got []string
	switch level {
	case "金卡":
		got = append(got, "機場接送")
		fallthrough
	case "銀卡":
		got = append(got, "免運")
		fallthrough
	case "一般":
		got = append(got, "生日禮")
	}
	return got
}

func switchFallthrough() {
	for _, lv := range []string{"金卡", "銀卡", "一般", "訪客"} {
		fmt.Println(lv, perks(lv))
	}
}

輸出

金卡 [機場接送 免運 生日禮]
銀卡 [免運 生日禮]
一般 [生日禮]
訪客 []

fallthrough 寫在 case 的最後一行，會不檢查下一個 case 的條件，直接執行下一個 case 的程式。會員等級是少數適合它的場景：金卡有銀卡的所有優惠，銀卡又有一般會員的所有優惠。使用時有三條規則：

  • fallthrough 必須是 case 裡的最後一個敘述，也不能出現在最後一個 case。
  • type switch（5.6）裡不能用 fallthrough。
  • 它不檢查下一個 case 的條件，即使下一個是 case x > 100: 也照樣執行，很容易被誤解。大部分情況下，把共同的程式抽成函式會更清楚。

5.6 預告：依照型別分支

func describe(x any) string {
	switch v := x.(type) {
	case nil:
		return "nil"
	case int:
		return fmt.Sprintf("整數 %d，兩倍是 %d", v, v*2)
	case string:
		return fmt.Sprintf("字串 %q，長度 %d", v, len(v))
	default:
		return fmt.Sprintf("其他型別 %T", v)
	}
}

func typeSwitch() {
	for _, x := range []any{42, "便當", 3.5, nil} {
		fmt.Println(describe(x))
	}
}

輸出

整數 42，兩倍是 84
字串 "便當"，長度 6
其他型別 float64
nil

x.(type) 只能寫在 switch 裡。它依照 interface 值實際存放的型別選擇 case，並且在每個 case 裡把 v 變成對應的型別：在 case int 裡 v 就是 int，所以能算 v*2。any 和 interface 在第 10 章介紹。

5.7 不能有重複的常數 case

package main

import "fmt"

func main() {
	day := "六"
	switch day {
	case "六", "日":
		fmt.Println("假日")
	case "日":
		fmt.Println("星期日")
	}
}

編譯錯誤

./main.go:10:7: duplicate case "日" (constant of type string) in expression switch
	./main.go:8:14: previous case

case 的值是常數時，編譯器會檢查有沒有重複。列表很長的時候，這個檢查能抓到複製貼上造成的錯誤：上面的 "日" 永遠只會走第一個 case，第二個 case 是死碼。

常見錯誤

1. 把 { 換到下一行

package main

import "fmt"

func main() {
	n := 3
	if n > 0
	{
		fmt.Println("正數")
	}
}

編譯錯誤

./main.go:7:10: syntax error: unexpected newline, expected { after if clause

Go 的語法其實需要分號，只是你不用自己寫：編譯器讀程式時，會在某些 token 結尾的行尾自動補上分號，例如識別字、數字、字串，以及 )、]、}。if n > 0 這一行以數字 0 結尾，於是被補成 if n > 0;，下一行的 { 就變成沒有歸屬的區塊。所以 Go 的大括號只有一種擺法，這也是 gofmt 能讓所有人的程式長得一樣的原因之一。

2. 在 if 裡用 := 蓋掉外層的變數

readSetting 會回傳設定值和錯誤。兩個版本都想把讀到的主題存進 theme：

錯誤寫法

func loadTheme(fromSettings bool) string {
	theme := "light"
	if fromSettings {
		theme, err := readSetting("theme")
		if err != nil {
			return "讀取失敗"
		}
		fmt.Println("if 裡讀到：", theme)
	}
	return theme
}

正確寫法

func loadThemeFixed(fromSettings bool) string {
	theme := "light"
	if fromSettings {
		var err error
		theme, err = readSetting("theme")
		if err != nil {
			return "讀取失敗"
		}
	}
	return theme
}
func shadowPitfall() {
	fmt.Println("錯誤寫法回傳：", loadTheme(true))
	fmt.Println("正確寫法回傳：", loadThemeFixed(true))
}

輸出

if 裡讀到： dark
錯誤寫法回傳： light
正確寫法回傳： dark

loadTheme 在 if 裡寫了 theme, err :=。在內層區塊裡，:= 左邊的名字都是這個區塊的新變數，於是 if 裡多了一個新的 theme。讀到的 "dark" 存進了新變數，離開 if 就消失了，函式回傳的還是外層的 "light"。修法是先 var err error，再用 = 賦值。go vet 預設不檢查 shadowing（有另外一個可以安裝的 shadow 分析器），最可靠的方法還是：看到 if 或 for 裡面的 := 時多看一眼。

3. 以為 switch 裡的 break 會離開迴圈

在 for 裡面的 switch 寫 break，只會離開 switch，迴圈照跑。要離開迴圈，請用標籤或 return，完整的例子見 4.3。

4. 用無號整數倒著數

錯誤寫法

func reverseBuggy(s []string) []string {
	var out []string
	for i := uint(len(s)) - 1; i >= 0; i-- {
		out = append(out, s[i])
	}
	return out
}

執行結果（用 recover 接住 panic 後印出）

panic: runtime error: index out of range [18446744073709551615] with length 2

正確寫法

func reverse(s []string) []string {
	var out []string
	for i := len(s) - 1; i >= 0; i-- {
		out = append(out, s[i])
	}
	return out
}

uint 不會小於 0，所以 i >= 0 永遠成立。i 從 1 減到 0，再減 1 就繞回 uint 的最大值 18446744073709551615（64 位元平台），接著 s[i] 索引越界而 panic。編譯器和 go vet 都不會提醒你。倒著走請用 int；Go 1.23 起也可以寫 for i, v := range slices.Backward(s)，連邊界都不用算。

5. 以為改迴圈變數就會改到 slice

for _, d := range menu 裡的 d 是複本，改它不會影響 menu。要修改元素請用索引 menu[i]，見 3.1。

	}
	return total
}

    例如 []int{3, 4, -1, 10} 應該得到 7，現在卻得到 17。測試：TestTotalUntilNegative。

重點回顧

  • 條件不加括號，大括號一定要寫，{ 不能換行；條件必須是 bool。
  • if v, err := f(); err != nil 讓暫時的變數只活在 if/else 裡。
  • 用 guard clause 先處理例外並 return，主流程靠左。
  • 在內層區塊用 := 會產生新變數，小心蓋掉外層的同名變數。
  • for 一個關鍵字涵蓋三段式、while、無窮迴圈和 range。
  • range 給的是複本；要修改 slice 的元素請用索引。
  • range 字串一次給一個 rune，位置是 byte 位置。
  • range map 沒有固定順序，需要時先排序 key。
  • range 的對象只求值一次；Go 1.22 起每一圈都是新的迴圈變數。
  • switch 不會往下掉；switch 裡的 break 只離開 switch，要離開迴圈請用標籤。
  • 沒有比對值的 switch 是一長串 if-else 的整齊寫法，case 由上往下求值，找到就停。
